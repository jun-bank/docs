# 외부 인터페이스 규격 — 공통 규약·색인

- 상태: 검토대기 (2026-08-06 신설 — `plans/2026-08-06/interface-specs/`)
- ★ **상위 정본 = UC §7 계약 블록**(의미·오류 코드·멱등 키) — 이 규격은 그 표면의 **물리 표현**이다. 충돌하면 규격이 틀린 것이다.

## 1. 공통 규약 (X-1~8)

| # | 규약 |
|---|---|
| **X-1 인코딩** | ASCII(숫자·영대문자·공백) — 한글·자유 텍스트 필드 없음(사유 등 서술 값은 **코드로만**). 바이트 = 문자 1:1 |
| **X-2 패딩** | 숫자(N) = **좌측 0 패딩** · 문자(AN) = **우측 공백 패딩**. 빈 선택 필드 = 전부 공백 |
| **X-3 금액** | **12N — 통화 최소단위 정수**(BR-07: 부동소수 금지. KRW = 원 단위). 통화 필드는 두지 않는다(단일 통화 — 도입 시 새 전문 버전) |
| **X-4 일시** | 전송일시 = 14N `YYYYMMDDHHMMSS`(발신측 시각 — 참고용). ★ **요청 방향에서 귀속 영업일의 판정 입력이 되는 필드는 없다** — 수신 시각 기준 BR-14가 정본(보고 5 정합: **응답에는 판정 결과인 귀속 영업일을 실을 수 있다** — 파일 헤더의 영업일 표기(X-8·BR-14 파일 특칙)와 같은 갈래) |
| **X-5 공통 헤더** (전 전문 선두 50바이트) | ①전문길이 4N(헤더 포함 전체) ②전문구분 10AN — ★ **물리 구분값**(정본 이름 K-2의 매핑 — X-7과 같은 원리): `AUTHREQ`·`AUTHRES`·`CANCELREQ`·`CANCELRES`·`RVSLREQ`·`RVSLRES`·`DEPADV`·`DEPADVRES`(전부 ≤10. 보고 1 해소 — K-2 이름 12자가 10AN을 넘던 충돌은 이름이 아니라 물리 값 층에서 푼다) ③전문버전 2N(`01`) ④상관 식별자 20AN(**멱등 키** — 채널별 의미는 각 규격 §멱등) ⑤전송일시 14N |
| **X-6 기관 코드** | 8AN — 발신 기관(매입사·입금원) 식별. **코드 체계 = [미확정 — 외부 규격 의존]**(자리만 고정) |
| **X-7 응답 코드** | 4N — ★ **정본 코드(신설 코드 대장·SM 응답 열의 문자 상수)의 물리 매핑**. 매핑 표는 각 규격 §응답 코드에 있으며 **숫자 값은 [미확정 — 대외 협의]**, 이 문서 단계의 정본은 문자 상수다. 시스템 채널은 **사유 구분**이 정본 요구(BR-36·15 — L7 비적용, C-2 채널 경계) |
| **X-8 파일 공통** | 고정길이 레코드 + **H/D/T**: 헤더(파일 ID·영업일·건수 예고) / 데이터(레코드 유형 코드로 구분) / 트레일러(**totalRecords·금액 합계** — 배치 INV-3의 입력). 레코드 구분자 없음(고정길이) · 파일 인코딩 X-1 |

> 재수신 = **최초 결과 재반환**(K-1 — 채널 유일 식별자 기준). 각 규격의 §멱등이 키의 정본 소유자를 지목한다.

| # | 규약 (추가) |
|---|---|
| **X-9 요청 지문** | BR-02·29의 `requestFingerprint` = ★ **본문(공통 헤더 제외)의 해시** — 전송일시·전문길이 등 헤더는 제외한다(포함하면 정상 재전송이 전부 `IDEMPOTENCY_CONFLICT`가 된다 — 보고 6 확정. BR-02 "요청 내용"의 물리 정의) |
