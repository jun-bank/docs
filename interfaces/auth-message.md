# 전문 규격 `AUTH-REQ` / `AUTH-RES` — 카드 결제 승인

- 상태: **검토대기** (2026-08-06 신설 — `plans/2026-08-06/interface-specs/`)
- ★ **정본 = [UC-01 §7 계약 블록](../usecases/UC-01-authorize-payment.md)** (의미 필드·오류 코드·멱등 키). 이 문서는 그 표면의 **물리 표현**이며, 충돌하면 **이 문서가 틀린 것이다**.
- 전제: **공통 규약 X-1~11**([README.md](README.md)) — 인코딩(X-1)·패딩(X-2)·금액 12N + **통화 3AN**(X-3)·일시(X-4)·공통 헤더 50바이트(X-5)·기관 코드(X-6)·응답 코드(X-7)·**요청 지문(X-9)**·**판정 순서(X-10)**·**PAN 취급(X-11)**. **여기서 재정의하지 않는다.**
- 채널: 매입사 → 발급사 · 실시간 동기 전문 · 내부 deadline **2.5초**(T-11 — UC-01 §7 예산)

> 오프셋은 **0-base 바이트**이며 X-1(ASCII, 바이트 = 문자 1:1)에 따라 문자 수와 같다.

---

## 1. 요청 전문 `AUTH-REQ` — 필드 표

**전문 길이 선언 = 104바이트** (`전문길이` 필드값 `0104`)

| # | 필드 | 오프셋 | 길이 | 타입 | 필수 | 의미 | 정본 연결 | ISO 8583 참조 |
|---|---|---|---|---|---|---|---|---|
| H | **공통 헤더** | 0 | 50 | — | ✓ | X-5 ①전문길이 4N ②전문구분 10AN = **`AUTHREQ`**(물리 구분값 — README X-5②가 정본, K-2 이름 `AUTH-REQ`의 매핑) ③전문버전 2N = `01` ④**상관 식별자 20AN** ⑤전송일시 14N | X-5 · ④ = BR-17 ① · K-2 | ② ≈ MTI `0100` · ④ ≈ DE 37(RRN an12 — 길이 상이) · ⑤ ≈ DE 7(MMDDhhmmss — 형식 상이) |
| 1 | **통화** | 50 | 3 | AN | ✓ | `KRW` 고정 — **본문 선두**(X-3 개정 · R-01). BR-07의 *"통화와 최소단위"* 를 필드로 충족한다 | **BR-07** · X-3 | **DE 49** (Currency Code, an3 — 일치) |
| 2 | 기관 코드 | 53 | 8 | AN | ✓ | 발신 매입사 식별 | X-6 (**코드 체계 [미확정]**) | DE 32 (LLVAR n..11 — 형식 상이) |
| 3 | 카드번호 (PAN) | 61 | 16 | N | ✓ | 승인 대상 카드. 계좌는 **시스템이 카드 참조로 유도**한다(UC-01 §6 — 전문은 계좌를 지목하지 않는다). ★ **X-11 적용** — 이 규격 5종에서 PAN을 싣는 유일한 필드이며, **평문은 멱등·승인 판정의 메모리 경로까지**다. 저장·로그·감사·불일치·DLQ 표면에는 **마스킹**(BIN 6 + 말미 4) | BR-36 · BR-15 · **X-11** · UC-01 §7 요청 | **DE 2** (PAN — LLVAR n..19, 고정 16N으로 축약) |
| 4 | 금액 | 77 | 12 | N | ✓ | 승인 요청 금액 — 통화 최소단위 정수(통화는 필드 1) | BR-07 · X-3 · UC-01 §7 요청 | **DE 4** (n12 — 일치) |
| 5 | 가맹점 ID | 89 | 15 | AN | ✓ | 결제가 발생한 가맹점 | UC-01 §7 요청 | **DE 42** (Card Acceptor ID, ans15 — 길이 일치) |

> ★ **길이 근거**: 금액 12N·통화 3AN은 X-3(BR-07) 고정값이며 금액은 BR-05의 한도 자릿수(1회 100만 · 1일 300만 — 7자리)를 **여유 있게 덮는다**. **카드번호 16N = 자행 카드 16자리 고정 전제**(BR-05 수치 칸에 정본 명시 — R-07. 다른 자릿수 체계 도입 = **새 전문 버전**)이고, 가맹점 ID 15AN·상관 식별자 20AN은 **관행 상식선**이다(BR-17 수치 칸 = *미확정* — §5).
>
> ★ **싣지 않는 것**: 귀속 영업일(X-4 — **전문의 필드가 아니다**, 수신 시각 기준 BR-14가 정본) · 요청 지문(§4 — 본문에서 **파생**한다 · X-9).

## 2. 응답 전문 `AUTH-RES` — 필드 표

**전문 길이 선언 = 89바이트** (`전문길이` 필드값 `0089`)

| # | 필드 | 오프셋 | 길이 | 타입 | 필수 | 의미 | 정본 연결 | ISO 8583 참조 |
|---|---|---|---|---|---|---|---|---|
| H | **공통 헤더** | 0 | 50 | — | ✓ | ②전문구분 = **`AUTHRES`**(물리 구분값 — README X-5②) · ④**상관 식별자 = 요청과 동일값**(멱등·대사의 연결 고리) | X-5 · K-2 | ② ≈ MTI `0110` |
| 1 | **통화** | 50 | 3 | AN | ✓ | `KRW` 고정 — 요청과 같은 자리·같은 값(X-3 · R-01) | BR-07 · X-3 | DE 49 |
| 2 | 기관 코드 | 53 | 8 | AN | ✓ | 요청의 기관 코드를 그대로 반향 | X-6 | DE 32 |
| 3 | **응답 코드** | 61 | 4 | N | ✓ | 승인/거절 및 **사유 구분**(§3) | X-7 · UC-01 §7 오류 표 · BR-36·15 | **DE 39** (an2/an3 — 길이·타입 상이) |
| 4 | 승인번호 | 65 | 12 | AN | 조건부 | 승인 성립 시 **발급사가 발번**. ★ **제3형태 `VOIDED_BY_RESERVATION`에서도 발번해 회신**한다(아래 주). 그 외 거절은 **전부 공백**(X-2) | BR-17 ② · UC-01 §7 응답(성공) · §4-B | DE 38 (an6 — 길이 상이) |
| 5 | 승인 금액 | 77 | 12 | N | 조건부 | 성립한 승인 금액. **거절 · 제3형태는 좌측 0 패딩된 0**(X-2 — 성립한 자금이 없다) | BR-07 · X-3 · UC-01 §7 응답(성공) | DE 4 |

> ★ **부분 승인이 없다** — UC-01 §5가 부분 승인·할부를 범위 밖으로 두므로 승인 금액은 항상 요청 금액과 같다. 필드를 남기는 이유는 매입사 대사(BR-30 계열)의 자기검증 값이기 때문이다.
>
> ★ **응답의 제3형태 — 취소 예약 소비**(2026-08-06 R-03 확정 · UC-01 §4-B): 뒤늦게 도착한 승인이 **유효한 취소 예약을 만나면** 승인 레코드가 **`VOIDED`로 생성**된다(승인 T3 · 예약 R2 — 홀딩 없이 한 커밋). 이때 응답은 **승인도 일반 거절도 아닌 제3형태**이며 직렬화는 다음과 같다:
>
> | 필드 | 값 |
> |---|---|
> | 응답 코드 | **`VOIDED_BY_RESERVATION`** 의 물리값(§3 — 코드 대장 등재) |
> | 승인번호 | ★ **발번해서 싣는다** — 승인 레코드가 `VOIDED` 상태로 **실재**하므로, 매입사가 그 건을 대사·조회로 지목할 **연결 고리**가 필요하다(BR-17 ②). 여기서만 *"거절인데 승인번호가 있다"* |
> | 승인 금액 | **0** — 성립한 자금이 없다(홀딩도 잡히지 않았다) |
>
> ⚠️ 승인번호를 비우면 매입사는 이 건을 **상관 식별자로만** 지목하게 되어, 나중에 도착하는 대사·조회 경로가 BR-17 ②를 쓸 수 없다.

## 3. 응답 코드 매핑

> **정본은 문자 상수**다(X-7 · K-1 ⑵⑶ — 신설 코드 대장). **물리 4N 값은 [미확정 — 대외 협의]** 이며 이 표는 자리만 고정한다.
> **판정 순서 = X-10**(2026-08-06 R-05 정정 — 구 *"① 자기 속성 → ② 대상 존재 → ③ 상태·인자"* 를 **대체**한다): **① 인자 형식 → ② 멱등 단락 → ③ 대상 존재 → ④ 상태.** 채널 인가(`FORBIDDEN_LEVEL`)는 전문 처리 **이전**의 ACL 판정이라 표에 **채널**로 적는다.
> ★ **L7 비적용** — 매입사 전문 채널의 사유 구분은 **BR-36·BR-15가 명시 요구하는 정본 특칙**이다(UC-01 §6 · C-2 채널 조항).

| 문자 상수 (정본) | 사유 | 정본 위치 | 판정 순서 | 물리 4N |
|---|---|---|---|---|
| (성공 — 승인) | 승인 성립 · 승인번호 발번 | UC-01 §3-6 · 승인 T1 | — | [미확정] |
| `FORBIDDEN_LEVEL` | 경로 식별자 부재·미인가 (대상 조회 전) | K-1 ① · UC-07 §7 선례 | 채널 | [미확정] |
| `IDEMPOTENCY_CONFLICT` | 같은 상관 식별자 · **다른 요청 지문**(X-9) | **BR-02** · 멱등 INV-2 · UC-01 §4-A | ② | [미확정] |
| `DECLINED_UNREGISTERED` | 미등록 카드번호 — **대상 존재** 단계 | **BR-36** · UC-01 §4-D | ③ | [미확정] |
| ★ `CARD_SUSPENDED` | 카드 **정지** — 사용 불가 (구 `DECLINED_CARD` 3분 ① · **SM 응답 열 CF4 재사용**, 신설 아님) | **BR-15** · UC-01 §4-C · 카드 SM **CF4** | ④ | [미확정] |
| ★ `CARD_EXPIRED` | 카드 **만료** — 사용 불가 (3분 ② · **CF6 재사용**) | **BR-15** · UC-01 §4-C · 카드 SM **CF6** | ④ | [미확정] |
| ★ `CARD_TERMINATED` | 카드 **해지** — 사용 불가 (3분 ③ · **CF3 재사용**) | **BR-15** · UC-01 §4-C · 카드 SM **CF3** | ④ | [미확정] |
| `DECLINED_FUNDS` | 가용잔액 부족 | BR-04 · UC-01 §4-E | ④ | [미확정] |
| `DECLINED_LIMIT` | 카드 1회/1일 한도 또는 계좌 한도 초과 | BR-05 · BR-44 · UC-01 §4-E | ④ | [미확정] |
| `DECLINED_RECEIVABLE_BLOCK` | 미결 미수 계좌 (차단 해제된 계좌는 통과) | **BR-45** · UC-01 §4-F | ④ | [미확정] |
| ★ `VOIDED_BY_RESERVATION` | ★ **제3형태** — 유효한 취소 예약을 소비해 승인이 `VOIDED`로 성립(§2 주 · 응답 = 코드 + **승인번호 발번** + 금액 0) | **코드 대장** · UC-01 §4-B · 승인 **T3** · 예약 **R2** | ④ | [미확정] |
| `DUPLICATE_AUTHORIZATION` | `REQUESTED` 외 상태에 `authorize` — ★ **실제로는 ② 멱등 단락이 선차단**한다(F8 주석) | 승인 SM **F8** | ④ | [미확정] — 물리 매핑 불요 후보 |
| `TIMEOUT_RETRYABLE` | 락 충돌·내부 deadline(2.5초) 초과 — 재시도 3회 내 미해결 | UC-01 §4-H · ADR-012 W-10 · T-11 | 처리 중 | [미확정] |

> ✅ **해소 (2026-08-06 메인 판정 — 보고 3 · R-04)**: 카드 사유 3분 = **SM 응답 열 재사용**(CF4·CF6·CF3 — K-1 ⑵ 원칙 그대로, 코드 대장 등재됨). 부가 사유 필드 불요. ★ **물리 값 자리도 3개로 분리**한다 — 한 행에 묶어두면 물리 매핑에서 **한 값으로 접힐 위험**이 있다(BR-15의 구분 요구가 사라진다).
>
> ★ `TIMEOUT_RETRYABLE`은 판정 단계의 결론이 아니라 **처리 중 중단**의 결과라 ①~④ 어디에도 속하지 않는다(어느 단계에서든 날 수 있다).

## 4. 멱등

| 항목 | 내용 |
|---|---|
| **키** | ★ **`(기관, 상관 식별자, 승인)`** — 헤더 ④ 20AN이 그 상관 식별자이고, **기관**은 본문 필드 2(발신 매입사)다. **매입사가 승인 요청 시점에 생성**한다(BR-17 ①) |
| **기관 축** | ★ **채널 키의 유일성은 발신 기관 스코프**다(2026-08-06 R-06 — 정본 개정: 멱등 레코드 INV-1). 매입사마다 자기 식별자 체계를 쓰므로 전역 유일을 가정하면 **다른 매입사의 우연한 같은 값이 남의 승인 결과를 반환**한다 |
| **정본 소유자** | **`IdempotencyRecord`**(key = 상관 식별자, operation = 승인, 기관 스코프 — **INV-1**) — C3 결제. `find`/`record`가 UC-01 §3-2·§3-6의 단계다 |
| **재수신** | 지문 동일 → **최초 결과 재반환**(무변화 — BR-02 · K-1 시스템 채널). ★ 이 판정은 **대상 조회보다 앞선다**(X-10 ②) / 지문 상이 → `IDEMPOTENCY_CONFLICT` |
| **보관** | **24시간**(BR-02 [1차] — Stripe 선례). 원거래 지목(BR-17)은 **영구**이며 이 창과 다른 메커니즘이다 |
| **요청 지문** | 전문 **본문에서 파생**한다 — 전송되는 필드가 아니다. ✅ **산출 범위·알고리즘 확정 = X-9**(2026-08-06 R-09): **(전문버전 + 정규화 본문)의 keyed hash(HMAC)** · **전송일시 제외**(넣으면 정상 재전송이 전부 충돌로 거절된다) · 키 관리는 **[구현 검증] IV-12** |
| **응답 유실** | 성립분은 성립한 대로 남고 매입사의 **망취소**(`REVERSAL-REQ`)가 정합을 회복한다 — BR-13·22 · UC-01 §4-G |
