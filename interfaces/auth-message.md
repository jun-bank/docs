# 전문 규격 `AUTH-REQ` / `AUTH-RES` — 카드 결제 승인

- 상태: **검토대기** (2026-08-06 신설 — `plans/2026-08-06/interface-specs/`)
- ★ **정본 = [UC-01 §7 계약 블록](../usecases/UC-01-authorize-payment.md)** (의미 필드·오류 코드·멱등 키). 이 문서는 그 표면의 **물리 표현**이며, 충돌하면 **이 문서가 틀린 것이다**.
- 전제: **공통 규약 X-1~8**([README.md](README.md)) — 인코딩(X-1)·패딩(X-2)·금액 12N(X-3)·일시(X-4)·공통 헤더 50바이트(X-5)·기관 코드(X-6)·응답 코드(X-7). **여기서 재정의하지 않는다.**
- 채널: 매입사 → 발급사 · 실시간 동기 전문 · 내부 deadline **2.5초**(T-11 — UC-01 §7 예산)

> 오프셋은 **0-base 바이트**이며 X-1(ASCII, 바이트 = 문자 1:1)에 따라 문자 수와 같다.

---

## 1. 요청 전문 `AUTH-REQ` — 필드 표

**전문 길이 선언 = 101바이트** (`전문길이` 필드값 `0101`)

| # | 필드 | 오프셋 | 길이 | 타입 | 필수 | 의미 | 정본 연결 | ISO 8583 참조 |
|---|---|---|---|---|---|---|---|---|
| H | **공통 헤더** | 0 | 50 | — | ✓ | X-5 ①전문길이 4N ②전문구분 10AN = `AUTH-REQ` ③전문버전 2N = `01` ④**상관 식별자 20AN** ⑤전송일시 14N | X-5 · ④ = BR-17 ① · K-2 | ② ≈ MTI `0100` · ④ ≈ DE 37(RRN an12 — 길이 상이) · ⑤ ≈ DE 7(MMDDhhmmss — 형식 상이) |
| 1 | 기관 코드 | 50 | 8 | AN | ✓ | 발신 매입사 식별 | X-6 (**코드 체계 [미확정]**) | DE 32 (LLVAR n..11 — 형식 상이) |
| 2 | 카드번호 | 58 | 16 | N | ✓ | 승인 대상 카드. 계좌는 **시스템이 카드 참조로 유도**한다(UC-01 §6 — 전문은 계좌를 지목하지 않는다) | BR-36 · BR-15 · UC-01 §7 요청 | **DE 2** (PAN — LLVAR n..19, 고정 16N으로 축약) |
| 3 | 금액 | 74 | 12 | N | ✓ | 승인 요청 금액 — 통화 최소단위 정수(KRW = 원). 통화 필드 없음(X-3) | BR-07 · X-3 · UC-01 §7 요청 | **DE 4** (n12 — 일치) |
| 4 | 가맹점 ID | 86 | 15 | AN | ✓ | 결제가 발생한 가맹점 | UC-01 §7 요청 | **DE 42** (Card Acceptor ID, ans15 — 길이 일치) |

> ★ **길이 근거**: 금액 12N은 X-3(BR-07) 고정값이며 BR-05의 한도 자릿수(1회 100만 · 1일 300만 — 7자리)를 **여유 있게 덮는다**. 카드번호 16N·가맹점 ID 15AN·상관 식별자 20AN은 **관행 상식선**이다(BR-17 수치 칸 = *미확정*이므로 정본이 값을 주지 않는다 — §5).
>
> ★ **싣지 않는 것**: 통화(X-3 단일 통화) · 귀속 영업일(X-4 — **전문의 필드가 아니다**, 수신 시각 기준 BR-14가 정본) · 요청 지문(§4 — 본문에서 **파생**한다).

## 2. 응답 전문 `AUTH-RES` — 필드 표

**전문 길이 선언 = 86바이트** (`전문길이` 필드값 `0086`)

| # | 필드 | 오프셋 | 길이 | 타입 | 필수 | 의미 | 정본 연결 | ISO 8583 참조 |
|---|---|---|---|---|---|---|---|---|
| H | **공통 헤더** | 0 | 50 | — | ✓ | ②전문구분 = `AUTH-RES` · ④**상관 식별자 = 요청과 동일값**(멱등·대사의 연결 고리) | X-5 · K-2 | ② ≈ MTI `0110` |
| 1 | 기관 코드 | 50 | 8 | AN | ✓ | 요청의 기관 코드를 그대로 반향 | X-6 | DE 32 |
| 2 | **응답 코드** | 58 | 4 | N | ✓ | 승인/거절 및 **사유 구분**(§3) | X-7 · UC-01 §7 오류 표 · BR-36·15 | **DE 39** (an2/an3 — 길이·타입 상이) |
| 3 | 승인번호 | 62 | 12 | AN | 조건부 | 승인 성립 시 **발급사가 발번**. 거절 시 **전부 공백**(X-2) | BR-17 ② · UC-01 §7 응답(성공) | DE 38 (an6 — 길이 상이) |
| 4 | 승인 금액 | 74 | 12 | N | 조건부 | 성립한 승인 금액. 거절 시 **좌측 0 패딩된 0**(X-2) | BR-07 · X-3 · UC-01 §7 응답(성공) | DE 4 |

> ★ **부분 승인이 없다** — UC-01 §5가 부분 승인·할부를 범위 밖으로 두므로 승인 금액은 항상 요청 금액과 같다. 필드를 남기는 이유는 매입사 대사(BR-30 계열)의 자기검증 값이기 때문이다.

## 3. 응답 코드 매핑

> **정본은 문자 상수**다(X-7 · K-1 ⑵⑶ — 신설 코드 대장). **물리 4N 값은 [미확정 — 대외 협의]** 이며 이 표는 자리만 고정한다.
> **판정 순서**(K-1) = ① 자기 속성(채널·경로) → ② 대상 존재 → ③ 상태·인자.
> ★ **L7 비적용** — 매입사 전문 채널의 사유 구분은 **BR-36·BR-15가 명시 요구하는 정본 특칙**이다(UC-01 §6 · C-2 채널 조항).

| 문자 상수 (정본) | 사유 | 정본 위치 | 물리 4N |
|---|---|---|---|
| (성공 — 승인) | 승인 성립 · 승인번호 발번 | UC-01 §3-6 · 승인 T1 | [미확정] |
| `FORBIDDEN_LEVEL` | 경로 식별자 부재·미인가 (대상 조회 전) | K-1 ① · UC-07 §7 선례 | [미확정] |
| `DECLINED_UNREGISTERED` | 미등록 카드번호 | **BR-36** · UC-01 §4-D | [미확정] |
| ★ `CARD_SUSPENDED` / `CARD_EXPIRED` / `CARD_TERMINATED` | 카드 사용 불가 — 정지/만료/해지 **3분**(구 `DECLINED_CARD` 단일 상수 대체 — **SM 응답 열 CF4·CF6·CF3 재사용**, 신설 아님. 2026-08-06 확정) | **BR-15** · UC-01 §4-C · 카드 SM CF3·4·6 | [미확정] (3값 자리) |
| `DECLINED_FUNDS` | 가용잔액 부족 | BR-04 · UC-01 §4-E | [미확정] |
| `DECLINED_LIMIT` | 카드 1회/1일 한도 또는 계좌 한도 초과 | BR-05 · BR-44 · UC-01 §4-E | [미확정] |
| `DECLINED_RECEIVABLE_BLOCK` | 미결 미수 계좌 (차단 해제된 계좌는 통과) | **BR-45** · UC-01 §4-F | [미확정] |
| `IDEMPOTENCY_CONFLICT` | 같은 상관 식별자 · **다른 요청 지문** | **BR-02** · 멱등 INV-2 · UC-01 §4-A | [미확정] |
| `TIMEOUT_RETRYABLE` | 락 충돌·내부 deadline(2.5초) 초과 — 재시도 3회 내 미해결 | UC-01 §4-H · ADR-012 W-10 · T-11 | [미확정] |
| `DUPLICATE_AUTHORIZATION` | `REQUESTED` 외 상태에 `authorize` — ★ **실제로는 멱등 레코드가 선차단**한다(F8 주석) | 승인 SM **F8** | [미확정] — 물리 매핑 불요 후보 |

> ✅ **해소 (2026-08-06 메인 판정 — 보고 3)**: 카드 사유 3분 = **SM 응답 열 재사용**(CF4·CF6·CF3 — K-1 ⑵ 원칙 그대로, 코드 대장 등재됨). 부가 사유 필드 불요.

## 4. 멱등

| 항목 | 내용 |
|---|---|
| **키** | **`(상관 식별자, 승인)`** — 헤더 ④ 20AN이 그 상관 식별자다. **매입사가 승인 요청 시점에 생성**한다(BR-17 ①) |
| **정본 소유자** | **`IdempotencyRecord`**(key = 상관 식별자, operation = 승인) — C3 결제. `find`/`record`가 UC-01 §3-2·§3-6의 단계다 |
| **재수신** | 지문 동일 → **최초 결과 재반환**(무변화 — BR-02 · K-1 시스템 채널) / 지문 상이 → `IDEMPOTENCY_CONFLICT` |
| **보관** | **24시간**(BR-02 [1차] — Stripe 선례). 원거래 지목(BR-17)은 **영구**이며 이 창과 다른 메커니즘이다 |
| **요청 지문** | 전문 **본문에서 파생**한다 — 전송되는 필드가 아니다. ⚠️ **산출 범위 [미확정]**: 재전송 시 헤더 ⑤ 전송일시가 갱신되므로, 범위에 ⑤를 넣으면 **정상 재전송이 전부 충돌로 거절**된다(§5) |
| **응답 유실** | 성립분은 성립한 대로 남고 매입사의 **망취소**(`REVERSAL-REQ`)가 정합을 회복한다 — BR-13·22 · UC-01 §4-G |

## 6. 자기검증

| 전문 | 필드 시작 오프셋 (연속) | 길이 합 | 선언 길이 | 일치 |
|---|---|---|---|---|
| `AUTH-REQ` | 0 → 50 → 58 → 74 → 86 → **101** | 50+8+16+12+15 = **101** | `0101` | ✓ |
| `AUTH-RES` | 0 → 50 → 58 → 62 → 74 → **86** | 50+8+4+12+12 = **86** | `0086` | ✓ |

- 오프셋 불연속·중첩: **없음** (각 행의 시작 = 직전 행의 시작 + 길이)
- 공통 헤더 50 = 4+10+2+20+14 (X-5) ✓
- 응답 코드 수: **10행**(성공 1 · 거절·오류 9) — UC-01 §7 오류 표 7종 전수 + K-1 ① `FORBIDDEN_LEVEL` + 승인 SM F8
