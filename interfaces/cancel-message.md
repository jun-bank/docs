# 전문 규격 `CANCEL-REQ` / `CANCEL-RES` — 승인취소 (매입 전 취소)

- 상태: **검토대기** (2026-08-06 신설 — `plans/2026-08-06/interface-specs/`)
- ★ **정본 = [UC-08 §7 계약 블록](../usecases/UC-08-void-payment.md)** (의미 필드·오류 코드·멱등 키). 이 문서는 그 표면의 **물리 표현**이며, 충돌하면 **이 문서가 틀린 것이다**.
- 전제: **공통 규약 X-1~8**([README.md](README.md)) — 인코딩(X-1)·패딩(X-2)·금액 12N(X-3)·일시(X-4)·공통 헤더 50바이트(X-5)·기관 코드(X-6)·응답 코드(X-7). **여기서 재정의하지 않는다.**
- 채널: 매입사 → 발급사 · 실시간 동기 전문(**BR-33** — 승인취소는 실시간) · 내부 deadline **2.5초**(T-11 상속)

> ★ **매입된 원거래는 이 전문으로 처리되지 않는다** — `AUTH_ALREADY_CAPTURED`로 **거절**되고 매입사가 **파일 취소 레코드**로 재접수한다(UC-08 §4-D · B-3 · 승인 SM v0.4 §4.3 — 강등은 파일 경로 한정). → [capture-file.md](capture-file.md)

## 1. 요청 전문 `CANCEL-REQ` — 필드 표

**전문 길이 선언 = 102바이트** (`전문길이` 필드값 `0102`)

| # | 필드 | 오프셋 | 길이 | 타입 | 필수 | 의미 | 정본 연결 | ISO 8583 참조 |
|---|---|---|---|---|---|---|---|---|
| H | **공통 헤더** | 0 | 50 | — | ✓ | X-5 ①전문길이 ②전문구분 = `CANCEL-REQ` ③전문버전 `01` ④**상관 식별자 = 이 취소 요청 자신의 것**(멱등 키 — §4) ⑤전송일시 | X-5 · K-2 · **UC8-1(B-4)** | ② ≈ MTI `0400` 계열 · ④ ≈ DE 37 |
| 1 | 기관 코드 | 50 | 8 | AN | ✓ | 발신 매입사 식별 | X-6 (**코드 체계 [미확정]**) | DE 32 |
| 2 | **원거래 상관 식별자** | 58 | 20 | AN | ✓ | 원 승인 요청의 상관 식별자 — 원거래 지목 ① | **BR-17 ①** · BR-12 · UC-08 §7 요청 | DE 90 (Original Data Elements — 구성 상이) |
| 3 | **원거래 승인번호** | 78 | 12 | AN | ✓ | 발급사가 발번한 승인번호 — 원거래 지목 ②. ★ **취소는 ①②를 모두 쓴다** | **BR-17 ②** · UC-08 §7 요청 | DE 38 / DE 90 |
| 4 | 취소액 | 90 | 12 | N | ✓ | 되돌릴 금액 — 통화 최소단위 정수. **전액/부분의 구분 필드는 없다**(취소액 = 승인액 − 누적취소액이면 전액) | BR-07 · X-3 · BR-11 · UC-08 §7 요청 | **DE 4** (n12) |

> ★ **헤더 ④와 본문 2가 다른 값이다.** ④는 *이 취소 요청*의 식별자(멱등 키)이고 2는 *원 승인*의 식별자(지목 수단)다 — 같은 값으로 두면 **부분취소 2회가 성립하지 않는다**(UC8-1 B-4 확정 · §4).
>
> ★ **싣지 않는 것**: 홀딩·두 층 한도의 복원 여부(내부 판정 `holdingFunds` — UC-08 §7 응답 칸) · 통화(X-3) · 귀속 영업일(X-4).

## 3. 응답 코드 매핑

> **정본은 문자 상수**다(X-7). **물리 4N 값은 [미확정 — 대외 협의]**.
> **오류 코드 정본 = 승인 SM §4.1 응답 열**(K-1 ⑵ — 계약이 코드를 재발명하지 않는다) + **신설 코드 대장**(K-1 ⑶).
> **판정 순서**(UC-08 §7) = ① 채널·경로 식별자 → ② 원거래 지목·존재 → ③ 상태·금액.
> ★ **L7 비대상**(C-2 채널 조항) — 매입사는 사유에 따라 조치가 갈린다(재시도 / 환불 전환 / 대사 조회). **거절도 전부 감사에 남는다**(BR-57).

| 문자 상수 (정본) | 사유 | 정본 위치 | 판정 순서 | 물리 4N |
|---|---|---|---|---|
| (성공) | 전액 취소(`VOIDED`) 또는 부분 취소(상태 유지) | 승인 T5·T6·T13·T14 · UC-08 §3-6 | — | [미확정] |
| `FORBIDDEN_LEVEL` | 경로 식별자 부재·미인가 (대상 조회 전) | K-1 ① · UC-07 §7 선례 | ① | [미확정] |
| `AUTH_NOT_FOUND` | **원거래 미발견** — ★ 취소 예약을 두지 **않는다**(BR-22는 망취소 전용) | **UC8-2(B-2)** · 코드 대장 · UC-08 §4-B | ② | [미확정] |
| `AUTH_ALREADY_CAPTURED` | 원거래가 **매입됨** — 매입사는 **파일 취소 레코드로 재접수**한다 | 승인 SM **F1 응답 열 재사용** · UC-08 §4-D(B-3) | ③ | [미확정] |
| `AUTH_ALREADY_SETTLED` | 원거래가 **정산완료** — 마감된 영업일의 순액은 움직이지 않는다 | 승인 SM **F2** · BR-47 · UC-08 §4-F | ③ | [미확정] |
| `AUTH_ALREADY_VOIDED` | 원거래가 이미 **무효** — 취소액 이중 계상 차단 | 승인 SM **F3** · UC-08 §4-E | ③ | [미확정] |
| `AUTH_ALREADY_REFUNDED` | 원거래가 **환불완료** — 잔여 채권 0 | 승인 SM **F4** · UC-08 §4-H | ③ | [미확정] |
| `AUTH_NOT_AUTHORIZED` | 원거래가 **거절됨** — 되돌릴 금액이 없다. ★ 망취소는 같은 상태에서 `◎`(무변화)인데 **승인취소는 거절**이다 | 승인 SM **F5** · UC-08 §4-G | ③ | [미확정] |
| `EXCEEDS_CANCELABLE` | **누적취소액 초과**(`취소액 > 승인액 − 누적취소액`) — 상태가 아니라 **금액이 만드는 거절** | **B-1** · BR-11 · 승인 INV-1 · 코드 대장 | ③ | [미확정] |
| `IDEMPOTENCY_CONFLICT` | 같은 취소 상관 식별자 · **다른 요청 지문** | BR-02 · 멱등 INV-2 · UC-08 §4-A | ③ | [미확정] |

> ★ **정본에 없어 싣지 않은 것**: 보류(`frozen = true`) 중인 승인의 취소는 **통과한다**(UC-08 §4-L — F17 범위는 `expire`·`capture`뿐). 만료 승인의 전액/부분 취소도 **정상 처리**이며 별도 코드가 없다(§4-I·J — T13·T14).

## 4. 멱등

| 항목 | 내용 |
|---|---|
| **키** | ★ **취소 요청 자신의 상관 식별자** = **헤더 ④** (원거래 상관 식별자가 **아니다**) |
| **근거** | **UC8-1 확정(B-4)** — 원거래 식별자로 묶으면 원거래당 취소가 1회가 되어 **부분취소 2회가 성립하지 않는다.** 금액 축은 **BR-11의 누적 상한**(INV-1)이 이미 막으므로 멱등 키가 그 역할을 겸할 필요가 없다 |
| **정본 소유자** | **`IdempotencyRecord`**(key = 취소 요청 상관 식별자, operation = 취소) — BR-02 *"보상 요청에도 동일하게 적용된다"* |
| **재수신** | 지문 동일 → **최초 결과 재반환**(무변화 — K-1 · UC-08 §4-A) / 지문 상이 → `IDEMPOTENCY_CONFLICT` |
| **원거래 지목** | 본문 2·3(상관 식별자 + 승인번호)이 담당하며 **멱등 키가 아니다** — BR-17은 **영구**, BR-02 멱등 창은 **24시간**으로 수명이 다르다 |
| **요청 지문** | `AUTH-REQ`와 같은 판정 — 본문에서 **파생**하며 산출 범위는 **[미확정]**(§5) |

## 6. 자기검증

| 전문 | 필드 시작 오프셋 (연속) | 길이 합 | 선언 길이 | 일치 |
|---|---|---|---|---|
| `CANCEL-REQ` | 0 → 50 → 58 → 78 → 90 → **102** | 50+8+20+12+12 = **102** | `0102` | ✓ |
| `CANCEL-RES` | 0 → 50 → 58 → 62 → 82 → 94 → 106 → 118 → **128** | 50+8+4+20+12+12+12+10 = **128** | `0128` | ✓ |

- 오프셋 불연속·중첩: **없음**
- 전문구분 `CANCEL-REQ`·`CANCEL-RES` = **각 10자** — X-5② 10AN에 **정확히** 들어간다 ✓
- 응답 코드 수: **10행**(성공 1 · 거절 9) — UC-08 §7 오류 표 전수(F1·F2·F3·F4·F5 + `EXCEEDS_CANCELABLE` + `AUTH_NOT_FOUND` + `IDEMPOTENCY_CONFLICT`) + K-1 ① `FORBIDDEN_LEVEL`
