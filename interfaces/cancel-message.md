# 전문 규격 `CANCEL-REQ` / `CANCEL-RES` — 승인취소 (매입 전 취소)

- 상태: **검토대기** (2026-08-06 신설 — `plans/2026-08-06/interface-specs/`)
- ★ **정본 = [UC-08 §7 계약 블록](../usecases/UC-08-void-payment.md)** (의미 필드·오류 코드·멱등 키). 이 문서는 그 표면의 **물리 표현**이며, 충돌하면 **이 문서가 틀린 것이다**.
- 전제: **공통 규약 X-1~11**([README.md](README.md)) — 인코딩(X-1)·패딩(X-2)·금액 12N + **통화 3AN**(X-3)·일시(X-4)·공통 헤더 50바이트(X-5)·기관 코드(X-6)·응답 코드(X-7)·**요청 지문(X-9)**·**판정 순서(X-10)**·**PAN 취급(X-11)**. **여기서 재정의하지 않는다.**
- 채널: 매입사 → 발급사 · 실시간 동기 전문(**BR-33** — 승인취소는 실시간) · 내부 deadline **2.5초**(T-11 상속)

> ★ **매입된 원거래는 이 전문으로 처리되지 않는다** — `AUTH_ALREADY_CAPTURED`로 **거절**되고 매입사가 **파일 취소 레코드**로 재접수한다(UC-08 §4-D · B-3 · 승인 SM v0.4 §4.3 — 강등은 파일 경로 한정). → [capture-file.md](capture-file.md)

## 3. 응답 코드 매핑

> **정본은 문자 상수**다(X-7). **물리 4N 값은 [미확정 — 대외 협의]**.
> **오류 코드 정본 = 승인 SM §4.1 응답 열**(K-1 ⑵ — 계약이 코드를 재발명하지 않는다) + **신설 코드 대장**(K-1 ⑶).
> **판정 순서 = X-10**(2026-08-06 R-05 정정 — 구 *"① 채널·경로 → ② 원거래 지목·존재 → ③ 상태·금액"* 을 **대체**한다): **① 인자 형식 → ② 멱등 단락 → ③ 대상 존재 → ④ 상태.** ★ **멱등 단락이 원거래 조회보다 앞선다** — 재수신은 원거래를 다시 읽지 않고 최초 결과를 반환한다(그 사이 원거래가 매입·정산되면 같은 요청에 다른 답이 나간다). 채널 인가(`FORBIDDEN_LEVEL`)는 전문 처리 이전의 ACL 판정이라 **채널**로 적는다.
> ★ **L7 비대상**(C-2 채널 조항) — 매입사는 사유에 따라 조치가 갈린다(재시도 / 환불 전환 / 대사 조회). **거절도 전부 감사에 남는다**(BR-57).

| 문자 상수 (정본) | 사유 | 정본 위치 | 판정 순서 | 물리 4N |
|---|---|---|---|---|
| (성공) | 전액 취소(`VOIDED`) 또는 부분 취소(상태 유지) | 승인 T5·T6·T13·T14 · UC-08 §3-6 | — | [미확정] |
| `FORBIDDEN_LEVEL` | 경로 식별자 부재·미인가 (대상 조회 전) | K-1 ① · UC-07 §7 선례 | 채널 | [미확정] |
| `IDEMPOTENCY_CONFLICT` | 같은 취소 상관 식별자 · **다른 요청 지문**(X-9) | BR-02 · 멱등 INV-2 · UC-08 §4-A | ② | [미확정] |
| `AUTH_NOT_FOUND` | **원거래 미발견** — ★ 취소 예약을 두지 **않는다**(BR-22는 망취소 전용) | **UC8-2(B-2)** · 코드 대장 · UC-08 §4-B | ③ | [미확정] |
| `AUTH_ALREADY_CAPTURED` | 원거래가 **매입됨** — 매입사는 **파일 취소 레코드로 재접수**한다 | 승인 SM **F1 응답 열 재사용** · UC-08 §4-D(B-3) | ④ | [미확정] |
| `AUTH_ALREADY_SETTLED` | 원거래가 **정산완료** — 마감된 영업일의 순액은 움직이지 않는다 | 승인 SM **F2** · BR-47 · UC-08 §4-F | ④ | [미확정] |
| `AUTH_ALREADY_VOIDED` | 원거래가 이미 **무효** — 취소액 이중 계상 차단 | 승인 SM **F3** · UC-08 §4-E | ④ | [미확정] |
| `AUTH_ALREADY_REFUNDED` | 원거래가 **환불완료** — 잔여 채권 0 | 승인 SM **F4** · UC-08 §4-H | ④ | [미확정] |
| `AUTH_NOT_AUTHORIZED` | 원거래가 **거절됨** — 되돌릴 금액이 없다. ★ 망취소는 같은 상태에서 `◎`(무변화)인데 **승인취소는 거절**이다 | 승인 SM **F5** · UC-08 §4-G | ④ | [미확정] |
| `EXCEEDS_CANCELABLE` | **누적취소액 초과**(`취소액 > 승인액 − 누적취소액`) — 상태가 아니라 **금액이 만드는 거절** | **B-1** · BR-11 · 승인 INV-1 · 코드 대장 | ④ | [미확정] |
| ★ `TIMEOUT_RETRYABLE` | 락 충돌·내부 deadline(2.5초) 초과 — 재시도 3회 내 미해결. ★ **`AUTH-REQ`의 선례를 그대로 상속**한다(2026-08-06 R-15): 같은 실시간 전문 채널이고 같은 T-11 예산을 쓰는데 취소만 이 코드가 없으면, 매입사는 **타임아웃을 재시도 가능으로 읽을 근거가 없어진다**(재시도 대신 대사로 넘어간다) | [auth-message.md](auth-message.md) §3 선례 · ADR-012 W-10 · **T-11** | 처리 중 | [미확정] |

> ★ **정본에 없어 싣지 않은 것**: 보류(`frozen = true`) 중인 승인의 취소는 **통과한다**(UC-08 §4-L — F17 범위는 `expire`·`capture`뿐). 만료 승인의 전액/부분 취소도 **정상 처리**이며 별도 코드가 없다(§4-I·J — T13·T14).

## 6. 자기검증

| 전문 | 필드 시작 오프셋 (연속) | 길이 합 | 선언 길이 | 일치 |
|---|---|---|---|---|
| `CANCEL-REQ` | 0 → 50 → 53 → 61 → 81 → 93 → **105** | 50+3+8+20+12+12 = **105** | `0105` | ✓ |
| `CANCEL-RES` | 0 → 50 → 53 → 61 → 65 → 85 → 97 → 109 → 121 → **131** | 50+3+8+4+20+12+12+12+10 = **131** | `0131` | ✓ |

- 오프셋 불연속·중첩: **없음**
- 전문구분 **물리 구분값** `CANCELREQ`(9자)·`CANCELRES`(9자) — X-5② 10AN에 들어간다(우측 공백 패딩 — X-2) ✓ ※ K-2 이름 `CANCEL-REQ/RES`는 **정본 이름**이고 전문에 싣는 값은 물리 구분값이다(R-14 — README X-5②가 정본)
- 통화 필드: 요청·응답 **같은 자리(50) · 같은 길이(3AN) · 같은 값(`KRW`)** — R-01 ✓
- 응답 코드 수: **11행**(성공 1 · 거절 9 · 처리 중 1) — UC-08 §7 오류 표 전수(F1·F2·F3·F4·F5 + `EXCEEDS_CANCELABLE` + `AUTH_NOT_FOUND` + `IDEMPOTENCY_CONFLICT`) + K-1 ① `FORBIDDEN_LEVEL` + **`TIMEOUT_RETRYABLE`**(auth 선례 상속 — R-15)
