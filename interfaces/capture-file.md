# 파일 규격 `CAPTURE-FILE` — 매입 파일 (매입 · 취소 레코드)

- 상태: **검토대기** (2026-08-06 신설 — `plans/2026-08-06/interface-specs/`)
- ★ **정본 = [UC-10 §7](../usecases/UC-10-capture-settlement-file.md)**(매입 레코드·파일 단위) **+ [UC-11 §7](../usecases/UC-11-refund-via-cancel-record.md)**(취소 레코드). 이 문서는 그 표면의 **물리 표현**이며, 충돌하면 **이 문서가 틀린 것이다**.
- 전제: **공통 규약 X-1~8**([README.md](README.md)) — 특히 **X-8 파일 공통**(고정길이 레코드 + H/D/T · 레코드 구분자 없음). **여기서 재정의하지 않는다.**
- 채널: 매입사 → 발급사 · **배치 파일** · ★ **응답 상대가 없다**(§2) · 실시간 아님(예산 = *진척 없음* 판정 — 배치 SM §7)

> ★ **X-5 공통 헤더(50바이트)를 쓰지 않는다.** X-5는 *"전 **전문** 선두"* 의 규약이고 파일의 구조는 **X-8**이 따로 정한다(H/D/T · 파일 ID·영업일·건수 예고 · 트레일러 합계). 파일에는 `전문길이`·`상관 식별자` 헤더가 없으며, 그 자리를 **파일 헤더 레코드**와 **레코드 순번**이 대신한다(§4 멱등).
>
> ★ **한 파일에 매입 레코드와 취소 레코드가 섞여 온다**(BR-33) — 유형으로 갈리며 처리 경로가 다르다(매입 → UC-10 E2 / 취소 → UC-11 E4). 둘 다 `(fileId, recordId)` 멱등 대상이다(BR-23 · HS8).

## 2. 응답 — ★ **없다**

**응답 전문이 없다.** 파일 채널에는 **거절할 상대가 접속해 있지 않다**(UC-10 §6 · 승인 SM §4 머리말). 성공도 실패도 **응답이 아니라 상태로 표현된다**:

| 결과 | 표현 | 정본 |
|---|---|---|
| 레코드 성공 | `processedRecords` 등재 (**E2 / E4 레코드 단위 커밋**) | B4 · UC-10 §7 응답 칸 |
| 레코드 실패 | ★ **격리(`isolatedRecords`) + 불일치 적재**(`Discrepancy.recordOrTouch`) | B5 · §3 |
| 파일 완료 | `COMPLETED` — ★ **건수 판정** `|처리| + |격리| = totalRecords` | **배치 INV-3** · B7 |
| 파일 중단 | `INTERRUPTED` — **진행분 보존**, 재개 시 두 집합에 있는 레코드는 건너뛴다 | B6·B3 · BF8 |
| 파일 손상(건수 미독) | `RECEIVED`에서 **거부 + 재전송 요청** — 배치를 시작하지 않는다 | **B-8**(UC10-2) · UC-10 §4-P |

> ★ **L7 해당 없음** — 격리 사유 구분은 **운영자 화면용**이며 매입사에게 응답으로 새지 않는다(UC-10 §6 · UC-11 §6).

## 3. 응답 코드 매핑 — ★ **없음 (격리 + 불일치가 대신한다)**

> **매입사에게 가는 응답 코드가 아니다**(UC-10·11 §7 오류 표 머리). 아래 두 표는 **내부 처리·운영자 화면·감사**의 표면이다.

### 3.1 레코드 금지 → 격리 + 불일치 유형 (정본 = 승인 SM §4.2 · `capture-batch.md` §5)

| 사유 | 유형 | 불일치 | 정본 |
|---|---|---|---|
| 선행 승인 없음 | `CAPTURE` | **M2** 미승인 매입 | BR-27 · UC-10 §4-F |
| 금액 초과 (`매입액 > 승인액 − 누적취소액`) | `CAPTURE` | **M4** 금액 초과 매입 — **상태는 정상이고 금액이 금지를 만든다** | **F15** · 승인 INV-3 · BR-16 ③ |
| 이미 매입된 승인 (후속 매입) | `CAPTURE` | **M7** — ★ **금액과 무관**하며 부분 매입 후 잔여분도 같다 | **F10·F11** · BR-32 |
| 무효 승인 (`DECLINED`·`VOIDED`·`REFUNDED`) | `CAPTURE` | **M8** — ★ **무효가 된 경로는 구분하지 않는다** | **F12·F13·F14** · BR-51 |
| **기한 초과** (승인일 + **10일**, CNP) | `CAPTURE` | **M19** — 격리 **즉시 적재**(대사 탐지 아님). M8과 다르다: 승인이 무효인 게 아니라 **매입 자격의 기한**이 지났다 | **BR-19**(Visa AI13522) · UC10-1 |
| 상한 초과 (`refundedTotal + 요청액 > capturedAmount`) | `CANCEL` | **M5** 취소 불일치 | **F18** · INV-7 · BR-43 ① |
| 원거래 매칭 실패 | `CANCEL` | **M5** — ★ **M5가 흡수한다**(B-13 · UC11-3. 매입 레코드의 M2·M8과 대칭이 아니다 — 조치가 갈리지 않는다) | BR-12 · UC-11 §4-M |
| **원승인 보류 중**(`frozen = true`) | `CAPTURE` | ★ **없음 — 불일치를 만들지 않는다**(우리가 의도한 지연). 대사에서 **M1로도 잡지 않는다.** 보류 해제 후 **재처리 배치**가 반영·승격한다 | **F17** · BR-50 · BR-28 |

> ★ **보류 격리 중 원승인이 종료되면 사유가 M8로 자동 재분류**된다(`reclassifyIsolated` — B9 · UC14-2). 이후 승격은 BF12에 막힌다.

### 3.2 배치 조작 거절 코드 (정본 = 배치 SM §4 처리 열 — 운영자 화면·감사에 남는다)

| 코드 | 상황 | 정본 |
|---|---|---|

## 4. 멱등

| 항목 | 내용 |
|---|---|
| **파일** | **`fileId`**(헤더 레코드 ②) **유일** — 배치 **INV-1**. 재수신 = **최초 배치를 반환**(BF7 · K-1 시스템 채널 규약) |
| **레코드** | ★ **`(fileId, recordId)`** — 헤더 ② + 데이터 레코드 ②. **BR-23**이 정본이며 **취소 레코드에도 적용**된다(BR-33 HS8 — 적용하지 않으면 재처리 시 **환불이 두 번 반영되어 고객에게 두 배**가 간다) |
| **정본 소유자** | **`CaptureBatch`**(`processedRecords` · `isolatedRecords`) — 두 집합은 **상호배타**(INV-2)이며 **어느 쪽에든 있으면 건너뛴다**(BF8) |
| **의미** | ★ **격리에 있다 = 미반영 · 처리에 있다 = 반영됨.** 승격(`promoteIsolated`)이 그 경계를 **원자적으로** 넘기므로 두 번 지시해도, 파일이 재전송돼도 걸러진다 |
| **재처리 배치** | 보류 격리의 재처리는 ★ **원 `(fileId, recordId)`를 승계**한다(BR-50 · B8) — **새 키를 발급하면 이중 출금**이다 |
| **커밋 경계** | `markProcessed`가 자금 반영과 **같은 커밋**(매입 = **E2** / 환불 = **E4**). 갈리면 반영만 남고 배치는 "미반영"이라 **재시도가 같은 레코드를 또 출금**한다 |
| **건수 판정** | 멱등의 짝이 **INV-3**이다 — 격리 쪽 중복 방지가 없으면 `|처리| + |격리|`를 인위적으로 채워 **절단된 파일이 완료로 통과**한다 |
