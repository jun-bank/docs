# ADR-008. 배치 실행 — **파티션 할당으로 단일 실행과 병렬을 동시에**

- 일자: 2026-08-05
- 상태: **채택**
- 결정자: 사용자 · AI 페어
- 관련: **HA-2** · **ADR-006**(커트오프) · **ADR-004**(배포 단위) · 품질 속성 **가용성(2)·탐지가능성(4)** · 시나리오 **QS-04·QS-07**

---

## 1. 맥락

**HA-2**: *배치·스케줄러의 단일 실행을 보장한다.* 다중 인스턴스에서 배치가 중복 실행되면
대사·정산이 두 번 돌아 **M9~M15가 허위 불일치를 쏟는다.**

### 그런데 단일 실행만으로는 부족하다

| 배치 | 무엇을 처리하나 | 규모 |
|---|---|---|
| **대사** | 그 영업일 전체 계좌·승인·전표 대조 | ★ 승인 **400만 건/일** 규모 (QS-01) |
| **매입 배치** | 매입 파일 레코드 반영 | 파일당 수십만 건 |
| **정산** | 영업일 순액 산출 | 계좌·가맹점 단위 집계 |
| 만료 배치 | 기한 지난 홀딩 해제 | 미매입 승인 전체 |

**대사는 마감 후 1시간 안에 끝나야 한다**(QS-04). 한 인스턴스가 400만 건을 훑으면 그 시간에 안 들어온다.

> ★ **"단일 실행"과 "병렬 처리"가 충돌하는 것처럼 보인다.** 그것이 이 ADR이 푸는 문제다.

---

## 2. 고려한 안

| # | 안 | 단일 실행 보장 | 병렬 | 새로 운영할 것 |
|---|---|---|---|---|
| **A** | **파티션 할당** | ✅ 파티션당 정확히 하나 | ✅ 파티션 수만큼 | 파티션 테이블 |
| **B** | 리더 선출 | ✅ 리더 하나 | ❌ **리더가 전부 처리** | 선출 메커니즘 |
| **C** | 전역 락 | ✅ | ❌ | DB 락 |
| **D** | 외부 스케줄러가 1회만 트리거 | ⚠️ 스케줄러 이중화 시 깨진다 | ❌ | 스케줄러 |

---

## 3. 결정

### **A. 파티션 할당**

```
배치 시작
  ① 그 실행(runId)에 대해 파티션 N개를 테이블에 등록   ← 한 트랜잭션
  ② 각 인스턴스가 미할당 파티션을 하나씩 집어간다      ← 원자적 UPDATE
  ③ 처리 후 완료 표시
  ④ 모든 파티션이 완료되면 배치 완료

파티션 키 = 계좌ID 해시 % N   (ADR-009)
```

### 왜 이것인가

| 근거 | 어디에 걸리나 |
|---|---|
| **단일 실행 보장과 병렬 처리를 동시에** 얻는다 — *"각 파티션을 정확히 하나가"* | **HA-2** |
| 인스턴스가 죽어도 **그 파티션만 미완**으로 남아 재할당된다 | **QS-07** |
| **진행 상황이 보인다** — 완료 파티션 수로 진척을 안다 | 탐지가능성 |
| 새 미들웨어가 없다 — **DB 테이블 하나**로 된다 | C-04 |

### 왜 나머지를 기각했나

| 안 | 기각 이유 | 이 이유가 바뀌면 |
|---|---|---|
| **B** 리더 선출 | ★ **리더 하나가 전부 처리하므로 스케일아웃이 안 된다.** 인스턴스를 늘려도 배치 시간이 안 줄어든다. QS-04(1시간)를 못 지키는 순간 답이 없다 | 배치 규모가 단일 인스턴스로 충분할 때 |
| **C** 전역 락 | B와 같은 문제 + **락 보유 중 인스턴스가 죽으면** 락 해제 시점이 모호하다 | — |
| **D** 외부 스케줄러 1회 트리거 | ★ **스케줄러를 이중화하는 순간 깨진다.** 가용성(2순위)을 위해 이중화하면 단일 실행이 무너지는 **자기모순** | 스케줄러가 단일 장애점이어도 되는 경우 — 우리는 아니다 |

> ★ **B와 D의 기각 이유가 대칭이다.** B는 *가용성은 되는데 확장이 안 되고*,
> D는 *확장을 하려면 가용성이 깨진다*. A만 둘을 동시에 만족한다.

## 4. 결과

| | 내용 |
|---|---|
| **얻는 것** | 단일 실행 + 병렬 · 부분 실패 격리 · 진척 가시성 |
| **내주는 것** | 파티션 경계를 **넘는 집계가 어렵다** · 파티션 수가 고정되면 재분배가 필요 |
| **새로 생기는 일** | ★ **파티션을 넘는 검증을 어떻게 할 것인가** (아래) · 좀비 파티션 회수 |

### 규칙

| # | 규칙 | 왜 |
|---|---|---|
| **B-1** | 파티션 할당은 **원자적**이다 (조건부 UPDATE — 미할당인 것만) | 둘이 같은 파티션을 집으면 HA-2 위반 |
| **B-2** | 각 파티션 처리는 **멱등**하다 — 재할당돼도 결과가 같다 | 인스턴스 사망 시 재할당 |
| **B-3** | 할당에 **임차 기간(lease)** 을 둔다. 만료되면 회수한다 | 죽은 인스턴스의 파티션이 영구 점유되면 안 된다 |
| **B-4** | **모든 파티션 완료 전에는 배치 완료가 아니다** | 부분 결과를 완료로 오인하면 조용한 절단 |
| **B-5** | 배치 실행 자체에 **runId**를 둔다 | 재실행과 이전 실행을 구분 |

> ★ **B-4가 Phase 2의 실측 교훈이다** — *"에러 없이 돌았다 ≠ 완료"*.
> 부분 실패를 완료로 위장하는 것이 **가장 많이 관찰된 사고 유형**이었다.

### ★ 파티션을 넘는 검증

일부 대사는 **계좌 단위로 안 나뉜다.**

| 유형 | 파티션 단위 | 왜 |
|---|---|---|
| **M9·M11·M12·M14** | ✅ **계좌** | 계좌별 등식이다 |
| **M10** 카드 한도 | ⚠️ **카드** — 카드는 계좌에 속하므로 계좌 파티션에 따라간다 | CM1 |
| **M15** 정산 합계 | ❌ **영업일 전체** — 계좌로 안 나뉜다 | 정산은 영업일 단위 순액 |
| **M1~M8** 매입 대사 | ⚠️ 승인 단위 → **승인은 카드 → 계좌**로 유도 가능 | BR-17 |

**M15만 전역이다.** 처리:

```
① 파티션 병렬로 M1~M14 처리 + 파티션별 부분합 기록
② 모든 파티션 완료 후 (B-4)
③ 부분합을 모아 M15 검증           ← 단일 실행. 값이 작아 병렬 불필요
```

> ★ **"전부 병렬"이 아니라 "병렬 + 마무리 단일"이다.** 부분합을 모으는 단계가
> B-4(모든 파티션 완료)를 **자연스럽게 강제**한다.

## 5. 되돌리는 조건

| # | 관찰되면 | 무엇을 뜻하나 | 그때 할 일 |
|---|---|---|---|
| **R1** | 파티션 수를 늘려도 **QS-04(1시간)를 못 지킨다** | 병렬로 안 풀리는 병목 (DB IO 등) | 배치 전용 읽기 경로 분리 → 그래도 안 되면 데이터 계층 분할 |
| **R2** | **좀비 파티션 회수가 반복해서 오작동**한다 | lease 설계 실패 | lease 기간 조정 → 그래도 안 되면 안 B로 축소 |
| **R3** | 파티션을 넘는 검증이 **M15 말고도 계속 늘어난다** | 계좌 파티션이 잘못된 축이다 | 파티션 키 재검토 (ADR-009 R1) |
| **R4** | 파티션 수 변경 시 **재분배가 매번 문제**가 된다 | 고정 해시의 한계 | 일관 해시 또는 범위 파티션 |

---

## 6. 검증

| 언제 | 무엇으로 | 통과 기준 |
|---|---|---|
| Phase 5 | 다중 인스턴스 배치 | **같은 파티션을 둘이 처리하지 않는다** (HA-2) |
| Phase 5 | 처리 중 인스턴스 강제 종료 | 해당 파티션이 **재할당되어 완료된다** |
| Phase 5 | 같은 파티션 2회 처리 | **결과 동일** (B-2) |
| Phase 5 | 파티션 1개 실패 주입 | 배치가 **완료로 표시되지 않는다** (B-4) |
| Phase 5 | QS-04 | 마감 후 **1시간 이내 완료** |

> ★ **네 번째가 B-4의 시험이다.** *"9개 성공, 1개 실패"* 를 완료로 표시하면
> **조용한 절단**이고, 그것이 Phase 2에서 가장 많이 관찰된 사고 유형이다.
