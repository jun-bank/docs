# ADR-010. 배포 단위 — **코어(대사 포함) + 정산 + 원장 = 3개**

- 일자: 2026-08-05
- 상태: **채택** — **ADR-004를 대체한다**
- 결정자: 사용자 · AI 페어
- 근거: **DC-004** · Phase 3 듀얼 리뷰
- 관련: 제약 **§0** · 품질 속성 **정합성(1)·탐지가능성(4)** · 시나리오 **QS-01·QS-04**

---

## 1. 맥락 — 왜 다시 여는가

ADR-004는 **코어 + 위성 3개(배포 4)** 를 채택했다.
Phase 3 듀얼 리뷰에서 **치명 4건**이 나왔고 **전부 그 분할의 이음매**였다(DC-004 §1).

| ADR-004가 본 것 | 안 본 것 |
|---|---|
| 코어 → 위성 (R5~R9, 전부 비동기) | ★ **위성 → 코어** — 정산 결과·드레인 실패 |
| — | ★ **밖에서 안을 읽는 것** — 대사가 M9~M15를 계산하려면 코어의 값이 필요하다 |

> ★ **R9(순응자·읽기 전용)가 함정이었다.** *"읽기 전용"* 은 **쓰기를 안 한다**는 뜻이지
> **읽을 수 있다**는 보장이 아니다. 같은 프로세스일 때는 자명해서 아무도 묻지 않았다.

---

## 2. 고려한 안

DC-004 §3의 판정을 그대로 따른다.

| # | 안 | T2 스냅샷 | T4 대사 읽기 | 학습 가치 |
|---|---|---|---|---|
| **A** | **대사를 코어로 (배포 3)** | ✅ 해소 | ✅ **해소** | 유지 — Outbox·정산 경계는 남는다 |
| **B** | 위성에 역방향 API 신설 (배포 4 유지) | ❌ | ⚠️ **사본** | — |
| **C** | 전부 코어로 (배포 1) | ✅ | ✅ | ❌ 이벤트 경계가 사라진다 |
| **D** | 현행 유지 (ADR-010) | ❌ | ❌ | — |

## 3. 결정

### **A. 배포 단위 3개**

```
[실시간 코어]  C1 뱅킹 · C2 카드 · C3 결제 · ★ C6 대사 · C7 인증
                 └ E1~E5 전부 · M9~M15 계산
[정산] C4        └ 집계를 받고, settledBusinessDate 를 돌려준다
[원장] C5        └ append-only 수신
```

### 왜 대사만 되돌리나

| 위성 | 판정 | 근거 |
|---|---|---|
| **C4 정산** | **밖** | 되돌아갈 것이 `settledBusinessDate` **하나**뿐이고 **이벤트로 충분**하다 |
| **C5 원장** | **밖** | append-only 수신. **되돌아갈 것이 없다** |
| **C6 대사** | ★ **안** | **다섯 컨텍스트의 진짜 값을 동시에** 읽어야 한다. 이벤트로는 **사본**만 얻는다 |
| **C7 인증** | ★ **안** | R4가 **동기**다 (context-map). ADR-010·004가 **배정을 빠뜨렸다**(리뷰 D8) |

> ★ **분할선은 "무엇이 나가는가"가 아니라 "무엇이 돌아와야 하는가"가 정한다.**

### 왜 나머지를 기각했나

| 안 | 기각 이유 | 이 이유가 바뀌면 |
|---|---|---|
| **B** 역방향 API | ★ **대사가 사본을 보면 감사가 아니다.** 그리고 **사본이 맞는지를 또 대사해야 한다.** 이 판단은 대화에서 두 번 확인했고 그때마다 분리를 택했다 — 세 번째는 안 된다 | — (이 이유는 안 바뀐다) |
| **C** 전부 코어로 | 치명 4건이 전부 해소되지만 **ADR-005(Outbox)·ADR-008(파티션)이 다룰 것이 없어진다.** `constraints.md` §0이 *"최대한 크게"* 를 요구한다 | 정산·원장 경계의 대가가 학습 가치를 넘을 때 |
| **D** 현행 유지 | 치명 4건이 남는다 | — |

## 4. 결과

| | 내용 |
|---|---|
| **얻는 것** | 대사가 **진짜 값**을 본다 · 마감 스냅샷이 **M12·M14에만** 필요 · 이벤트 경계는 유지 |
| **내주는 것** | ★ **배치와 실시간이 자원을 공유**한다 — ADR-004가 안 A를 기각했던 이유가 돌아온다 |
| **새로 생기는 일** | 정산 역방향 경로(N-1) · 두 번째 드레인(N-2) |

### 무엇이 해소되나

| 결함 | |
|---|---|
| **T2** 스냅샷 시점 | ★ M9~M11·M15는 **한 읽기 트랜잭션**으로 계산 — 스냅샷 불필요 |
| **T4** 대사가 값을 못 읽음 | ★ **소멸** — 같은 DB |
| **D7** 드레인 실패 통지 | 대사가 코어 안이므로 **자기 DB에 M16 적재** |
| **D8** C7 배정 누락 | 코어에 배정 |
| **D9** 달력일/영업일 | M11이 **실시간 값**을 보므로 스냅샷 키 불일치가 사라진다 |

### 남는 것 (DC-004 §5)

| # | | 어떻게 |
|---|---|---|
| **N-1** | 정산 결과 → 승인 | ★ **context-map에 C4 → C3 관계 추가** · `SettlementCompleted` 구독 |
| **N-2** | 커트오프 두 번째 게이트 | 정산 완료 후 **드레인 한 번 더** → M15 검증 |
| **N-3** | 원장 대사(M12·M14) 시점 | `DailySnapshot` 유지. **범위가 4개에서 1개(계좌 잔액)로 축소** |
| **N-5** | C7 인증 | 코어에 배정 (이 ADR에서 처리) |

## 5. 되돌리는 조건

| # | 관찰되면 | 그때 할 일 |
|---|---|---|
| **R1** | 대사 배치 실행 중 **QS-01(100 TPS · p99 3초)이 침해**된다 — 2회 이상 측정 | 대사 전용 읽기 경로 분리(같은 DB, 별도 커넥션 풀) → 그래도 안 되면 안 B 재검토 |
| **R2** | 정산 역방향(N-1)이 **또 다른 역방향을 부른다** | 정산도 코어로 |
| **R3** | 원장 대사 시점(N-3)이 **T2와 같은 규모**(단일 대사에서 1,000건 이상 허위)로 재발 | 원장 분리 재검토 |
| **R4** | 코어 배포가 **대사 때문에 지연**되는 일이 월 2회 이상 | 대사를 별도 프로세스로(같은 DB) — **배포 단위만** 분리 |

> ★ **R4가 중간 지점이다.** *"같은 DB, 다른 프로세스"* 는 T4를 안 만들면서 배포를 가른다.
> 처음부터 그렇게 하지 않는 이유는 **먼저 가장 단순한 것을 시도**하기 위해서다.
