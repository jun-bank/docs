## 1. 맥락 — 결정이 하나 빠져 있어서 절차가 닫히지 않았다

ADR-024 **RL-7**은 배포 실행 주체를 하나로 못박았다 — *"CI가 … VPN 안의 배포 API를 호출하면(오라클 프록시 → `.9` → agent) agent가 대상 서버에 적용한다. 사람이 서버에 들어가 손으로 바꾸지 않는다."*
그런데 **거기서 멈췄다.** `.9`의 agent가 위성 두 대(`.158`·`.164`)에 **어떻게 닿는지**가 어느 정본에도 없었고, `operations/cicd.md`가 그것을 **CDT-1**로 이월하면서 상태를 이렇게 적었다 — *"⚠️ 위성 배포·롤백이 실행 불가."*

| 공백 | 무엇이 없었나 | 그 결과 |
|---|---|---|
| **CDT-1** | agent → 위성의 **⑴ 전송 방식 ⑵ 위성 측 실행 주체 ⑶ 인증 ⑷ 실패 경계** | 위성 배포·롤백이 **실행 불가**. §6.2의 러너 위치 판정도 이 행에 걸려 **조건부**로 강등돼 있었다 |
| **CDT-2** | agent **자기 배포의 복원 경로** — 교체 직후 스모크가 실패하면 누가 무엇으로 되돌리나 | agent 교체를 **되돌릴 수 없는 조작**으로 취급할 수밖에 없었다 |

> ⚠️ ★ **이 공백을 *"일단 수동으로"* 로 메울 수 없다는 것이 문제의 핵심이었다.** RL-7이 *"사람이 서버에 들어가 손으로 바꾸지 않는다"* 로 **수동 대체 경로를 이미 막았기** 때문에, 공백을 수동으로 적는 순간 **RL-7의 예외를 신설**하는 것이 된다. 그래서 `cicd.md`는 채우지 않고 이월했다(CF-1). **결정이 필요한 자리였다.**

### 실측이 무엇을 열었나 (2026-08-07)

| 실측 | 이 결정에 무엇을 의미하나 |
|---|---|
| ★ **집 서버 3대가 SSH 키 하나로 공통 접근**된다 | **새 전송 채널을 만들 필요가 없다.** C-08의 순서(요구 → 계약 → 도구)에서 *"이미 보유한 것"* 이 먼저다 |
| ★ **배포 계정이 docker 그룹 소속 — docker·compose는 무암호** / **sudo는 암호 필요** | agent가 **원격에서 실행할 수 있는 조작의 집합**이 정확히 **컨테이너 조작**이다. 그 밖(유닛 설치·재시작)은 자동화가 성립하지 않는다 — ADR-024 **§2.1 재판정 사유 ⑴** 과 같은 실측 |
| ★ **엣지(오라클)가 이미 리버스 프록시로 도메인 여럿을 종단**하고 있다 | 배포 엔드포인트의 진입점을 **새로 만들지 않는다** — 다만 그 엣지는 **여러 프로젝트가 공유**하므로 설정 사고의 반경이 우리 프로젝트 밖까지 간다(§4) |
| ★ **호스트 수집 에이전트가 컨테이너 헬스를 걷어 경보**한다 | 관제 v1이 **가동 여부 감시를 다시 만들 필요가 없다** — 관제가 소유하는 것은 **배포 이력·상태·모드**다(C-08) |
| ⚠️ ★ **"repo보다 오래된 코드가 도는 사건"이 실제로 있었다** | 배포 도구 없이 파일 동기화로 배포하면 *"커밋했는데 배포는 안 됐다"* 가 **조용히** 남는다. 이 ADR의 관제(**DO-6**)가 *"지금 무엇이 돌고 있나"* 를 화면 하나로 만드는 이유다 — RL-7의 *"배포 이력이 곧 사실"* 을 **볼 수 있게** 만드는 축 ★ 2026-08-07 정합: 관제는 PREEMPT 대기와 「열림 미적재 채무」를 별도 상태로 구별한다(ADR-024 §2.4). |

SSH는 그 한 겹을 **이미 있는 것**으로 제공한다(새 도구 0). ★ **RL-11의 도입 조건 ⓐⓑ가 이 한 자리에서 이미 충족된다**는 것이 예외의 근거다(ADR-024 §2.3) |
| **DO-9** | ★ **호스트가 레지스트리에서 직접 이미지를 가져온다**(v1 판정) — agent가 대상 호스트에서 pull을 실행하고, 그 호스트에 **조회 전용 자격**을 둔다. ⚠️ ★ **대가를 적는다**: 시크릿이 **호스트 수만큼** 생긴다. ★ **되돌리는 조건**: 그 자격의 배포·교체가 감당되지 않거나(IV-14 축) 사설망 밖 전송량이 문제가 되면 ★ **agent가 한 번 받아 각 호스트로 밀어 넣는 형태**로 바꾼다 — 그때 시크릿은 **agent 한 곳**으로 줄고 전송이 늘어난다 | 두 형태의 차이는 **자격증명 면**과 **전송 경로**의 맞바꿈이다. v1이 직접 pull인 이유는 **compose의 표준 경로**여서 절차에 특수 단계가 생기지 않고, 롤백이 어느 쪽이든 **호스트 로컬 이미지**로 닫히기 때문이다 |

### 2.1 ★ 2026-08-07 개정 — 설계 선검증 반영 (DO-10~DO-20)

> ★ **이 절은 §2를 뒤집지 않는다 — 열려 있던 자리를 닫는다.** 선검증이 지적한 것은 *"DO-1~DO-9의 결정이 틀렸다"* 가 아니라 ⑴ 두 관문의 **계약이 비어 있고**(무엇에 서명하나 · 무엇을 검증하나 · 같은 요청이 두 번 오면), ⑵ *"권한을 축소했다"* 는 주장이 **실제로는 축소가 아니었으며**(docker 그룹), ⑶ 원격·자기 실행의 **실패 가지가 열린 채**였다는 것이다.
> ⚠️ ★ **상위 정본을 재판정한 자리는 하나뿐이다** — **DO-8 ↔ RL-11 충돌**이며, **몰래 해소하지 않고 개정으로 올렸다**(**ADR-024 §2.3**). 나머지 열은 **신설**이고, `cicd.md`·`infrastructure.md`는 이 절을 **인용**한다.

| `job_workflow_ref` | ★ **배포 워크플로 하나** | 같은 저장소의 **다른 워크플로**가 토큰을 받아도 배포하지 못한다 |
| `exp` · `nbf` · `iat` | 유효 창 · 허용 skew 안 | DO-10의 freshness와 **같은 축**(둘 다 본다) |
| `jti` | ★ **부작용 전에 선점**(DO-10 ⑶과 같은 저장) | 토큰 재사용 = 재전송이다 |
| `environment` | 운영 모드 요청 = **보호된 environment** 값 | ⚠️ **성립 여부 = `[구현 검증]`** — 판정 전까지 운영 승인은 **자기 신고**임을 이력에 남긴다 |

> ⚠️ ★ **`sub`는 대조 대상이 아니라 파생값이다** — 위 칸들을 각각 보는 것이 `sub` 문자열 비교보다 강하다(형식이 바뀌어도 판정이 조용히 무너지지 않는다).

### 2.2 ★ 2026-08-07 개정 — 잔여-1·2·3 닫힘 · 저장 정본 이관 · 구현 언어 (v0.3)

> ★ **이 절은 §2·§2.1을 뒤집지 않는다 — §7이 「열린 채로 두기로 했다」고 적었던 셋 중 셋을 닫는다**(사용자 지시 2026-08-07 *"일부 먼저 닫고 가자"*).
> ⚠️ ★ **셋 다 이 ADR이 스스로 닫은 것이 아니다** — **상위 정본 둘이 개정으로 열어 준 것**이고(**ADR-022 §2.1** · **ADR-024 §2.4**), 이 절은 **그 결과가 DO-*에 무엇을 하는지**를 적는다. §7이 *"이 packet에서 그것까지 열면 상위 정본 둘을 동시에 재판정하는 형태가 되고 그것은 CF-1이 막는 것"* 이라 적었던 이유가 그대로 지켜졌다 — **정본을 먼저 고치고 여기가 인용한다.**

| | 내용 |
|---|---|
| ★ **잔여-1 닫힘 — 코어가 죽어도 락을 원자적으로 잡는다** | **정본 = ADR-022 §2.1**(**DT-9** 배포 스키마 · **DT-10** deploy-agent 계정 · **DT-11** 커트오프 락 계정). ⑴ ★ **배포 창 락 단일 행이 코어 스키마에서 배포 스키마로 옮겨 온다** — 제공자가 **코어의 조작**에서 **DB 자체**로 바뀌므로 `cicd.md` CD-3의 **제공자 순환이 끊긴다** ⑵ **획득 계약은 불변**이다(조건부 UPDATE 1건 · fencing token · lease · 양방향 경합) ⑶ ⚠️ ★ **닫힌 범위를 정확히 적는다 — 코어 앱 다운까지이고 DB 다운은 아니다.** DB가 죽으면 **배포 대상 셋이 이미 전부 멈춰 있고**(ADR-022 §4 — 호스트 장애 HA 없음) 그때 필요한 것은 롤백이 아니라 DB 복구다. ★ **새 잔여를 만들지 않는다** — 그 칸은 ADR-022 §4가 **이미 수용한 위험**이다 |
| ★ **잔여-2 닫힘 — 락과 이력이 한 곳에서 대조된다** | ⑴ **배포 이력 테이블이 락과 같은 스키마**에 서므로 *"락을 잡은 시각과 배포 이력이 맞나"* 가 ★ **한 읽기 트랜잭션**으로 판정된다 ⑵ ★ **덤 — `cicd.md` CD-4 ⑩의 공백이 구조적으로 닫힌다**: **이력 기록과 락 해제가 같은 DB의 한 트랜잭션**이 될 수 있어 *"배포는 됐지만 이력이 없다"* 는 상태가 **만들어지지 않는다**(⑩의 「직전 점유 대조」는 방어선으로 남긴다) ⑶ ★ **§4 ⑺(내주는 것)의 문면이 바뀐다** — 백업 대상이 **agent 파일**에서 **DB**로 옮겨 가고, ⚠️ *"SSH 키는 백업 제외 / 내구 저장은 백업 대상"* 이 **같은 호스트에서 갈리던 비대칭이 사라진다**(DB 백업은 이미 ADR-022 §4의 축이다) |
| ★ **DO-17 개정 — 저장 정본 이관**(로컬 → DB) | ★ **정본 = 배포 스키마 · 로컬 = 캐시·버퍼**. ⑴ ★ **부작용을 여는 판정은 DB에서만** 한다 — **`requestId`·`jti` 선점**(DO-10 ⑶) · **`mode version` 원자 검증**(DO-17 ⑵) · **락 획득**(CD-3). ★ **이 셋이 같은 DB에 있으므로 「적용 직전 검증」이 락 획득과 한 트랜잭션**이 된다(DO-17 ⑵가 요구하던 원자성이 구조로 선다) ⑵ ★ **fail-closed는 그대로다**(DO-17 ⑷) — **DB에 쓸 수 없으면 자동 배포를 시작하지 않는다**. *"모드를 모르면 dev"* 가 아니라 **운영(승인) 모드**로 판정한다 ⑶ ★ **로컬 버퍼가 담는 것은 이미 일어난 사건의 기록**(단계 결과·완료 사건)이며 ⚠️ **이력의 정본이 되지 않는다** — DB 복구 시 **flush + 대조**한다 ⑷ ⚠️ ★ **로컬이 정본으로 남는 항목이 정확히 하나 있다 — 자기 교체 의도**(DO-19 ⑹): ★ **watchdog에게 DB 계정을 주지 않기 위해서**다. watchdog이 사는 근거가 *"요청을 받지 않고 상태가 거의 없다"* 인데(DO-19 ⑷) **DB 자격을 쥐는 순간 그 성질이 깨진다**. ★ **그래서 watchdog은 로컬만 읽고, 할 수 있는 조작은 여전히 직전 manifest 재기동 하나다** ⑸ ★ **새 서버 제품을 들이지 않는다는 것은 그대로다**(C-08) — 들어온 것은 **이미 있는 MySQL의 스키마 하나**이지 새 저장 제품이 아니다 |
| ★ **잔여-3 닫힘 — 커트오프 중 긴급 롤백** | **정본 = ADR-024 §2.4**(RL-4의 명시 예외 1건 — **롤백만** · **사람 2단 확인** · **그 영업일 커트오프 판정을 「열림」으로 표시** · **발동 2회 = 재판정 R9**). ⑴ ★ **override는 락을 무시하지 않고 우선 획득**한다 — 새 fencing token이 발급되고 **빼앗긴 스케줄러는 단계 경계에서 정지**한다 ⑵ ★ **DO-*에 새 규칙이 필요하지 않다** — override는 **CD-3 획득의 한 형태**이고 이후 경로는 **§4 롤백 표 그대로**다. **agent가 하는 일은 여전히 컨테이너 조작뿐**(DO-4) ⑶ ⚠️ ★ **DO-5 ⑶(토글은 락을 잡지 않는다)과 섞지 않는다** — 모드 토글과 override는 **다른 조작**이며, override는 **락을 잡는다** ⑷ ★ **관제(DO-6)가 보여주는 넷에 override 점유가 구별되어 보여야 한다** — *"락이 잡혀 있다"* 와 *"배치를 밀어내고 잡았다"* 가 같은 화면에서 같아 보이면 R9의 관측이 성립하지 않는다 |
| ★ **구현 언어 — Go 확정**(2026-08-07 사용자 결정) | ★ **deploy-agent · dispatcher · watchdog · (후속) 로그 콜렉터의 구현 언어 = Go**. 근거·대조표·되돌림 비용은 `operations/infrastructure.md` **§4**가 소유한다(이 ADR은 **인용**). ⚠️ ★ **C-05를 재판정한 것이 아니다** — 은행 도메인(코어·정산·원장)은 **Kotlin/JVM 불변**이고, 새 언어는 ★ **인프라 층에만** 산다. ★ **C-08 관점의 대가는 「언어 하나가 운영 대상으로 남는다」** 이며 그것을 명시 수용한다. ⚠️ ★ **되돌림 신호**: 인프라 층 도구가 **은행 도메인 판정을 담기 시작하면**(예: agent가 커트오프·자금 상태를 해석) 그것은 **언어 선택의 문제가 아니라 경계 침범**이다 — `infrastructure.md` §4가 그 관측을 소유한다 |

> ⚠️ ★ **닫힌 것은 「결정 공백」이지 「검증」이 아니다.** 위 셋은 전부 **§6의 검증 대상이 늘어난다**(ADR-022 §6 · ADR-024 §6 · 이 ADR §6) — *"정본이 결정했다"* 와 *"실제로 그렇게 선다"* 는 다른 판정이다(C-09 — 실측 장소는 운영뿐).

## 2.3 컴포넌트 모델 — 단일 바이너리·모드 구성 (2026-08-07 개정 — DO-3·DO-13 대체)

> ★ 사용자 토폴로지·설계(2026-08-07): 각 호스트가 자기 서버를 배포하고 자기 PC를 모니터링한다. .9는 오케스트레이터이면서 자기도 배포 대상(코어가 여기 있다)이라 배포 능력을 겸한다. 인프라 도구 자체는 **컨테이너로 못 띄운다**(docker·systemctl을 제어해야 하므로) — 네이티브 바이너리로 systemd 유닛 상주.

**DO-21. 단일 Go 바이너리·역할은 `.env`로 정한다** — `ROLE=main` 또는 `ROLE=agent`. 하나를 크로스컴파일해 3호스트에 배포하고 모드만 가른다(ADR-028·029 IA-4). 프로세스를 나누지 않고 **모드로 역할을 분리**하는 것이 사용자 결정이다(2인 프로세스 안은 오히려 "따로 나누는" 게 되어 모드의 단순함을 해친다).

- **`ROLE=main`**(.9): 외부 HTTP 수신·서명 검증(DO-10·11)·모드 판정(DO-5)·각 호스트에 서명 명령 분배 **+ 자기 호스트(.9)의 로컬 배포**. .9가 자기 코어를 배포해야 하므로 **메인도 특권을 갖는다**(단일 모드의 귀결 — 사용자 확인).
- **`ROLE=agent`**(.158·.164): 메인에서 서명 명령만 받아(LAN 전용) 자기 호스트를 배포·모니터링한다.

**DO-22. 서버 간 전송 = HTTP+JSON + HMAC 서명**(gRPC 아님·SSH 아님 — DO-3 대체). 외부 진입과 같은 프로토콜·툴체인 하나로 최소화(C-08). gRPC는 스트리밍·성능 필요 시 도입 조건. **3서버 공통 SSH 키가 사라진다**(F-05의 그 축은 해소). ⚠️ 내부 RPC 서명 알고리즘·키 방향·응답 인증·bind·방화벽 = `[구현 검증]`.

**DO-23. 특권 부여 = `.env` 서버 자격 + sudo (★ 수용된 잔여 위험 — §7 잔여-7).** 서버 id/비밀번호를 그 호스트 `.env`에 두고 특권 조작(systemctl 등)에 쓴다. ⚠️ ★ **codex 선검증이 이를 채택 차단 사유로 지적**했고(인터넷 경로 침해 시 임의 root), **사용자가 수용 결정**했다(2026-08-07). 몰래 우회하지 않고 §7에 잔여 위험으로 기록한다. **최대 완화(선택 안에서)**: ⑴ 실행은 **열거된 명령만**(raw shell·임의 flag 금지 — 구 DO-13 dispatcher를 내부 모듈로) ⑵ 인터넷 입력은 **서명 검증 통과 후에만** 특권 경로에 닿는다(코드 층 경계) ⑶ `.env` 0600·gitignore·**git 이력 절대 0**(public repo) ⑷ agent 리스너 **LAN 한정·bind 제한**. DO-13(docker 그룹·무sudo)을 이 조항이 대체한다.

**DO-24. watchdog는 별도 바이너리로 상주한다**(모드 통합 안 함) — agent가 죽어도 감시해야 하므로 같은 프로세스면 안 된다(DO-19). 호스트별.

| **얻는 것** | ★ **CDT-1·CDT-2가 닫힌다** — 위성 배포·롤백이 **실행 가능**해지고, agent 교체가 **되돌릴 수 있는 조작**이 된다 · ★ **새 전송 채널·새 인증 축을 만들지 않았다**(C-08 — SSH·엣지·컨테이너 전부 보유분) · ★ **무엇이 돌고 있는지가 한 화면에 있다**(DO-6) · `cicd.md` **§6.2**의 러너 위치 판정이 걸려 있던 **조건(위성 경로 미정)이 해소**된다 |
| ⚠️ **내주는 것 ⑴ — agent가 단일 장애점** | ★ **agent가 죽으면 3대 전부 배포·롤백이 멈춘다.** 이것은 RL-7이 *"경로를 하나로"* 정했을 때 이미 생긴 성질이고, 이 ADR은 그것을 **위성 두 대까지 확대**한다. 완화는 셋뿐이다 — ⑴ **DO-8**(자기 교체·복원이 agent 밖에서 완주) ⑵ **DO-6**(관제가 agent 무응답을 보여준다) ⑶ ★ **호스트 자체가 죽은 경우의 경로는 `cicd.md` CD-3 「제공자 순환」과 같은 축**(사람이 읽고·기록하고·실행) 이며 ✅ ★ **2026-08-07 — 그중 「코어가 죽어 락을 못 잡는다」 칸은 닫혔다**(**§2.2** · ADR-022 §2.1 — 락의 제공자가 DB로 바뀌어 **원자 획득이 성립**한다). ⚠️ **남는 것은 「agent 호스트(`.9`) 자체가 죽는 칸」**이고 거기에는 **여전히 원자성이 없다**(그때는 락 이전에 배포 주체가 없다). ★ **이중화하지 않는 이유**: 배포 주체가 둘이면 **동시 배포**가 가능해지고 그것을 막는 것이 다시 락이다 — 단일 장애점을 **감추지 않고 관측 대상으로 두는 편**이 v1에서 싸다(R1) |
| ⚠️ **내주는 것 ⑵ — SSH 키가 고가치 표적** | ⚠️ ★ **2026-08-07 개정 — v0.1은 「키 하나로 3대」였고 그것을 DO-14가 호스트별 분리로 바꿨다.** 축소 수단을 **전부** 적는다: ⑴ ★ **키는 agent에만 있고 이미지에 넣지 않는다** — 이미지는 레지스트리에 있으므로 **이미지에 넣는 순간 키가 레지스트리에 있는 것**이다 ⑵ **배포 전용 계정**으로 분리한다 — ⚠️ ★ **다만 「sudo를 주지 않는다」를 권한 축소로 읽지 않는다**(DO-13 · 아래 ⑸행) ⑶ ★ **강제 명령 = root 소유 dispatcher**이고 **고정 열거 인자만** 받는다(DO-13 — 임의 셸·임의 flag 금지) ⑷ **출발지 제한 + `restrict`(no-pty·forwarding 금지) + host key pinning**(DO-14) ⑸ ★ **서명 검증이 먼저**다(DO-2 — SSH는 두 번째 관문) ⑹ ★ **호스트별 키 분리**로 유출 반경을 **호스트 하나**로 줄인다(DO-14 ⑴) ⑺ **교체 절차는 IV-14 축**에 등재한다. ⚠️ ★ **⑶⑷의 실효성과 ⑺의 무중단 성립은 문서로 판정할 수 없다** = `[구현 검증]`(§6) |
| ⚠️ **내주는 것 ⑶ — 엣지가 경로에 들어간다** | 엣지는 **여러 프로젝트가 공유**하고 **설정 오류 시 그 도메인들이 함께 죽는다**(실측). 그래서 ⑴ ★ **설정 검증 통과 전 반영 금지** ⑵ ★ **기존 도메인 설정은 건드리지 않는다**(추가만) ⑶ 엣지는 **프록시일 뿐**이므로(DO-1) 배포 판정 로직이 그쪽에 새지 않는다. ⚠️ 그럼에도 **우리 배포가 남의 서비스를 죽일 수 있는 경로가 생겼다** — 이 사실을 R3의 관측 대상으로 둔다 |
| ⚠️ **내주는 것 ⑷ — 호스트마다 레지스트리 조회 자격** | **DO-9**의 대가다. 시크릿 종류가 하나 늘고 **호스트 수만큼 복제**된다 — 되돌리는 형태와 조건은 DO-9에 함께 적혀 있다. ⚠️ ★ **DO-14의 호스트별 키 분리로 SSH 키도 같은 성질이 된다**(키 수 = 호스트 수) — **반경을 줄인 대가가 개수**다 |
| ⚠️ ★ **내주는 것 ⑸ — docker 그룹은 root 동등이다**(2026-08-07 명시 수용) | ★ **이것을 위험으로 수용하고 넘어간다**(DO-13). 즉 **배포 키·dispatcher가 뚫리면 그 호스트의 root와 같다** — v0.1이 *"sudo 없음 = 권한 축소"* 로 적었던 것은 **잘못된 안전성 주장**이었다. ★ **대신 얻는 것**: 도달 가능한 조작이 **열거 가능한 유한집합**이 된다(입력의 자유도를 낮췄다). ★ **되돌리는 조건 = R7** — rootless 런타임 또는 권한 분리 도입 |
| ⚠️ ★ **내주는 것 ⑹ — 관제가 LAN 안에만 있다**(DO-12) | 외부에서 배포 상태·모드를 **볼 수 없다**(VPN 경유가 유일). ★ **그 불편을 외부 노출로 풀지 않는다** — 모드 토글이 외부에 서는 순간 **승인 게이트가 인터넷 표면**이 된다(R5가 세려던 사건이 원격에서 실행 가능해진다) |
| ⚠️ ★ **내주는 것 ⑺ — 배포 상태가 새 축이다**(DO-17 · ★ **2026-08-07 개정** — §2.2) | ⚠️ ★ **v0.2 문면**: *"백업 대상이 하나 늘고(SSH 키는 반대로 백업 제외 — 두 규칙이 같은 호스트에서 갈린다) 저장이 손상되면 fail-closed로 배포가 멈춘다. **그래도 CDT-4는 닫히지 않는다**"*. ★ **v0.3 — 정본이 DB로 옮겨 가면서 셋이 바뀐다**: ⑴ ✅ **CDT-4가 닫혔다**(락과 이력이 같은 스키마 — §2.2) ⑵ ★ **백업 비대칭이 사라진다** — 정본이 **DB 백업 축**(ADR-022 §4 백업·PITR)으로 흡수되고, 호스트에 남는 것은 **캐시·버퍼와 자기 교체 의도**뿐이다(⚠️ **SSH 키 백업 제외는 그대로**) ⑶ ⚠️ ★ **대신 배포 경로가 DB 가용성에 묶인다** — **DB가 죽으면 배포·롤백이 fail-closed로 멈춘다**(ADR-022 §4 «내주는 것 ⑶»). ★ **그 상태는 배포 대상 셋이 이미 멈춘 상태**라 성질이 다르지만 **묶였다는 사실은 감추지 않는다** ⑷ **계정이 둘 는다**(ADR-022 DT-10·DT-11 — 형상 관리·커넥션 총량) |
| **새로 생기는 일** | deploy-agent 구현(★ **언어 = Go** — §2.2 · `infrastructure.md` §4) · **엣지 프록시 설정 1건**(추가 · ★ **deploy 전용 제한 포함** — DO-15) · **SSH 배포 키(호스트별)·전용 계정·root 소유 dispatcher** · **레지스트리 조회 자격**(호스트별) · **관제 페이지·이력 API**(★ **LAN 전용 + 인증·CSRF** — DO-12 · ★ **override 점유를 구별해 보여준다** — §2.2) · **모드 토글과 그 기록** · ★ **배포 스키마 + DB 계정 2개**(ADR-022 **DT-9~DT-11** — v0.2의 *"agent 내구 저장"* 을 대체) · ★ **호스트 상주 watchdog**(DO-19 — 일회성 provisioning · **로컬 의도만 읽는다**) · 이미지 정리(보관 개수 — CD-5 · CDV-5) |

## 5. 되돌리는 조건

| # | 관찰되면 | 그때 할 일 |
|---|---|---|
| **R1** | ★ **agent 장애로 배포·롤백이 막힌 사건이 2회** 실측된다 | **DO-3을 재판정**한다 — 위성에 최소 실행 주체를 두거나 agent를 이중화한다. ⚠️ 그때 **동시 배포를 무엇이 막는가**(락의 소유)를 함께 결정하지 않으면 RL-7이 깨진다 |
| **R2** | ★ **배포 SSH 키·계정으로 배포 조작 집합 밖의 명령이 실행된 사건**이 **1회라도** 발견된다 | 즉시 **키 교체 + 명령 제한 재설계**. ★ **RL-8 R5와 같은 무관용 축**이다 — 관문 둘 중 하나가 새면 나머지 하나의 의미가 사라진다 |
| **R3** | **엣지 설정 변경으로 우리 배포 밖의 도메인이 죽은 사건**이 **1회** 난다 | 배포 엔드포인트를 **그 엣지에서 분리**한다(별도 진입 또는 별도 인스턴스). 공유 엣지의 반경을 우리 프로젝트가 계속 키우지 않는다 |
| **R4** | **배포 대상 호스트가 늘어** SSH 분기가 agent 절차로 감당되지 않는다 | **ADR-024 기각 B의 도입 조건**이 발동한 것이다 — 오케스트레이터를 다시 본다(안 A) |
| **R5** | ★ **모드 토글이 승인을 우회하는 데 쓰인 사건**(운영 대상을 dev로 내려 자동 배포시킨 경우) 이 **1회** 관측된다 | **토글 권한을 배포 지시 권한과 분리**하거나 **dev 모드를 철회**한다 — **ADR-024 R7**과 같은 관측 대상이며, 그 관측이 성립하려면 **DO-5의 토글 기록**이 반드시 남아 있어야 한다 |
| **R6** | **레지스트리 조회 자격의 배포·교체가 감당되지 않는다**(호스트별 시크릿) | **DO-9의 형태를 바꾼다** — agent가 받아 각 호스트로 밀어 넣는 경로로 전환(시크릿 1곳 · 전송 증가) |
| ★ **R7**(2026-08-07 신설) | ★ **dispatcher를 우회한 실행 경로가 1회라도 발견된다**(raw shell 도달 · 임의 flag·volume 주입 · dispatcher 파일을 배포 계정이 쓸 수 있음) | ★ **R2와 같은 무관용 축** — 즉시 차단·재설계하고, 그때 **rootless 런타임 또는 권한 분리**를 다시 본다(DO-13이 v1에서 미룬 자리). ⚠️ **docker 그룹이 root 동등이므로 이 발견은 「권한 상승 가능」이 아니라 「이미 root」다** |
| ★ **R8**(2026-08-07 신설) | ★ **DO-8의 자동 재기동이 ⑴ 같은 교체에서 2회 이상 실행되거나 ⑵ 자기 교체 밖(코어·위성)에서 실행된 사건**이 **1회** 관측된다 | ★ **RL-11 예외를 철회**한다(**ADR-024 §2.3**과 같은 관측 대상) — 예외의 경계가 지켜지지 않으면 그것은 **예외가 아니라 자동 롤백**이다 |
| ★ **R9**(2026-08-07 신설) | ★ **UNKNOWN 상태가 사람 개입 없이 닫히지 않은 사건이 2회** 실측된다(조회로도 판정되지 않음) | **DO-16을 재판정**한다 — 원격 결과 회수를 dispatcher 상태 조회가 아닌 **별도 회수 채널**(호스트가 결과를 되보내는 형태)로 바꾼다. ⚠️ 그때 **새 인증 축이 생기는지**를 함께 판정한다(C-08) |

| ★ Phase 5 | ★ **저장 정본 이관**(§2.2 · DO-17 개정) | ⑴ ★ **락 행과 배포 이력을 한 읽기 트랜잭션**으로 대조한다(ADR-022 §6과 같은 축) ⑵ ★ **이력 기록 직후·락 해제 직전에 agent를 죽인다** → *"배포됐는데 이력 없음"* 이 **만들어지지 않는다** ⑶ ★ **DB 단절 구간의 사건이 로컬 버퍼에 쌓였다가 복구 후 flush** → **이중 기록·순서 역전이 없다** ⑷ ★ **watchdog은 DB 없이도 자기 교체 의도를 읽어 1회 복원**한다(로컬 정본이 남는 유일한 항목) |
| ★ Phase 5 | ★ **override 경계**(§2.2 · ADR-024 §2.4) | ⑴ 배치 점유 중 **override 롤백** → 실행되고 **빼앗긴 배치가 단계 경계에서 정지**한다 ⑵ 같은 상태에서 **전진 배포** → **거절·기록** ⑶ ★ **관제 화면에서 override 점유가 일반 점유와 구별**된다(구별되지 않으면 **R9 관측이 성립하지 않는다**) |
| ★ Phase 5 | ★ **manifest 롤백**(DO-18) | **이미지는 그대로 두고 compose revision만 바꾼 배포**를 한 뒤 롤백 → ★ **compose 정의까지 직전으로 돌아간다**(이미지만 되돌아가면 실패) · pull·up이 **digest로 고정**됐음을 확인 |
| ★ Phase 5 | ★ **엣지 유량 제한**(DO-15) | 무서명 대량 요청·초과 크기 본문·POST 아닌 method → ★ **엣지에서 잘린다** · ★ **`bank.` 진입이 영향을 받지 않는다** · **agent·엣지의 로그가 디스크를 채우지 않는다**(회전·상한) |
| Phase 5 | ★ **롤백** | 이전 태그로 재기동 → **재빌드·레지스트리 조회 없음**(네트워크를 끊고도 성립) · 소요 기록(RL-5 · DO-7) |
| Phase 5 | ★ **모드**(DO-5) | dev 대상 = 자동 실행 / 운영 대상 = 승인 대기 · ★ **토글이 이력에 남는다** · ★ **dev에서도 배치 중 배포는 거절**(RL-4) |

## 7. ★ 승인된 잔여 위험 — 이 설계가 닫지 **않은** 것 (2026-08-07 신설 · 사용자 합의 대상 · ★ **v0.3에서 1·2·3 닫힘 — 4·5·6 잔존**)
