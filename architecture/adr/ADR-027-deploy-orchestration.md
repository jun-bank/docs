# ADR-027. 배포 오케스트레이션 — **agent 하나가 엣지 뒤에 서고, 이미 있는 SSH로 3대에 닿는다**

- 일자: 2026-08-07
- 상태: **채택**
- 결정자: 사용자 · AI 페어
- 근거: **ADR-024 RL-7·RL-8**(배포 경로·인증) · `operations/cicd.md` **CDT-1·CDT-2**(닫히지 않은 공백 2건) · ★ **2026-08-07 홈랩 실측**(집 서버 3대 + 오라클 엣지 — 접속·권한·컨테이너 형상) · **C-08**(도구 최소주의) · **C-09**(스테이징 없음)
- 관련: **ADR-024**(릴리스 — 특히 **§2.1** 배포물 · **RL-5** 이미지 롤백 · **RL-10** 모드 조항 · **RL-11**) · **ADR-019**(CH-1 진입점 · CH-4 어댑터 · CH-8) · **ADR-020**(RT-1 정적 라우팅) · **ADR-022**(권한 매트릭스 — agent에게 DB 계정을 주지 않는다) · **ADR-023**(OB-1 관측 독립성) · `operations/cicd.md`(**CD-1~CD-5**) · `implementation-verification.md`(**IV-14 ⑶** 배포 인증키)
- 규칙 ID 접두어: **`DO-`**

## 1. 맥락 — 결정이 하나 빠져 있어서 절차가 닫히지 않았다

ADR-024 **RL-7**은 배포 실행 주체를 하나로 못박았다 — *"CI가 … VPN 안의 배포 API를 호출하면(오라클 프록시 → `.9` → agent) agent가 대상 서버에 적용한다. 사람이 서버에 들어가 손으로 바꾸지 않는다."*
그런데 **거기서 멈췄다.** `.9`의 agent가 위성 두 대(`.158`·`.164`)에 **어떻게 닿는지**가 어느 정본에도 없었고, `operations/cicd.md`가 그것을 **CDT-1**로 이월하면서 상태를 이렇게 적었다 — *"⚠️ 위성 배포·롤백이 실행 불가."*

| 공백 | 무엇이 없었나 | 그 결과 |
|---|---|---|
| **CDT-1** | agent → 위성의 **⑴ 전송 방식 ⑵ 위성 측 실행 주체 ⑶ 인증 ⑷ 실패 경계** | 위성 배포·롤백이 **실행 불가**. §6.2의 러너 위치 판정도 이 행에 걸려 **조건부**로 강등돼 있었다 |
| **CDT-2** | agent **자기 배포의 복원 경로** — 교체 직후 스모크가 실패하면 누가 무엇으로 되돌리나 | agent 교체를 **되돌릴 수 없는 조작**으로 취급할 수밖에 없었다 |

> ⚠️ ★ **이 공백을 *"일단 수동으로"* 로 메울 수 없다는 것이 문제의 핵심이었다.** RL-7이 *"사람이 서버에 들어가 손으로 바꾸지 않는다"* 로 **수동 대체 경로를 이미 막았기** 때문에, 공백을 수동으로 적는 순간 **RL-7의 예외를 신설**하는 것이 된다. 그래서 `cicd.md`는 채우지 않고 이월했다(CF-1). **결정이 필요한 자리였다.**

### 실측이 무엇을 열었나 (2026-08-07)

| 실측 | 이 결정에 무엇을 의미하나 |
|---|---|
| ★ **집 서버 3대가 SSH 키 하나로 공통 접근**된다 | **새 전송 채널을 만들 필요가 없다.** C-08의 순서(요구 → 계약 → 도구)에서 *"이미 보유한 것"* 이 먼저다 |
| ★ **배포 계정이 docker 그룹 소속 — docker·compose는 무암호** / **sudo는 암호 필요** | agent가 **원격에서 실행할 수 있는 조작의 집합**이 정확히 **컨테이너 조작**이다. 그 밖(유닛 설치·재시작)은 자동화가 성립하지 않는다 — ADR-024 **§2.1 재판정 사유 ⑴** 과 같은 실측 |
| ★ **엣지(오라클)가 이미 리버스 프록시로 도메인 여럿을 종단**하고 있다 | 배포 엔드포인트의 진입점을 **새로 만들지 않는다** — 다만 그 엣지는 **여러 프로젝트가 공유**하므로 설정 사고의 반경이 우리 프로젝트 밖까지 간다(§4) |
| ★ **호스트 수집 에이전트가 컨테이너 헬스를 걷어 경보**한다 | 관제 v1이 **가동 여부 감시를 다시 만들 필요가 없다** — 관제가 소유하는 것은 **배포 이력·상태·모드**다(C-08) |
| ⚠️ ★ **"repo보다 오래된 코드가 도는 사건"이 실제로 있었다** | 배포 도구 없이 파일 동기화로 배포하면 *"커밋했는데 배포는 안 됐다"* 가 **조용히** 남는다. 이 ADR의 관제(**DO-6**)가 *"지금 무엇이 돌고 있나"* 를 화면 하나로 만드는 이유다 — RL-7의 *"배포 이력이 곧 사실"* 을 **볼 수 있게** 만드는 축 |

## 2. 결정

| # | 규칙 | 왜 |
|---|---|---|
| **DO-1** | ★ **배포의 외부 진입은 엔드포인트 하나다** — **`deploy.junproject.xyz`** → **오라클 엣지 nginx**(TLS 종단·프록시) → **허브(`.9`)의 deploy-agent**. ★ **엣지는 인증하지 않는다 — 전달만 한다.** DB·내부 API·위성은 **인터넷에 노출하지 않는다**(LAN 유지). ★ **엣지에는 은행 서비스용 진입도 함께 선다** — **`bank.junproject.xyz`**(실시간 대시보드 — **별도 산출물**이며 이 ADR은 *"그 진입이 존재한다"* 만 기록한다). ⚠️ **두 진입은 소유가 다르다**: 배포 진입은 **배포 경로의 관문**(DO-2)이고 서비스 진입은 **사람 채널**(ADR-019 CH-1)이다 — **같은 엣지에 서 있다는 이유로 인증·속도 제한을 공유하지 않는다** | RL-7이 정한 경로의 **실물**이다. ★ 엣지에서도 서명을 보면 **판정 주체가 둘**이 되고, 둘이 갈리는 순간 *"거절은 어디 기록되나"* 가 흐려진다 — 판정은 **agent 한 곳**(RL-8·R5의 거절 기록이 성립하려면 한 곳이어야 한다) |
| **DO-2** | ★ **인증은 RL-8 그대로 — 서명 검증 실패 = 적용하지 않고 거절 기록**(예외 없음). 키는 **CI 플랫폼의 시크릿 저장소**가 보관하고, 발급·보관·교체는 **IV-14 ⑶** 이 소유한다. ★ **SSH는 인증 수단이 아니라 그 뒤의 전송**이다 — 서명 검증을 통과한 뒤에만 SSH가 열린다 | 배포 API는 **인터넷에서 도달 가능한 원격 코드 실행**이다(RL-8 원문). ★ 두 관문의 순서가 뒤집히면 — SSH가 먼저면 — **서명 없는 요청이 호스트에 닿는 경로**가 생긴다 |
| **DO-3** | ★ **위성 적용은 agent가 SSH로 한다**(**CDT-1 소화**) — ⑴ **전송 = SSH**(3대 공통 키) ⑵ ★ **위성 측 실행 주체를 두지 않는다** — 위성에 agent를 설치하지 않고, **허브의 agent가 원격에서 컨테이너 조작을 실행**한다 ⑶ **인증 = SSH 키**(권한 축소는 §4) ⑷ ★ **실패 경계 = 연결 실패·명령 실패는 그 단계의 실패로 접힌다** — `cicd.md` **CD-4 ⑷** 의 해당 단계(회수 / 정지 / 교체 / 기동 / 헬스체크)가 실패한 것으로 판정하고, **부분 실패는 위성 정지 구간 상한(CD-2 ⒞)** 이 소유한다 | ★ **위성에 agent를 두면 배포 실행 주체가 셋이 되어 RL-7이 깨진다.** 게다가 **자기 배포 복원 문제(CDT-2)가 세 배**가 된다. 반대로 SSH는 **이미 있는 채널**이고 새 인증 축을 만들지 않는다(C-08) |
| **DO-4** | ★ **agent가 하는 일은 컨테이너 조작뿐이다** — **이미지 조회(pull) → compose 기동·종료 → 상태 판정 → 이력 기록**. ★ **호스트에 빌드 도구를 두지 않는다**(빌드는 CI가 소유 — P1·P3) · ★ **sudo가 필요한 조작을 배포 절차에 넣지 않는다**(유닛 설치·패키지 설치·재시작) | 배포가 요구하는 권한이 **docker 그룹 하나**로 닫힌다 — 그 경계를 넘는 순간 배포는 **사람의 대화형 개입**을 요구하고(실측), 그것은 RL-7이 막은 형태로 되돌아간다 |
| **DO-5** | ★ **모드 토글은 관제가 소유한다**(RL-10 모드 조항의 실행 형태) — **배포 대상마다** `dev`/`운영` 을 두고 **사람이 토글**하며 ⑴ **토글은 배포 이력과 같은 기록에 남는다**(누가·언제·어느 대상·어느 방향) ⑵ ★ **운영 → dev 방향은 되돌림으로 취급**한다 — 사용자 확인을 거치고 **그 사실이 눈에 띄게 남는다** ⑶ 토글은 **배포 요청이 아니다** — CD-4를 타지 않고 **락도 잡지 않는다** | ★ **토글이 곧 승인 게이트의 on/off** 다. 기록이 없으면 *"승인 없이 배포된 것"* 과 *"승인이 필요 없는 대상이었던 것"* 이 **사후에 구별되지 않는다**(ADR-024 R7의 관측이 이 기록에 걸린다) |
| **DO-6** | ★ **관제 v1 = 배포 이력·상태 API + 최소 페이지**다. 보여주는 것은 넷 — ⑴ 대상별 **현재 가동 이미지 태그**와 **직전 가동 태그** ⑵ **마지막 배포 이력**(요청자·커밋 SHA·각 단계 결과·거절 사유) ⑶ **배포 창 락의 점유 상태** ⑷ **모드**. ★ **대시보드 제품을 도입하지 않는다**(C-08) · ★ **가동 여부 감시는 만들지 않는다** — 호스트 수집 에이전트의 컨테이너 헬스 경보가 이미 그 축이다 | *"무엇이 돌고 있는지 아무도 모른다"* 가 RL-7이 막으려던 상태이고, **실측으로 이미 한 번 일어난 사건**이다(§1). 이력이 **있는 것**과 **보이는 것**은 다르다 |
| **DO-7** | ★ **롤백은 이전 태그로의 compose 재기동**이다(**RL-5** 개정 조항 그대로) — 재빌드도 **레지스트리 조회도 하지 않고** 호스트 로컬 이미지를 쓴다. ★ **롤백도 배포다** — 같은 락(CD-3)을 잡고 같은 이력에 남는다. ★ **자동 롤백은 두지 않는다**(**RL-11** — 판정 주체는 사람) | 장애 중에 **네트워크에 의존하는 되돌림**은 되돌림이 아니다 — 레지스트리가 안 되는 상황이 곧 롤백이 필요한 상황일 수 있다 |
| **DO-8** | ★ **agent는 자기 자신도 「원격 대상」으로 취급한다**(**CDT-2 소화**) — 자기 교체·복원을 **DO-3과 같은 SSH 경로**로 실행한다: ⑴ **사람 확인**(CD-4 ⑹ ⒜ 그대로) ⑵ 현재 가동 태그를 **기록** ⑶ ★ **자기 호스트로 SSH 세션을 열어 교체 명령을 던진다** — 실행 주체가 **agent 프로세스 밖(sshd 세션)** 이므로 agent가 내려가도 교체가 완주한다 ⑷ **스모크**(임의 배포 요청 1건이 정상 거절/수락되는지 — CD-4 ⑹ ⒝) ⑸ ★ **스모크 실패 시 같은 세션이 직전 태그로 재기동**하고 결과를 기록한다. ⚠️ ★ **이것은 RL-7의 예외가 아니다** — 되돌리는 것은 **사람이 아니라 배포 경로가 낸 명령**이다 | ★ **자기를 교체하는 주체는 교체 중에 존재하지 않는다** — 그래서 실행 주체를 **자기 프로세스 밖**으로 한 겹 옮기는 것 말고는 답이 없다. SSH는 그 한 겹을 **이미 있는 것**으로 제공한다(새 도구 0) |
| **DO-9** | ★ **호스트가 레지스트리에서 직접 이미지를 가져온다**(v1 판정) — agent가 대상 호스트에서 pull을 실행하고, 그 호스트에 **조회 전용 자격**을 둔다. ⚠️ ★ **대가를 적는다**: 시크릿이 **호스트 수만큼** 생긴다. ★ **되돌리는 조건**: 그 자격의 배포·교체가 감당되지 않거나(IV-14 축) 사설망 밖 전송량이 문제가 되면 ★ **agent가 한 번 받아 각 호스트로 밀어 넣는 형태**로 바꾼다 — 그때 시크릿은 **agent 한 곳**으로 줄고 전송이 늘어난다 | 두 형태의 차이는 **자격증명 면**과 **전송 경로**의 맞바꿈이다. v1이 직접 pull인 이유는 **compose의 표준 경로**여서 절차에 특수 단계가 생기지 않고, 롤백이 어느 쪽이든 **호스트 로컬 이미지**로 닫히기 때문이다 |

### 경로 한 장

```
[GitHub Actions]  빌드 → 이미지 push → (모드에 따라) 배포 요청 + HMAC 서명
        │  인터넷
        ▼
[오라클 엣지 nginx]  TLS 종단 · 프록시만 — ★ 인증하지 않는다 (DO-1)
        ├─ deploy.junproject.xyz  → 허브 deploy-agent      ← 이 ADR이 소유
        └─ bank.junproject.xyz    → 은행 실시간 대시보드    ← 별도 산출물 (표면만 기록)
        │
        ▼
[허브 .9 · deploy-agent]  ★ 서명 검증 (DO-2 · RL-8) → 배포 창 락 (CD-3) → CD-4 순서 적용
        ├─ 자기 호스트(.9 코어)  : SSH 세션 → 이미지 pull → compose up/down
        ├─ 정산 .158            : SSH        → 〃                     (DO-3)
        ├─ 원장 .164            : SSH        → 〃                     (DO-3)
        └─ agent 자신           : ★ 자기도 원격 대상 (DO-8) — sshd 세션이 교체·복원을 완주
                 │
                 ▼
        [관제 v1]  이력 · 가동 태그 · 락 점유 · 모드 (DO-5·DO-6)
```

> ★ **엔드포인트는 하나, 관문은 둘이다** — ⑴ **서명**(누가 요청했나 · DO-2) ⑵ **SSH 키**(어디에 닿나 · DO-3).
> 순서가 고정이라는 것이 이 구조의 안전 성질이다: **서명을 통과하지 못한 요청은 SSH를 만나지 못한다.**

## 3. 왜 나머지를 기각했나

| 안 | 기각 이유 | 이 이유가 바뀌면 (도입 조건) |
|---|---|---|
| **A. 쿠버네티스 계열 오케스트레이터에 배포를 맡긴다** | **ADR-024 기각 B 그대로** — 얻는 것이 RL-2·RL-5로 이미 덮이고, 서버 3대에 클러스터를 올리면 **배포보다 플랫폼이 더 큰 문제**가 된다. ⚠️ **이 ADR은 그 기각을 재판정하지 않는다**(인용) | ★ **ADR-024 기각 B의 조건** — 배포 대상 호스트가 늘어 **수작업 스왑이 안 될 때** |
| **B. Watchtower류 자동 pull**(각 호스트가 레지스트리를 감시해 새 태그를 스스로 당긴다) | ★ **결정 셋을 동시에 깬다.** ⑴ **RL-10** — 방아쇠가 *"레지스트리에 태그가 올라온 것"* 이 되어 **사람의 지시가 사라진다**(모드 조항의 운영 모드가 성립하지 않는다) ⑵ **RL-7** — 적용 주체가 **호스트마다 하나씩** 생겨 실행 주체가 셋이 된다 ⑶ ★ **CD-3 배포 창 락을 아무도 잡지 않는다** — **커트오프 도중에 버전이 바뀐다**(RL-4가 막으려던 바로 그 사태이며, BR-52의 앞·뒤 단계가 다른 버전으로 판정된다). 게다가 **블루-그린 전환·전문 정지 창·이력 기록**이 전부 빠진다 | ★ **RL-10과 RL-4가 함께 철회될 때** — 즉 사람 방아쇠 요구가 없고 배치 창 락도 필요 없어질 때. ⚠️ 그 전에는 **dev 모드조차 이 형태로 구현하지 않는다**(dev에서도 락·서명·이력은 그대로다 — RL-10 모드 조항) |
| **C. 서버별 개별 웹훅**(CI가 3대에 각각 요청) | ⑴ ★ **노출면이 셋**이 된다 — 위성이 인터넷 도달 대상이 되어 *"앱 포트만 엣지에 붙이고 내부는 LAN"* 이라는 경계(DO-1)가 깨진다 ⑵ ★ **이력이 세 곳으로 흩어진다** — RL-7의 *"배포 이력이 곧 사실"* 이 성립하지 않는다 ⑶ ★ **락 → 적용 → 기록의 순서를 아무도 소유하지 않는다**(CD-4가 한 주체를 전제한다) | — (구조적 — RL-7을 되돌리지 않는 한 열리지 않는다) |
| **D. CI가 서버에 직접 SSH로 배포** | **ADR-024 기각 D 그대로** — **CI 자격증명 유출 = 서버 전면 장악**. ⚠️ ★ **이 ADR이 SSH를 쓰는 것과 혼동하지 않는다**: 여기서 키는 **VPN 안 agent에만** 있고 인터넷에 없다. CI가 가진 것은 **서명 키**뿐이고, 그것이 유출되면 **배포 요청을 위조**할 수 있을 뿐 **호스트 셸을 얻지는 못한다** — 그 차이가 노출면의 전부다 | — |
| **E. 관제를 대시보드 제품으로**(수집·시각화 스택 도입) | ⑴ **가동 감시는 이미 있다**(호스트 수집 에이전트의 컨테이너 헬스 경보) ⑵ 관제가 **새로 소유하는 것은 배포 이력·모드**뿐이라 제품을 들일 규모가 아니다(C-08) ⑶ **ADR-023 OB-2**가 관측 노출을 이미 정의했고, 배포 이력은 **관측이 아니라 운영 기록**이다(OB-7의 범주 구분) | ★ **배포 대상·이력의 양이 최소 페이지로 읽히지 않을 때**, 또는 **ADR-023의 수집기가 도입되어 같은 화면에 얹는 것이 더 싸질 때** |

## 4. 결과

| | 내용 |
|---|---|
| **얻는 것** | ★ **CDT-1·CDT-2가 닫힌다** — 위성 배포·롤백이 **실행 가능**해지고, agent 교체가 **되돌릴 수 있는 조작**이 된다 · ★ **새 전송 채널·새 인증 축을 만들지 않았다**(C-08 — SSH·엣지·컨테이너 전부 보유분) · ★ **무엇이 돌고 있는지가 한 화면에 있다**(DO-6) · `cicd.md` **§6.2**의 러너 위치 판정이 걸려 있던 **조건(위성 경로 미정)이 해소**된다 |
| ⚠️ **내주는 것 ⑴ — agent가 단일 장애점** | ★ **agent가 죽으면 3대 전부 배포·롤백이 멈춘다.** 이것은 RL-7이 *"경로를 하나로"* 정했을 때 이미 생긴 성질이고, 이 ADR은 그것을 **위성 두 대까지 확대**한다. 완화는 셋뿐이다 — ⑴ **DO-8**(자기 교체·복원이 agent 밖에서 완주) ⑵ **DO-6**(관제가 agent 무응답을 보여준다) ⑶ ★ **호스트 자체가 죽은 경우의 경로는 `cicd.md` CD-3 「제공자 순환」과 같은 축**(사람이 읽고·기록하고·실행) 이며 ⚠️ **거기에는 원자성이 없다는 사실이 그대로 남는다**. ★ **이중화하지 않는 이유**: 배포 주체가 둘이면 **동시 배포**가 가능해지고 그것을 막는 것이 다시 락이다 — 단일 장애점을 **감추지 않고 관측 대상으로 두는 편**이 v1에서 싸다(R1) |
| ⚠️ **내주는 것 ⑵ — SSH 키가 고가치 표적** | ★ **키 하나로 3대 전부에 닿는다.** 축소 수단을 **전부** 적는다: ⑴ ★ **키는 agent에만 있고 이미지에 넣지 않는다** — 이미지는 레지스트리에 있으므로 **이미지에 넣는 순간 키가 레지스트리에 있는 것**이다 ⑵ **배포 전용 계정**으로 분리하고 **sudo를 주지 않는다**(docker 그룹만 — DO-4가 그것으로 닫히게 설계된 이유) ⑶ ★ **그 키로 실행 가능한 명령을 배포 조작 집합으로 제한**한다(임의 셸 금지) ⑷ **접속 출발지를 허브로 제한**한다 ⑸ ★ **서명 검증이 먼저**다(DO-2 — SSH는 두 번째 관문) ⑹ **교체 절차는 IV-14 축**에 등재한다. ⚠️ ★ **⑶⑷의 실효성과 ⑹의 무중단 성립은 문서로 판정할 수 없다** = `[구현 검증]`(§6) |
| ⚠️ **내주는 것 ⑶ — 엣지가 경로에 들어간다** | 엣지는 **여러 프로젝트가 공유**하고 **설정 오류 시 그 도메인들이 함께 죽는다**(실측). 그래서 ⑴ ★ **설정 검증 통과 전 반영 금지** ⑵ ★ **기존 도메인 설정은 건드리지 않는다**(추가만) ⑶ 엣지는 **프록시일 뿐**이므로(DO-1) 배포 판정 로직이 그쪽에 새지 않는다. ⚠️ 그럼에도 **우리 배포가 남의 서비스를 죽일 수 있는 경로가 생겼다** — 이 사실을 R3의 관측 대상으로 둔다 |
| ⚠️ **내주는 것 ⑷ — 호스트마다 레지스트리 조회 자격** | **DO-9**의 대가다. 시크릿 종류가 하나 늘고 **호스트 수만큼 복제**된다 — 되돌리는 형태와 조건은 DO-9에 함께 적혀 있다 |
| **새로 생기는 일** | deploy-agent 구현 · **엣지 프록시 설정 1건**(추가) · **SSH 배포 키·전용 계정·명령 제한** · **레지스트리 조회 자격**(호스트별) · **관제 페이지·이력 API** · **모드 토글과 그 기록** · 이미지 정리(보관 개수 — CD-5 · CDV-5) |

## 5. 되돌리는 조건

| # | 관찰되면 | 그때 할 일 |
|---|---|---|
| **R1** | ★ **agent 장애로 배포·롤백이 막힌 사건이 2회** 실측된다 | **DO-3을 재판정**한다 — 위성에 최소 실행 주체를 두거나 agent를 이중화한다. ⚠️ 그때 **동시 배포를 무엇이 막는가**(락의 소유)를 함께 결정하지 않으면 RL-7이 깨진다 |
| **R2** | ★ **배포 SSH 키·계정으로 배포 조작 집합 밖의 명령이 실행된 사건**이 **1회라도** 발견된다 | 즉시 **키 교체 + 명령 제한 재설계**. ★ **RL-8 R5와 같은 무관용 축**이다 — 관문 둘 중 하나가 새면 나머지 하나의 의미가 사라진다 |
| **R3** | **엣지 설정 변경으로 우리 배포 밖의 도메인이 죽은 사건**이 **1회** 난다 | 배포 엔드포인트를 **그 엣지에서 분리**한다(별도 진입 또는 별도 인스턴스). 공유 엣지의 반경을 우리 프로젝트가 계속 키우지 않는다 |
| **R4** | **배포 대상 호스트가 늘어** SSH 분기가 agent 절차로 감당되지 않는다 | **ADR-024 기각 B의 도입 조건**이 발동한 것이다 — 오케스트레이터를 다시 본다(안 A) |
| **R5** | ★ **모드 토글이 승인을 우회하는 데 쓰인 사건**(운영 대상을 dev로 내려 자동 배포시킨 경우) 이 **1회** 관측된다 | **토글 권한을 배포 지시 권한과 분리**하거나 **dev 모드를 철회**한다 — **ADR-024 R7**과 같은 관측 대상이며, 그 관측이 성립하려면 **DO-5의 토글 기록**이 반드시 남아 있어야 한다 |
| **R6** | **레지스트리 조회 자격의 배포·교체가 감당되지 않는다**(호스트별 시크릿) | **DO-9의 형태를 바꾼다** — agent가 받아 각 호스트로 밀어 넣는 경로로 전환(시크릿 1곳 · 전송 증가) |
