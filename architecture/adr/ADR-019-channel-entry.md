# ADR-019. 채널 진입 — **nginx 라우팅 + 서명된 내부 컨텍스트 + 코어 내 전문 어댑터**

- 일자: 2026-08-06
- 상태: **채택**
- 결정자: 사용자 · AI 페어
- 근거: Phase 5 진입 아키텍처 스케치 v4(미니멀) · 선검증 F-21·F-25 · 판정 ① · 사용자 확정(*"도구는 실제 필요할 때 추가"*)
- 관련: **ADR-016**(인가 — 기각 B 재확인) · **ADR-002**(`payment/adapter`) · **ADR-010**(배포 3) · **ADR-013**(시간 예산) · `interfaces/README.md` **X-5·X-8·X-10** · context-map **R1·R4**

---

## 1. 맥락 — 배포는 정했는데 "요청이 어디로 들어오나"가 없다

ADR-010이 배포 3개를 확정했다. 그런데 **밖에서 들어오는 경로**는 어느 문서에도 없다.
들어오는 것은 셋이고, **셋이 전부 다른 프로토콜**이다.

| 채널 | 무엇이 들어오나 | 프로토콜 | 규격 정본 |
|---|---|---|---|
| **사람 채널** | 고객 조회·운영자 조작 | HTTP | Phase 4 계약 |
| **대외계 전문** | 승인·취소·망취소·입금통지 | ★ **고정길이 바이트열** | `interfaces/` X-5 |
| **대외계 파일** | 매입 파일(매입·취소 레코드 혼재) | 파일 수신 | X-8 |

### 두 가지가 이 결정을 좁힌다

| 제약 | 잘리는 것 |
|---|---|
| **C-04(예산 0)** + ★ **보유 인프라에 nginx가 이미 있다** | 새 게이트웨이 제품을 하나 더 운영할 근거가 없다 |
| **ADR-016 기각 B** — *"게이트웨이는 '이 API를 부를 수 있나'만 알고 '이 계좌가 네 것인가'를 모른다"* | 진입점에 인가를 두는 안이 **이미 기각돼 있다** |

> ★ **그러면 진입점에 남는 일은 무엇인가**가 이 ADR의 질문이다.
> 답: **라우팅·TLS·사람 채널 속도 제한**은 진입점, ★ **인증은 코어 진입 필터**(컨텍스트 발급)·★ **인가는 각 컨텍스트 진입점**(로컬 판정 — AU-3), **번역과 전문 채널 속도 제한**은 어댑터.

## 2. 결정

| # | 규칙 | 왜 |
|---|---|---|
| **CH-1** | 사람 채널의 진입점은 ★ **nginx(보유·운영 중)** 다 — TLS 종단 · **정적 라우팅**(ADR-020) · **사람 채널 속도 제한**(CH-8). **새 게이트웨이 제품을 도입하지 않는다**. ★ **배치와 공존 제약**: 이 nginx는 **`.9` 호스트의 기존 인스턴스**이고 **local-llm 등 기존 서비스와 같은 호스트를 공유**한다 — **포트 대역·자원(메모리·CPU) 분리는 [구현 검증]**(실측 없이 배치를 확정하지 않는다). ★ **TLS는 이중 종단**이다 — **오라클 리버스 프록시**(도메인·공인 인증서)에서 한 번, **`.9` nginx**에서 다시 종단한다. ★ **CH-3 ⑴의 "진입"이 가리키는 지점 = `.9` nginx** 이며, **외부 동명 헤더 strip은 거기서** 한다(오라클 프록시는 우리 신뢰 경계 밖의 홉으로 취급한다) | 배포가 3개로 고정이고 라우팅 규칙이 설정 수준을 넘지 않는다. 도구를 늘리면 그 자체가 운영 대상이 된다. ★ 공존·이중 종단은 **보유 인프라를 재사용하는 대가**이고, strip 지점을 안 적으면 *"어느 홉이 신뢰 경계인가"* 가 열린 채 남는다 |
| **CH-2** | ★ **인증과 인가는 층이 다르다**(ADR-016 AU-3 그대로). ⑴ **인증 = 코어의 진입 필터**가 소유한다 — 신원을 확인하고 **C7이 확정한 요청 컨텍스트를 발급**한다(CH-3) ⑵ ★ **인가 판정은 각 컨텍스트의 진입점에서 로컬로** 한다 — 발급된 컨텍스트를 입력으로 받아 **리소스 접점에서** 판정한다. nginx는 **주체를 모른다** ⑶ ★ **사람 채널의 진입은 코어에만 있다** — **위성(C4 정산 · C5 원장)에는 사람 채널 진입점을 두지 않고**, 위성에 대한 운영자 조작은 **C8의 정정 지시(R15) 이벤트로만** 들어간다 | ADR-016 기각 B — 객체 수준 인가는 리소스 접점에서만 판정된다. 진입점이 판정하면 내부 경로·배치가 안 걸린다. ★ ⑶ 이 없으면 *"위성에도 운영 화면이 붙나"* 가 열려 있고, 붙는 순간 **위성이 자기 인증·인가를 따로 갖게** 된다(배포별 버전 스큐 = 배포마다 다른 인가). 조작 경로를 R15 하나로 묶으면 **행위자 기록(BR-57)도 C8 한 곳**에 남는다 |
| **CH-3** | ★ **R4 전파는 C7이 발급한 서명된 단기 내부 컨텍스트**다 — 담는 것 = **주체 · 단계 · 스코프 · `authzVersion` · 운영자 `status`**(ADR-016 AU-3 그대로). ⑴ 외부에서 들어온 **동명 헤더는 진입에서 제거**한다(strip — 위조 차단) ⑵ **각 배포가 로컬로 서명·만료를 검증**한다(발급자 신뢰만으로 통과시키지 않는다) ⑶ 수명 상한 = **[구현 검증 — IV-1]**, 직렬화 형식·크기 = **[구현 검증 — IV-9]** | 진입점이 헤더를 주입하는 순간 **그 헤더를 흉내낸 요청**이 신뢰 경계를 통과한다. 서명이 없으면 진입점 우회 경로가 전부 인증 우회가 된다 |
| **CH-4** | ★ **대외계 전문 어댑터는 코어 안의 인바운드 어댑터**다 — `payment/adapter/`(ADR-002 기존 배치). 고정길이 파싱(X-5)·요청 지문(X-9)·판정 순서(X-10)를 수행하고 **도메인 조작을 인프로세스로 호출**한다 | ★ **멱등 판정(`IdempotencyRecord`)과 망취소 예약(`ReversalTombstone`)이 E1 트랜잭션 안**이다. 어댑터를 별도 프로세스로 빼면 그 사전조건이 **프로세스 경계를 넘는 동기 호출**이 되고, 그것은 ADR-010이 막은 형태다 |
| **CH-5** | **파일 어댑터는 코어 옆 별도 프로세스로 두어도 된다** — 단 ★ **무상태**여야 한다: 수신 · 무결성 검사(H/T 건수·합계 — X-8) · 저장까지만 하고, **배치 투입·격리 판정은 코어의 조작**이다 | 파일은 비동기·건별 원자성 요구가 없다. 상태를 들지 않는 한 경계를 넘어도 E 경계에 걸리지 않는다 |
| **CH-6** | **채널별 표현 변환은 어댑터·진입 필터가 소유**한다 — 코어는 **공통 오류 코드**만 던지고, HTTP 상태·전문 응답 코드로의 변환은 채널 쪽에서 한다 | 도메인이 채널을 알면 채널이 늘 때마다 도메인이 바뀐다(R1 ACL과 같은 원리) |
| **CH-7** | ★ **전송 프로토콜 계층은 이 ADR이 정하지 않는다 — [미확정]**: 상시 연결/요청당 연결 · 프레이밍 · 연결 타임아웃·재연결. **어댑터의 상세 설계는 이것이 확정된 뒤**에 한다 | 규격(`interfaces/`)이 정한 것은 **전문의 내용**이지 **운반 방식**이 아니다. 운반을 모르는 채 어댑터 구조를 확정하면 CH-4·CH-5의 배치 판정이 근거를 잃는다 |
| **CH-8** | ★ **속도 제한의 자리는 채널마다 다르다**. ⑴ **사람 채널 = 진입 계층(nginx)** ⑵ ★ **대외계 전문 채널 = 전문 어댑터가 소유**하고 **기관별**로 건다 — 전문은 nginx를 지나지 않으므로(§2 그림) 진입 계층에 걸어도 걸리지 않는다. 값·창·기관별 구분은 **[구현 검증 — IV-11]** | X-10 ⑷ — 판정 순서가 좁힌 **뒤에도 남는 열거 노출**을 끊는 자리가 여기다. ★ **IV-11의 원 의미가 "입금 채널(전문)"** 인데 이 규칙이 nginx로 적으면 **대장이 가리키는 자리와 결정이 어긋난다**. 실트래픽 없이 값을 정할 수 없다 |

### 채널별 진입 경로 (한 장)

```
[고객·운영자]  HTTP ──▶ 오라클 리버스 프록시 (TLS ①) ──▶ .9 nginx (TLS ② · 헤더 strip · 정적 라우팅 · 속도 제한)
                          └─▶ ★ 코어 진입 필터 (인증 → C7 발급 서명 컨텍스트) ──▶ 각 컨텍스트 진입점 (인가 로컬 판정)
                          └─▶ ★ 위성(C4·C5)에는 사람 채널 진입이 없다 — 조작은 C8 지시(R15)로만

[매입사/VAN]  고정길이 전문 ──▶ ★ 코어 내 인바운드 어댑터 (payment/adapter · 기관별 속도 제한)
                                  └─▶ E1 안에서 멱등·예약 판정

[매입사/VAN]  매입 파일 ──▶ 파일 어댑터 (별도 프로세스 허용 · 무상태)
                              └─▶ 무결성 검사 후 코어 배치 조작이 투입
```

> ★ **대외계는 nginx를 지나지 않는다.** HTTP가 아니기 때문이다 — 진입점이 못 보는 것을
> 진입점에 태우면 **아무 일도 안 하는 홉**이 하나 늘 뿐이다.

## 3. 왜 나머지를 기각했나

| 안 | 기각 이유 | 이 이유가 바뀌면 (도입 조건) |
|---|---|---|
| **A. Spring Cloud Gateway 도입** | 라우팅·TLS·속도 제한은 **보유한 nginx로 충분**하고, 배포가 3개로 고정이라 동적 라우팅 요구가 없다. 도구 하나가 곧 운영 대상 하나다(C-08) | ★ **라우팅 로직이 설정 수준을 넘을 때** — 응답 집계·요청 변환·조건부 라우팅이 필요해지면 |
| **B. 진입점이 인가를 판정한다** | ★ **ADR-016 기각 B 그대로** — 진입점은 *"이 계좌가 네 것인가"* 를 모른다. 내부 경로·배치(L4·L5)도 안 걸린다 | — (구조적) |
| **C. 전문 어댑터를 별도 프로세스로** | 멱등 판정·망취소 예약이 **E1 안**이다. 밖으로 빼면 그 사전조건이 배포 경계를 넘는 동기 호출이 되고, 3초 예산(BR-01)에 홉이 하나 더 붙는다 | CH-7이 확정되고 **어댑터가 상태를 안 드는 형태**로 정리될 때 — 그때 파일 어댑터와 같은 판정을 받는다 |
| **D. 진입점이 전문을 파싱해 내부 HTTP로 번역** | 번역이 **도메인 밖 두 곳**(진입점 + 어댑터)에 생기고, 고정길이 규격 변경이 진입점 배포를 부른다. R1 ACL이 *"번역은 한 곳"* 을 요구한다 | — |
| **E. 진입점이 신뢰 컨텍스트를 서명 없이 헤더로 주입** | 진입점을 우회하는 경로 하나가 곧 **인증 전면 우회**다. 내부망 신뢰는 경계가 늘어나는 순간 깨진다 | — (CH-3이 이것의 답이다) |

## 4. 결과

| | 내용 |
|---|---|
| **얻는 것** | 새 미들웨어 0 · 인가 판정 위치가 ADR-016과 일관 · 전문 경로의 홉이 늘지 않는다 |
| **내주는 것** | nginx 설정이 라우팅 정본이 된다(변경 이력 관리 필요) · 파일 어댑터가 프로세스 하나 늘어난다 |
| **새로 생기는 일** | ★ **서명 컨텍스트의 발급·검증·키 관리**(발급·보관·교체 = **IV-14**) · `.9` nginx의 동명 헤더 strip 규칙 · **채널별** 속도 제한 값 확정(IV-11) · ★ **기존 서비스와의 포트 대역·자원 분리**([구현 검증]) |

- ADR-016 AU-3의 *"C7이 확정해 요청 컨텍스트로 전파"* 가 **전파 매체까지** 정해졌다.
- `interfaces/` 규격 5종의 **수신 주체**가 정해졌다 — 전문은 코어 내 어댑터, 파일은 별도 프로세스.

## 5. 되돌리는 조건

| # | 관찰되면 | 그때 할 일 |
|---|---|---|
| **R1** | 라우팅 규칙이 **설정으로 표현되지 않는다**(집계·변환·조건부) | 안 A 재검토 — 그때가 게이트웨이의 도입 조건이다 |
| **R2** | ★ **관측형** — 승인 경로 p99에서 **컨텍스트 검증 구간의 지연 기여분**(구간 계측 — ADR-023 OB-2 노출)이 **BR-01 3초 예산의 [미확정] 비중**을 넘는 사건이 ★ **2회 이상 측정**된다 | 검증 캐시를 검토하되 **ADR-016 §5의 캐시 선판정 3조건을 먼저** 통과시킨다 |
| **R3** | 파일 어댑터가 **상태를 들기 시작한다**(중복 판정·진행률) | 무상태 전제가 깨졌다 — 코어 안으로 되돌린다(CH-4와 같은 판정) |
| **R4** | 채널이 늘어 **nginx 설정이 배포마다 중복**된다 | 라우팅 정본을 설정 생성으로 — 그래도 안 되면 안 A |
| **R5** | ★ **CH-7(전송 프로토콜)이 확정되면서 어댑터 배치 근거가 바뀐다** | CH-4·CH-5를 **그 시점에 재판정**한다 — 이 ADR은 그 재판정을 예약해 둔 것이다 |

## 6. 검증

| 언제 | 무엇으로 | 통과 기준 |
|---|---|---|
| Phase 5 | ★ **헤더 위조** | 외부에서 내부 컨텍스트와 **같은 이름의 헤더**를 실어 보낸다 → 진입에서 제거되고, 서명 없는 컨텍스트는 **각 배포가 거절** |
| Phase 5 | 서명 검증 | 만료·변조 컨텍스트 → 거절. 응답이 *"없음"* 과 구별되지 않는다(BR-58) |
| Phase 5 | 전문 재수신 | 같은 상관 식별자 재수신 → **최초 결과 그대로**(X-10 ②) · 대상 재조회 없음 |
| Phase 5 | 파일 무결성 | H/T 건수·합계 불일치 파일 → **투입되지 않고** 거절 기록 |
| Phase 5 | 속도 제한 | ★ **채널별로 각각** — 사람 채널은 nginx에서, **전문 채널은 어댑터에서 기관별로** 차단되고 **정상 트래픽은 통과**(IV-11 값 확정 후) |
