# ADR-016. 인가 — 주체·스코프를 계약으로 강제한다

- 일자: 2026-08-05
- 상태: **채택**
- 결정자: 사용자 · AI 페어
- 근거: **BR-54·55·58** · 멀티테넌시 전수 스캔(`plans/2026-08-05/mt-02·03`) · `study/09` §2
- 관련: **ADR-007**(같은 원리 — "쓸 수 없게 만든다") · **ADR-002**(모듈 그래프) · **ADR-013**(시간 예산) · context-map **R4·R14**

---

## 1. 맥락 — 인가 모델이 없었다 (G-1)

C7은 **인증**("누구인가")이고, **"무엇을 할 수 있는가"는 어디에도 없었다.**

| 사실 | 출처 |
|---|---|
| 조작 62개 전수에 **명시적 소유자 조건 0건** — 전부 키 매칭 | 전수 스캔 W-B |
| 규칙 31개가 *"운영자"* 를 무자격 주어로 쓴다 | 전수 스캔 W-A |
| 조회 표면 자체가 없다 — 고객 대면 조회 조작 0개, BR-31이 유일한 조회 규칙 | 〃 |
| 권한을 조건으로 제한한 유일한 전례 = 정산 `resumeByOperator`(`retryCount ≥ 임계`) | settlement.md |

### 제약이 선택지를 자른다

| 제약 | 잘리는 것 |
|---|---|
| **C-07 (MySQL)** | DB 행 수준 보안(RLS)이 없다 — `study/09` §2가 최강으로 꼽은 수단이 **불가** |
| **ADR-013 T-10** (한 작업 = 커넥션 1개) · 내부 deadline **2.5초** | 자금 트랜잭션 안에서 인가를 **외부 서비스 호출**로 하는 안이 불가 |
| **C-04 (예산 0)** | 외부 IdP·정책 서비스 불가 |

남는 최강 수단 = **타입으로 강제** — 소유자 없는 조회는 **호출 자체가 성립하지 않는다.**
ADR-007 §4가 자금 경로에 이미 쓴 방식이다(*"쓰지 마라"가 아니라 "쓸 수 없게 만든다"*).

## 2. 결정

| # | 규칙 | 왜 |
|---|---|---|
| **AU-1** | **모든 조작·조회 계약은 주체(스코프)를 필수 인자로 갖는다** — `findById(id)` 가 아니라 `findById(id, requesterScope)`. 주체 없는 호출은 컴파일/계약 수준에서 거부된다 | 조건 누락(L1)은 리뷰로 못 막는다 — 구조가 막아야 한다 (BR-54) |
| **AU-2** | 주체는 3종 — **고객**(자기 소유만) · **운영자**(단계 BR-55 + 조직·지점 스코프) · **시스템**(배치·전문·릴레이 — 경로 식별자 필수). ★ **시스템만 소유자 필터 면제**이고 그 예외 목록은 BR-54가 소유한다 | 대사(R9)·배치(L5)는 전체를 보는 것이 설계된 정상 동작 — 예외를 **정의하지 않으면** 대사가 불법이 되거나 예외가 무한히 넓어진다 |
| **AU-3** | 인가 판정은 **코어 안 인프로세스 호출**이다 — 외부 서비스가 아니다. C7이 인증 시점에 **주체·단계·스코프**를 확정해 요청 컨텍스트로 전파하고(R4), 판정은 각 컨텍스트 진입점에서 로컬로 한다 | T-10(커넥션 1개) · 내부 deadline 2.5초 · C-04. 전파 계약은 Phase 4 |
| **AU-4** | 판정 시점 = **조작·조회 진입 시 1회.** E1~E5 트랜잭션 안에서 재판정하지 않는다 — 인가는 **E 참여자가 아니다** | E는 자금 이동 경계다(README:59). 판정은 변경이 없는 `조회`이므로 경계 배정 대상이 아니다(기존 표기 규칙과 정합) |
| **AU-5** | 인가 실패 응답은 **"없음"과 구별되지 않는다**(BR-58). 거절된 시도는 **기록된다**(BR-57) | 존재 여부 자체가 새는 것을 막고(L7), 반복 시도를 탐지 가능하게 |
| **AU-6** | 인가 계약 타입(주체·단계·스코프)은 **공용 모듈**에 둔다 — `core:shared` 와 같은 하향 의존 위치. **ADR-002 M-3 그래프에 새 상향·순환 의존을 만들지 않는다** | 인가가 전 컨텍스트에서 호출되므로 의존 방향이 전부 아래로 향해야 한다 |
| **AU-7** | ★ **책임자 승인 4조작(BR-56)의 사전조건 = "승인된 요청 존재"** — C8에 동기 조회(R14). 승인 워크플로 자체는 ADR-017 | 실행과 승인을 컨텍스트 경계로 가른다 — 자기 승인은 구조적으로 불가 |

## 3. 왜 나머지를 기각했나

| 안 | 기각 이유 | 이 이유가 바뀌면 |
|---|---|---|
| **A. DB RLS** | C-07 — MySQL에 없다 | DB가 바뀌면 최강 수단으로 재검토 |
| **B. 게이트웨이 중앙 인가** (진입점에서만 판정) | 객체 수준 인가(IDOR/BOLA)는 **리소스 접점에서만** 판정할 수 있다 — 게이트웨이는 "이 API를 부를 수 있나"만 알고 *"이 계좌가 네 것인가"* 를 모른다. 내부 경로·배치(L4·L5)도 안 걸린다 | — (구조적) |
| **C. 인가 전용 외부 서비스** | T-10 위반(트랜잭션 중 두 번째 연결) · 2.5초 예산 · C-04 | 예산·운영 제약이 풀리고 정책이 자주 바뀌는 요구가 생기면 |
| **D. 공통 리포지토리 관행** ("이 리포지토리만 써라") | 그 리포지토리를 **안 쓰면** 뚫린다 — `study/09` §2가 "중" 강도로 판정. 주의력에 의존하는 규칙은 지켜지지 않는다(이 프로젝트 실측 결론) | — |

## 4. 결과

- BR-54·55·58이 실행 가능해진다 — 계약 형태가 정해졌다.
- **Phase 4 계약 설계의 선행 제약**: 모든 API·조회 시그니처에 주체 인자. 엔드포인트 목록을 **생성**해 "남의 식별자 → 거절" 전수 시험(BR-58 검증).
- 카드 상태 머신 C2(`resume` 주체 미규정)·C4(`changeLimit`)의 주체가 BR-55 배정 표로 채워진다.

## 5. 되돌리는 조건

| 신호 | 그때 |
|---|---|
| 인가 판정·컨텍스트 전파가 승인 경로 p99에 유의미하게 잡힌다 (QS-01 측정) | 판정 결과 캐시를 검토하되 ★ **HA-1(인스턴스 로컬 상태로 자금 판단 금지)과의 관계를 먼저 판정**한다 — 인가가 자금 판단인지가 그때의 쟁점이다 |
| 시스템 주체 예외 목록이 늘어난다 (신규 배치마다 추가) | 예외가 규칙을 삼키는 신호 — BR-54 예외 구조 재설계 |

## 6. 검증

- ① 주체 없는 호출이 계약 수준에서 거부되는 것을 샘플 코드로 실증 (Phase 5)
- ② **남의 식별자로 호출 → 거절 + 응답이 "없음"과 동일 형태** — 전 조회 경로 전수 (Phase 4 목록 생성 후)
- ③ 예외 목록 ↔ 실제 배치 경로 양방향 대응
- ④ 거절 시도가 기록에 남는지 (BR-57 검증과 공유)
