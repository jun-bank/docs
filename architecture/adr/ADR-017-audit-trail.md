# ADR-017. 감사 기록 — 행위자를 원장과 별개의 append-only로

- 일자: 2026-08-05
- 상태: **채택**
- 결정자: 사용자 · AI 페어
- 근거: **BR-56·57** · 전자금융감독규정 제13조(가동기록·조회 통제) · 멀티테넌시 전수 스캔
- 관련: **ADR-003**(안 C 재개 조건 발동) · **ADR-005**(outbox 계약 재사용) · **ADR-010**(C8 배정) · context-map **R13·R14**

---

## 1. 맥락 — 원장은 자금을 남기고, 행위자는 아무도 안 남긴다 (G-4)

| 사실 | 출처 |
|---|---|
| 자금 이벤트 payload 전부에 행위자가 없다 — `DepositReversed`(운영자 역분개)조차 **사유는 있고 행위자는 없다** | account.md §6 |
| *"운영자 식별자 + 사유 기록"* 을 요구한 전이는 정산 S6 **하나** | settlement.md |
| ★ **ADR-003 안 C(변경 이력)의 재개 조건이 문자 그대로 발동했다** — *"운영·감사에서 '누가 언제 이 값을 바꿨나' 요구가 생길 때"* = BR-57 | ADR-003:56 |
| 규제는 기록을 **의무**로 둔다 — 가동기록 자동 기록·1년 이상(제13조 ①9호), 조회·출력 통제(①8호), 공용 계정도 개인 귀속(②) | mt-02-scan-r |

### 트랜잭션 소속이 쟁점이다

기존 판례를 전수했다(mt-02-scan-b §5):

- **"같은 커밋"을 요구한 5건의 이유는 전부 멱등(자금)** — *기록이 없으면 재실행이 자금을 두 번 움직인다*.
- **"별도(커밋 뒤 유실되지 않는 경로)"의 선례 = 전표**(BR-40 · ADR-005 O-1) — outbox INSERT는 같은 커밋, 전달은 비동기, 수신측 멱등(INV-8).
- E1~E5의 배제 기준: **자금이 움직이지 않는 참여자는 E에 넣지 않는다**(reversal-tombstone.md §6).

감사 기록은 **자금을 움직이지 않지만 유실되면 규제 위반이다.** 전표와 정확히 같은 요구 형태다.

## 2. 결정

| # | 규칙 | 왜 |
|---|---|---|
| **AD-1** | 감사 기록은 **C8 소유의 append-only 저장**이다. 수정·삭제 조작이 **존재하지 않는다** — 변조 방지를 조작 부재로 강제한다 | 원장 INV-2(BR-10)·불일치 INV-1("조작 목록의 부재로 강제")과 같은 원리 |
| **AD-2** | **조작의 행위자 기록은 전표와 같은 형태로 수집한다** — 조작 커밋과 **같은 트랜잭션에서 outbox INSERT**, 릴레이가 C8로 전달(R13), C8이 감사 언어로 번역(ACL). ★ **E1~E5 참여자 표는 바뀌지 않는다** — 전표가 E 밖이듯 감사도 outbox 행일 뿐이다 | 유실되면 규제 위반 + 사고 조사 불능. 이미 검증된 계약(ADR-005 O-1~O-5)을 재사용하고 새 경계를 만들지 않는다 |
| **AD-3** | 수신 멱등 — 같은 원천 이벤트로 **두 번 적재하지 않는다**(`sourceEventId` 유일 — 전표 INV-8과 같은 형태) | outbox는 at-least-once — 비멱등 수신측은 재전달이 곧 이중 기록 |
| **AD-4** | **조회 기록은 조작과 경로가 다르다** — 조회에는 커밋이 없으므로 **비동기 적재**하되, ★ **적재 실패는 조회를 막지 않는 대신 실패 사실이 불일치로 적재된다**(탐지가능성 — 대사와 같은 원리) | 조회마다 동기 기록을 강제하면 조회 API가 기록 저장소 가용성에 묶인다. 무음 유실만은 금지 — **silent failure가 이 프로젝트 최다 사고 유형**이다 |
| **AD-5** | **감사 기록에 대한 접근도 감사 대상이다** — 조회 기록과 같은 경로로 남는다 | 기록을 보는 행위가 안 남으면 내부자가 자유롭다 (PCI 10.2 계열·제13조 ①8호) |
| **AD-6** | **2인 승인 워크플로(BR-56)의 요청·승인 상태는 C8 소유**다. 실행 사전조건은 — 코어 안 ①~④: **"승인된 요청 존재"의 동기 조회**(R14) / ⑤ 원장 역분개: **승인된 정정 지시 이벤트**(R15 — 멱등 키 = 지시 ID). 요청·승인·거절 각각이 AD-2 경로로 기록된다. 상태·전이의 정본 = `state-machines/approval-request.md` | 승인 상태를 실행 컨텍스트가 들면 자기 승인을 막을 수 없다 — 경계가 직무 분리를 강제한다. C5는 별도 배포라 동기 조회가 ADR-010을 어긴다 |
| **AD-7** | 행위자 필드의 **원천은 인가 컨텍스트**(ADR-016 — 주체·단계·스코프)다. 이벤트에 행위자 필드를 싣는 것은 **Phase 4 이벤트 계약 최초 설계에 포함**한다(S-6a — 기존 이벤트에 의미 필드 추가 금지) | 지금 기존 이벤트에 얹으면 ADR-015 자기 규칙 위반. 계약이 굳기 전이 유일한 창이다 |

## 3. 왜 나머지를 기각했나

| 안 | 기각 이유 | 이 이유가 바뀌면 |
|---|---|---|
| **A. 원장에 행위자를 싣는다** (전표 확장) | 원장은 **자금 언어**다(ADR-003) — 자금이 안 움직이는 조작·조회·거절 시도는 전표가 될 수 없다. 절반만 남는 감사는 감사가 아니다 | — (구조적) |
| **B. 각 컨텍스트가 자체 감사 테이블** | 같은 종류의 사실을 **8곳이 소유** — DC-001이 경고한 "같은 사실을 두 곳이 소유"의 확장형. 운영 조회가 8곳을 훑어야 하고 보존·변조 방지 정책이 8벌이 된다 | — |
| **C. 다른 컨텍스트가 C8 테이블에 직접 기록** (같은 커밋, 직접 쓰기) | 유실은 막지만 **소유권 위반** — *"다른 컨텍스트는 쓰지 않는다"*(데이터 뷰 §1). 스키마 결합이 전 컨텍스트로 퍼진다 | — |
| **D. 애플리케이션 로그로 갈음** | 로그는 **회전·유실이 정상**인 매체다. append-only·보존 기간·변조 방지를 강제할 수 없다. D-05(관측 포기)와 범주 혼동 — 감사는 관측이 아니라 **기록 의무**다 | — |

## 4. 결과

- G-4가 닫힌다 — *"누가 했나"* 의 소유자·경로·멱등이 정해졌다.
- 릴레이(ADR-014)의 처리량에 감사 이벤트가 더해진다 — **[미검증]**, Phase 5 실측 대상.
- `operator` 인자가 없던 운영자 조작 3건(`reverseDeposit` · 승인 `freeze/unfreeze`)과 행위자 불명 5건은 **B-4에서 시그니처에 주체를 받는다** — 없으면 AD-2가 실을 것이 없다.

## 5. 되돌리는 조건

| 신호 | 그때 |
|---|---|
| 감사 outbox가 릴레이 지연·DLQ 임계(ADR-014 R1)를 끌어올린다 | 감사 전용 릴레이 분리 — 자금 이벤트와 큐를 가른다 |
| 조회 기록 적재 실패가 반복 적재된다 (AD-4의 불일치) | 조회 기록 경로를 동기화하거나 버퍼 내구성을 올린다 |
| C8 동기 승인 조회(R14)가 관리 조작 지연에 유의미하다 | 승인 상태 캐시 검토 — 단 **승인 확인은 자금 조작의 사전조건**이므로 HA-1 판정 선행 |

## 6. 검증

- ① **기록 실패를 주입**했을 때 — 조작: outbox INSERT 실패 = 조작 롤백(같은 커밋) / 조회: 조회는 성공하되 불일치 적재 확인 — **조용한 유실의 부재를 반증**
- ② 같은 이벤트 재전달 → 적재 1건 (AD-3)
- ③ 같은 운영자 요청+승인 → 거절 (AD-6 — BR-56 검증과 공유)
- ④ 감사 기록 조회 행위가 다시 기록에 남는지 (AD-5)
