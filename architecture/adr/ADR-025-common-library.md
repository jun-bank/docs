# ADR-025. 공통 라이브러리 — **계약과 인프라만 공유한다. 도메인은 공유하지 않는다**

- 일자: 2026-08-06
- 상태: **채택**
- 결정자: 사용자 · AI 페어
- 근거: Phase 5 진입 아키텍처 스케치 v2·v3(F-11·F-12·F-16·F-17) · **E1 리뷰 N5** · 사용자 지시(*"공통 라이브러리로 서버 간 통신을 공유한다"*)
- 관련: **ADR-002**(모듈 그래프 M-1~M-7) · **ADR-005·014**(outbox·릴레이) · **ADR-021**(봉투 ET-4 · payload 소유 ET-5) · **ADR-016**(인가 AU-3·AU-6) · **ADR-017**(감사 AD-3) · **ADR-015**(S-6a) · **ADR-023**(OB-3) · **BR-07·55**

---

## 1. 맥락 — 배포가 셋이면 "같은 코드"가 셋이 된다

배포 3개(ADR-010)가 **같은 봉투·같은 요청 컨텍스트·같은 금액 타입**을 쓴다.
공통 라이브러리를 안 두면 셋이 각자 만들고, 그 순간 **계약이 셋으로 갈린다.**

**그런데 반대 방향의 위험이 더 크다.** 공통에 무엇이든 넣을 수 있게 두면

| 공통에 잘못 들어가는 것 | 무엇이 깨지나 |
|---|---|
| **payload 타입**(발행 이벤트의 본문) | 발행·수신이 **lockstep 배포**로 묶인다 — S-6a·ET-5가 막는 형태 |
| **판정 술어**(서브트리·전사 — BR-55) | 배포마다 라이브러리 버전이 달라 **배포마다 다른 인가**가 된다 |
| **도메인 로직**(멱등 사전조건 등) | 컨텍스트 소유가 공통으로 새어 **ADR-002 모듈 경계**가 무의미해진다 |
| **값 타입을 두 벌로**(`Money`를 공통에 새로 정의) | 정본이 둘 — 한쪽만 고치면 **금액 의미가 갈린다**(BR-07) |

> ★ **이 ADR의 질문은 "무엇을 공유하나"가 아니라 "무엇을 공유하면 안 되나"** 다.
> 공유가 편해서 넣은 것이 곧 **배포 독립성을 되돌리는 결합**이 된다.

## 2. 결정

| # | 규칙 | 왜 |
|---|---|---|
| **CL-1** | ★ **공통 라이브러리는 별도 repo(`jun-bank-common`)** 이고 **버전으로 배포**된다(Gradle 멀티모듈 — 모듈 = 아래 CL-2~CL-5). ⚠️ **업무 배포 3은 이것을 의존만 하고, 공통은 어느 배포도 의존하지 않는다** — 의존 방향은 **아래로만**(ADR-002 M-3와 같은 요구) | 공통이 업무 코드를 알면 **순환**이고, 순환이 생기면 배포 순서가 강제된다 |
| **CL-2** | **`common-kernel` — 값·오류만.** ⑴ ★ **`Money`의 정본은 `core:shared`** 이고 공통은 **그것을 모듈로 재수출**한다 — **두 벌로 정의하지 않는다**(BR-07: 통화 + 최소단위 정수) ⑵ **오류 모델**은 코드 대장을 **기계 판독 원천으로 생성**한다 — **수기 미러 금지**(드리프트) ⑶ **영업일·기관 코드** 같은 무의미 결정이 없는 값 타입 | 값 타입은 전 배포가 같은 의미로 읽어야 하고, **정본이 둘이면 그 의미가 갈린다**(F-17) |
| **CL-3** | **`messaging-infra` — 전달의 골격만.** ⑴ **outbox 발행**(같은 트랜잭션 INSERT — 브로커·원격 직접 발행 금지, ADR-005 O-1~O-5) ⑵ **릴레이 러너**(파티션 소유·재시도·DLQ 상태 전이 = ADR-014 O-6~O-16) ⑶ **inbox 골격**(수신 엔드포인트·봉투 파싱·전달 계약 = ADR-021 ET-3). ⚠️ ★ **여기까지가 공통이다** — **멱등 키의 선택 · 유니크 제약 · 핸들러의 커밋 경계는 수신 컨텍스트가 소유**한다 | 골격을 공유하면 재시도·순서·DLQ가 한 번만 구현된다. 그러나 **무엇이 중복인가는 도메인 지식**이다 — 공통이 정하면 **틀린 멱등 키가 전 배포에 퍼진다** |
| **CL-4** | ★ **C3(결제)의 멱등은 도메인 사전조건이다** — `markSettled()` 류는 **조작의 사전조건 자체가 멱등**이므로 **inbox 골격의 멱등 장치를 얹지 않는다.** 골격이 대신하는 것처럼 표시하지도 않는다 | *"어댑터가 멱등을 보장한다"* 고 적으면 **도메인이 자기 사전조건을 느슨하게** 만든다. 멱등의 소유자가 흐려지는 것이 그 자체로 결함이다(F-16) |
| **CL-5** | ★ **계약 모듈은 발행자별로 나눈다**(`banking-published-contracts` 같은 형태) — ⑴ **공통이 소유하는 것은 봉투뿐**이다(**ADR-021 ET-4** — 8항목) ⑵ ★ **payload를 담는 전역 계약 모듈을 만들지 않는다** — payload는 **발행 컨텍스트가 소유**하고 수신측이 **ACL로 번역**한다(ET-5 · R5~R7) | 전역 payload 모듈은 **모든 수신자를 발행자 릴리스에 묶는다**(lockstep). 발행자별로 갈라야 **한 발행자의 변경이 그 구독자에게만** 닿는다 |
| **CL-6** | **`common-auth` — 타입과 전파까지.** ⑴ 요청 컨텍스트 **타입**(주체·단계·스코프·`authzVersion`·운영자 `status` — AU-3) ⑵ ★ **전파 컨텍스트의 파싱·서명/만료 검증**까지 공통이 소유한다(ADR-019 CH-3의 *"각 배포가 로컬로 검증"* 을 **같은 구현으로**) ⑶ ⚠️ ★ **판정 술어(서브트리 포함·전사 동일성 — BR-55)의 구현은 C7이 소유**한다 — 공통에 넣지 않는다 | 파싱·검증이 배포마다 다르면 **검증이 약한 배포 하나가 전체의 인증 경계**가 된다. 반대로 **술어가 라이브러리에 있으면 버전 스큐 = 배포마다 다른 인가**이고, 그것은 ADR-016이 막은 형태다(F-12) |
| **CL-7** | ★ **`traceparent` 전파는 공통이 소유**한다 — HTTP는 표준 계측, ★ **메시징 구간은 `messaging-infra`가 outbox 컬럼 → 봉투 → 수신측 복원**을 **자동으로** 수행한다(ADR-023 **OB-3** · 필수 항목의 정본은 **ET-4**) | 자동 계측이 못 넘는 유일한 구간이 메시징이고, **소급이 불가능**하다. 각 배포에 맡기면 **한 배포만 빠뜨려도 문맥이 끊긴다** |
| **CL-8** | ★ **공통에 도메인 로직·조작·저장소를 두지 않는다.** 애그리게이트·불변식·업무 규칙은 **컨텍스트 소유**다(ADR-002 M-1·M-2) | 공통은 **모든 배포가 의존하는 지점**이다. 여기에 업무 규칙이 들어가면 규칙 하나를 고치는 데 **세 배포를 같이 올려야** 한다 |

### 무엇이 어디에 있나 (한 장)

```
jun-bank-common (별도 repo · 버전 배포)
 ├─ common-kernel        값·오류        ← Money = core:shared 재수출(정본은 core) · 오류는 대장에서 생성
 ├─ messaging-infra      전달 골격      ← outbox 발행 · 릴레이 러너 · inbox 골격
 │                                        ⚠️ 멱등 키·유니크·핸들러 커밋 = 수신 컨텍스트 소유 (CL-3)
 │                                        ⚠️ C3는 도메인 사전조건이 멱등 (CL-4)
 ├─ <발행자>-contracts    봉투 + 발행자별 payload  ← 전역 payload 모듈 없음 (CL-5 · ET-5)
 └─ common-auth          컨텍스트 타입 · 파싱 · 서명/만료 검증
                                          ⚠️ 술어(BR-55) 구현 = C7 소유 (CL-6)

 traceparent : 컬럼 → 봉투 → 복원 을 messaging-infra 가 자동 수행 (CL-7 · OB-3 · ET-4)
```

## 3. 왜 나머지를 기각했나

| 안 | 기각 이유 | 이 이유가 바뀌면 (도입 조건) |
|---|---|---|
| **A. 전역 `common-contracts` 하나에 모든 payload** | ★ **lockstep 배포** — 한 발행자의 필드 추가가 전 배포의 라이브러리 갱신을 부른다. S-6a가 *"의미를 바꾸는 필드는 새 이벤트 타입"* 으로 막아둔 자리를 **패키징이 다시 연다** | — (구조적 · CL-5가 답이다) |
| **B. 판정 헬퍼(술어)까지 공통에** | 배포마다 라이브러리 버전이 다를 수 있고, 그것이 곧 **배포마다 다른 인가 판정**이다. 인가는 *"어디서 판정해도 같아야"* 성립한다 | — (ADR-016이 이미 판정) |
| **C. 공통이 도메인 모델(애그리게이트)까지 제공** | 컨텍스트 소유가 무너지고 **ADR-002 M-1·M-2가 무의미**해진다. "재사용"으로 얻는 것보다 **경계를 잃는 대가**가 크다 | — |
| **D. 공통을 모노repo 안 서브모듈로**(업무 코드와 같은 repo) | 버전이 곧 커밋이 되어 **배포 3이 같은 커밋에 묶인다** — 독립 배포의 이점을 패키징이 되돌린다. ⚠️ 단 **repo를 가르면 변경이 두 단계**가 된다(§4 내주는 것) | 배포 독립성보다 변경 속도가 중요해질 때 — 지금은 아니다 |
| **E. `Money`를 공통에 새로 정의**(core와 별개로) | ★ **정본이 둘**이 된다 — 금액 타입은 **BR-07의 의미**를 들고 있고, 두 벌이면 한쪽만 고쳐지는 날이 온다 | — (CL-2가 답이다 — 재수출) |

## 4. 결과

| | 내용 |
|---|---|
| **얻는 것** | 봉투·전달·요청 컨텍스트가 **한 번만 구현**된다 · 전파 규약(traceparent)이 **빠질 수 없는 위치**에 들어간다 · 공통에 못 넣는 것이 명시돼 **경계 침범이 리뷰 없이도 드러난다** |
| **내주는 것** | ★ **공통 변경이 2단계**가 된다(공통 릴리스 → 각 배포 갱신) · 발행자별 계약 모듈이 늘어 **모듈 수가 는다** · 공통 버전 스큐를 **배포마다 관리**해야 한다 |
| **새로 생기는 일** | 공통 repo의 버전·릴리스 정책(ADR-024 RL-6과 같은 호환 규칙) · 오류 코드 대장의 **기계 판독 원천**과 생성 절차 · 공통 버전 스큐 확인 |

## 5. 되돌리는 조건

| # | 관찰되면 | 그때 할 일 |
|---|---|---|
| **R1** | ★ **공통 릴리스가 세 배포의 동시 갱신을 강제한 사건이 2회 이상** 난다 | 무엇이 공통에 잘못 들어갔는지부터 본다 — 대개 **payload 또는 도메인 규칙**이다(CL-5·CL-8 위반) |
| **R2** | 배포마다 **다른 공통 버전**이 돌아 인가·봉투 해석이 갈린다 | 파싱·검증(CL-6 ⑵)·봉투(CL-5 ⑴)는 **하위 호환 필수 구간**으로 못 박고, 버전 하한을 배포 절차가 검사한다(ADR-024 `E4`) |
| **R3** | 수신측이 **공통이 정한 멱등 키로 중복을 놓친다** | CL-3 위반 — 멱등 키를 **수신 컨텍스트 소유**로 되돌린다(AD-3의 `sourceRef` 값 규칙이 그 예다) |
| **R4** | 공통에 **업무 규칙(BR 인용)이 들어간 코드**가 발견된다 | CL-8 위반 — 해당 컨텍스트로 되돌린다. 아키텍처 테스트로 막히는지 함께 확인한다 |
| **R5** | `Money`·오류 코드가 **공통과 코어에 각각 정의**돼 있다 | CL-2 위반 — 재수출로 되돌린다. 두 정본은 **언젠가 반드시 갈린다** |

## 6. 검증

| 언제 | 무엇으로 | 통과 기준 |
|---|---|---|
| Phase 5 | ★ **경계 강제** | 아키텍처 테스트 — 공통 모듈이 **업무 배포 코드·애그리게이트를 참조하지 않는다**(CL-1·CL-8) |
| Phase 5 | ★ **payload 비공유** | 한 발행자의 payload 필드 추가 → **그 구독자만** 갱신하면 되고 **다른 배포는 빌드가 안 깨진다**(CL-5) |
| Phase 5 | ★ **`Money` 단일 정본** | 공통이 노출하는 `Money`가 **`core:shared`의 그 타입**이다(별도 정의가 없다 — CL-2) |
| Phase 5 | 컨텍스트 검증 | 만료·변조 컨텍스트를 **세 배포 각각에** 보낸다 → **같은 판정으로 거절**(CL-6 ⑵ · ADR-019 CH-3) |
| Phase 5 | ★ **술어 소유** | 공통 라이브러리에 **BR-55 술어 구현이 없다**(호출은 C7 — CL-6 ⑶) |
| Phase 5 | ★ **문맥 자동 전파** | 핸들러가 아무것도 안 해도 **outbox → 봉투 → 수신측**에서 `traceparent`가 이어진다(CL-7 · ADR-023 §6 문맥 연속성) |
