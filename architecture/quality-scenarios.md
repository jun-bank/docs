## 0. 근거의 등급

| 등급 | 뜻 | 설계에 쓸 수 있나 |
|---|---|---|
| **[1차]** | 규정·표준·기업 공식 문서 원문에서 직접 확인 | ✅ |
| **[2차]** | 기사·블로그 등 인용 | ⚠️ 표시하고 사용 |
| **[유도]** | 1차 수치에서 계산 (가정 명시) | ⚠️ 가정과 함께 |
| **[미검증]** | 출처를 못 찾음 | ❌ **설계 근거 금지** |

## 1. 시나리오

### QS-01. 평시 승인 부하

| 항목 | 내용 |
|---|---|
| **품질 속성** | 응답시간 · 정합성 |
| **출처(자극원)** | 매입사/VAN (모의) |
| **자극** | 승인 요청 전문 |
| **환경** | **평시** (07~23시 주간대) |
| **대상** | 승인 경로 (E1) |
| **응답** | 승인 또는 거절 응답. **홀딩·한도·멱등이 같은 커밋** |
| **측정** | ★ **100 TPS 지속에서 p99 ≤ 3초** — 매입사 전문 수신 ~ 응답 송신 구간 |
| **측정 방법** | 부하 도구로 승인 전문 주입, 애플리케이션 진입/이탈 타임스탬프 차 |
| **근거** | **[유도]** 국내 카드 승인 일평균 8,159만 건(여신금융협회 2025) × **점유율 7.08%**(리서치 §1.3의 **실제 최저 — 우리카드**) = 578만 건/일 → **67 TPS**. 주간 집중 계수 1.5 적용 → **약 100 TPS**. ⚠️ 초안은 *"중견 5%"* 를 썼으나 **그 숫자가 리서치 표에 없었다**(Phase 3 리뷰 D10) — 표에 있는 값 중 가장 보수적인 것으로 교체 |
| **파생 수치** | 커넥션 풀 하한 · 승인 경로 락 보유 시간 상한 |

> ⚠️ **주간 집중 계수 1.5는 [미검증]이다.** 카드 승인의 시간대별 분포 자료를 못 찾았다.
> 이 계수가 틀리면 QS-01의 **100 TPS**가 틀린다 — **반증 신호로 등재**(§3 F1).

### QS-02. 특수일 피크

| 항목 | 내용 |
|---|---|
| **품질 속성** | 응답시간 · 가용성 |
| **출처** | 매입사/VAN |
| **자극** | 승인 요청 급증 |
| **환경** | ★ **특수일** (명절·대형 프로모션) |
| **대상** | 승인 경로 (E1) |
| **응답** | 응답시간 목표를 유지하거나, **초과 시 거절**한다 (정합성 우선 — 대기열로 밀지 않는다) |
| **측정** | ★ **400 TPS에서 p99 ≤ 3초** · 부하 테스트는 **1,000 TPS까지** 무결성 확인 |
| **측정 방법** | 부하 도구 램프업. **응답시간과 함께 M9~M15 불일치 0건**을 동시 확인 |
| **근거** | **[1차]** 카카오페이 11/11 실측 평시 대비 **3~5배**, 개선 후 처리 400 TPS. QS-01의 100 × 4 = 400과 같은 범위 |
| **파생 수치** | 스레드 풀 상한 · 서킷 브레이커 임계 |

> ⚠️ **명절 배수 3~5배는 11/11에서 유추한 값이다.** 국내 명절 결제 피크 실측은 **[미검증]**.
>
> ★ **Visa 용량 83,000 msg/s를 목표로 삼지 않는다.** 그것은 스트레스 테스트 용량이지 실사용량이
> 아니다(Visa 실사용 평균 8,160 TPS). 자료 오독은 **근거 없는 큰 수**를 만들고, 그것은
> 근거 없는 작은 수와 똑같이 나쁘다(D-03).

### QS-03. 승인 응답 지연과 망취소

| 항목 | 내용 |
|---|---|
| **품질 속성** | 정합성 (응답시간은 하위 목표) |
| **출처** | 매입사 |
| **자극** | 우리 응답이 매입사 타임아웃을 초과 → **망취소 전문 수신** |
| **환경** | 평시·피크 무관 |
| **대상** | 승인 · 취소 예약 (E1) |
| **응답** | 승인이 이미 성립했으면 **홀딩·한도 복원 후 무효**, 아직이면 **취소 예약 기록 후 후속 승인 무효화** (BR-13·22·49) |
| **측정** | 망취소 처리 후 **가용잔액·한도 등식이 성립** (M9·M10·M11 불일치 0건) |
| **측정 방법** | 응답 지연을 인위 주입 → 망취소 전문 → 대사 배치 실행 |
| **근거** | **[1차]** ISO 8583 0400/0420. **0421(Repeat)의 종료 조건은 "응답 수신"뿐이고 횟수·간격 규정이 없다**(Worldpay Ref Guide V2.63) → **at-least-once 전제 + 수신측 멱등 흡수**가 유일한 안전 구조 |
| **파생 수치** | 취소 예약 TTL · 망취소 재시도 정책 |

> ★ **표준이 재시도 횟수를 안 정한다는 것이 핵심 발견이다.** 즉 **"몇 번 오는지 모른다"** 가 전제이고,
> Phase 2가 취소 예약(`ReversalTombstone`)과 멱등을 둔 것이 정확히 이 구조다.

### QS-04. 대사 탐지

| 항목 | 내용 |
|---|---|
| **품질 속성** | 탐지가능성 |
| **출처** | 대사 배치 (일 1회) |
| **자극** | 영업일 마감 후 정합성 검증 |
| **환경** | 배치 시간대 |
| **대상** | 대사 (C6) · ③ 의식적 예외 4건 |
| **응답** | M1~M15 유형별로 불일치를 **적재**한다. **자동 정정하지 않는다** (BR-09) |
| **측정** | ★ **BR-09의 배치 탐지 대상 전부를 인위 주입 → 전부 탐지, 자동 정정 0건** · 배치 완료 **마감 후 1시간 이내** (건수는 BR-09 정본이 소유한다) |
| **측정 방법** | 결함 주입 후 배치 실행, `Discrepancy` 적재 건수·유형 확인 |
| **근거** | BR-09 검증 방법. ⚠️ **1시간은 [미검증] 자체 목표다.** 초안은 *"RTO 3시간의 1/3"* 이라 썼으나 **RTO는 재해복구 규정이고 대사 배치와 범주가 다르다**(Phase 3 리뷰 D11). 실제 근거는 *"다음 영업일 시작(09:00) 전에 운영자가 결과를 볼 수 있어야 한다"* 이며, 마감 23:00 기준 **여유가 10시간**이므로 1시간은 보수적 목표다 |
| **파생 수치** | 배치 실행 시간 상한 |

### QS-05. 프로세스 종료 후 복구

| 항목 | 내용 |
|---|---|
| **품질 속성** | 복구가능성 |
| **출처** | 인프라 (프로세스 강제 종료) |
| **자극** | 자금 경로 커밋 **직후** 프로세스 종료 (전표 기표 전 · 멱등 기록 전 등) |
| **환경** | 장애 중 |
| **대상** | E1~E5 · Outbox |
| **응답** | 재시작 후 **자동으로** 정상 상태 도달. **사람 개입 0회** (C-02) |
| **측정** | ★ 종료 지점 **N개**(각 트랜잭션 경계의 커밋 직후)에서 각각 재시작 → **자금 이중 반영 0건 · 유실 0건** |
| **측정 방법** | 커밋 후 강제 종료를 주입하는 테스트, 재시작 후 잔액·미수·원장 검산 |
| **근거** | C-02(운영 1명) · HA-3(모든 자금 경로 멱등). Phase 2 변이 검사 20건이 이 시나리오의 **결함 목록**이다 |
| **파생 수치** | Outbox 재시도 간격·상한 |

### QS-06. 의존 대상(매입사) 장애

| 항목 | 내용 |
|---|---|
| **품질 속성** | 가용성 · 정합성 |
| **출처** | 매입사/VAN |
| **자극** | 무응답 · 지연 · 중복 응답 · 순서 역전 (Phase 1이 모의 대상으로 명시) |
| **환경** | 장애 중 |
| **대상** | 승인 경로 · 매입 배치 |
| **응답** | 승인은 **거절**(정합성 우선), 매입 파일은 **격리**하고 처리를 계속한다 (BR-50) |
| **측정** | 매입사 무응답 시 우리 응답 **p99 ≤ 3초 유지**(대기하지 않음) · 격리된 레코드는 **재처리 시 이중 출금 0건** |
| **측정 방법** | 모의 매입사에 지연·무응답·중복 주입 |
| **근거** | Phase 1 제품 정의(모의 외부가 의도적으로 이상을 주입) · 상충표(정합성 ↔ 가용성 → 거절) |

### QS-07. 인스턴스 장애와 복구

| 항목 | 내용 |
|---|---|
| **품질 속성** | **가용성** |
| **출처** | 인프라 |
| **자극** | 인스턴스 1대 강제 종료 (다중 인스턴스 가정) |
| **환경** | 평시 부하 중 |
| **대상** | 전체 |
| **응답** | 진행 중 요청은 실패하되 **재시도로 복구**, 신규 요청은 **남은 인스턴스가 처리**. 배치는 **중복 실행되지 않는다**(HA-2) |
| **측정** | ★ **RTO ≤ 3시간** (규제 기준) · 인스턴스 1대 종료 시 **자금 정합성 위반 0건** · 배치 중복 실행 0건 |
| **측정 방법** | 다중 인스턴스 기동 후 1대 강제 종료, 대사 배치로 정합성 확인 |
| **근거** | ★ **[1차] 전자금융감독규정 제23조 ⑧⑨ — RTO 3시간 이내.** 신용카드업자는 재해복구센터 구축 대상 |
| **파생 수치** | 헬스체크 주기 · 배치 락 TTL |

> ★ **규제는 가동률(%)을 요구하지 않는다. RTO를 요구한다.**
> 전자금융감독규정 전문에 **가동률 % 수치가 없음**을 리서치가 확인했다.
> *"규제상 99.9%"* 같은 표현은 **[미검증]** 이며 이 문서는 쓰지 않는다.
>
> ⚠️ **C-04(예산 0)로 실제 다중화 운영은 하지 않는다.** QS-07은 **구조가 그것을 허용하는지**를
> 재는 시나리오이고, HA-1~HA-5가 그 판정 항목이다 (`quality-attributes.md` §2.1).

## 2. 수치 근거 대장 ★★

**Phase 2가 미룬 수치와 이번에 근거가 뒤집힌 수치를 전부 올린다.**
미정이어도 올린다 — 대장에 없으면 구현자가 임의로 정한 값이 굳는다.

### 2.1 근거를 확보한 것

| 상수 | 값 | 등급 | 출처 |
|---|---|---|---|
| **평시 승인 부하** | **100 TPS** | [유도] | 여신금융협회 2025 × **7.08%**(리서치 표의 실제 최저) × 주간계수 1.5 (QS-01) |
| **피크 승인 부하** | 400 TPS | [1차] | 카카오페이 기술블로그 (11/11 실측) |
| **부하 테스트 상한** | 1,000 TPS | [유도] | 피크의 2.5배 여유 |
| **망취소 유효기간(취소 예약 TTL)** | **1시간** | [1차] | NICEPAY 매뉴얼 — *"1시간 초과건은 망취소가 실패"* |
| **멱등키 보관 기간** | **24시간** | [1차] | Stripe API Reference. IETF draft-ietf-httpapi-idempotency-key-header-07은 **"만료 정책 공표 MUST"** 만 규정하고 값은 서버에 위임 |
| **RTO** | **3시간 이내** | [1차] | 전자금융감독규정 제23조 ⑧⑨ |
| **승인→매입 기한** | CNP **10일** · CP **5일** | [1차] | Visa Business News AI13522 (2024-04-13 시행) |
| **매입 대금 지급** | 매출전표 **접수일 + 3영업일 이내** | [1차] | 신용카드 가맹점 표준약관 (2024-04-20 시행) 제12조① |
| **대사 배치 완료** | 마감 후 1시간 이내 | [유도] | RTO 3시간의 1/3 (QS-04) |

### 2.2 ★ 근거가 뒤집힌 것 — **Phase 2 문서 수정 대상**

| 규칙 | Phase 2가 적은 값 | 리서치 결과 | 판정 |
|---|---|---|---|
| **BR-01** | 매입사 타임아웃 **5초** / 목표 p99 3초 | **[1차]** Worldpay: 승인 타임아웃 **최소 25초 권장**. Mastercard: 프로세서 응답 **7초**(초과 시 STIP), 수신 네트워크 **40초** | ⚠️ **5초의 근거가 없다.** 국내 VAN 규격은 NDA라 확인 불가 → **가정임을 명시하고 유지**하되 출처를 *"자체 가정"* 으로 정정 |
| **BR-06** | 정산 반영 **D+1 09:00** | **[1차]** 약관은 *"접수일 + 3영업일 이내"* 만 정한다. **D+n은 결과값이지 규정값이 아니다** | ⚠️ **상수화 금지.** *"3영업일 이내"* 를 규칙으로 두고 D+1은 **우리 운영 목표**로 분리 |
| **BR-22** | 취소 예약 TTL **미확정** | **[1차]** 망취소 유효 **1시간** | ✅ **닫힘 — 1시간** |
| **BR-02** | 멱등키 보관 **미확정** | **[1차]** Stripe 24시간 · IETF는 공표 의무만 | ✅ **닫힘 — 24시간** (공표 의무도 함께 채택) |
| **BR-19** | 만료 후 매입 허용 기간 미확정 | **[1차]** Visa CNP 10일 / CP 5일 | ✅ **닫힘 — CNP 10일 기준** |

> ★ **BR-01과 BR-06이 이 리서치의 가장 큰 소득이다.** 둘 다 *"근거가 있다고 믿고 쓰던 값"* 이었고,
> 실제로는 **하나는 출처가 없었고 하나는 규정을 잘못 읽은 것**이었다.
> Phase 2가 열 라운드를 돌면서도 못 잡았다 — **문서 리뷰는 "이 수치가 맞나"를 묻지 않기 때문이다.**

### 2.3 여전히 [미검증] — 설계 근거로 쓰지 않는다

| 항목 | 시도 | 영향 |
|---|---|---|
| 국내 VAN 승인 응답 규격 | 연동규격서 NDA 배포 | BR-01의 5초가 가정으로 남는다 |
| **망취소 재시도 횟수·간격** | 국내외 어디에도 없음 | ★ **표준이 안 정한다** — 자체 결정 사항임이 확인됐다(QS-03) |
| 카드사 정산 마감 시각(cut-off) | 못 찾음 | BR-06 23:00이 가정으로 남는다 |
| 카드 승인 시간대별 분포 | 못 찾음 | QS-01의 주간 계수 1.5가 가정 |
