## 7. ADR 간 정합 — 확인한 것과 남은 것

### 확인됨 ✅

| 쌍 | 확인 |
|---|---|
| **003 × 011** | 상태 저장(003)이라 워터마크 재구성이 불가 → 011이 lazy close를 택한 것과 **일관** |
| **007 × 012** | 007이 ORM 단일 경로를 의무화 → 그것이 lost update 노출 → 012가 낙관적 락으로 덮는다. **012 없이 007만 있으면 F-01이 열린다** |
| **009 × 010** | 파티션 키(계좌ID)와 배포 경계가 **충돌하지 않는다** — 코어 안에서만 파티션한다 |
| **005 × 014** | 005의 선언(O-4 순서)을 014가 장치로 만든다 |
| **008 × 014** | B-1~B-5의 좀비 구멍을 014 B-6~B-9가 막는다 |
| **011 × 015** | lazy close의 배포 스큐 위험(F-17)을 015 S-10~S-13(플래그)이 다룬다 |
| **013 × 012** | ★ **두 번 고쳤다** — 첫 수정(공유 deadline 3초)도 T-1을 어겨 **내부 deadline 2.5초**로. 초안은 — 재시도 3회 × (락 0.5 + 백오프) + 앱 2.5초 = **4.1초 > 3초**. **T-11~T-13(공유 deadline)** 으로 결합 |
| **002 × 010** | ★ **실제 모순이었다** — ADR-002가 C6·C7을 위성으로 두고 있었다(대체된 ADR-004 구조). **v0.2에서 고침** + **M-6** 신설 |
| **014 × 003** | ★ **DLQ가 드레인 완료를 위조**할 수 있었다 — **O-15·O-16**(DLQ_UNRESOLVED는 완료가 아니다) |
| **015 × 원장 ACL** | ★ *"필드 추가는 안전"* 이 **회계 의미를 바꿀 수 있었다** — **S-6a** 신설 |
| **005 × 010 N-1** | ★ **역방향에 Outbox가 없었다** — 정산 완료 후 발행 전 종료면 **재발행 조작이 하나도 없어** 하루치 대사가 무음 정지. **O-17**(정산 outbox) |
| **012 × DC-005** | ★ *"범위 스캔이 없다"* 근거가 무효화됐고 **자식 행 seed 경쟁**이 생겼다 — **W-17** |
| **015 × DC-005** | ★ **플래그 off가 안전 상태가 아니다** — 구 동작이던 `DailySnapshot`이 폐기돼 off = 좌변 부재. **S-19** |
| **008 × 009 R3** | ★ 파티션 축이 **셋인데 하나로 단언**했다 — ADR-008 §2 표 |
| ★ **016 × 013** | 인가 판정이 자금 트랜잭션 안의 외부 호출이면 **T-10(커넥션 1개)·내부 deadline 2.5초와 충돌**한다 — **인프로세스·진입 시 1회**(AU-3·AU-4)로 회피 |
| ★ **017 × 005** | 감사 수집이 outbox 계약(O-1~O-5)을 재사용한다 — at-least-once 위에서 **수신 멱등**(AD-3)이 이중 적재를 막는다. **릴레이 부하 증가는 [미검증]** |
| ★ **018 × 012 · 009** | 축 컬럼이 **인덱스 선두·파티션 축을 건드리지 않는다**(IS-3) — 건드리면 갭 락 전파(012 계약)·파티션 재설계(009)가 재발한다 |

> ★ **O-4의 우려가 맞았다.** ADR 4건에서 **치명 3건**이 나왔고 셋 다
> *"각각은 맞는데 합치면 깨지는"* 형태였다 —
> **012×013(예산)** · **014×BR-52(드레인)** · **015×원장 ACL(회계 의미)**.
>
> **DC-003·DC-004에 이은 세 번째다.** 이 프로젝트에서 **가장 반복되는 결함 형태**이고,
> 그래서 §7의 쌍별 대조를 **관행으로 남긴다**.
