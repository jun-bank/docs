## 7. ADR 간 정합 — 확인한 것과 남은 것

### 확인됨 ✅

| 쌍 | 확인 |
|---|---|
| **003 × 011** | 상태 저장(003)이라 워터마크 재구성이 불가 → 011이 lazy close를 택한 것과 **일관** |
| **007 × 012** | 007이 ORM 단일 경로를 의무화 → 그것이 lost update 노출 → 012가 낙관적 락으로 덮는다. **012 없이 007만 있으면 F-01이 열린다** |
| **009 × 010** | 파티션 키(계좌ID)와 배포 경계가 **충돌하지 않는다** — 코어 안에서만 파티션한다 |
| **005 × 014** | 005의 선언(O-4 순서)을 014가 장치로 만든다 |
| **008 × 014** | B-1~B-5의 좀비 구멍을 014 B-6~B-9가 막는다 |
| **011 × 015** | lazy close의 배포 스큐 위험(F-17)을 015 S-10~S-13(플래그)이 다룬다 |
| **013 × 012** | 재시도 상한(W-8)과 타임아웃(T-1)이 **같은 3초 예산**을 공유 — W-10이 그것을 명시 |

### ⚠️ 남은 것

| # | 무엇 | 왜 |
|---|---|---|
| **O-1** | **012~015의 근거가 QS로 환원되지 않는다** | 장애 사례가 근거다. *"우리에게 일어날 확률"* 을 재는 시나리오가 없다 |
| **O-2** | **013 초기값 3개 · 014 상한 2개가 [미검증]** | 실측 전까지 **이 값을 근거로 다른 결정을 하면 안 된다** |
| **O-3** | **009 §4 E2·E4가 계좌 파티션에서 안 닫힌다** | 미해결로 명시했으나 **샤딩 시 발현**한다 |
| **O-4** | ★ **012~015를 아무도 리뷰하지 않았다** | Phase 3 리뷰는 011까지만 봤다 |
| **O-5** | **멀티테넌시 공백 G-1~G-4** | 인가 모델·운영자 권한 단계·감사 행위자 — `study/09` §5 |

> ★ **O-4가 지금 가장 큰 위험이다.** ADR 4건을 급히 만들었고,
> **DC-004 때처럼 "각각은 맞는데 합치면 깨지는" 것**이 있을 수 있다.
