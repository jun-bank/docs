# 토대 변경 절차 (Design Change)

> **이미 합의된 설계를 되돌려 다시 쪼개는 절차.** 개별 결함을 고치는 것(패치)과 다르다.
>
> 이 절차는 **어느 Phase에서도 발동**할 수 있다. Phase 순서를 벗어나 앞 단계 산출물을 여는 유일한 정식 경로다.

---

## 1. 왜 별도 절차가 필요한가

리뷰에서 결함이 나오면 고친다. 그게 정상이다. **그런데 고친 자리가 또 깨지면, 고치는 행위 자체가 문제를 감춘다.**

| 패치 | 토대 변경 |
|---|---|
| 이 결함을 없앤다 | **이 결함이 계속 나오는 구조**를 없앤다 |
| 지적된 곳을 본다 | **왜 그 자리만 반복해서 지적되나**를 본다 |
| 리뷰 라운드 안에서 끝난다 | 라운드를 **멈추고** 시작한다 |

> **핵심**: 패치를 반복하는 동안에는 "고쳐지고 있다"는 신호가 계속 나온다. 라운드마다 결함 수가 줄어들기까지 한다. **그 신호가 토대 문제를 가장 오래 숨긴다.**

---

## 2. 발동 조건 ★

**하나라도 해당하면 패치를 멈추고 이 절차로 들어간다.**

| # | 조건 | 왜 이것이 신호인가 |
|---|---|---|
| **T1** | **같은 자리를 2회 이상 고쳤는데 또 깨진다** | 고친 것이 증상이었다는 뜻이다 |
| **T2** | 리뷰 라운드마다 **같은 뿌리**에서 결함이 나온다 | 뿌리를 안 건드리고 가지만 쳤다 |
| **T3** | 어떤 불변식을 **사람이 지켜야 한다** — 구조가 막아주지 않는다 | 규칙을 문서에만 적어 둔 상태 |
| **T4** | 어떤 선택지를 기각한 근거가 **채택한 안에도 그대로 적용된다** | 기각이 실제로는 성립하지 않았다 |
| **T5** | 한 결함을 고치면 **다른 곳이 깨지는 것이 반복**된다 | 책임이 잘못 나뉘어 있다 |
| **T6** | 수정이 **새 결함을 만든 비율**이 라운드마다 줄지 않는다 | 손대는 면적이 문제의 크기를 넘었다 |

> **T4가 가장 놓치기 쉽다.** 결정을 내릴 때 쓴 기각 근거를, 채택안이 실제로 어떻게 구현되는지 본 뒤에 다시 읽어야 드러난다.

### 발동 조건이 아닌 것

- 결함이 많다 — 개수는 신호가 아니다. **분포**가 신호다.
- 리뷰가 어렵다 — 어려운 도메인은 원래 어렵다.
- 더 나은 설계가 떠올랐다 — **지금 것이 실제로 실패하고 있어야** 한다.

## 3. 절차

```
① 패치 중단          진행 중인 수정을 멈춘다. 미적용 findings는 보류로 표시
② 실패 이력 수집      라운드별로 "어디가 깨졌나"를 표로
③ 공통 뿌리 지목      그 실패들이 공유하는 단 하나의 결정을 특정
④ 기각 근거 재심      과거에 그 뿌리를 이렇게 정한 이유가 아직 유효한가 (T4)
⑤ 대안과 영향 범위    선택지 + 각각이 여는 문서 수
⑥ 사용자 합의        ★ 여기서 멈춘다. 자율 진행 금지
⑦ 변경 실행          기준소스부터 — 규칙 → 애그리게이트 → 상태 머신 순
⑧ 기존 findings 재판정 ★ 토대가 바뀌면 일부는 무효가 된다
⑨ 재리뷰             ②의 실패 이력이 재현되지 않는지 확인
```

### ⑥에서 멈추는 이유

토대 변경은 **되돌리기 비싼 결정**이다. 앞 Phase 산출물을 열고, 이미 합의된 규칙을 바꾸고, 사용자가 이미 답한 질문의 답을 무효로 만들 수도 있다. **자율 실행 대상이 아니다.**

### ⑧이 이 절차의 고유 단계다 ★

토대를 바꾸면 **기존 findings의 상당수가 저절로 사라진다.** 재판정 없이 목록대로 고치면:

| 판정 | 뜻 | 처리 |
|---|---|---|
| **소멸** | 그 결함이 존재할 구조가 없어졌다 | 고치지 않는다. **소멸했다는 사실을 기록**한다 |
| **잔존** | 토대와 무관하게 여전히 결함 | 고친다 |
| **변형** | 같은 문제가 다른 형태로 남았다 | **새 finding으로 다시 쓴다** — 옛 서술을 고치면 안 된다 |

> **소멸을 기록하지 않으면 다음 리뷰가 같은 것을 또 지적한다.** "이건 이미 없앴다"의 근거가 변천 문서다.

## 4. 산출물

| 무엇 | 어디에 | 언제 |
|---|---|---|
| **변천 문서** (`DC-nnn`) | `docs/design-changes/` | ②~⑧ 전 과정을 여기 쓴다 |
| 기준소스 수정 | 해당 Phase 산출물 | ⑦ |
| 각 문서 변경 이력 1행 | 수정된 문서 | ⑦ — `DC-nnn` 참조 |

**변천 문서는 결정이 아니라 과정을 남긴다.** 결정만 남기면 다음에 같은 자리에서 또 흔들릴 때 "그때 왜 이렇게 정했나"를 재구성할 수 없다.

양식: [record-format.md](record-format.md)

## 5. ADR과 무엇이 다른가

| | ADR | 변천 문서 |
|---|---|---|
| 언제 | **결정할 때** | 이미 한 결정이 **실패했을 때** |
| 무엇을 남기나 | 선택지와 근거 | **실패 이력** + 뿌리 진단 + 선택지와 근거 |
| 범위 | 하나의 결정 | 그 결정이 **퍼진 모든 문서** |
| 후속 | 없음 | **기존 findings 재판정**(⑧) |

> 토대 변경도 결정이므로 ADR을 함께 남길 수 있다. 다만 **실패 이력과 재판정은 ADR 양식에 자리가 없다** — 그래서 별도 문서다.

## 6. 흔한 실수

| # | 실수 | 왜 문제인가 |
|---|---|---|
| 1 | **발동 조건을 확인하지 않고 시작** | "더 나은 설계"는 발동 조건이 아니다. 실제로 실패하고 있어야 한다 |
| 2 | 실패 이력을 **요약해서** 적음 | 라운드별 원문이 있어야 뿌리가 보인다. 요약하면 "비슷한 문제들"로 뭉뚱그려진다 |
| 3 | **⑥ 없이 진행** | 되돌리기 비싼 결정을 혼자 내린 것 |
| 4 | **⑧을 건너뛰고** 기존 findings를 그대로 소화 | 이미 사라진 결함을 고치느라 새 결함을 만든다 |
| 5 | 상태 머신부터 고침 | 기준소스(규칙)가 안 바뀐 채 파생 문서만 바뀌면 **다음 리뷰가 원복을 요구**한다 |
| 6 | 변천 문서에 **결정만** 남김 | 다음에 같은 자리가 흔들릴 때 재구성 불가 |

---

## 7. 완료 기준

- [ ] 발동 조건(§2) 중 **어느 것에 해당하는지** 변천 문서에 적혀 있다
- [ ] 실패 이력이 **라운드별·원문 인용**으로 있다
- [ ] 공통 뿌리가 **하나의 결정**으로 특정돼 있다
- [ ] 과거 기각 근거를 **다시 읽고 판정**했다 (T4)
- [ ] 사용자 합의가 기록돼 있다
- [ ] 기존 findings가 **소멸 / 잔존 / 변형**으로 전부 재판정됐다
- [ ] 수정 순서가 **기준소스 → 파생** 이었다
- [ ] 영향받은 모든 문서에 `DC-nnn` 참조가 남았다
