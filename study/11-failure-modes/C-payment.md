# C. 결제 도메인 실패 (F-20 ~ F-25)

> **앞의 두 그룹이 "어떻게 깨지나"라면 이 그룹은 "무엇이 걸려 있나"다.**
> 같은 기술적 결함이라도 **결제에서는 돈이 움직인다.**

---

## F-20. 이중 결제·이중 출금

### 원리 — 세 곳에서 갈린다

```
① 요청 전달   전문이 두 번 온다        (F-11 중복)
② 내부 처리   재시도가 두 번 반영한다   (F-01 lost update · F-09 재시도)
③ 응답 유실   상대가 못 받아 다시 보낸다 (두 장군 문제)
```

**③이 가장 흔하고 가장 안 보인다.** 우리는 성공했는데 **상대는 모른다.**

### 왜 "성공/실패" 2분류가 부족한가

```
승인 요청 → 처리 성공 → 응답 송신 → ★ 유실
  우리    : 성공
  매입사  : 모름
  → 매입사가 망취소를 보낸다
  → 우리가 그것을 "이미 성공한 건의 취소"로 안 다루면 상태가 갈린다
```

> ★ **카카오페이(2022)** 가 이것을 **성공/실패/`Unknown` 3분류**로 정면 인정했다.
> *"돈은 나갔는데 주문은 실패"* 가 그 상태의 이름이다.

### 막는 구조

| 층 | 무엇 |
|---|---|
| **멱등 키** | 같은 요청은 한 번만 반영. **유니크 제약**으로 (F-11) |
| **취소 예약** | 원 승인보다 망취소가 먼저 와도 **나중 승인을 무효화** |
| **집합 승격** | *"격리에 있다 = 미반영, 처리에 있다 = 반영됨"* — 원자 이동이 곧 멱등 |

### 우리 자리

| 경로 | 막는 것 |
|---|---|
| 승인 재전송 | `IdempotencyRecord` `(correlationId, operation)` |
| 망취소 선행 | `ReversalTombstone` — 예약 자체가 멱등(DC-004 M3) |
| 입금·정정 | `DepositReceipt` `(key, operation)` + **INV-4·INV-5** |
| **매입 재처리** | ★ `promoteIsolated`가 **E2 참여자** (R8 S1) |

> ★ **R8 S1이 이 유형의 실제 사례다.** `promoteIsolated`를 단독 조작으로 두면
> *"출금은 됐는데 배치는 미반영이라 재시도가 또 출금"* 이 된다.
> **경계 배정 하나가 이중 출금 방어선이었다.**

## F-21. 정산 불일치 — 탐지가 늦다

### 원리 — 무엇이 어긋나나

```
우리 기록          매입사 파일         원장
승인 100건    vs   매입 98건     vs   전표 99건
                         ↑                 ↑
                    2건 미도착        1건 기표 누락
```

**세 곳이 각자 정본을 주장한다.** 대사는 **어느 것이 틀렸는지 판정하지 않고 적재만** 한다
— 원인이 우리 쪽인지 상대 쪽인지 모르기 때문이다(BR-09).

### 진짜 위험 — 탐지 자체가 안 도는 것

> ★ **Revolut $20M (2022)**: 미국/유럽 시스템 불일치로 **거절된 거래를 자사 자금으로 환불**했다.
> **탐지 시점이 핵심이다** — 자체 대사가 아니라 **파트너 은행이 *"현금이 예상보다 적다"* 고 통보**해서 알았다.

**대사가 있어도 "안 돌고 있다"를 아무도 안 보면 없는 것과 같다.**

### 세 가지 실패 방식

| # | 방식 | 증상 |
|---|---|---|
| **①** | 대사가 **안 돈다** | 조용하다 — ★ 가장 나쁘다 |
| **②** | 대사가 **허위를 쏟는다** | *"어차피 매일 뜨는 것"* → 진짜가 묻힌다 |
| **③** | 대사가 **틀린 기준**으로 본다 | 통과하는데 실제로는 어긋나 있다 |

> ★ **②가 ①만큼 나쁘다.** 노이즈가 신호를 죽인다 — ADR-006이 커트오프를 만든 이유다.

### 우리 자리

**막는 것**: M12·M14·M15 + 커트오프(ADR-011) + M16(드레인 미완 적재)

⚠️ **①에 대한 방어가 미완이다.** *"며칠째 안 돌고 있다"* 를 누가 언제 보는가 —
**BR-52 드레인 상한 · BR-48 알림 임계 · BR-37 미결 허용시간이 한 사슬인데 셋 다 미정**이다.

## F-22. 초과 승인

### 원리 — 가용잔액이라는 개념

```
계좌잔액  100      실제로 있는 돈
홀딩       30      이미 점유된 돈 (승인은 났고 매입은 안 됨)
가용잔액   70      ★ 새 승인이 쓸 수 있는 돈
```

**계좌잔액으로 판단하면 이미 점유된 돈을 다시 승인한다**(BR-04).

### 어디서 뚫리나

| # | 경로 | 예 |
|---|---|---|
| **①** | 동시성 | 둘이 같은 가용잔액을 보고 각자 승인 (F-01) |
| **②** | 오래된 값 | 복제본·캐시를 읽는다 (F-04) |
| **③** | ★ **장애 중 우회** | *"검증이 안 되니 일단 승인"* |
| **④** | 가용화 시점 | 입금이 *"결제완료"* 보다 먼저 쓸 수 있게 된다 |

> ★ **③이 가장 크게 터진다.** **Bank of Ireland 2023** — 장애 중 잔액 검증을 우회하자
> 사람들이 ATM에 몰렸다. **Chase 2024** — 수표 가용화가 결제완료보다 빨라 *"무한 돈 버그"*.

### 우리 자리 — 네 층으로 막는다

| 층 | 무엇 |
|---|---|
| ① | **BR-04** 가용잔액 기준 (계좌잔액 아님) |
| ② | **E1 한 커밋** — 홀딩·한도·승인이 같이 |
| ③ | **ADR-012 낙관적 락** — lost update 차단 |
| ④ | **ADR-007** 복제본 금지 |

> ★ **그리고 degraded 승인 모드가 설계에 없는 것 자체가 방어다.**
> *"검증 불가 시 개별 요청 거절"*(상충표)이라 **③의 경로가 없다.**
> **없어서 못 뚫린다** — 이것도 설계 판단의 결과다.

## F-23. 전표 누락·중복

### 원리 — 복식부기가 무엇을 보장하나

```
모든 전표에서  차변 합계 = 대변 합계   (BR-08)
```

**이것은 "전표 하나가 균형"만 보장한다.**

| 보장하는 것 | ★ 보장하지 않는 것 |
|---|---|
| 전표 내부의 차대 균형 | **전표가 있어야 하는데 없는 것** |
| | **같은 사실이 두 번 기표된 것** — 각각은 균형이다 |
| | **금액이 틀린 것** — 틀린 금액도 균형일 수 있다 |

> ★ **시산표가 맞는데 틀린 상태가 가능하다.** 이것이 이 유형이 안 보이는 이유다.

### 사례

| | |
|---|---|
| **Citi/Revlon $900M** (2020) | UI 체크박스 **3개 중 1개만** 체크. **six eyes(3인 검토) 전원 통과**. 이자만 보낼 것을 원금 전액 송금 |
| **Deutsche Bank €28bn** (2018) | 엔↔유로 혼동 |
| ★ **삼성증권** (2018) | 배당 입력 오류로 **발행총수의 30배**가 생성 — **아무 검사에도 안 걸렸다** |

> ★ **삼성증권이 이 유형의 극단이다.** *"발행총수를 넘을 수 없다"* 는 **불변식이 없었다.**
> 복식부기는 균형만 보고 **총량은 안 본다.**

### 우리 자리

| 막는 것 | |
|---|---|
| 누락 | **ADR-005 Outbox** (F-10) · **M12·M14** |
| 중복 | ★ **INV-8** `sourceEvent` 유일 (F-11) |
| 어느 이벤트가 어느 줄을 쓰나 | **ACL 소유 규칙** (ADR-006 §4) |

> ★ **ACL 소유 규칙이 이 유형 전용 장치다.** *"이벤트는 자기가 단독 소유한 분개만 쓴다"* —
> 이것이 없어서 R7 U4(이중 기표)와 R8 S6(아무도 안 씀)이 **한 자리에서 두 번** 났다.

## F-24. 문서·설정 잔재 — 한 곳만 고친다

### 원리

```
같은 사실이 두 곳에 손으로 적혀 있다
  → 한 곳을 고친다
  → 다른 곳은 옛 값 그대로
  → ★ 둘 다 "맞아 보인다"
```

**틀린 쪽이 스스로를 틀렸다고 말하지 않는다.**

### 코드에서도 같다

> ★ **Knight Capital (2012)**: 8대 중 **7대만 새 코드 배포**.
> 그리고 새 코드가 **옛 플래그를 재사용**했다 — 구 코드에서 그 플래그는 다른 의미였다.
> 1대가 45분간 **$460M**을 태웠고, **롤백이 상황을 악화**시켰다.

**"재사용된 플래그"가 정확히 이 유형이다** — 의미는 바뀌었는데 이름은 그대로.

### 왜 리뷰로 안 잡히나

```
사람은 "지금 보는 문서"가 맞는지만 본다
  → 다른 문서에 같은 값이 있다는 것을 모른다
  → ★ 두 곳을 동시에 펴놓고 대조하는 일은 거의 없다
```

### 우리 자리 — 실제로 여러 번 걸렸다

| 언제 | 무엇 |
|---|---|
| R7 U8 | BR-09 *"10종 … 9종 전부 탐지"* |
| R8 K13 | 상태 머신 헤더 *"7종"* vs 파일 8개 |
| Phase 3 G8 | BR-02 본문 24시간 · 표 30일 / QS-01 100 vs 80 |

**막는 것**: ★ **검사 ⑥⑩⑫⑰㉑** — 전부 이 유형 전용이다.

> ★ **이 유형만 검사가 다섯 개다.** 그만큼 자주 났고,
> **사람이 못 잡는다는 것이 실측으로 확인**됐기 때문이다.

## F-25. 조용한 실패 — 에러 없이 틀린다

### 원리

```
정상적인 실패   예외 · 에러 코드 · 알림     → 안다
조용한 실패     그냥 진행된다              → ★ 모른다
```

### 어떤 모습으로 나타나나

| 형태 | 예 |
|---|---|
| **부분 실패를 완료로** | 파티션 10개 중 9개 성공 → *"배치 완료"* |
| **무음 스킵** | 조건에 안 맞는 레코드를 **로그도 없이** 건너뛴다 |
| **조용한 절단** | 목록 1000건 중 100건만 처리하고 정상 종료 |
| **fail-open** | 검증 실패인데 **통과**시킨다 |
| ★ **지표가 없다** | 문제가 있는데 **볼 방법이 없다** |

> ★ **Stripe RCA (2019)** 가 마지막 형태다 —
> *"복제 지연 메트릭은 안 내면서 **헬스체크는 정상 응답**"*.
> 시스템은 *"나 괜찮다"* 고 말하고 있었다.

### 왜 가장 위험한가

```
드러나는 실패   비용 = 그 건
조용한 실패     비용 = 그 건 × 발견까지의 기간
```

**Revolut $20M(F-21)도 조용한 실패였다** — 몇 달치가 쌓였다.

### 우리 자리

| 막는 것 | |
|---|---|
| 부분 실패를 완료로 | ★ **ADR-008 B-4** — *"모든 파티션 완료 전에는 완료가 아니다"* |
| 무음 스킵 | BR-50 격리는 **적재**한다 (조용히 건너뛰지 않는다) |
| 검증 자체가 안 도는 것 | M16 · 변이 검사 |
| **문서가 스스로 안심하는 것** | ★ 리뷰가 **두 건** 잡았다 — *"이미 준비돼 있다"* 고 적혔는데 아니었다 |

> ★ **마지막 행이 이 프로젝트 고유의 형태다.**
> **문서에도 조용한 실패가 있다** — *"막고 있다"* 고 적어두면 아무도 다시 안 본다.
> 그래서 `study/11` 카탈로그의 판정 기준을 **"이름을 댈 수 있으면 막힘, 문장뿐이면 뚫림"** 으로 두었다.

## 정리 — 결제 도메인이 다른 점

```
① 되돌리기가 비싸다            잘못 나간 돈은 회수 절차가 필요하다
② 상대가 있다                  우리만 맞으면 안 된다 (매입사·원장·정산)
③ 조용히 틀리는 것이 많다      시산표가 맞는데 틀린 상태가 가능하다
④ 발견이 늦으면 배수로 는다     하루 놓치면 하루치가 쌓인다
```

> ★ **그래서 이 도메인은 "막는 것"보다 "빨리 아는 것"에 더 투자한다.**
> 대사·M 유형·커트오프가 전부 그 투자다. **Revolut이 그것을 안 해서 파트너에게 들었다.**
