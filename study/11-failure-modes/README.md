# 실패 유형 카탈로그 (F-01 ~ F-25)

> **"이런 문제가 있다"를 번호로 정리한다.**
> 근거는 실제 사고 사례이며 원문은 `reference/failure-scenarios/` 세 문서에 있다.
>
> ★ **이 문서는 카탈로그다.** 각 유형이 **우리 프로젝트의 어디에 걸리는지**와
> **무엇이 막는지**를 함께 적어, 설계할 때 체크리스트로 쓴다.

---

## 읽는 법

| 칸 | 뜻 |
|---|---|
| **증상** | 겉으로 보이는 것 — 이것만 보면 원인을 못 찾는다 |
| **뿌리** | 실제 원인 |
| **우리 자리** | 이 프로젝트의 어느 구조가 같은 형태인가 |
| **막는 것** | 이름을 댈 수 있으면 막힘, **계약 문장뿐이면 뚫림** |

> ★ **"막는 것" 칸이 비어 있거나 문장뿐이면 그것은 안 막고 있는 것이다.**
> 이 프로젝트의 실측 결론이다 — *주의력에 의존하는 규칙은 지켜지지 않는다.*

---

## A. 동시성·데이터베이스 (F-01 ~ F-08)

### F-01 Lost update — 커밋된 변경이 조용히 사라진다

| | |
|---|---|
| **증상** | 에러 없음. 숫자만 틀리다 |
| **뿌리** | `load → modify → save` 패턴. 두 트랜잭션이 같은 값을 읽고 각자 덮어쓴다 |
| **사례** | ★ **Jepsen MySQL 8.0.34** (2023-12) — RR에서 **198건 / 9,048 트랜잭션** |
| **우리 자리** | **E1** 승인 (계좌 `holdTotal`·카드 `usage`) — ADR-007이 ORM 단일 경로를 **의무화**해 이 패턴이 강제된다 |
| **막는 것** | **ADR-012 W-5** 낙관적 락 + **W-7** 아키텍처 테스트 |

> ⚠️ **`@Version` 누락은 컴파일도 아키텍처 테스트도 통과한다** — W-7이 그래서 필요하다.

### F-02 데드락

| | |
|---|---|
| **증상** | 간헐적 실패. 부하가 오르면 급증 |
| **뿌리** | ① 락 순서 불일치 ② **중복 키 INSERT의 S락**(MySQL §17.7.3) ③ 갭 락 vs INSERT |
| **사례** | **ideeli** — `autoinc_lock_mode` 조정 후 **갭 락 충돌로 재발** |
| **우리 자리** | 락 순서 ①미수→⑤배치 · **망취소 동시 INSERT**(BR-01이 정상 경로로 규정) |
| **막는 것** | **ADR-012 §2.4** 쓰기 순서 · **W-12** INSERT 후 중복이면 조회 |

### F-03 커넥션 풀 고갈

| | |
|---|---|
| **증상** | 앱을 증설했더니 **더 느려진다** |
| **뿌리** | 한 작업이 커넥션을 **둘 이상** 잡는다 · 앱 인스턴스 × 풀 크기가 DB 상한을 넘는다 |
| **사례** | **우아한형제들** — 컨슈머 16 vs 풀 10, `GenerationType.AUTO` 채번이 **두 번째 커넥션**을 잡아 풀 데드락 |
| **우리 자리** | 배치와 실시간이 **같은 DB**(ADR-010) |
| **막는 것** | ★ **ADR-007 W-1** — 자금 경로에 JDBC가 없으므로 **두 번째 커넥션이 생길 수 없다**(예상 밖 이득). ⚠️ 단 **풀 분리 규칙은 아직 없다** |

### F-04 복제 지연 — 방금 쓴 것이 안 보인다

| | |
|---|---|
| **증상** | *"저장했는데 목록에 없다"* · **멱등 조회가 못 찾아 재처리** |
| **뿌리** | 읽기 복제본이 아직 못 받았다 |
| **사례** | ★ **Airbnb Orpheus** — *"replica에서 멱등 조회를 하면 이중 결제가 난다"* |
| **우리 자리** | 멱등 레코드 조회 · 가용잔액 조회 |
| **막는 것** | **ADR-007 W-2** 자금 판단은 쓰기 데이터소스에서만 · **HA-1** |

### F-05 롱 트랜잭션 — undo가 쌓인다

| | |
|---|---|
| **증상** | 시간이 갈수록 **SELECT가 느려진다** |
| **뿌리** | 오래 열린 읽기 트랜잭션이 **purge를 막는다** |
| **사례** | **Percona** — 940 ACTIVE → **History List Length 6,000,000** |
| **우리 자리** | 대사가 *"한 읽기 트랜잭션"* (ADR-011 §1) |
| **막는 것** | **ADR-012 §2.2** 배치는 RC + 짧은 트랜잭션 |

### F-06 마이그레이션 사고

| | |
|---|---|
| **증상** | 배포 중 오류. 롤백이 더 나쁘다 |
| **뿌리** | 온라인 DDL이 **복제본에서는 논블로킹이 아니다** · `INSTANT`는 인덱스·타입 변경 불가 |
| **사례** | **PlanetScale** (INPLACE 3시간 = 복제 지연 3시간) · ★ **GitHub 2025-08** — 컬럼 드롭, *"안 쓴다"* 인데 **ORM이 이름을 부른다** |
| **우리 자리** | **HA-5** expand-contract |
| **막는 것** | ⚠️ **선언뿐 — 절차를 소유한 ADR이 없다** |

### F-07 ORM flush 타이밍

| | |
|---|---|
| **증상** | 같은 트랜잭션 안에서 **변경 전 값**을 읽는다 |
| **뿌리** | JPQL은 실행 전 자동 flush되지만 **JdbcTemplate은 그 흐름 밖** |
| **우리 자리** | 자금 판단 조회 |
| **막는 것** | ★ **ADR-007 W-1** — 혼용 자체를 **모듈 분리로** 불가능하게 |

### F-08 채번·시퀀스 병목

| | |
|---|---|
| **뿌리** | 중앙 채번이 인스턴스 증가에 비례해 병목 |
| **우리 자리** | 승인번호·전표번호 |
| **막는 것** | ⚠️ **미정** |

## B. 분산·비동기 (F-09 ~ F-19)

### F-09 재시도 폭풍 / 캐스케이딩

| | |
|---|---|
| **증상** | A가 느려지면 B·C까지 무너진다 |
| **뿌리** | 재시도가 **이미 느린 시스템에 부하를 곱한다** |
| **사례** | **Twilio 빌링 (2013)** — 잔액 갱신 전에 카드를 긁고 확인이 안 되니 **무한 재과금** |
| **우리 자리** | ★ **규모와 무관하게 해당** — 망취소가 at-least-once(QS-03), 낙관적 락 재시도, Outbox 릴레이 |
| **막는 것** | **ADR-012 W-8~W-11** (락 재시도) · ⚠️ **Outbox 릴레이 재시도 정책은 아직 없다** |

### F-10 메시지 유실

| | |
|---|---|
| **뿌리** | **커밋 후 발행 전** 프로세스 종료 |
| **우리 자리** | 원장 기표 · 정산 집계 |
| **막는 것** | ★ **ADR-005** Outbox — 사실과 이벤트가 **같은 트랜잭션** |

### F-11 메시지 중복

| | |
|---|---|
| **뿌리** | at-least-once. **전달 후 완료 표시 전** 종료 |
| **우리 자리** | ADR-005 **O-1** |
| **막는 것** | **O-2** 수신측 멱등 → ★ **`JournalEntry` INV-8**(유일 제약). ⚠️ **정산의 멱등 키는 아직 없다** |

### F-12 순서 역전

| | |
|---|---|
| **뿌리** | 병렬 전달. 파티션이 없거나 릴레이가 다중 인스턴스 |
| **사례** | **우아한형제들** — 커넥터 **단일 태스크 + 키→테이블 고정**이라는 **소유권 구조**로 해결 |
| **우리 자리** | ADR-005 **O-4** |
| **막는 것** | ⚠️ **선언뿐 — 장치가 없다.** 검증표도 중복만 재고 순서는 안 잰다 |

### F-13 Head-of-line blocking — 독약 메시지

| | |
|---|---|
| **증상** | 이벤트 하나가 실패하는데 **뒤 전부가 멈춘다** |
| **뿌리** | 순서대로 훑는 릴레이 + 영구 실패 |
| **우리 자리** | Outbox 폴링 릴레이 |
| **막는 것** | ⚠️ **없다** — 독약 격리(DLQ) 미정 |

### F-14 좀비 — fencing token 부재

| | |
|---|---|
| **증상** | 두 소유자가 같은 자원에 쓴다 |
| **뿌리** | ★ **lease 만료만으로는 못 막는다.** GC 정지한 프로세스가 깨어나 쓴다 |
| **사례** | **Kleppmann fencing token** (2016) |
| **우리 자리** | **ADR-008 B-3** 파티션 lease |
| **막는 것** | ⚠️ **B-1은 *할당*의 원자성이지 *쓰기*의 배타성이 아니다** |

### F-15 배치 중복 실행

| | |
|---|---|
| **사례** | ★ **Toss Payments (2025)** — *"K8s CronJob은 정확히 한 번을 보장 못 한다"* · **토스 자동이체 2026-06** 38분 21.4억 원 · **Santander £130m** |
| **우리 자리** | 대사·정산·만료 배치 |
| **막는 것** | **ADR-008 A** 파티션 할당 (안 D 기각이 이 사례들로 실증됐다) |

### F-16 타임아웃 계층 역전

| | |
|---|---|
| **증상** | 상위가 포기했는데 **하위는 계속 돈다** — 락이 안 풀린다 |
| **뿌리** | 하위 타임아웃 > 상위 타임아웃 |
| **우리 자리** | 승인이 3초에 포기해도 **DB 트랜잭션이 안 죽으면 계좌 로우가 계속 잠긴다** |
| **막는 것** | ⚠️ **없다** — BR-01은 목표값이지 장치가 아니다 |

### F-17 배포 스큐 — 구/신 버전 동시 가동

| | |
|---|---|
| **사례** | ★ **Knight Capital (2012)** — 8대 중 **1대만 구 코드** → 45분 **$460M**. 롤백이 악화시켰다 |
| **우리 자리** | ★ **ADR-011 lazy close** — *"거래가 D를 닫는다"* 인데 **어느 버전의 거래가 닫는지**가 없다 |
| **막는 것** | ⚠️ **HA-5 선언뿐** |

### F-18 Split-brain

| | |
|---|---|
| **사례** | **GitHub 2018-10** — 43초 단절 → 크로스리전 페일오버 → **24시간 11분**, 954건 미복제. *"data integrity over site usability"* |
| **우리 자리** | 단일 DB라 지금은 안 난다 |
| **막는 것** | ⚠️ **HA-3 멱등의 근거가 단일 DB 유니크 제약**이라는 사실이 안 적혀 있다 |

### F-19 핫스팟·편중

| | |
|---|---|
| **뿌리** | 균등 분산 가정이 깨진다. **샤드를 늘려도 안 풀린다** |
| **우리 자리** | ★ **매입 배치 파티션이 실질 1개** — 매입 파일은 통상 일 1회 1개다. **규모가 아니라 구조** |
| **막는 것** | ⚠️ **ADR-009 R3이 "관찰 대상"이 아니라 기본 상태다** |

## C. 결제 도메인 (F-20 ~ F-25)

### F-20 이중 결제·이중 출금

| | |
|---|---|
| **사례** | **토스 자동이체 2026-06** · **카카오페이 2022**(*"돈은 나갔는데 주문은 실패"* → 성공/실패/**Unknown 3분류**) |
| **우리 자리** | E1 승인 · E2 매입 재처리 |
| **막는 것** | 멱등 애그리게이트 셋 · **`promoteIsolated`가 E2 참여자**(R8 S1) |

### F-21 정산 불일치 — 탐지가 늦다

| | |
|---|---|
| **사례** | ★ **Revolut $20M (2022)** — 자체 대사가 아니라 **파트너 은행이 통보**해서 알았다 |
| **우리 자리** | M12·M14·M15 |
| **막는 것** | 대사는 있으나 ⚠️ **"며칠째 안 돌고 있다"를 누가 언제 보는지 미정** (BR-52·48·37 임계가 **한 사슬인데 셋 다 미정**) |

### F-22 초과 승인

| | |
|---|---|
| **사례** | **Bank of Ireland 2023**(장애 중 잔액 검증 우회) · **Chase 2024**(가용화 < 결제완료) |
| **우리 자리** | E1 |
| **막는 것** | ★ **네 층** — BR-04 + E1 한 커밋 + 낙관적 락(ADR-012) + 복제본 금지(ADR-007). **degraded 승인 모드가 설계에 없는 것 자체가 Bank of Ireland형 방어다** |

### F-23 전표 누락·중복

| | |
|---|---|
| **사례** | **Citi/Revlon $900M**(체크박스 3개 중 1개, six eyes 전원 통과) · **Deutsche Bank €28bn** |
| **우리 자리** | 원장 ACL |
| **막는 것** | **ACL 소유 규칙**(ADR-006 §4) · **INV-8** 유일 제약 · M12·M14 |

### F-24 문서·설정 잔재 — 한 곳만 고친다

| | |
|---|---|
| **증상** | 본문은 맞는데 **요약표가 옛날 값** |
| **사례** | ★ **Knight Capital** — 재사용된 플래그. **삼성증권** — 발행총수 30배가 **아무 검사에 안 걸렸다** |
| **우리 자리** | 미확정 수치 표 · 집계 선언 |
| **막는 것** | **검사 ⑥⑩⑫⑰㉑** — 실제로 여러 번 잡았다 |

### F-25 조용한 실패 — 에러 없이 틀린다

| | |
|---|---|
| **뿌리** | 부분 실패를 완료로 표시 · 무음 스킵 · 조용한 절단 |
| **사례** | ★ **Stripe RCA 2019** — *"복제 지연 메트릭은 안 내면서 **헬스체크는 정상 응답**"* |
| **우리 자리** | 배치 완료 판정 · 대사 |
| **막는 것** | **ADR-008 B-4**(모든 파티션 완료 전에는 완료가 아니다) · 변이 검사 |

## 우리가 지금 뚫려 있는 것 — "막는 것" 칸이 ⚠️ 인 것

| # | 유형 | 무엇이 없나 |
|---|---|---|
| **F-06·F-17** | 마이그레이션 · 배포 스큐 | **expand-contract 절차를 소유한 ADR** |
| **F-09·F-13** | 재시도 폭풍 · 독약 메시지 | **Outbox 릴레이 재시도·DLQ 정책** |
| **F-12** | 순서 역전 | **파티션 내 순서 장치** (선언만 있다) |
| **F-14** | 좀비 | **fencing token** |
| **F-16** | 타임아웃 역전 | **타임아웃 계층** |
| **F-19** | 핫스팟 | 매입 배치가 **구조적으로 파티션 1개** |
| **F-21** | 탐지 지연 | **알림 임계 사슬** (BR-52·48·37) |
| **F-03·F-08·F-18** | 풀 분리 · 채번 · split-brain 전제 | 각각 규칙·근거 미기재 |

> ★ **이 표가 다음 작업 목록이다.** 각 항목은 실험 시나리오로 재현 가능하며,
> 주입 지점·통과 기준은 `reference/failure-scenarios/` 각 문서 §4에 있다.
