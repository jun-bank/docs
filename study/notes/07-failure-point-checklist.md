# 07. (절차) 실패 지점 되짚기 습관

> 이건 지식이 아니라 **절차** 문서다.
> 05번을 놓친 원인은 Kafka를 몰라서가 아니라, **질문이 어느 실패 지점을 묻는지 확정하지 않고 답을 시작했기 때문**이다.

---

## 1. 진단: 무엇이 실패했는가

지식이 있어도 **질문의 범위를 좁게 잡으면** 답이 반쪽이 된다.

- "메시지 유실을 어떻게 막나요?" → 머릿속에서 **발행 측 문제로 자동 축소** → 아웃박스만 설명 → 소비 측 공백
- 면접관 입장에서는 "발행만 알고 소비는 모른다"로 읽힌다

**교정 방법은 지식 추가가 아니라 절차 추가다.**

---

## 2. 습관: 답하기 전 한 문장으로 되짚기

파이프라인/신뢰성 질문을 받으면, **답을 시작하기 전에** 다음을 한 문장으로 말한다.

> "말씀하신 게 **[N]번 지점**(발행 전 / 발행 중 / 브로커 / 소비 중 / 소비 후) 이야기로 이해했는데, 맞을까요? 아니면 전 구간을 말씀하시는 걸까요?"

효과가 세 가지다.
1. **범위를 확정**해서 반쪽 답을 막는다
2. **5칸을 입 밖으로 꺼내는 순간** 내가 어디를 빼먹었는지 스스로 보인다
3. 면접관에게 **전체 구조를 알고 있다는 신호**를 준다 (되묻는 것 자체가 감점이 아니라 가점)

전 구간을 묻는 것이면, 5칸을 순서대로 훑으면 답이 자동으로 완성된다.

---

## 3. 5칸 체크리스트

| # | 지점 | 실패 형태 | 대응 |
|---|---|---|---|
| **1** | **발행 전**<br>(비즈니스 TX ↔ 이벤트) | 이중 쓰기: DB는 커밋됐는데 이벤트가 안 나감 | **트랜잭셔널 아웃박스** (06번) |
| **2** | **발행 중**<br>(앱 → 브로커) | 네트워크 실패, 브로커 미응답, 부분 성공 | `acks=all`, `enable.idempotence`, 재시도+백오프, 릴레이가 ack 전까지 미완료 유지 |
| **3** | **브로커**<br>(저장·복제) | 리더 장애, 복제 미달, 보존 기간 만료로 소실 | `replication.factor≥3`, `min.insync.replicas=2`, `unclean.leader.election=false`, 보존 기간 vs 컨슈머 최대 지연 |
| **4** | **소비 중**<br>(poll → 처리 → 커밋) | 처리 실패, 크래시, **커밋 순서에 따른 유실/중복**, 리밸런싱 | 수동 커밋, 재시도 토픽, DLT, 멱등 소비(인박스) (05번) |
| **5** | **소비 후**<br>(다운스트림 반영) | 처리는 됐는데 하위 시스템 미반영, 중복 반영 | 멱등 upsert, 정합성 대조 배치, 종단 추적(trace id) |

### 각 칸의 확인 질문 (스스로에게)
1. **발행 전** — 비즈니스 커밋과 이벤트 기록이 원자적인가?
2. **발행 중** — 브로커가 받았다는 확인을 받고 완료 처리하는가?
3. **브로커** — 노드 하나가 죽어도 데이터가 남는가? 컨슈머가 밀렸을 때 보존 기간 안에 따라잡을 수 있는가?
4. **소비 중** — 커밋이 처리 **후**인가? 중복이 와도 안전한가? 영구 실패가 파티션을 막지 않는가?
5. **소비 후** — 최종 상태가 원천과 일치하는지 확인할 수단이 있는가?

---

## 4. 같은 절차의 다른 적용 (일반화)

이 습관은 Kafka 전용이 아니다. **"어느 지점을 묻는지 먼저 확정한다"**는 절차 자체가 자산이다.

| 질문 유형 | 되짚을 축 |
|---|---|
| "성능을 어떻게 개선했나요?" | 클라이언트 / 네트워크 / 앱 / DB — 어디 구간의 레이턴시? |
| "장애 대응 경험은?" | 감지 / 진단 / 완화 / 복구 / 사후 — 어느 단계? |
| "동시성 문제를 어떻게 풀었나요?" | 단일 프로세스 내 / 인스턴스 간 / DB 레벨 — 어느 범위의 경합? |
| "캐시를 어떻게 쓰셨나요?" | 무효화 / 정합성 / 스탬피드 / 만료 정책 — 어느 문제? |
| "확장성을 어떻게 확보했나요?" | 앱 / DB 읽기 / DB 쓰기 / 외부 의존 — 어느 병목? |

---

## 5. 연습 방법

1. 지금까지의 프로젝트 하나를 골라 **5칸 표를 직접 채워본다.** 빈칸이 곧 취약점이자, 면접에서 나올 질문이다.
2. 빈칸이 있으면 **"거기는 이런 이유로 열어뒀습니다"**를 준비한다. 모든 칸을 닫은 시스템은 없다. **닫지 않은 칸을 인지하고 있느냐**가 실력의 지표다.
3. 모의 답변 시 **첫 문장을 항상 범위 확정으로 시작**하는 연습. 반사가 될 때까지.

---

## 6. 한 줄 요약

> 파이프라인 질문은 지식 문제가 아니라 **범위 확정 문제**인 경우가 많다.
> 답하기 전에 5칸 중 어디인지 한 문장으로 되짚고 시작한다.
