- 작성일: 2026-08-03
- 상태: 검토대기
- 양식: `study/project-workflow/phase1/02-business-rules-format.md`
- **이 문서가 규칙의 정본이다.** 다른 문서는 `BR-nn`으로 참조만 하고 규칙 문장을 복사하지 않는다.

> **수치 정책 (결정 #3)**: 문서에는 **실제 업계 값**을 쓴다. 다만 **모든 수치는 설정값으로 분리**하여 테스트에서 분·초 단위로 축약할 수 있어야 한다. 설정 키는 `설정 키` 칸에 명시한다.

## 규칙 분류

| 분류 | 뜻 | 구현 위치 |
|---|---|---|
| **계산** | 어떤 값이 무엇으로부터 도출되는가 | 도메인 모델 메서드 |
| **제약** | 항상 참이어야 하는 한계 | 도메인 불변식 |
| **상태전이** | 어떤 전이가 허용/금지되는가 | 상태 머신 |
| **시간** | 시각·기한·주기에 관한 규칙 | 도메인 + 배치 |
| **표현** | 값을 어떻게 다루는가 | 값 객체 |
| **절차** | 무엇을 어떤 순서로 하는가 | 애플리케이션 서비스 |

## BR-01. 승인 응답 시간

| 항목 | 내용 |
|---|---|
| **규칙** | 승인 요청에 대한 응답은 매입사 타임아웃 이내에 반환된다. 우리 목표는 p99 3초 이내다 |
| **분류** | 시간 |
| **근거** | 매입사가 타임아웃으로 간주하면 망취소가 발생한다. 망취소는 **예외 경로여야지 정상 경로가 되면 안 된다.** 상대 타임아웃(5초)보다 충분히 빨라야 한다 |
| **수치** | 매입사 타임아웃 **5초** / 우리 목표 **p99 3초** — 근거: 상대 임계값의 60% 수준으로 여유 확보 |
| **설정 키** | `payment.authorization.timeout`, `payment.authorization.target-p99` |
| **예외** | 없음 (확인함) |
| **적용 범위** | S3 결제 승인 |
| **검증 방법** | 부하 테스트 후 응답 시간 분포 측정. p99 ≤ 3초 |
| **상태** | 확정 |
| **관련** | S3, S4, BR-13 |

## BR-02. 멱등 재요청

| 항목 | 내용 |
|---|---|
| **규칙** | 동일한 멱등키로 재요청이 오면 **최초 처리 결과를 그대로 반환**하며, 재처리하지 않는다 |
| **분류** | 절차 |
| **근거** | 네트워크 실패 시 요청자는 성공 여부를 알 수 없어 재시도한다. 재처리하면 **이중 승인**이 되어 고객 자금이 두 번 빠진다 |
| **수치** | 멱등키 보관 기간 **30일** — 근거: 임시값. 취소·환불 요청이 원거래를 참조할 수 있는 기간보다 길어야 함 |
| **설정 키** | `payment.idempotency.retention` |
| **예외** | 없음. **보상 요청(망취소·취소)에도 동일하게 적용된다** |
| **적용 범위** | 모든 상태 변경 요청 |
| **검증 방법** | 같은 멱등키로 N회 요청 후 최종 상태와 응답이 1회 처리와 동일한지 확인 |
| **상태** | 확정 |
| **관련** | S3, S4, S7, BR-13 |

## BR-03. 홀딩 만료

| **검증 방법** | 만료 기한을 분 단위로 축약한 환경에서 배치 실행 후 홀딩 잔류 0건 확인 |
| **상태** | 확정 |
| **관련** | S3, S8, BR-04 |

## BR-16. 매입은 승인 없이 발생할 수 없다 🔒
