## 1. 파이프라인 — 빌드 → 머지 게이트 → 아티팩트 → 배포

### 1.1 단계 (각 행에 실패 처리·판정 주체·막지 않는 것 — 양식 ①)

| 단계 | 트리거 | 하는 일 | 산출 | ★ 실패 시 | 판정 주체 | ★ 이 단계가 막지 **않는** 것 |
|---|---|---|---|---|---|---|
| **P1 빌드** | PR push · main 갱신 | 컴파일·정적 검사(**Gradle 멀티모듈** — ADR-025 **CL-1** 인용, 이 문서의 확정이 아니다) | 실행 가능 산출물(아직 아티팩트가 아니다 — P3에서 식별자가 붙는다) | **머지 불가 · 아티팩트 없음 · 배포 요청이 가리킬 대상이 없다.** 재실행은 **같은 커밋 SHA로만** 한다(다른 커밋의 재실행은 새 빌드다) | **기계** | 컴파일이 통과한다고 **모듈 경계가 지켜진 것이 아니다** — 그 강제는 아키텍처 테스트이고 **아직 도구가 없다**(E3 §6.3 — 잠정 리뷰 6건) |
| **P2 머지 게이트** | PR | **E2 §3.0 원문 인용**(재정의 금지 — CF-1 · PR-3): ⑴ **단위 · ★ 통합 · 계약 전부 green** ⑵ **머지 전 최소 안전선 ①~⑥**(E2 §3.1) ⑶ ★ **관련 탐색 판정이 유효**(재실행 규칙에 걸리지 않았다) | 머지 가능 판정 | ⑴ 실패 → **머지 차단**(기계) · ⑵⑶ 미충족 → **리뷰가 막는다**(사람). ⚠️ ★ **⑵⑶은 CI가 관측하지 못한다** — CI 초록만으로 머지하면 안전선 ①(스모크)·⑤(public contract)·탐색 판정 유효성이 **조용히 생략**된다 | ⑴ **기계** · ⑵⑶ ★ **사람**(CF-3 — 자동으로 적지 않는다) | ★ **인수·탐색을 머지마다 돌리지 않는다**(E2 §3.0 — *"막게 하면 … 통과하도록 약하게 쓰인다"*). **마일스톤 게이트는 머지를 막지 않는다.** ⚠️ 단 **정본 개정으로 만료된 탐색 판정**은 *"해당 자산에 닿는 변경의 머지"* 를 막는다(⑶ — 전면 차단이 아니다) |
| **P3 아티팩트** | main 머지 | 배포 산출물에 **불변 식별자**를 붙이고 **체크섬**과 함께 보관한다(**CD-5**) | 배포 가능 아티팩트 | **배포 불가**(배포 요청이 참조할 대상이 없다). ⚠️ ★ **부분 업로드가 최다 위험**이다 — 완료 표시는 **체크섬 검증 후 원자적으로** 붙이고, 표시 없는 산출물은 **없는 것으로 취급**한다(CF-2 · silent failure) | **기계** | 아티팩트가 있다고 **배포해도 되는 것이 아니다** — 배포 창 락(**CD-3**)과 서명 검증(RL-8)이 뒤에 있다 |
| **P4 배포 요청** | 사람의 배포 지시(★ **자동 배포를 두지 않는다** — §1.2) | CI가 **HMAC 서명 + OIDC 신원**을 실어 **오라클 프록시 → `.9` → deploy-agent** 로 요청한다(RL-7·RL-8) | 배포 요청(아티팩트 식별자 · 대상 배포 · 커밋 SHA · 요청자) | ★ **서명·신원 검증 실패 = 적용하지 않고 거절을 기록**한다(RL-8 — 예외 없음). 거절 기록이 **남지 않는 경로가 하나라도 발견되면 ADR-024 R5**다 | **기계**(검증) / **사람**(지시) | 요청이 유효하다고 **적용되는 것이 아니다** — 배포 창 락(CD-3)이 먼저 판정한다 |
| **P5 배포 적용** | agent가 요청을 수락 | **CD-4의 순서**대로 적용(락 → 회수 → green 기동 → 헬스체크 → 채널별 전환 → blue 종료 → 락 해제·기록) | 새 버전 가동 + 배포 이력 | 단계별로 갈린다 — **헬스체크 실패 = 미전환**(§2.1) · **드레인 상한 초과 = §2.2** · **전환 이후 실패 = 롤백**(§4). ⚠️ ★ **어느 실패든 락은 반드시 해제**된다(CF-10) | **기계**(실행·판정) / ★ **사람**(롤백 결정 · 불가역 턱) | 배포 성공이 **동작 확인이 아니다** — 스모크(E2 §3.1 ①)는 계층이 대체하지 못한다 |

### 1.2 ★ 자동 배포를 두지 않는다 (구조 판정)

main 머지가 **곧 배포**가 되면 **RL-4(배포 창 락)** 가 사람의 지시 없이 배치 창과 부딪히고, 배포 시각이 **머지 시각의 부산물**이 된다. 파이프라인은 **P3까지 자동**이고 **P4는 사람의 지시**다.

> ⚠️ 이것은 ADR-024의 재판정이 아니라 **RL-7의 절차적 귀결**이다 — RL-7이 정한 것은 *"실행 주체가 하나(agent)"* 이고, **누가 방아쇠를 당기나**는 이월 범위(RL-9)에 있었다.

## 2. ADR-024 RL-9 이월분 — 세부 절차 (전수)

> RL-9 원문: *"헬스체크 판정 기준 · 드레인 대기 상한 · 배포 창 정의 · agent 구현 · 아티팩트 보관 개수는 **Phase 5 진입 절차 E4**로 이월한다."* — 소화 전수 확인은 **§8**.

### 2.1 CD-1 — 헬스체크 판정 (RL-2의 *"헬스체크 통과 확인"* 이 무엇인가)

| 항목 | 절차 |
|---|---|
| **대상** | ★ **green 프로세스 자신**이 노출하는 상태 엔드포인트. 판정 주체 = **deploy-agent**(기계) — nginx가 아니다(nginx는 **전환 후** 트래픽만 본다) |
| ★ **무엇을 보나** | ⑴ **프로세스가 응답**한다 ⑵ ★ **자기 스키마 DB 커넥션을 실제로 획득**한다(**용도별 풀** 각각 — ADR-013 · DT-3) ⑶ ★ **자기 계정 권한이 기대대로**다(ADR-022 권한 매트릭스 — 자기 스키마 쓰기 가능 · 남의 스키마 쓰기 거부) ⑷ ★ **스키마 상태가 코드가 기대하는 expand 단계와 일치**한다(ADR-015 **S-1**) ⑸ **서명 컨텍스트 검증에 필요한 자료가 로드**됐다(CH-3 — ★ **값은 보지 않고 「검증이 성립하는가」만** 본다) |
| ★ **무엇을 보지 않나** | ⓐ ★ **전문 listener 활성 여부** — green은 **비활성으로 기동**하는 것이 정상이다(ADR-024 말미 정정). 여기에 넣으면 **정상 상태가 실패로 판정**된다 ⓑ **외부 기관 연결** — 대외 장애가 배포를 막으면 안 된다(그 축은 QS-06) ⓒ **배치 실행 여부** — 그것은 **CD-3**이 본다 ⓓ **관측 수집기** — OB-1 독립성(수집이 죽어도 자금 경로는 산다) |
| ★ **몇 번·얼마나** | **연속 성공 N회**(간격 T)를 통과로 본다. **전체 대기 상한 D** 안에 N회를 채우지 못하면 실패. **N·T·D = `[구현 검증]` — CDV-1** |
| ★ **판정** | ⑴ **연속 N회 성공 → 통과**(전환 진행) ⑵ **D 초과 → 실패 → green 종료 · blue 유지 · 배포 거절 기록 · 락 해제.** ★ 이것은 **롤백이 아니라 미전환**이다(트래픽이 한 번도 green에 가지 않았다 — §4의 롤백과 구분한다) ⑶ ★ **플랩**(성공·실패가 섞여 연속 N을 못 채우는 상태)은 **실패와 따로 기록**한다 — 통과했더라도 *"D 안에서 재시도로 통과했다"* 는 사실이 남아야 **CDV-1 재산정의 입력**이 된다(기록이 없으면 상한이 넉넉해서 통과한 것과 구별되지 않는다) |
| ⚠️ **그린 위장** | ★ *"프로세스가 떴다"* 만 보는 헬스체크는 **DB 권한 오설정·스키마 불일치를 통과시킨다** — E2 §3.2 그린 위장 점검의 **배포 판**이다. ⑵⑶⑷를 빼면 **배포는 성공하고 첫 요청에서 죽는다** |

### 2.2 CD-2 — 드레인 상한 (RL-2의 *"구 버전 드레인"* 과 RL-3의 *"수신 정지 창"* 은 다른 축이다)

★ **드레인은 하나가 아니라 둘이다.** 대상·초과 시 처리·불가역성이 서로 다르므로 상한도 따로 둔다.

| 축 | 대상 | 상한 | ★ 상한 초과 시 | 판정 주체 |
|---|---|---|---|---|
| ★ **⒜ 사람 채널 in-flight**(RL-2) | nginx 전환 **이후** blue에 남은 진행 중 HTTP 요청 | ★ **사람 채널 요청의 최대 지속시간보다 커야** 한다 — 그보다 작으면 **정상 요청을 자르는** 상한이다. 시간 예산 계층의 정본은 **ADR-013**이다(★ 전문 채널의 p99 3초 목표 **BR-01**은 ⒝ 축이지 이 행이 아니다). 값 = `[구현 검증]` — **CDV-2** | **남은 요청을 종료하고 blue를 내린다.** 쓰기 요청은 **트랜잭션 롤백**으로 원자성이 유지되고(E1~E5는 **한 커밋** — `constraints.md` §5 · ADR-022 기각 D), 조회는 실패한다. ⚠️ ★ **이 순간 RL-2의 *"실패 0"*(ADR-024 §6 검증 행)이 깨진다** — **사건으로 기록**하고 상한을 재산정한다 | **기계**(종료) · **사람**(상한 재산정) |
| ★ **⒝ 전문 수신 정지 창**(RL-3) | blue 전문 어댑터의 **신규 수신 거절 → 진행 중 전문 응답 완료** 까지 | 값 = `[구현 검증]` — **CDV-3**. ★ **창의 길이 = ⒝ 시작 ~ green listener 활성**(CD-4 ⑦~⑧)이며, 이 창이 곧 **기관 재전송에 의존하는 구간**이다 | ★ **기본 = 배포 중단·원복** — blue 어댑터의 **수신을 재개**하고 green을 폐기한다(사람 채널은 이미 전환됐다면 §4의 스왑백). ⚠️ ★ **강제 종료는 불가역 턱**이다: 진행 중 전문은 **자금 조작(E1)** 이고 멱등 판정·망취소 예약이 그 트랜잭션 안에 있다(CH-4) — **운영자 확인 + 기록 후에만** 실행한다(CF-8) | ★ **사람**(강제 종료 여부) · 기계(대기·측정) |

> ★ **왜 상한이 필요한가**: 상한이 없으면 배포가 무한 대기하고, 그동안 **배포 창 락(CD-3)이 점유**되어 **배치·커트오프가 밀린다**(BR-52는 순서 있는 절차다). 드레인 상한은 가용성 수치가 아니라 **락 점유 상한**이다.
>
> ⚠️ ★ **부분 드레인을 완료로 읽지 않는다**(CF-2) — *"응답 중인 전문이 0건"* 은 **수신 거절이 실제로 걸린 뒤**에만 의미가 있다. 거절이 안 걸린 상태의 0건은 **다음 순간 1건**이 된다.

### 2.3 CD-3 — 배포 창 락 (RL-4의 *"배포가 거절된다"* 를 무엇이 판정하나)

| 항목 | 절차 |
|---|---|
| **락이 막는 것** | ★ **배치·커트오프 실행 중의 배포**(RL-4). 대상 = **코어 배포**(배치·스케줄러가 코어 안에 있다)와 ★ **커트오프 절차에 참여하는 위성**(정산 `.158` — BR-52 ③ · 원장 `.164` — ④의 전달 대상) |
| ★ **"실행 중"의 판정 근거** | **배치 실행의 `runId`**(ADR-008 **B-5**)와 **파티션 할당 lease**(**B-3**)가 정본이다 — ★ **새 상태를 만들지 않고 이미 있는 것을 읽는다.** *"모든 파티션 완료 전에는 배치 완료가 아니다"*(**B-4**)가 곧 실행 중의 정의다 |
| ★ **조회 경로**(구조 판정) | ★ **코어가 소유하는 조작으로 노출**하고 agent는 **호출만** 한다 — agent에게 DB 계정을 주지 않는다. 이유: ADR-022 권한 매트릭스에 **배포 주체 계정이 없고**, 새로 만들면 *"소유권을 권한으로 강제한다"*(DT-2)는 결정 밖에 계정이 하나 생긴다. ⚠️ 이 조작의 계약(요청·응답·오류)은 **구현 시 `usecases/` 계약 규약을 따른다** — 이 문서가 계약을 정하지 않는다 |
| ★ **경합(TOCTOU)** | ⚠️ *"실행 중인지 조회하고 배포한다"* 는 **조회와 시작 사이**에 배치가 시작될 수 있다(CF-9). 그래서 **조회가 아니라 획득**이다 — **조건부 UPDATE로 원자적으로 잡는다**(B-1 파티션 할당과 같은 형태). ★ **락은 양방향**이다: 배포 락이 잡혀 있으면 **배치 스케줄러가 시작하지 않고 대기**한다(그 대기는 배치 지연으로 기록된다) |
| ★ **만료·해제**(CF-10) | 락은 **lease**를 갖는다(B-3과 같은 형태 — 만료되면 회수). **해제 주체 = 배포를 잡은 agent**이고, **agent가 죽으면 lease 만료로 회수**된다. ⚠️ ★ **만료 없는 락은 배포를 영구히 막고, 그 상태는 장애로 보이지 않는다.** lease 길이 = `[구현 검증]` — **CDV-4**(⒝ 드레인 상한 + 헬스체크 상한 D보다 커야 한다 — 정상 배포가 스스로 만료되면 안 된다) |
| **거절 시** | 배포 요청을 **거절하고 기록**한다(사람의 주의가 아니라 절차가 막는다 — RL-4). 재시도는 **사람이 다시 지시**한다(자동 재시도를 두지 않는다 — 배치가 끝나는 시각을 파이프라인이 모른다) |
| ⚠️ **stale 판정** | 배치 프로세스가 **비정상 종료**하면 `runId`가 열린 채 남을 수 있다 — 그 회수는 **B-3 lease 만료**가 소유한다(이 문서가 새로 정의하지 않는다). 회수 전까지 배포는 거절되며, ★ **그 상태가 2회 이상 반복되면 ADR-024 R3**(배포 창 락으로 배포가 막히는 일)의 관측 대상이다 |

### 2.4 CD-4 — deploy-agent 절차 (RL-7의 *"배포 실행 주체는 하나"* 의 실행 형태)

**⑴ 요청 (무엇이 담기나)** — 아티팩트 식별자(CD-5) · 대상 배포(코어 / 정산 / 원장 / 진입 설정) · 커밋 SHA · 요청자 신원 · 서명. ★ **값·비밀은 담기지 않는다**(CF-6).

**⑵ 검증** — RL-8 그대로: **HMAC 서명 + GitHub OIDC/서명 검증**. ★ 실패 = **적용하지 않음 + 거절 기록**. 여기에 예외를 두지 않는다(R5). ★ **아티팩트 무결성(체크섬)은 별도 축**이다 — 서명은 *"요청이 진짜인가"*, 체크섬은 *"산출물이 그대로인가"* 를 본다. **둘 다** 통과해야 적용한다. 키의 발급·보관·교체(병행 검증 창) = **IV-14**(이 문서는 절차를 갖지 않는다).

**⑶ 적용 순서 (코어)** — ★ 실패는 **가장 마지막에 성공한 지점으로 되돌린다**.

```
① 배포 창 락 획득 (CD-3 · 원자적)        실패 → 거절·기록 (배치 실행 중)
② 아티팩트 회수 + 체크섬 검증 (CD-5)      실패 → 거절·기록 · 락 해제
③ green 기동 (다른 포트 · ★ 전문 listener 비활성)
④ 헬스체크 (CD-1)                        실패 → green 종료 · blue 유지 · 락 해제  ← 미전환(롤백 아님)
─── 여기서부터 사람 채널 축과 전문 채널 축이 갈린다 (독립) ───
⑤ nginx upstream 전환 (RT-1 설정 정본 변경 · RL-2)   실패 → 설정 원복 · green 종료
⑥ blue 사람 채널 in-flight 드레인 (CD-2 ⒜)
⑦ blue 전문 어댑터 수신 거절 → 진행 중 전문 완료 (CD-2 ⒝)   ← ★ 수신 정지 창 시작
⑧ green 전문 listener 활성 토글                              ← ★ 정지 창 종료 (단일 수신 보장)
⑨ blue 종료
⑩ 락 해제 · 배포 이력 기록
```

> ★ **⑦~⑧이 창이다.** ⑧을 ④ 직후로 당기면 **blue와 green이 동시에 수신**해 이중 수신·포트 충돌이 난다(ADR-024 말미 정정이 막은 형태). ⑧을 ⑨ 뒤로 미루면 **창이 불필요하게 길어진다** — 창의 하한은 *"old의 drain 완료"* 이고 그것이 곧 ⑦의 종료다.

**⑷ 적용 순서 (위성 `.158` 정산 / `.164` 원장)** — ★ **사람 채널 진입이 없고**(CH-2 ⑶) 유입이 **릴레이 전달뿐**이라(ET-3) **블루-그린이 필요 없다**: ① 락 → ② 회수·검증 → ③ 정지 → ④ 교체 → ⑤ 기동 → ⑥ 헬스체크(CD-1) → ⑦ 락 해제·기록. 정지 구간의 inbox 호출은 **릴레이 재시도가 흡수**하고, ★ **수신측 커밋 전 종료는 `DELIVERED`가 아니므로 재전달**된다(**ET-2** — outbox에 쌓이는 것이지 유실이 아니다).

**⑸ 감사·이력 (구조 판정)** — ★ **배포 이력은 C8 감사(BR-57 행위자 기록)가 아니다.** 감사는 **업무 조작의 행위자**를 기록하는 의무이고(ADR-017), 배포는 업무 조작이 아니다. ⚠️ ADR-022 권한 매트릭스의 **C8 감사 계정은 `INSERT`만** 갖는 업무용 경로이며, 여기에 배포 이력을 섞으면 **감사 조회가 운영 기록으로 오염**된다(OB-7의 범주 혼동). ★ 배포 이력은 **agent가 소유하는 별도 기록**이고, 최소 항목 = **요청자 · 커밋 SHA · 아티팩트 식별자 · 대상 · 각 단계 결과 · 거절 사유 · 락 획득·해제 시각**이다.

**⑹ agent 자신의 배포 (CF-11)** — ★ **배포 주체가 자기를 교체하는 경로에는 되돌릴 주체가 없다.** 그래서 agent·파이프라인 정의·러너 설정의 변경은 ⒜ **사람 확인**을 거치고 ⒝ **교체 직후 스모크**(임의 배포 요청 1건이 정상 거절/수락되는지)를 즉시 돌리며 ⒞ **실패 시 직전 agent 산출물로 즉시 복원**한다. ⚠️ 이 복원은 **배포 경로 밖**이다 — 그 사실을 감추지 않는다.

**⑺ agent가 하지 않는 것** — ★ **DB 마이그레이션을 코드 배포와 같은 창에 묶지 않는다**(RL-6 · S-1) · **자동 롤백을 하지 않는다**(§4 판정 주체) · **DB에 직접 쓰지 않는다**(CD-3 조회 경로) · **사람이 서버에 들어가 손으로 바꾸는 경로를 대체 경로로 두지 않는다**(RL-7).

### 2.5 CD-5 — 아티팩트 보관·식별

| 항목 | 절차 |
|---|---|
| ★ **식별자** | **커밋 SHA + 대상 배포 + 빌드 일련**의 조합. ★ **불변** — 같은 식별자로 **재업로드를 거절**한다. ⚠️ 덮어쓰기를 허용하면 *"직전 아티팩트로 되돌렸다"* 가 **다른 산출물로 되돌린 것**이 된다(RL-5가 성립하지 않는다) |
| **무결성** | 체크섬을 함께 보관하고 **회수 시 검증**(CD-4 ⑵). 완료 표시는 **검증 후 원자적으로** 붙인다(부분 업로드 = 없는 것) |
| ★ **보관 하한**(구조 판정) | ⚠️ **개수 N만으로는 부족하다.** RL-5의 롤백이 성립하려면 ★ **진행 중인 expand-contract 창의 시작 버전까지** 남아 있어야 한다 — **S-2**가 *"④까지는 되돌릴 수 있다"* 로 정한 구간의 코드가 사라지면, 스키마는 되돌릴 수 있는데 **되돌릴 코드가 없다**. 그래서 보관 하한 = **max(기본 N, 열린 마이그레이션 창의 시작 이후 배포 수)**. 기본 N = `[구현 검증]` — **CDV-5** |
| ★ **보관 위치와 소유** | ⑴ **CI 아티팩트 저장소**(빌드 산출물의 원본 — 소유 = 파이프라인) ⑵ ★ **대상 호스트 로컬**(롤백이 실제로 쓰는 사본 — 소유 = deploy-agent). ★ **롤백은 ⑵만 쓴다** — *"재빌드하지 않는다"*(RL-5)의 의미는 ⑴에서 내려받는 것도 아니고 **이미 그 호스트에 있는 것으로 스왑**한다는 뜻이다 |
| **회수 실패 시** | 롤백이 **스왑 한 번**이 아니게 된다 → ★ **ADR-024 R4**(*"롤백이 스왑으로 안 된다"*)의 관측 대상. 이때 재빌드로 때우지 않고 **보관 정책부터 점검**한다 |
| ⚠️ **비대상** | 아티팩트에 **설정값·시크릿을 담지 않는다** — 설정의 소유는 §5이고, 담는 순간 *"환경별로 다른 아티팩트"* 가 되어 **롤백 대상이 환경마다 갈린다** |

## 4. 롤백 (배포물별 — 양식 ④)

> ★ **자동 롤백을 두지 않는다**(구조 판정). 헬스체크 실패는 **전환 전**이라 롤백이 아니라 **미전환**(CD-1)이고, 전환 후의 자동 되돌림은 **플랩**(전환 ↔ 되돌림 반복)을 만든다 — 그 사이 사람 채널은 두 버전을 오간다. **되돌림 판정 주체는 사람**이다.

| 배포물 | 되돌리는 방법 | 판정 주체 | 전제조건 | ★ 불가역 턱 |
|---|---|---|---|---|
| **코어 애플리케이션** | ★ **직전 아티팩트로 포트 스왑**(RL-5 — 재빌드 없음, 호스트 로컬 사본 CD-5). 순서는 **CD-4 ⑶의 역순**: 전문 수신 정지 창 → listener 토글 → nginx 원복 → 신 버전 드레인·종료 | **사람**(운영자) | ★ **스키마가 expand-contract ④ 이전**(**S-2**) · 직전 아티팩트가 **호스트에 있다**(CD-5) | 없음(가역) — 단 ★ **전문 정지 창이 다시 열린다**(RL-3의 대가를 **한 번 더** 낸다) |
| **위성(`.158`·`.164`)** | 직전 아티팩트로 **재기동**(블루-그린 불필요 — CD-4 ⑷) | **사람** | 같음 | 없음 — 정지 구간은 **릴레이 재시도가 흡수**(ET-2·ET-3) |
| ★ **진입 설정(nginx)** | 직전 설정으로 되돌리고 reload. ⚠️ ★ **nginx 설정이 라우팅 정본**이다(RT-1 · ADR-019 §4 *"변경 이력 관리 필요"*) — **손으로 고치지 않고 배포 경로(RL-7)로만** 바꾸며, 되돌림도 같은 경로다 | **사람** | 직전 설정이 **버전으로 보관**돼 있다 | 없음(가역) |
| ★ **DB 스키마** | **expand-contract 단계 되감기**(RL-6 · ADR-015) | **사람** | ★ **④(전환)까지만** 되돌릴 수 있다(**S-2**) | ★ **⑤ 축소(contract) 실행 = 불가역.** 실행 **직전에 사용자·운영자 확인**을 두고, 그 시점 이후 *"코드만 롤백"* 이 성립하지 않는다는 사실을 기록한다(CF-8 · **R4**) |
| ★ **백필된 데이터** | ★ **되돌아가지 않는다**(데이터 변경 = 불가역) | **사람** | — | ★ **백필 실행 자체가 턱**이다 — 실행 전 사용자 확인 · **record-level 검증**(count·sample·orphan)으로 완료를 판정한다(*"에러 없이 돌았다" ≠ 완료* — E2 §3.2 데이터 특칙) |
| ★ **배치·커트오프** | ★ **롤백이 아니라 재실행**이다 — 파티션 처리는 **멱등**(**B-2**)이고 `runId`로 구분한다(**B-5**) | **사람** | **모든 파티션 완료 전에는 완료가 아니다**(B-4) | ★ **BR-52의 순서는 되감지 않는다** — 드레인 미완이면 대사를 실행하지 않고 **M16을 적재**한다. *"되돌려서 다시"* 가 아니라 **그 영업일의 판정이 열린 채로 남는다** |
| ★ **파이프라인·agent 자신** | 직전 산출물로 **즉시 복원**(CD-4 ⑹ — 배포 경로 **밖**) | **사람** | 직전 산출물 보관 | ★ **복원 주체가 자기 자신이 아니다** — 실패 시 남는 것은 **수동 경로뿐**이며, 그 사실을 감추지 않는다 |

> ★ **rollback / forward-fix 판단은 머지 전 최소 안전선 ④**이기도 하다(E2 §3.1 — *"배포 절차(ADR-024) 소관"*). 이 표가 그 소관의 실행 형태다.

## 5. 구성 관리 — 무엇이 어디 소유인가 (값·경로 없음)

> ⚠️ ★ **이 절은 값·경로·파일명을 적지 않는다**(CF-6). 적는 것은 **소유·정본·변경 경로**뿐이다.

| 대상 | 소유(정본) | 변경이 지나는 경로 | ⚠️ 이 문서가 적지 않는 것 |
|---|---|---|---|
| **nginx 라우팅·TLS 종단·사람 채널 속도 제한** | **ADR-019 CH-1·CH-8** · **ADR-020 RT-1**(설정이 라우팅 정본) | 배포 경로(RL-7) — **손으로 고치지 않는다** | 구체 upstream·포트·속도 제한 값(포트 대역·자원 분리 = ADR-019 `[구현 검증]` · 속도 제한 값 = **IV-11**) |
| **애플리케이션 설정**(커넥션 풀·타임아웃 계층) | **ADR-013**(시간 예산) · **DT-3**(배포별·용도별 풀) | 아티팩트와 **분리**되어 배포된다(CD-5 비대상) | 풀 크기·타임아웃 수치 |
| **DB 계정·권한 형상** | ★ **ADR-022 권한 매트릭스**(코어·정산·원장·대사 배치·C8 감사 `INSERT`만·관측 읽기 전용) | 마이그레이션 경로(코드 배포와 **다른 창** — RL-6) | 계정명·접속 정보 — ★ **탐색하지 않는다** |
| **스키마 마이그레이션** | **ADR-015**(expand-contract 5단계 · S-1~S-13) | 배포와 **같은 창에 묶지 않는다**(RL-6) | DDL 본문·실행 시각 |
| **배치 스케줄·커트오프 시각** | **ADR-008** · **BR-52** | 정본 개정 → 설정 반영 | 시각·드레인 상한(BR-52 *"수치 — 미확정"*) |
| **관측 노출 설정**(구조화 로그 필드·Micrometer) | **ADR-023 OB-2** | 애플리케이션 설정과 같은 경로 | 수집기·대시보드 제품(OB-2 `[구현 검증]`) · 경보 임계(**IV-13**) |
| ★ **시크릿 ⑴ 내부 mTLS 인증서**(릴레이 → inbox) | ★ **IV-14 ⑴**(ADR-021 ET-3) | IV-14가 소유(발급·보관·교체·병행 검증 창) | ★ **위치·값·교체 주기 — 없음** |
| ★ **시크릿 ⑵ 서명 컨텍스트 키**(CH-3) | ★ **IV-14 ⑵**(ADR-019 CH-3 · 수명 상한 IV-1) | 〃 | 〃 |
| ★ **시크릿 ⑶ 배포 요청 인증키**(HMAC·OIDC) | ★ **IV-14 ⑶**(ADR-024 RL-8) | 〃 · **CI 측 보관은 파이프라인 플랫폼의 시크릿 저장소 소유** | 〃 · ★ **러너 로그에 노출되지 않아야 한다**(절차 규칙 — 기계 강제 수단은 `[구현 검증]` CDV-7) |

> ★ **설정이 두 곳에서 손으로 바뀌는 것이 이 절이 막는 유일한 것이다.** 소유가 적히지 않은 설정은 **배포된 것과 저장소의 것이 갈리고**, 그 갈림은 장애가 나기 전까지 보이지 않는다(상태 오인).

## 6. CI 도구 — C-08(요구 → 계약 → 도구) · 성질까지

> ★ **확정하지 않는다**(CF-5). 단 **구조의 귀결인 물음**(러너 형태 등)에는 **조건과 함께 답을 적는다.**

### 6.1 파이프라인이 요구하는 성질과 충족 판정 기준

| # | 요구하는 성질 | ★ 충족 판정 기준 | 근거 |
|---|---|---|---|
| ⑴ | **Kotlin/JVM 멀티모듈 빌드 실행** | 모듈 그래프대로 빌드·의존 방향 강제가 가능한가 | C-05 · **ADR-025 CL-1**(Gradle 멀티모듈 — ★ **인용이며 이 절의 확정이 아니다**) |
| ⑵ | ★ **머지 게이트를 매 빌드 실행**(단위·통합·계약) | ★ **실행 환경에서 컨테이너 런타임이 되나** — 통합 계층이 **실 MySQL 컨테이너**를 요구한다(**TL-2** · E2 §4.1 ②) | E2 §3.0 ⑴ · TL-2 |
| ⑶ | **아티팩트의 불변 식별·보관·회수** | 같은 식별자 **재업로드를 거절**하나 · 체크섬 검증이 되나 · **보관 하한**(CD-5)을 만족하나 | RL-5 · CD-5 |
| ⑷ | ★ **배포 요청의 신원 발급** | **OIDC 신원 + HMAC 서명**을 실을 수 있나 | **RL-8** · IV-14 ⑶ |
| ⑸ | ★ **VPN 밖에서 배포 API 도달** | 오라클 프록시 → `.9` → agent 경로로 **인터넷에서 호출 가능**한가 | **RL-7** |

### 6.2 ★ 구조 판정 — 셀프호스트 러너가 필요한가

| | |
|---|---|
| **판정** | ★ **v1에서는 필요 없다** |
| **근거** | ⑸ **배포 경로가 이미 인터넷 경유로 설계돼 있다** — RL-7이 *"CI가 **VPN 안의 배포 API를 호출**(오라클 프록시 → `.9` → agent)"* 로 고정했으므로, **러너가 사설망 안에 있어야 할 이유가 없다**. ⚠️ 반대로 러너를 사내에 두면 **RL-7이 좁힌 노출면(엔드포인트 하나)** 대신 **러너 호스트**가 새 노출면이 되고, 그것은 기각 **D**(*"CI가 서버에 직접 SSH"*)가 막은 형태로 되돌아가는 방향이다 |
| ⚠️ **가정** | ⑵ **호스팅 러너에서 컨테이너 런타임(TL-2)이 성립한다**는 것은 ★ **실확인 전 가정**이다 — `[구현 검증]` **CDV-8**(첫 통합 테스트 실행이 스파이크) |
| ★ **도입 조건**(관찰되면 다시 연다) | ⓐ **TL-2 R3** — *"CI 실행 환경에서 컨테이너 런타임을 쓸 수 없을 때"*(E3 §6.2 인용 — 그때는 격리된 실 MySQL을 다른 수단으로 제공한다) ⓑ **RL-7이 재판정**되어 배포 API를 인터넷에 노출하지 않기로 할 때 ⓒ **IV-15의 선언 상한을 호스팅 러너 성능이 넘는 것이 2회 실측**될 때(관측 대장 = `dev-conventions.md` §9) |

### 6.3 도입하지 않는 도구 — 도입 조건과 함께 (C-08)

| 후보 | v1에서 안 넣는 이유 | ★ 도입 조건 |
|---|---|---|
| **컨테이너 레지스트리 / 이미지 배포** | ★ **배포물이 컨테이너가 아니다** — RL-2가 *"컨테이너 오케스트레이터를 도입하지 않는다"* 로 포트 스왑을 택했다 | ★ **ADR-024 기각 B의 조건 인용** — *"배포 대상 호스트가 늘어 수작업 스왑이 안 될 때"*. ⚠️ **이 문서가 그 조건을 재판정하지 않는다**(D6과 같은 축) |
| **구성 관리·배포 자동화 도구**(Ansible 류) | 대상이 **3대**이고 배포 경로가 **하나**(RL-7)라 agent가 곧 그 역할이다. 도구 하나 = 운영 대상 하나(C-08) | 위와 같은 축 — **대상 호스트 증가** 또는 **배포 대상 종류가 늘어 agent 절차가 분기로 감당되지 않을 때** |
| **전용 아티팩트 저장소 제품** | CI 플랫폼의 보관으로 ⑶을 만족할 수 있다 | ★ **CD-5의 보관 하한**(열린 expand-contract 창)이 **플랫폼 보존 정책을 넘을 때** |
| **시크릿 관리 제품**(Vault 류) | 시크릿이 **3종**(IV-14)이고 절차 정본이 IV-14에 있다 | ★ **IV-14가 요구하는 병행 검증 창을 수동 교체로 무중단 달성하지 못한다고 판정**될 때 |
| **배포 승인 워크플로 제품** | **승인 주체가 아직 갈리지 않았고**(역할 분리 요구가 없다) P4가 이미 **사람 지시**다 | **배포 승인과 배포 실행이 다른 사람이어야 한다는 요구**를 수신할 때(역할 분리) |
