## 상태 머신이 없는 애그리게이트

| 애그리게이트 | 왜 없는가 |
|---|---|
| **전표** `JournalEntry` | **상태가 없다.** 기표되면 끝이며 수정·삭제 조작이 아예 없다(BR-10). 역분개는 전표의 상태 변경이 아니라 **새 전표 생성**이다 |
| **계좌** `Account` | 현재 설계에 `status` 필드가 없다 — **아래 열린 질문 참조** ⚠️ |

### ⚠️ 계좌에 상태가 없는 것이 맞는가 (ACS1)

계좌 애그리게이트에는 상태 대신 **두 개의 플래그와 금액**이 있다.

| 있는 것 | 없는 것 |
|---|---|
| `receivable` (미수) · `receivableBlockLifted` | 개설 / 정상 / 동결 / 해지 |

**지금 범위에서는 성립한다.** 제품 정의(S1~S12)에 계좌 해지·동결이 없고, 승인 차단은 `receivable`과 사전조건(PRE-2)이 처리한다.

**그러나 두 가지가 걸린다.**

1. **카드는 해지되는데 계좌는 안 된다.** 카드 해지(BR-35)는 정의돼 있는데 계좌를 닫는 경로가 없다 — 마지막 카드를 해지한 계좌는 어떤 상태인가.
2. **미수 차단이 상태가 아니라 플래그다.** `receivable > 0`이 사실상 "승인 차단" 상태인데, 상태로 표현되지 않아 **상태 머신으로 금지 전이를 열거할 수 없다.** BR-45의 차단 규칙이 사전조건에만 존재한다.

> **Phase 3에서 판단한다.** 지금 상태를 만들면 쓰이지 않는 전이가 생기고, 안 만들면 위 둘이 미해결로 남는다. **미해결로 남기는 쪽을 택했다** — 제품 범위가 계좌 해지를 요구하지 않기 때문이다.

## 읽는 법

### 기호 (전 문서 공통)

| 기호 | 뜻 |
|---|---|
| **O** | 허용 |
| **◎** | **멱등 무시** — 오류가 아니라 no-op. 최초 결과를 반환한다 |
| **X** | 금지 — 각 문서 §4에 등재 |
| **▲** | 다른 조작으로 **강등** |
| **-** | 도달 불가 — 이 상태에 그 메시지가 올 수 없다 |

### `X`와 `◎`를 가르는 기준

**외부가 같은 메시지를 두 번 보내는 것이 정상인가?**

| 정상이다 → `◎` | 정상이 아니다 → `X` |
|---|---|
| 중복 망취소 (BR-13) | 매입된 승인에 또 망취소 |
| 매입 배치 재개 시 처리된 레코드 | 완료된 배치에 레코드 추가 |
| 같은 payload의 멱등 재요청 | **다른 payload에 같은 키** |
| 중복 도착한 취소 예약 | 소비된 예약의 재소비 |

> **둘을 섞으면 어느 쪽으로 가도 사고가 난다.** 전부 `◎`로 하면 진짜 오류를 놓치고, 전부 `X`로 하면 정상 재시도가 실패한다.

## 이 묶음에서 반복되는 설계 판단 5가지

작성하면서 같은 판단이 여러 문서에 걸쳐 나왔다. **어느 하나가 흔들리면 나머지도 흔들린다.**

### ① 종료 상태를 함부로 만들지 않는다

| 애그리게이트 | 종료로 보이지만 아닌 것 | 이유 |
|---|---|---|
| 승인 | `EXPIRED` | 지연 매입(BR-19) 또는 취소(BR-49)가 온다 |
| 매입 배치 | `INTERRUPTED` | 재개하면 이어서 처리된다 |
| 정산 | `FAILED` | 재시도하면 된다 |
| 불일치 | `RESOLVED` | **재발견되면 미처리로 돌아온다** (BR-48) |

> **종료로 잘못 두면 정상 경로가 막힌다.** 만료를 종료로 두면 지연 매입이 전부 격리되고, 처리완료를 종료로 두면 잘못된 처리가 은폐된다.

### ② 조용한 실패를 상태로 막는다

| 위험 | 막는 장치 |
|---|---|
| 부분 실패를 완료로 위장 | 매입 배치 INV-3 — **건수 판정**(BF1) |
| 마감 없이 집계해 순액 누락 | 정산의 `close`/`calculate` 분리(SF3) |
| 처리 중 프로세스 사망 → 영구 갇힘 | 매입 배치·정산의 **진척 감시 전이** |

> 셋 다 **에러가 나지 않는다.** 그냥 숫자가 작게 나오거나 상태가 멈춰 있을 뿐이다.

### ③ 자금이 움직이는 조작은 기본이 금지다

승인의 `capture`는 8개 상태 중 **2개에서만** 허용된다. 나머지는 전부 격리 대상이며, 격리 사유가 곧 불일치 유형(M2·M4·M7·M8)이다.

> **매입 파일은 거절할 상대가 접속해 있지 않다.** 실시간 전문은 응답 코드로 거절할 수 있지만 파일은 그럴 수 없으므로, **격리가 유일한 자동 방어선**이다.

### ④ 중간 상태를 관리하기보다 없앤다

멱등 레코드에 `IN_FLIGHT`를 두지 않은 것이 대표 사례다. 중간 상태를 만들면 **고아 레코드와 회수 타임아웃**이 따라오고, 그 타임아웃이 곧 새로운 이중 처리 창구가 된다. 대신 **처리와 기록을 한 트랜잭션**에 넣어 중간을 지웠다.

### ⑤ 직교 플래그를 상태로 승격하지 않는다

보류(`frozen`)는 승인의 8개 상태 전부에 겹칠 수 있지만, 실제로 영향을 주는 것은 **`expire`와 `capture` 두 칸**뿐이다. 상태로 만들면 8종이 16종이 되고 얻는 것이 없다.

> 같은 이유로 카드의 **유효기간 경과**도 상태가 아니라 파생 판정이다.
