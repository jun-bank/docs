# 애그리게이트: 정산

- 작성일: 2026-08-03
- 상태: 검토대기
- 소속 컨텍스트: **C4 정산**
- 코드명: `Settlement`

---

## 1. 책임

> **영업일 하루치 자금 의무를 순액으로 확정한다.**

청산(매입)이 **건별로 고객 계좌**를 건드렸다면, 정산은 **영업일 단위로 매입사에 지급할 총액**을 정한다. 둘은 다른 단계다.

---

## 2. 구성

| 필드 | 타입 | 뜻 |
|---|---|---|
| `businessDate` | `BusinessDate` | 대상 영업일 — **유일 키** |
| `captureTotal` | `Money` | 그날 반영된 매입 합계 |
| `refundTotal` | `Money` | 그날 확정된 매입취소·환불 합계 |
| `netAmount` | `Money` | **순액** = `captureTotal − refundTotal` (BR-21) |
| `status` | `SettlementStatus` | 마감대기 / 산출중 / 완료 / 실패 |
| `retryCount` | `int` | 자동 재시도 횟수 (BR-37) |

---

## 3. 불변식

| # | 불변식 | 근거 | 위반 시 |
|---|---|---|---|
| **INV-1** | `businessDate`는 유일하다 | BR-21 | 같은 날 정산이 둘 |
| **INV-2** | `netAmount = captureTotal − refundTotal` | BR-21 | 순액이 근거 없이 존재 |
| **INV-3** | **`netAmount`는 음수일 수 있다** | BR-43 | — (이것은 정상이다) |
| **INV-4** | `status = 완료` 이면 `netAmount`가 바뀌지 않는다 | BR-21 | 확정 후 금액 변동 |

> ⚠️ **INV-3이 반직관적이다.** 환불이 그날 매입보다 많으면 순액이 음수가 되고, 이는 **매입사가 우리에게 지급**하는 방향이다. 정상이며 막으면 안 된다.

> **INV-4를 지키는 장치가 BR-47이다.** 완료된 영업일의 순액이 사후에 움직이지 않으려면, 역분개가 **정정 시점의 영업일**에 귀속되어야 한다 (`journal-entry.md` INV-6).

---

## 4. 조작

| 조작 | 코드명 | 사전조건 | 사후조건 | 이벤트 |
|---|---|---|---|---|
| **영업일 마감** | `close(businessDate)` | 마감 시각 도래 (BR-06) | 상태 = 산출중 | `BusinessDateClosed` |
| **순액 산출** | `calculate(captureTotal, refundTotal)` | 상태 = 산출중 | `netAmount` 확정, 상태 = 완료 | `SettlementCompleted` |
| **산출 실패** | `fail(reason)` | 상태 = 산출중 | 상태 = 실패, `retryCount` 증가 | `SettlementFailed` |
| **재시도** | `retry()` | `retryCount < 임계` (BR-37) | 상태 = 산출중 | `SettlementRetried` |
| **운영자 통지** | `escalate()` | `retryCount ≥ 임계` | 운영자 목록에 오름 | `SettlementEscalated` |

### 멱등한 재산출 (BR-37)

**정산은 집계이므로 재산출이 안전하다.** 매입 반영과 달리 상태를 누적하지 않고, 같은 영업일에 대해 몇 번을 계산해도 결과가 같다.

```
calculate() 를 N회 실행 → netAmount 동일   ← 멱등
```

> 이것이 **자동 재시도를 허용할 수 있는 근거**다. 매입(BR-23)이 파일·레코드 멱등을 따로 두어야 했던 것과 대비된다.

---

## 5. 경계 근거

| 질문 | 답 |
|---|---|
| **왜 이 범위인가** | 순액 산식(INV-2)이 `captureTotal`·`refundTotal`을 **함께** 요구한다. 영업일 단위 유일성(INV-1)도 이 안에서 성립 |
| **왜 더 크지 않은가** | 개별 매입을 넣으면 정산이 건별 데이터를 떠안는다. 정산은 **합계만** 안다 |
| **왜 더 작지 않은가** | `status`·`retryCount`를 빼면 "청산은 성공했는데 정산이 미결"인 상태를 표현할 수 없다 |
| **트랜잭션 단위인가** | 예 — 영업일 하나가 한 트랜잭션 |
