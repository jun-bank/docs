# 애그리게이트: 멱등 레코드

- 작성일: 2026-08-03
- 상태: 검토대기
- 소속 컨텍스트: **C3 결제**
- 코드명: `IdempotencyRecord`

> 이 문서를 다 읽으면 멱등 레코드가 **무엇을 소유하고**(요청 하나의 최초 결과와 그 지문) **무엇을 통제하는지**(같은 요청의 이중 처리 차단) 설명할 수 있어야 한다.

---

## 1. 책임

이 애그리게이트가 지는 책임은 한 문장이다.

> **같은 요청이 두 번 처리되지 않게 하고, 재요청에 최초 결과를 그대로 돌려준다.**

이것이 없으면 재시도가 **이중 승인**이 된다.\
결제 도메인에서 가장 값싼 방어선이다.

---

## 2. 구성

### 애그리게이트 루트

루트는 하나이며, 식별자가 이 애그리게이트의 핵심 설계 결정이다.

`IdempotencyRecord` — 식별자 ★ **`(발신 기관, correlationId, operation)`**(2026-08-06 개정 R-06 — 구 `(correlationId, operation)` 대체)

식별자가 세 축으로 늘어난 이유는 §3 INV-1 아래 산문에서 푼다.

### 상태 필드

레코드가 드는 필드는 아래와 같다.

| 필드 | 타입 | 뜻 |
|---|---|---|
| `institution` | `InstitutionCode` | 발신 기관 — 키의 스코프 축 (R-06) |
| `correlationId` | `CorrelationId` | 멱등 키 — 요청자(매입사)가 생성 (BR-17 ①) |
| `operation` | `OperationType` | 승인 / 망취소 / 취소 |
| `requestFingerprint` | `Fingerprint` | 요청 본문의 해시 (BR-02) |
| `result` | `StoredResult` | 최초 처리 결과 (응답 전문) |
| `recordedAt` · `expiresAt` | `Instant` | 보관 기간 (BR-02) |

세 필드가 표만으로는 설명이 부족하므로 아래에 풀어 둔다.

`institution`은 **ACL이 인증한 발신 기관**이다.\
전문 본문의 X-6 기관 코드와 일치하는지 검증하며, 불일치는 `ARG_MISMATCH`로 거절한다 (2026-08-06 R-06).

`correlationId`는 요청자(매입사)가 자기 채번 체계로 만든다 (BR-17 ①).\
매입사마다 체계가 다르므로 **그 자체로는 전역 유일이 아니다.**

`operation`은 승인·망취소·취소를 가른다.\
**키가 같아도 작업이 다르면 별개**로 취급한다.

멱등 범위는 **(발신 기관 + 작업 종류 + 키)** 셋을 합친 것이다.\
키만으로 판별하면 승인과 취소가 같은 키를 쓸 때 충돌하고, 기관을 빼면 다른 매입사의 우연히 같은 값이 남의 결과를 반환한다 (R-06).

멱등 레코드가 소유하는 것은 **요청 하나의 최초 결과**뿐이고, 처리 대상과 같은 트랜잭션으로 이중 처리를 막는다.\
대상 객체는 참조하지 않는다.

### 협력·소유 구조

아래 그림은 이 레코드가 누구와 협력하고 무엇을 소유하는지 한 장으로 보여준다.

```
                           소속: C3 결제
  ┌───────────────────── IdempotencyRecord ──────────────────────┐
  │ 소유: institution · correlationId                            │
  │       operation(승인/망취소/취소)                            │
  │       requestFingerprint · result · expiresAt                │
  │ 식별자: (institution, correlationId, operation) 유일 (INV-1) │
  └─┬───────────────┬────────────────────────────────────────────┘
    │ [C3 승인]     │ 키 채번
    │ 처리와 같은   │ 요청자
    │ 트랜잭션      │ (매입사)
    ▼ 멱등 보증     ▼ ◀ 생성
    (BR-02 ID-5)    BR-17 ①
    유니크 제약

  발행:
   IdempotencyConflict (지문 불일치 — assertSameRequest)

  참조 없음: 대상 애그리게이트 객체를 들지 않는다 (순서가 뒤바뀌지 않게).
```

## 3. 불변식

이 애그리게이트가 항상 지키는 명제는 셋이다.

| # | 불변식 | 근거 | 위반 시 |
|---|---|---|---|
| **INV-1** | `(발신 기관, correlationId, operation)`은 유일하다 | BR-02 | 같은 요청에 결과가 둘 |
| **INV-2** | `result`는 한 번 설정되면 바뀌지 않는다 | BR-02 | 재요청마다 다른 결과 반환 |
| **INV-3** | `requestFingerprint`가 다르면 같은 키로 저장할 수 없다 | BR-02 | 다른 거래의 결과를 반환 |

INV-1의 스코프가 왜 발신 기관까지 포함하는지 풀어 둔다.

상관 식별자는 매입사가 채번하므로 유일성의 스코프는 발신 기관이다 (2026-08-06 개정 R-06).\
전역 유일을 가정하면 다른 매입사의 우연히 같은 값이 남의 승인·취소 결과를 반환한다.\
이것이 INV-1을 세 축으로 정의한 이유다.

## 4. 조작

레코드가 제공하는 조작은 넷이다.

| 조작 | 코드명 | 사전조건 | 사후조건 | 이벤트 |
|---|---|---|---|---|
| **조회** | `find(institution, correlationId, operation)` | — | 있으면 `result` 반환 | — |
| **기록** | `record(institution, key, operation, fingerprint, result)` | INV-1·INV-3 | 레코드 생성 | — |
| **충돌 판정** | `assertSameRequest(institution, fingerprint)` | — | 다르면 충돌 오류 (BR-02) | `IdempotencyConflict` |
| **만료 정리** | `expire(now)` | `now ≥ expiresAt` | 삭제 대상 | — |

두 조작에서 기관 축이 어떻게 작동하는지 덧붙인다.

`find`는 **기관이 다르면 "없음"으로 답한다** — 같은 상관 식별자라도 남의 결과를 보지 않는다 (R-06).\
`assertSameRequest`에서 기관은 **판정 대상 레코드를 지목하는 축**이며, 키의 일부다.

### 처리 순서 (BR-02)

아래 흐름이 조회부터 기록까지의 정해진 순서다.

```
1) find(institution, key, operation)          ← 기관 = ACL이 인증한 발신 기관 (R-06)
   ├─ 있음 → assertSameRequest(institution, fingerprint)
   │          ├─ 같음 → 저장된 result 반환 (재처리 없음)
   │          └─ 다름 → 충돌 오류로 거절
   └─ 없음 → 처리 → record(...)   ← 처리와 같은 트랜잭션 (BR-02 ID-5)
```

이 순서에는 두 가지 강한 요구가 딸린다.

⚠️ **기록과 처리가 같은 트랜잭션이어야 한다.**\
나누면 처리는 됐는데 기록이 없는 순간이 생기고, 그때 재요청이 오면 이중 처리된다.

⚠️ **저장소에 유니크 제약이 필요하다** (BR-02 ID-4).\
동시 요청 둘이 동시에 `find` → 둘 다 없음 → 둘 다 처리하는 경합을 애플리케이션 로직만으로는 못 막는다.\
제약의 열은 `(발신 기관, correlationId, operation)` 세 개다 — 기관을 빼면 제약이 남의 키 공간까지 막는다 (R-06).

## 5. 경계 근거

이 애그리게이트를 왜 이 크기로 그었는지에 대한 답이다.

| 질문 | 답 |
|---|---|
| **왜 이 범위인가** | 유일성(INV-1)과 결과 불변(INV-2)이 한 레코드 안에서 성립해야 한다 |
| **왜 더 크지 않은가** | 승인과 합치면 승인이 생기기 전에 멱등 판정을 할 수 없다 — 순서가 뒤바뀐다 |
| **왜 더 작지 않은가** | `requestFingerprint`를 빼면 INV-3(다른 payload 거절)을 지킬 수 없다 |
| **트랜잭션 단위인가** | 아니오 — 처리 대상과 같은 트랜잭션이어야 한다 (의식적 예외) |
