## 2. 검산 스크립트가 강제하던 계약 → **코드에서 무엇이 대신하는가** ★

`tools/check_docs.py`의 검사 18종은 **문서를 떠나는 순간 무의미해진다.**
각각을 코드에서 무엇이 승계하는지 적는다. **이 표가 이 문서의 핵심이다.**

| # | 문서에서 강제하던 것 | 코드에서 대신하는 것 |
|---|---|---|
| ① | 조작 대장 == 각 문서 §5 조작 전집 | **공개 메서드 목록** — 리플렉션/아키텍처 테스트 |
| ② | 모든 변경 조작에 트랜잭션 경계 배정 | **트랜잭션 단위 함수** 하나에 조작이 모이는 구조 |
| ③·③-b | 경계 참여자·참여 조작 == 배정 | **통합 테스트** — 그 커밋에 참여한 애그리게이트를 검증 |
| ④ | 없는 경계 참조 | 컴파일 |
| ⑤ | 부수 효과 `〃` · 폐기 심볼 | 컴파일 (심볼이 없으면 안 컴파일된다) |
| ⑥·⑩·⑫·⑰ | 손으로 쓴 집계 수치 | **열거형(enum)** — 개수를 셀 필요가 없다 |
| ⑦·⑨ | 없는 규칙·불변식 참조 | 상수/타입 참조 → 컴파일 |
| ⑧·⑧-b | 교차 호출이 같은 트랜잭션인가 | **트랜잭션 경계 어노테이션 + 통합 테스트** |
| ⑪ | `별도`(Outbox)와 즉시 커밋의 구분 | **Outbox 테이블 경유 여부** — 타입으로 갈린다 |
| ⑬ | ACL 소유 규칙이 모든 경계를 덮는가 | **이벤트 → 전표 번역 함수의 전수 패턴 매칭** (합 타입) |
| ⑭ | 등식 우변 필드 ↔ 전이 사후조건 | **불변식 어서션 + 속성 기반 테스트** |
| ⑮ | ACL이 쓰는 필드가 payload에 있는가 | ★ **이벤트 레코드 타입** — 컴파일이 강제 |
| ⑯ | 배정 커버리지 하한 | (승계 없음 — 코드에서는 구조가 곧 배정이다) |
| ⑱ | ③ 예외의 등식·정본·탐지 실재 | **대사 배치 구현 + 그 배치의 테스트** |

> ★ **⑮가 가장 큰 전환이다.** 마크다운 표를 파싱해 필드 존재를 확인하던 것이
> **레코드 타입 하나**로 대체된다. R10에서 나온 치명 중 셋이 이 유형이었다.
>
> ⚠️ **`tools/`를 지우지 않는다.** Phase 3~5 동안 도메인 문서는 계속 정본이고,
> 코드가 그 계약을 승계할 때까지 검사가 살아 있어야 한다. **승계가 끝난 검사부터 뺀다.**

### 변이 검사도 함께 넘어간다

`tools/mutation_test.py`의 **20건**은 *"과거에 실제로 났던 결함"* 의 목록이다.
코드로 옮길 때 **그 20건이 테스트로 재현되는지**가 승계 완료의 기준이다.

## 3. 변천 문서의 반증 신호 — **되돌아오는 조건**

구현 중 아래가 관찰되면 **코드를 다듬지 말고 Phase 2로 올라온다.**

| DC | 신호 | 뜻 |
|---|---|---|
| **DC-001** | 합계 필드에서 치명이 또 나온다 | ②(분리) 판정이 부족했다 |
| **DC-002** F1 | **M15**가 매 영업일 불일치를 적재한다 | 정산 등식·정본 판정이 틀렸다 |
| **DC-002** F2 | `settledBusinessDate`만으로 부분집합을 못 고른다 | 키가 하나로 부족하다 |
| **DC-002** F3 | `SETTLED` 환불이 **당일** 순액에 반영돼야 한다 | *"별도 차감 거래"* 전제가 틀렸다 |
| **DC-003** F1 | 당일 매입 경로가 또 다른 분기를 요구한다 | 기준일 하나로 부족했다 |
| **DC-003** F2 | 카드와 계좌의 기준일이 달라야 한다 | 한도 버킷이 애그리게이트마다 달라야 한다 |
| **DC-003** F3 | 지난 버킷을 되돌려야 하는 요구가 나온다 | *"닫힌 버킷"* 전제가 틀렸다 |

## 4. ③ 의식적 예외 — **Phase 5의 검증 항목**

저장을 택한 합계 필드 넷. 각각 **등식·정본·경계·탐지**가 문서에 있고,
**구현되지 않으면 ③이 성립하지 않는다.**

| 필드 | 소유 | 등식 우변의 정본 | 탐지 |
|---|---|---|---|
| `Account.holdTotal` | C1 | 승인 `heldAmount` | **M9** |
| `Card.usage` | C2 | 승인 `limitContribution` (+ `limitBasisDate`) | **M10** |
| `Account.dailyUsage` | C1 | 승인 `limitContribution` (+ `limitBasisDate`) | **M11** |
| `Settlement.captureTotal`·`refundTotal` | C4 | 승인 `capturedAmount`·`refundedTotal` (+ `settledBusinessDate`) | **M15** |

> ★ **탐지 배치를 구현하지 않으면 이 넷은 그냥 "어긋날 수 있는 저장값"이다.**
> Phase 5 완료 기준에 **M9~M15 배치가 실제로 도는 것**을 넣는다.

## 5. Phase 3이 입력으로 받는 것

```
컨텍스트 맵 (C1~C6 · 관계 유형 R1~R7 · 데이터 소유권)  ──▶ 서비스 분할 ★ 가장 중요
애그리게이트 11종 + 트랜잭션 경계 E1~E5                ──▶ 트랜잭션 경계 설계
상태 머신 8종                                          ──▶ Phase 4 유스케이스 예외 흐름
용어사전 (코드명 포함)                                  ──▶ 전 Phase 어휘
불일치 유형 M1~M15 + 대사 규칙                          ──▶ 배치·운영 아키텍처
```

**넘어가지 않는 것**: 서비스 개수 · 배포 단위 · 기술 선택.
컨텍스트 ≠ 서비스이며, 그 판단은 Phase 3의 일이다.
