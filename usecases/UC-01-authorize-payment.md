# UC-01. 카드 결제를 승인받는다

- 작성일: 2026-08-05
- 상태: **확정** (파일럿 — 듀얼 1패스 반영, 2026-08-05)
- 액터: **매입사/VAN** (시스템 주체 — R1 전문 경로. 카드소지자의 결제를 **대리**한다: 목표의 주인은 소지자, 요청의 주체는 매입사)
- 권한 요건: 시스템 주체 — BR-54 예외 목록 밖(횡단 아님 — 단건 카드 지목). 운영자·고객 단계 무관
- 트랜잭션 경계: **E1** (승인 · 계좌 · 카드 · 멱등 · 취소예약 — 한 커밋)
- 관련 규칙: BR-01·02·04·05·13·15·17·22·36·44·45·54 (참조만 — F-24)

## 1. 목표 (한 문장)

매입사가 카드 결제 요청 전문에 대해 **p99 3초 안에 승인(승인번호) 또는 사유가 구분된 거절**을 받는다.

## 2. 사전 조건 / 사후 조건

- 사전: 전문이 R1 ACL 검증(포맷·상관 식별자 존재 — BR-17)을 통과했다.
- 사후(성공): 승인 `AUTHORIZED` · 홀딩 생성 · 카드+계좌 한도 사용액 증가 · 승인번호 발번 — **전부 한 커밋**(E1). 감사 outbox 행이 같은 커밋에 있다(AD-2).
- 사후(거절): **자금 상태 무변화.** 거절 사유 코드 응답 + 거절 사실이 감사에 남는다(BR-57 — 독립 커밋).
- 사후(실패 — 응답 유실 포함): 성립했으면 성립한 대로 남는다 — 매입사의 망취소(BR-13·22)가 정합을 회복한다(UC 범위 밖 경로, §4-G).

## 3. 주요 성공 시나리오

1. 전문 수신 → R1 ACL이 도메인 언어로 번역 + **경로 식별자 부여** [BR-54 시스템 주체]
2. 멱등 조회 `find(correlationId, 승인)` — 기존 결과 있으면 §4-A로 [BR-02]
3. 유효한 취소 예약 조회 — 있으면 §4-B로 [BR-22]
4. 카드 `assertUsable(now)` — 상태·유효기간·정지 [BR-15]
5. 가용잔액(BR-04) · 카드 1회/1일 한도(BR-05) · 계좌 한도(BR-44) · 미수 차단(BR-45) 판정
6. `authorize` — 홀딩 생성 · 두 층 한도 사용 · 승인번호 발번 · 멱등 기록 [승인 T1 · E1 같은 커밋]
7. 승인 응답 송신 (내부 deadline 2.5초 — 0.5초는 응답 예약분) [ADR-013 T-11]

## 5. 대체 시나리오

- 없음 — 승인의 목표 달성 경로는 하나다(§3). 부분 승인·할부 등은 범위 밖(제품 정의). *(U-6: "해당 없음" 근거)*

## 6. 인가·감사 ★

- 주체 판정: R1 ACL 진입 시 1회 (AU-3·AU-4) — 시스템 주체 + 경로 식별자. **소유자 필터는 없다**(시스템 주체 — AU-2). 카드→계좌 결합은 IDOR 표면이 아니다: 전문은 카드번호만 지목하고 계좌는 **시스템이 카드 참조로 유도**한다(Card.AccountId — CM1).
- L7: ★ **확정 (리뷰 반영)** — 매입사 전문 채널의 거절 사유 구분은 **BR-36·BR-15가 명시 요구하는 정본 특칙**이다("뭉뚱그리면 운영자가 원인을 알 수 없다"). BR-58의 L7은 사람 주체 채널(고객·운영자 API)을 대상으로 한다 — 해석 예외가 아니라 정본 간 역할 분담. 02 양식 C-2에 이 경계가 조항으로 올라갔다
- 감사: 성공 = E1 커밋 내 감사 outbox(AD-2 — 주체·경로·대상 카드/계좌·결과). 거절 = **독립 커밋**(AD-2 — 롤백에 쓸리지 않게). 조작 감사 유실은 outbox 멱등이, 거절 기록 유실은 M18이 지킨다.

## 7. 계약 (계약 블록 — 02 양식)

#### 전문 `AUTH-REQ` (API가 아니라 R1 ACL 인터페이스 — 블록 형식은 동일하게 적용)

| 항목 | 내용 |
|---|---|
| 주체 | 시스템 — 매입사 전문 경로 (ACL이 경로 식별자 부여) |
| 요청 | 카드번호 · 금액(BR-07) · 가맹점 ID · **상관 식별자**(매입사 생성 — BR-17. 유일성 범위는 Phase 4 계약 전수 시 확정 — 미확정 수치 표) |
| 응답(성공) | 승인번호 · 승인 금액 |
| 오류 표 ★ | `DECLINED_CARD`(정지/만료/해지 구분) · `DECLINED_UNREGISTERED`(BR-36) · `DECLINED_FUNDS` · `DECLINED_LIMIT` · `DECLINED_RECEIVABLE_BLOCK`(BR-45) · `IDEMPOTENCY_CONFLICT`(BR-02) · `TIMEOUT_RETRYABLE`(§4-H) — 전부 감사 기록 |
| 멱등 | `(상관 식별자, 승인)` — 최초 결과 반환 (BR-02) |
| 예산 | 외부 p99 3초 · 내부 deadline **2.5초** (T-11) |
| 감사 | 주체(경로) · 카드/계좌 · 결과 · 거절 사유 (AD-8) |

#### 이벤트 `HoldPlaced` (기존 — account.md §6이 정본. 여기선 계약 확인만)

| 항목 | 내용 |
|---|---|
| payload | accountId · 금액 — **행위자 없음(자금 이벤트 — AD-7)** ✓ 정본 일치 · ★ **축 필드 판정: 불요** — 같은 트랜잭션 내부 이벤트(구독자 없음)라 계약 발행 대상이 아니다. 발행되는 자금 이벤트의 축은 Phase 4 계약 전수에서(IS-5) |
| 구독 | — (같은 트랜잭션) |
| 멱등 키 | E1 커밋 원자성이 담보 (별도 수신자 없음) |
| 스키마 버전 | ★ **`schemaVersion: 1`** (K-3 — 2026-08-06 계약 전수. 의미 필드 추가 = 새 타입, S-6a) |
