# UC-08. 결제를 취소한다

- 작성일: 2026-08-05
- 상태: **초안 (계약 블록 후속)**
- 액터: **매입사/VAN** (시스템 주체 — R1 전문 경로. 가맹점·소지자의 취소 의사를 **대리**한다: 목표의 주인은 가맹점·소지자, 요청의 주체는 매입사 — UC-01과 같은 대리 구도)
- 권한 요건: 시스템 주체 — BR-54 예외 목록 밖(횡단 아님 — 단건 원거래 지목). 운영자 단계 무관 · **BR-56 5조작에 없으므로 승인 대상 아님**(과잉 배정도 결함이다)
- 트랜잭션 경계: **E1** (승인 · 계좌 · 카드 — 홀딩 해제·두 층 한도 복원이 한 커밋)
- 관련 규칙: BR-02·11·12·17·24·26·33·44·49·54·57 · 승인 T5·T6·T13·T14 · INV-1 (참조만 — F-24)

## 1. 목표 (한 문장)

매입사가 **아직 매입되지 않은 결제**를 전액 또는 부분 취소해, 점유된 고객 자금(홀딩)과 두 층 한도를 **같은 응답 안에서** 되돌린다.

## 2. 사전 조건 / 사후 조건

- 사전: 취소 전문이 R1 ACL 검증을 통과했다. 요청이 **BR-17의 식별 수단으로 원거래를 지목**한다(BR-12 — 지목 없는 취소는 성립하지 않는다).
- 사후(성공·전액): 승인 `VOIDED` · `heldAmount → 0` · `limitContribution → 0`(카드 `usage`·계좌 `dailyUsage` 동반 감액) · **원장 전표 없음**(매입 전이므로 확정 거래가 없다 — BR-26) — 전부 한 커밋(E1). 감사 outbox가 같은 커밋에 있다(AD-2).
- 사후(성공·부분): 상태는 그대로(`AUTHORIZED` 또는 `EXPIRED`) · `cancelledAmount` 증가 · 홀딩·두 층 한도는 **`holdingFunds = true`일 때만** 부분 복원(T6). 만료 건은 금액만 오른다(T14).
- 사후(거절): **자금 무변화.** 사유가 구분된 응답 + 거절 사실이 감사에 남는다(BR-57 — 독립 커밋).
- 사후(강등): 원거래가 이미 매입됐으면 이 유스케이스의 조작이 아니라 **환불**로 처리된다(BR-26) → UC-11. 취소가 실패한 것이 아니라 **유형이 갈린 것**이다.

## 3. 주요 성공 시나리오

1. 취소 전문 수신 → R1 ACL이 도메인 언어로 번역 + **경로 식별자 부여** [BR-33 실시간 전문 · BR-54]
2. 멱등 조회 `find(멱등키, 취소)` — 기존 결과 있으면 §4-A로 [BR-02 — 보상 요청도 멱등 대상]
3. 원거래 지목·조회 [BR-12 · BR-17]
4. **유형 분기** — 원거래의 매입 여부로 `void`인지 `refund`인지 결정 [BR-26 · 승인 SM §4.3. 분기는 애플리케이션 계층에서 일어난다]
5. 상한 판정 `취소액 ≤ 승인액 − 누적취소액` [BR-11 · INV-1]
6. `void` 실행 — 전액이면 T5(`AUTHORIZED`)·T13(`EXPIRED`), 부분이면 T6·T14
7. 복원 — **`holdingFunds`가 참일 때만** 홀딩 해제·`Card.restoreLimit`·`Account.restoreAccountLimit` 호출 [BR-24·44 · 이중 복원 차단]
8. [E1 커밋] 승인·계좌·카드 + 멱등 기록 + 감사 outbox → 응답 송신

## 5. 대체 시나리오

- **매입 후 취소 = 환불** — 목표(거래를 없던 것으로/줄인다)는 같으나 **접수 경로와 자금 흐름이 다르다**: 실시간 전문이 아니라 매입 파일의 취소 레코드로 들어오고, 홀딩 해제가 아니라 역분개·반환액 계산이 일어난다 (BR-33·26·43) → **UC-11**.
- 망취소(UC-09)는 대체 경로가 **아니다** — 취소 의사의 전달이 아니라 응답 유실 상황의 정합 회복이며, 목표가 다르므로 파일이 나뉜다(U-1).

## 6. 인가·감사 ★

- 주체 판정: R1 ACL 진입 시 1회(AU-3·AU-4) — 시스템 주체 + 경로 식별자. **소유자 필터는 없다**(AU-2 — 시스템 주체만 면제). 원거래는 상관 식별자·승인번호로 지목되고, 계좌·카드는 **시스템이 승인 참조로 유도**하므로 IDOR 표면이 아니다.
- L7: ✕ **대상 아님** — 02 양식 C-2의 채널 조항(사람 주체 API 한정)에 따른다. 매입사는 사유에 따라 조치가 갈린다(재시도 / 환불 전환 / 대사 조회)므로 §4의 거절 사유를 뭉뚱그리면 안 된다 — UC-01이 확정한 전문 채널 특칙(BR-36·15)과 같은 경계다.
- 감사: 성공 = E1 커밋 내 감사 outbox(AD-2 — 주체·경로·대상 승인/계좌/카드·취소액·전액 여부). 거절 = **독립 커밋**(AD-2 — 거절되면 조작 트랜잭션이 롤백되므로 같은 커밋 outbox는 사라진다). 항목은 AD-8.
