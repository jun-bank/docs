# UC-04. 카드 분실을 신고한다

- 작성일: 2026-08-05
- 상태: **리뷰 반영 — ★ 정본 판정 2건 대기** (UC4-1·UC4-2 — `plans/2026-08-05/phase4-pilot/log.md` 정본 보고 목록. 판정 후 확정)
- 액터: **고객(소지자) ∪ 운영자 담당자** — ★ 두 주체가 같은 전이를 공유하는 유일한 조작 (카드 SM C1)
- 권한 요건: 고객 = 자기 카드만 / 운영자 = **담당자** 단계 + 스코프 안 (BR-55 배정 표)
- 트랜잭션 경계: **없음 — 단일 애그리게이트 상태 전이** (카드 `suspend` — 자금 무이동)
- 관련 규칙: BR-15·35·54·55·57·58 · 카드 SM C1·C2 (참조만)

## 1. 목표 (한 문장)

분실·도난이 의심되는 카드를 **즉시 정지**해 신규 승인을 막는다 (기존 매입 반영은 계속된다 — BR-35).

## 2. 사전 조건 / 사후 조건

- 사전: 카드가 해지 상태가 아니다 (C1 조건).
- 사후(성공): `status = 정지` — **신규 승인만 차단**(BR-15). 홀딩·한도 사용액 불변. 매입·환불은 계속 반영(BR-35). 신고 주체가 감사에 남는다.
- 사후(거절): 상태 무변화 + 시도 기록.

## 3. 주요 성공 시나리오

1. 신고 접수 — 주체 판정 (고객 본인 카드 / 운영자 스코프 안) [BR-54·55]
2. `suspend(requester)` — `NORMAL → SUSPENDED` [카드 SM C1]
3. `CardSuspended` 발행 (운영자 전용 이벤트 아님·자금 이벤트 아님 — payload에 **신고 주체 유형** 포함 여부는 §9) 
4. 감사 기록 — **누가**(소지자인지 운영자인지) 정지시켰는가 [BR-57 · CDS1이 예고한 신호]

## 4. 예외 시나리오 ★

| # | 트리거 | 시스템 반응 → 종결 | 근거 |
|---|---|---|---|
| A | **타인 카드 지목** (고객) | `NOT_FOUND` — 부재와 동일 형태 + 시도 기록 | BR-58 (L7) |
| B | 운영자 스코프 밖 카드 | 〃 | BR-58 · IS-4 |
| C | 해지된 카드 | 거절 — `TERMINATED`에서 전이 없음 | 카드 SM C1 조건 |

| E | 정지 직후 승인 전문 도착 | 거절 (`DECLINED_CARD` — 정지 사유 구분) | BR-15 · UC-01 §4-C |

## 5. 대체 시나리오

- **운영자 대행 신고** — 고객이 전화로 신고하면 운영자(담당자)가 대행. 같은 목표·같은 전이, **주체 기록만 다르다**(감사가 구분한다 — CDS1: "운영자가 정지된 카드를 만지고 있다는 신호").

## 6. 인가·감사 ★

- 주체 판정: 진입 1회 — 고객(본인 카드) / 운영자(담당자·스코프). **두 주체의 스코프 판정이 다르다**: 고객 = 소유, 운영자 = 조직.
- L7: §4-A·B — 두 주체 모두 범위 밖 = 부재와 동일.
- 감사: 정지·해제 각각 **주체 유형·개인 식별** 포함(AD-8). 이것이 상태 머신 CDS1이 예고한 "감사 로그 설계"의 착지다.

## 7. 계약 (계약 블록)

#### `POST /me/cards/{cardId}/suspension` (고객) · `POST /ops/cards/{cardId}/suspension` (운영자)

| 항목 | 내용 |
|---|---|
| 주체 | 고객(본인) / 운영자 담당자(스코프 안) — 경로 분리로 주체 계약을 가른다 |
| 요청 | 사유 코드(분실/도난/기타 — [미정: 코드 체계]) |
| 응답(성공) | `SUSPENDED` + 효과 고지(신규 승인 차단 · **기존 매입은 계속** — BR-35를 사용자에게도 고지) |
| 오류 표 ★ | `NOT_FOUND`(부재·타인·스코프 밖 동일 — L7) · `TERMINATED`(§4-C) · `ALREADY_SUSPENDED`(§4-D — 판정 대기) |
| 멱등 | §4-D 판정에 따름 (열린 의문 UC4-1) |
| 예산 | 실시간 — 분실 신고는 지연이 곧 위험. 목표치 [미검증] |
| 감사 | 주체 유형·개인·카드·사유 (AD-8 — **경로: 성공 = 커밋 내 outbox · 거절 = 독립 커밋, AD-2 규칙**) |

#### `DELETE /me/cards/{cardId}/suspension` (고객) · `DELETE /ops/cards/{cardId}/suspension` (운영자) — 해제

| 항목 | 내용 |
|---|---|
| 주체 | 고객(본인) / 운영자 담당자(스코프 안) — 정지와 대칭 (SM C2 확정) |
| 요청 | 해제 사유 코드([미정 — 정지와 같은 체계]) |
| 응답(성공) | `NORMAL` — 신규 승인 재개 고지 |
| 오류 표 ★ | `NOT_FOUND`(부재·타인·스코프 밖 동일 — L7) · `NOT_SUSPENDED`(정지 상태 아님 — C2 조건) · `TERMINATED` |
| 멱등 | `NOT_SUSPENDED`가 멱등 경계 (상태 전이) |
| 예산 | 실시간 아님 (신고와 달리 지연이 위험이 아니다) |
| 감사 | 주체 유형·개인·카드·사유 (AD-8 — 경로: 성공 = 커밋 내 outbox · 거절 = 독립 커밋, AD-2 규칙) |

#### 이벤트 `CardSuspended` (기존 — card.md가 정본. 계약 확인 블록)

| 항목 | 내용 |
|---|---|
| payload | cardId — ★ **신고 주체 포함 여부 = 미판정** (UC4-2: 고객도 발생시키는 비자금 이벤트 — AD-7의 선이 이 중간 사례를 안 다룬다. **판정 전까지 payload에 행위자를 싣지 않는다** — 행위자는 감사가 나른다는 보수 기본값) |
| 구독 | — (구독자 정의는 card.md 정본 확인 필요 — Phase 4 계약 전수) |
| 멱등 키 | 상태 전이 자체가 멱등 경계 (§4-D 판정과 연동) |
| 스키마 버전 | Phase 4 계약 전수 시 S-9 일괄 — **[미정]** |

## 9. 열린 의문

| # | 의문 |
|---|---|
| UC4-1 | `SUSPENDED × suspend`(재신고)의 판정 — 카드 SM 금지 표에 이 칸이 없다. 멱등 무시(◎)가 자연스러우나 **정본(SM) 확정이 먼저**다 — 파일럿이 발견한 정본 공백, P4-5 보고 대상 |
| UC4-2 | `CardSuspended` payload에 신고 주체를 싣는가 — 운영자 전용 이벤트가 아니고(고객도 발생시킴) 자금 이벤트도 아니다. **AD-7의 선이 이 중간 사례를 판정하지 않는다** — P4-5 보고 대상 |
