# UC-15. 실패한 정산을 강제 재개한다

- 작성일: 2026-08-05
- 상태: **초안 (계약 블록 후속)** — §7은 요약 수준, 상세 블록은 계약 전수 패스로 이월
- 액터: **운영자 2인** — 요청 = 담당자(maker) · 승인 = 책임자(checker) (BR-55 · 같은 사람 불가)
- 권한 요건: **BR-56 ④** (책임자 승인 조작) · 스코프 = ★ **전사 스코프만** (BR-55 특칙 — 대상이 영업일이라 고객·조직 귀속 축이 없다)
- 트랜잭션 경계: ★ **E1~E5 아님 — 자금 무이동** (커밋은 둘: ① C8 `consume` + 재개 지시 이벤트 outbox INSERT가 같은 커밋 ② C4 수신측 `resumeByOperator` 커밋 — **R15**, 원자적으로 묶이지 않는다)
- 관련 규칙: BR-37·52·53·54·55·56·57·58 · Settlement INV-4 · 정산 SM S6·SF1·SF6·SF8·SF10 · ApprovalRequest INV-1~4·A1~A5 · ADR-014 O-13·O-16 · ADR-017 AD-2·5·6·8 (참조만 — F-24)

## 1. 목표 (한 문장)

자동 재시도가 소진되어 `FAILED`로 굳은 영업일의 정산을 **2인 승인을 거쳐 재개**해, 그날 순액이 확정될 수 있게 한다.

## 2. 사전 조건 / 사후 조건

- 사전: 대상 정산이 `FAILED` **이고** `retryCount ≥ 임계`다 (S6 사전조건 — 임계 미만이면 SF10). 요청자가 **전사 스코프** 담당자다. 임계값은 **[미확정]**(BR-37 — 미확정 수치 표).
- 사후(성공): 승인 `CONSUMED` + 지시 이벤트 발행(**같은 커밋** — R15) → C4 수신 → `retryCount = 0` · 상태 `CALCULATING` · **사유 기록 필수** · `SettlementResumedByOperator` 발행 · 감사 기록. ★ **이 UC의 목표는 재개까지다** — 그 뒤 `calculate` 성공 여부는 정산 배치 경로(운영 절차)에 속한다.
- 사후(거절/만료): 정산 상태 **무변화**. 요청이 `REJECTED`/`EXPIRED`(종료 — 재사용 불가), 사유가 감사에 남는다.
- 사후(승인은 됐으나 지시가 정체): 승인은 이미 `CONSUMED`인데 재개는 일어나지 않았다 — ★ **유실이 아니라 정체**(M17)다. **새 승인 없이 재투입**이 경로이고(UC-19), 이중 실행은 **지시 ID 멱등**이 막는다.
- 사후(수신측 거절 — 대상 상태가 바뀌었다): 정산 무변화 + 거절 사실이 감사에 남는다(§4-H).

## 3. 주요 성공 시나리오

1. 담당자 A가 `escalate`로 운영자 목록에 오른 미결 정산을 확인한다 [S5 · BR-53 ④ 통지]
2. A → C8 `request(정산 강제 재개, **지시 ID** · businessDate · 사유)` — ★ 지시 ID는 maker가 생성해 요청 인자에 싣는다(UC-16과 통일 — INV-3 검사 대상이 되고, EXPIRED 후 재요청은 새 ID) — `PENDING` [A1 · 감사 직접 append]
3. 책임자 B → C8 `approve(B)` — **B ≠ A** 검사 → `APPROVED` [A2 · INV-1]
4. ★ 승인 시점에 C8이 **`consume` + 재개 지시 이벤트 outbox INSERT를 같은 커밋**으로 수행 [A4 ④ 경로 · **R15** · AD-6] — **실행 엔드포인트는 없다**
5. 릴레이가 지시 이벤트를 C4로 전달 — 계좌ID 없는 이벤트라 **파티션 0** [ADR-014 O-6·O-8]
6. C4 수신 — **지시 ID 멱등** 검사 후 `resumeByOperator(operator, reason)` 호출. 기술 실행자는 수신 시스템이고 **업무 귀속 = maker**(지시 이벤트에 maker·checker가 실린다) [A4 · settlement.md §4]
7. `retryCount = 0` · `CALCULATING` · `SettlementResumedByOperator` 발행 · 감사 outbox (커밋 내 — AD-2) [S6]
8. 이후 정산 배치가 `calculate`로 `COMPLETED`에 도달한다 — **이 UC 밖**(운영 절차)

|---|---|---|---|

| B | **승인 없이 재개 시도** | ★ **경로 자체가 없다** — 운영자용 재개 엔드포인트가 존재하지 않고, C4는 **지시 이벤트로만** 트리거된다 | AF1 · R15 · settlement.md `resumeByOperator` 사전조건 |

| F | 지시 이벤트 **중복 전달**(at-least-once) | 수신측이 **지시 ID 멱등**으로 무연산 — ★ 두 번 재개되면 `retryCount`가 또 0으로 밀려 SF6 임계가 무의미해진다 | R15 · A4 · ADR-014 O-1 |

| I | 책임자 **거절** | `REJECTED` + **사유 필수** — 감사에 남는다 | A3 |

## 5. 대체 시나리오

- **임계 도달 전 자동 재시도**(S4 `retry`) — 목표(순액 확정)는 같고 주체가 시스템이다. 임계 안에서 성공하면 이 UC는 발생하지 않는다. 임계를 넘으면 자동 경로는 닫히고 **이 UC가 `FAILED`의 유일한 탈출구**가 된다(SF6 주석).

## 6. 인가·감사 ★

- 주체 판정 순서: ★ **① 단계(담당자/책임자) + 전사 스코프 — 둘 다 요청자의 자기 속성이라 대상 조회 전에 판정**(FORBIDDEN_LEVEL이 대상 존재 탐색 채널이 되지 않는다 — UC-02 선례) → **② 대상 정산 존재** → **③ 상태·`retryCount`**(SF8·SF10).
- L7: ★ **존재 비노출의 대상이 아니다** — 대상 식별자가 **영업일**이라 추측 가능한 공개 축이고 고객·조직 귀속이 없다(BR-58의 소유 축이 성립하지 않는다). 대신 **거절 시도는 기록**한다(독립 커밋 — AD-2). *(U-6 근거)*
- 감사 경로: 요청·승인·거절·만료 = **C8 직접 append**(AD-5) / C4 재개 실행 = **커밋 내 outbox**(AD-2 · R13) / 거절·실패 = **독립 커밋**(AD-2) / 목록 조회 = 비동기(AD-4).
- 항목: AD-8 — 주체·시각·대상(영업일)·스코프·종류·결과 + **사유·요청자·승인자**(BR-56 조작).

## 7. 계약 (요약 — 상세 블록은 **계약 전수 패스로 이월**)

> BR-56 공통 승인 계약(`POST /ops/approval-requests` · `/approve` · `/reject`)의 **정본은 UC-02 §7**이다 — 여기서는 참조만 하고 복사하지 않는다(U-7). 이 UC가 정의하는 것은 **조작별 인자**뿐이다.

| 인터페이스 | 주체 (유형·단계·스코프) | L7 대상 |
|---|---|---|
| `POST /ops/approval-requests` — 대상 조작 = **정산 강제 재개**, 인자 = `businessDate` · 사유 (정본 = UC-02 §7) | 운영자 **담당자** · **전사** | ✕ — 대상이 영업일(공개 축, §6) · 단계·스코프 거절은 기록 |
| `POST /ops/approval-requests/{id}/approve` · `/reject` (정본 = UC-02 §7) | 운영자 **책임자** · 전사 · `checker ≠ maker` | ✅ 요청 ID는 스코프 축을 탄다 |
| ★ **실행 엔드포인트 없음** (R15) — 승인 시 C8이 `consume` + 지시 이벤트를 같은 커밋으로 발행 | — | — |
| 지시 이벤트 **C8 → C4** (이름·payload **[미정]** — 계약 전수 시 명명 · 멱등 키 = **지시 ID**) | 시스템(릴레이 경로 — 파티션 0) | — |
| 이벤트 `SettlementResumedByOperator` (기존 — **정본 = settlement.md §4.1**) | 시스템(C4) · payload = `businessDate` · 운영자 · 사유 | — |

- 오류·응답·멱등·예산·감사 상세 칸, 스키마 버전(S-9) = **계약 전수 패스로 이월**.
