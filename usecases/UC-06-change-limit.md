# UC-06. 한도를 변경한다

- 작성일: 2026-08-05
- 상태: **검토대기 (계약 블록 완결)**
- 액터: **고객(소지자 — 자기 카드·계좌) ∪ 운영자 담당자** (BR-46이 주어를 확정 · BR-55 배정 표)
- 권한 요건: 고객 = 자기 소유만 / 운영자 = **담당자** 단계 + 스코프 안 (BR-55 · IS-4). 2인 승인 대상 아님 — **가역이고 기존 승인을 무효화하지 않는다**(BR-56 목록 밖 · 배정 표 "왜" 칸)
- 트랜잭션 경계: **없음 — 단일 애그리게이트 갱신** (카드 `changeLimit` = 상태 불변 · 계좌 한도 = 계좌 자기 필드. 자금 무이동)
- 관련 규칙: BR-05·07·15·44·46·54·55·57·58 · 카드 INV-3·PRE-1·2 · 계좌 INV-4·PRE-3 · 카드 RC-1 · 계좌 RC-3 · 카드 SM C4·CF5·CDS1 (참조만 — F-24)

## 1. 목표 (한 문장)

소지자 또는 운영자 담당자가 **카드 한도(1회·1일) 또는 계좌 1일 한도**를 바꿔, 이후 신규 승인이 새 한도로 판단되게 한다 (이미 성립한 승인은 건드리지 않는다 — BR-46).

## 2. 사전 조건 / 사후 조건

- 사전: 대상이 요청자 범위 안이다(고객 = 소유 / 운영자 = 스코프). 카드 층이면 카드가 **해지 상태가 아니다**(CF5).
- 사후(성공): `limit`(카드) 또는 `dailyLimit`(계좌)이 **교체**된다. ★ **`usage`·`dailyUsage`는 건드리지 않는다** — 그 값은 승인들의 `limitContribution` 합이므로 변경하면 등식(카드 RC-1 · 계좌 RC-3)이 깨진다. 기존 승인·홀딩·미수 전부 불변(BR-46). 변경 주체가 감사에 남는다.
- 사후(성공 — 한도를 낮춘 경우): **새 한도 < 현재 사용액 상태가 정상으로 존재할 수 있다.** 카드 INV-1·계좌 INV-4의 검증 위치가 `useLimit()`·`useAccountLimit()` **후**로 한정된 이유가 이 경로다 — 한도 검사가 불변식이 아니라 사전조건인 근거(카드 PRE-1·2 · 계좌 PRE-3).
- 사후(거절): 무변화 + 시도 기록(독립 커밋 — AD-2).

## 3. 주요 성공 시나리오 (카드 한도 층)

1. 변경 요청 접수 — 주체 판정 **진입 1회**: 고객(본인 카드) / 운영자(담당자 단계 · 스코프 안) [BR-54·55 · AU-3·4]
2. 새 한도 검증 — `1회 ≤ 1일` [카드 **INV-3** · C4 조건] · 금액 표현 [BR-07]
3. `changeLimit(newLimit, requester)` — **상태 불변**, `limit` 교체 [카드 SM **C4**]
4. ★ 기존 승인 **비무효화** 확인 — 소급 무효가 없다는 것이 이 조작의 계약이다 [BR-46]
5. `LimitChanged` 발행 (자금 이벤트 아님 — 원장으로 가지 않는다, card.md §6)
6. 감사 기록 — **누가**(소지자인지 운영자인지)·대상·이전/이후 값 (성공 = 커밋 내 outbox — AD-2·AD-8) [BR-57]

> **계좌 한도 층은 §5-①** — 대상과 조작만 다르고 1~6의 형태는 같다. 계좌 쪽 조작 = **`changeDailyLimit(newLimit, requester)`** (2026-08-06 UC6-1 확정 — account.md §5).

## 5. 대체 시나리오

- ① **계좌 1일 한도 변경** — 같은 목표(한도를 바꾼다), 다른 층. 계좌 한도는 그 계좌의 **모든 카드 사용액 합계**에 적용되므로 대상·엔드포인트가 갈린다(BR-44). 조작 = `changeDailyLimit(newLimit, requester)` · 이벤트 = `AccountDailyLimitChanged`(UC6-1 확정).
- ② **운영자 담당자 대행** — 고객이 요청하면 담당자가 대행한다. 같은 목표·같은 전이, **주체 기록만 다르다**(감사가 구분 — UC-04 §5와 같은 형태).

## 6. 인가·감사 ★

- 판정 순서: ① **단계**(운영자 — 자기 속성이라 대상 조회 없이 판정. 고객은 유형 판정) → ② **스코프·존재**(`NOT_FOUND` 동일 형태) → ③ **상태**(CF5). UC-02가 확정한 순서 — 대상을 본 뒤 단계를 판정하면 단계 오류가 존재 탐색 채널이 된다.
- 두 주체의 스코프 축이 다르다: 고객 = **소유**(자기 카드·계좌), 운영자 = **조직**(IS-4).
- L7: §4-A·B — 두 주체 모두 범위 밖 = 부재와 동일. 사람 주체 채널이라 C-2 채널 조항 적용 ✅.
- 감사: 성공 = 커밋 내 outbox(AD-2) / 거절 = 독립 커밋(AD-2). 항목 = AD-8 + **주체 유형 구분**(소지자/운영자) — CDS1이 요구한 신호가 여기서 착지한다(§4-D).
- 조회 아님 → AD-4 비적용. *(U-6 근거)*
