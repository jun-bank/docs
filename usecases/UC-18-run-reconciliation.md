# UC-18. 대사를 수동 실행한다

- 작성일: 2026-08-05
- 상태: **검토대기 (계약 블록 완결)**
- 액터: **운영자 담당자** — ★ 트리거는 사람이고 **실행 주체는 배치**다(BR-54 예외 ① — 시스템 주체의 횡단 접근 예외 목록에 대사 배치가 있다). U-2와의 관계는 §6
- 권한 요건: **담당자** 단계 (BR-55 배정 표 — *대사 수동 실행 = 담당자, 읽기 전용 배치 트리거*) · 스코프 = ★ **전사 스코프만**(BR-55 특칙 — 대상이 영업일이라 판정할 축이 없다) · **2인 승인 대상 아님**(BR-56 목록 5개 밖 — 과잉 배정도 결함이다)
- 트랜잭션 경계: **없음 — 트리거·읽기 전용**. 대사는 상류를 **읽기만** 한다(R9 순응자 · Discrepancy INV-1). 쓰기는 C6 자기 소유의 불일치 적재뿐이며 불일치 하나가 한 트랜잭션이다
- 관련 규칙: BR-09·30·41·42·48·52·53·54·55·57·58 · Discrepancy INV-1~4 · 불일치 SM D1·D4·D5·DF2·DF6 · ADR-008 B-1~B-5 · ADR-014 O-16 · ADR-011 (참조만 — F-24)

## 1. 목표 (한 문장)

운영자가 **정산 완료 트리거를 기다리지 않고** 특정 영업일의 대사를 즉시 실행해, 그날의 불일치를 최신 상태로 확인한다.

## 2. 사전 조건 / 사후 조건

- 사전: 대상 영업일이 지정된다. 요청자 = **전사 스코프 담당자**.
- 사전(★ 전제조건): **그 영업일 Outbox 드레인이 완료**돼 있어야 한다 — 코어 outbox·정산 outbox **두 축 모두** `DLQ_UNRESOLVED` = 0 (BR-52 ② · ADR-014 O-16). ★ **BR-42는 트리거이고 BR-52는 전제조건이다** — 트리거가 무엇이든 전제조건 미충족이면 실행하지 않는다.
- 사후(성공): 3자 비교(승인·홀딩 ↔ 매입 레코드 ↔ 원장)와 내부 등식 검증이 수행되고, 탐지분이 `recordOrTouch`로 적재·갱신된다. **상류는 변하지 않는다**(INV-1). 실행 사실과 **트리거한 운영자**가 감사에 남는다.
- 사후(성공) ⚠️ **재실행이 검증하는 것과 아닌 것이 갈린다** — M1~M8·M12·M14·M15는 그 영업일을 재현하지만 **M9·M10·M11은 코어 실시간 값이라 "현재 시점 검사"** 가 된다(BR-42).
- 사후(전제조건 미충족): 대사를 **실행하지 않고** **M16 적재**(+ 원인이 DLQ면 M17 동반). ★ *"대사를 못 했다"* 는 사실 자체가 기록된다.
- 사후(부분 실패): 파티션 하나라도 미완이면 **배치는 완료가 아니다**(ADR-008 B-4) — 부분 결과를 완료로 표시하지 않는다.

## 3. 주요 성공 시나리오

1. 담당자가 대상 영업일로 수동 실행을 요청한다 — 단계·전사 스코프 판정 [BR-55 · AU-4]
2. **전제조건 검사** — 그 영업일 드레인 완료 여부(두 축) [BR-52 ② · O-16]
3. 배치 기동 — `runId` 발급 · 파티션 N개 등록(원자적 할당) [ADR-008 B-1·B-5]
4. 파티션 병렬로 **외부 대사**(승인·홀딩 ↔ 매입 ↔ 원장 — BR-30)와 **내부 대사**(계좌별 마감 잔액 ↔ 보조부 · 합계 등식 — BR-41) 수행. ★ **읽기 전용**(R9)
5. 탐지분 `recordOrTouch(type, scope, subject, on, expected, actual)` — 신규는 `OPEN`(D1) / 기존은 갱신(D5) / **`RESOLVED`였으면 `OPEN` 복귀**(D4 · INV-4)
6. **전 파티션 완료 후** 부분합을 모아 **M15 마무리 단일 검증** [ADR-008 §4]
7. 완료 — 유형별 건수 요약 반환 · 감사 기록(트리거 운영자 + 실행 경로 식별자)

## 5. 대체 시나리오

- **정산 완료 자동 트리거**(BR-42 ①) — 목표는 같고 주체가 시스템이다. 그 자체는 **운영 절차**다(U-2).
- **정산 미결 임계 초과 강제 실행**(BR-42 ③) — 역시 시스템 경로. 임계 **[미확정]**.
- 즉 이 UC는 BR-42의 **세 트리거 중 사람이 주체인 하나**이며, 셋 다 BR-52의 전제조건을 똑같이 통과해야 한다.

## 6. 인가·감사 ★

- ★ **U-2와의 관계**: 대사 배치 자체는 유스케이스가 아니라 운영 절차다. **운영자가 트리거할 때만** 액터의 목표가 되며, 그때도 **실행 주체는 배치**다(BR-54 ③ 시스템 주체 · 예외 목록 ①). 그래서 감사에 **두 주체가 남는다** — 트리거한 운영자(개인 식별)와 실행 경로 식별자.
- 주체 판정 순서: **① 단계(담당자) + 전사 스코프 — 요청자 자기 속성** → **② 대상 영업일 유효성**(§4-I) → **③ 전제조건**(드레인 — §4-A).
- L7: ★ **존재 비노출의 대상이 아니다** — 대상이 영업일(공개 축)이고 전사 조작이라 소유 축이 성립하지 않는다. 거절 시도는 기록한다(독립 커밋 — AD-2). *(U-6 근거)* 다만 **불일치 목록·결과 조회**는 `subject`가 다형이라 축 판정이 유형별로 갈린다(IS-2 — 조회 계약은 UC-17·계약 전수 소관).
- 감사: 실행 트리거·실행 결과 = 커밋 내 outbox(AD-2 · R13) / 거절 = 독립 커밋 / 결과 열람 = 비동기(AD-4). 항목 = AD-8(주체·시각·대상 영업일·스코프·종류·결과). **2인 승인 조작이 아니므로 사유·승인자 칸은 비운다** — BR-56 목록 밖이다.

## 7. 계약 (계약 블록)

> ★ **2인 승인 계약이 아니다** — BR-56 목록 5개 밖이므로 `POST /ops/approval-requests` 경로를 타지 않고, **감사의 사유·승인자 칸도 비운다**(과잉 배정 금지 — §6).
> ★ **L7 ✕** — 대상이 **영업일**(공개 축)이고 전사 조작이라 소유 축이 성립하지 않는다. 그래서 `NOT_FOUND`는 **부재만** 뜻하고 *"스코프 밖과 동일"* 조항이 붙지 않는다(§6 · BR-55 특칙). **거절 시도는 기록한다**(독립 커밋 — AD-2).
> 오류 코드 3계층 = K-1 ⑴ 공통 4종 / ⑵ 불일치 SM 응답 열은 **적재 대상**(D1·D4·D5)이지 이 계약의 응답이 아니다 / ⑶ 신설 = `DRAIN_INCOMPLETE` 1종(아래 근거).

| 응답(성공) | `runId` · 접수 상태 · 등록된 **파티션 수**(B-1·B-5). ★ **접수까지의 응답이다** — 완료는 `GET`으로 본다(§4-D: 부분 결과를 완료로 표시하지 않는다) |
| 오류 표 ★ | **K-1 판정 순서** ① `FORBIDDEN_LEVEL` — 단계 미달 **및 전사 스코프 미보유**(§4-J. 둘 다 자기 속성이고 L7 축이 없어 코드를 가르지 않는다 — ★ 확정 **P-6**: `FORBIDDEN_SCOPE` 신설 없음, K-1 ⑶ · **UC-14·15·19와 통일**) → ② 대상 영업일 유효성: **비영업일·미래 영업일** = ★ **`INVALID_BUSINESS_DATE`**(확정 **D-UC18** — 코드 신설 수용 + **판정 위치 = ②**(대상 유효성). `Settlement`가 생성되지 않아 대사 기준일이 성립하지 않는다 — settlement SM §7. UC18-2 닫힘) → ③ ★ **전제조건 `DRAIN_INCOMPLETE`**(§4-A — 그 영업일 **두 축**(코어 outbox·정산 outbox) `DLQ_UNRESOLVED` ≠ 0. BR-52 ② · O-16. ★ **확정 D-UC18 — 신설 수용**, 코드 대장 등재). **응답에 미해결 건수·축을 담아** 운영자가 UC-19로 갈 수 있게 한다 · ★ **진행 중 동시 실행 = `ALREADY_RUNNING` + 진행 중 `runId` 반환**(확정 **D-UC18** — UC18-1 닫힘) |
| 멱등 | ★ **같은 영업일 재실행은 정상 동작이고 멱등이다**(§4-B — `lastDetectedOn`이 그 영업일이면 `detectionCount`가 오르지 않는다: BR-48 · INV-2. *발견 횟수 ≈ 미해결 영업일 수*가 유지된다). ★ 단 **진행 중 재요청은 `ALREADY_RUNNING` 명시 거절 + 진행 중 `runId`** 다(D-UC18 — K-1 CDS3: 무음으로 기존 `runId`를 돌려주면 *"내 요청으로 지금 돌고 있다"* 는 상태 오인이 된다. §4-E는 동시성이 **무해**함을 말할 뿐 응답을 정하지 않는다) |
| 예산 | 실시간 아님 — 접수 응답만 동기이고 **실행은 비동기 배치**다. 배치 처리 시간·lease는 ADR-008 소관(B-2·B-3) |
| 감사 | ★ **두 주체**(트리거한 **운영자 개인** + **실행 경로 식별자** — BR-54 ③ · §6) · 경로 = 성공 **커밋 내 outbox**(AD-2 · R13) / **거절·`DRAIN_INCOMPLETE` = 독립 커밋**(AD-2) · AD-8 = `sourceRef`(요청 식별자) · 시각 · 대상(`businessDate`) · ★ **스코프 = `전사`**(K-4 — 판정에 실제 쓰인 값) · 종류 · 결과. ★ **사유·승인자 칸은 비운다**(BR-56 밖) |

> ★ **`DRAIN_INCOMPLETE`는 "실패"가 아니라 "기록된 거절"이다.** 거절 응답과 **동시에 M16이 적재**되고, 원인이 DLQ면 **M17이 동반**된다(§4-A) — *"대사를 못 했다"* 는 사실 자체가 남는다. 드레인이 나중에 완료되면 그 영업일 대사가 **재실행되고 M16이 닫힌다**(§4-L · BR-42). 신설 코드 1종을 감수한 이유는 **공통 4종 어느 것도 이 상태를 표현하지 못하기 때문**이다(`INVALID_STATE`는 대상 영업일의 상태로 오독된다).

| 감사 | ★ **조회도 남는다**(BR-57) · 경로 = **비동기 적재**(AD-4) · 적재 실패는 조회를 막지 않고 **M18**로 적재된다(R16) · AD-8 항목 + 조회 범위(`runId`) · 스코프 = `전사`(K-4) |

#### (내부 트리거) 정산 완료 · 정산 미결 임계 초과 — ★ **엔드포인트가 아니다**

| 항목 | 내용 |
|---|---|
| 주체 | **시스템**(배치 경로 식별자 필수 — C-1 · BR-54 예외 ①·④) |
| 계약 | BR-42의 세 트리거 중 **사람이 주체인 하나**가 위 `POST`이고, 나머지 둘은 **운영 절차**다(U-2 · §5). ★ 셋 다 **BR-52 전제조건을 똑같이 통과**한다 — 트리거가 무엇이든 드레인 미완이면 M16이다 |
| 감사 | 실행 사실은 남되 주체가 **경로 식별자**다(개인 아님 — BR-54 ③). 임계 수치 **[미확정]**(§9 UC18-4 · BR-37 연동) |

#### 이벤트 `DiscrepancyRecorded` · `DiscrepancyRedetected` (기존 — **정본 = discrepancy.md §5.1**. 계약 확인 블록)

| 항목 | 내용 |
|---|---|
| payload | `Recorded` = `(type, scope, subject)` · `firstDetectedOn` · `expected` · `actual` / `Redetected` = `(type, scope, subject)` · `lastDetectedOn` · `detectionCount` · **처리완료→미처리 복귀 여부**(INV-4) ✓ 정본과 일치 — ★ **행위자 비포함**(AD-7 ② — 시스템 적재. 트리거한 운영자는 **이벤트가 아니라 감사 outbox**가 나른다) · 축 필드 = `subject`가 다형이라 **기존 파티션 축 유지**(K-4 · IS-2) · ★ **`ownerId` 비포함**(K-4 보정 확정 — **이벤트 payload 전면 비포함**. IS-1 6종은 저장 모델 대상) |
| 구독 | **운영**(정본). ★ BR-53 통지는 **적재와 별개 경로**이므로 이 구독이 통지를 대신하지 않는다 |
| 멱등 키 | 발신측이 이미 멱등이다 — `recordOrTouch`가 `(type, scope, subject)` 유일이고 **영업일당 1회만** `detectionCount`가 오른다(BR-48 · §4-B) |
| 스키마 버전 | **`schemaVersion: 1`**(K-3 — 전 이벤트 일괄) |

#### 불일치 **목록·상세 조회** — ★ **UC-17 소관**(여기서 정의하지 않는다 — U-7)

`GET /ops/discrepancies`(색인 등재분)는 UC-17이 정본이다. ★ 이 UC는 `subject`가 다형이라 **축 판정이 유형별로 갈린다**는 점만 남긴다(IS-2 — 영업일·계좌·outbox 레코드가 섞인다. UC17-1 대기).
