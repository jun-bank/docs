# UC-10. 매입 파일로 청산받는다

- 작성일: 2026-08-05
- 상태: **검토대기 (계약 블록 완결)**
- 액터: **매입사/VAN** (시스템 주체 — R1 파일 경로. 목표의 주인은 매입사(지급받을 채권의 확정)이고, 처리 주체는 우리 **매입 배치**다 — 배치가 액터의 목표를 대신 이루는 U-2 허용 형태)
- 권한 요건: 시스템 주체 — ★ **BR-54 시스템 예외 목록 ②(매입 배치·재처리 배치)**. 파일이 전 계좌를 횡단하므로 예외 목록이 유일한 근거다(목록 밖 경로는 같은 조회를 할 수 없다)
- 트랜잭션 경계: **E2** (승인 · 계좌 · 카드 · 매입 배치 · (부족 시) 미수 — **레코드 단위 커밋**)
- 관련 규칙: BR-14·16·17·18·19·20·23·24·27·32·33·35·48·50·51·52·54·57 · 배치 B1~B8 · 배치 INV-1~5 · 승인 T8·T9 · F10~F17 (참조만 — F-24)

## 1. 목표 (한 문장)

매입사가 영업일 매입 파일을 보내 **승인된 거래를 확정 채권으로 청산**받고, 반영할 수 없는 레코드는 조용히 버려지지 않고 **격리되어 운영자에게 드러난다**.

## 2. 사전 조건 / 사후 조건

- 사전: ★ **`(기관, fileId)`가 유일하다**(배치 INV-1 — `fileId`는 매입사가 채번하므로 유일성 스코프는 **발신 기관**이다. 2026-08-06 **R-06**. **기관 = ACL이 인증한 발신 기관** — 파일 헤더 X-6 기관 코드와 일치 검증) · `totalRecords`를 읽을 수 있다(못 읽으면 §4-P) · **귀속 영업일은 파일이 표기한 영업일**이며 처리 시각이 아니다(BR-14).
- 사후(레코드 성공): 승인 `CAPTURED` · 계좌 `balance` 감소 · **홀딩 전액 해제**(미매입 잔여분 포함 — BR-18) · **당일 매입이면** 미매입분만큼 두 층 한도 복원(BR-24 · `limitBasisDate` 일치 시에만 — DC-003) · 부족분은 `Receivable.incur(CAPTURE, …)`(BR-20) · `processedRecords`에 추가 · `AccountDailyMovement`(귀속 영업일) 갱신 — **전부 한 커밋**(E2).
- 사후(레코드 격리): **자금 무변화** + `isolatedRecords`에 추가 + **즉시 불일치 적재**(`Discrepancy.recordOrTouch` — 보류 격리는 제외).
- 사후(배치 완료): `|처리| + |격리| = totalRecords`가 성립할 때만 `COMPLETED`(INV-3 · B7).
- 사후(중단): `INTERRUPTED` — **진행분은 보존된다.** 재개 시 두 집합에 있는 레코드는 건너뛴다(B3 · BF8).
- 사후(건수 불일치): `complete` 거절 — **부분 실패를 완료로 위장하는 것이 최악의 실패 모드**다(BF1).

## 3. 주요 성공 시나리오

1. 파일 수신 → R1 ACL 번역 · `receive(기관, fileId, totalRecords, businessDate)` — ★ **기관 = ACL이 인증한 발신 기관**(파일 헤더 X-6 코드 일치 검증 — 불일치 = `ARG_MISMATCH`) [B1 · BR-23 INV-1 · **R-06**]
2. `start()` [B2]
3. 레코드마다 ★ **`(기관, fileId, recordId)`** 를 **두 집합 모두**에서 확인 — 있으면 건너뛴다 [BR-23 · BF8 · **R-06**]
4. 원승인 매칭 [BR-17] → **자동 반영 3조건** 판정: ① 매칭되는 선행 승인 ② 그 승인의 첫 매입 ③ `매입액 ≤ 승인액 − 누적취소액` [BR-16]
5. 반영 — `Authorization.capture`(T8 / 만료 건은 T9) · `Account.capture` · 부족분 `Receivable.incur` · 두 층 한도 복원 · `CaptureBatch.markProcessed` — **한 커밋**(E2) [BR-18·20·24]
6. 반영 불가 → `isolate(recordId, 사유)` + 불일치 적재 [B5 · BR-27·32·50·51]
7. `complete()` — **건수로 판정**한다 [B7 · INV-3]
8. (후속) 커트오프 절차 — 드레인 → 정산 산출 → 두 번째 드레인 → 대사 [BR-52]

## 5. 대체 시나리오

- **보류 해제 후 재처리 배치** — 같은 목표(그 레코드의 청산)를 **원 배치를 다시 열지 않고** 별도 배치가 이룬다. 원 ★ **`(기관, fileId, recordId)`** 를 승계하고, 반영과 `promoteIsolated`(격리 → 처리 원자 이동)가 **같은 커밋**(E2)이다. *격리에 있다 = 미반영 · 처리에 있다 = 반영됨*이 곧 멱등이므로 두 번 지시해도, 파일이 재전송돼도 걸러진다 (BR-50 · B8). ★ **승격 지시 자체는 2인 승인 대상**이므로 별도 유스케이스다 → **UC-14**(BR-56 ③).

## 6. 인가·감사 ★

- 주체 판정: 배치 진입 시 1회(AU-3·AU-4) — 시스템 주체 + **경로 식별자**(매입 배치). 소유자 필터는 적용하지 않으며(AU-2), 그 근거는 **BR-54 예외 목록 ②** 하나다. 재처리 배치도 같은 목록에 있다.
- L7: **해당 없음** — 파일 채널에는 **거절할 상대가 접속해 있지 않다**(응답이라는 개념이 없다). 그래서 금지는 응답 코드가 아니라 **격리 + 불일치 적재**로 표현된다(승인 SM §4 머리말). 격리 사유 구분은 **운영자 화면용**이며 매입사에게 응답으로 새지 않으므로 존재 노출 표면이 아니다.
- 감사: 레코드 반영 = **E2 커밋 내 outbox**(AD-2 — 주체 = 배치 경로 식별자, 대상 = 승인/계좌, 결과) · 격리 = 배치만 변경하고 불일치 적재는 유실되지 않는 경로(BR-40 · 조작 대장 `isolate` = `별도`) · 승격 = `promoteIsolated(recordId, operator)`로 **운영자 행위자**가 함께 남는다(UC-14) · 배치 실행 자체도 기록 대상이다(BR-57 적용 범위 = 시스템 주체 실행 포함).
