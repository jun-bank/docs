# UC-11. 취소 레코드로 환불을 확정한다

- 작성일: 2026-08-05
- 상태: **검토대기 (계약 블록 완결)**
- 액터: **매입사/VAN** (시스템 주체 — R1 파일 경로. 카드소지자에게 돌아갈 반환을 **대리** 요청한다: 목표의 주인은 소지자, 레코드의 주체는 매입사 — UC-01과 같은 대리 구도)
- 권한 요건: 시스템 주체 — **BR-54 예외 목록 ②**(매입 배치 — 취소 레코드도 같은 파일·같은 배치로 들어온다). 운영자 단계 무관 · BR-56 승인 대상 아님
- 트랜잭션 경계: **E4** (승인 + **그 승인의 미수** + 계좌 + 반환액이 회수하는 **다른 미수들** + **매입 배치** — 한 커밋)
- 관련 규칙: BR-11·12·14·17·21·23·26·33·34·43·47·51·54·57 · 승인 T10·T11·T16 · INV-7·8·9 · RC-1·RC-2 · 미수 V4·V5 (참조만 — F-24)

## 1. 목표 (한 문장)

매입사가 매입 파일의 **취소 레코드**로 이미 매입된 거래를 **얼마로 줄일지** 통보하면, 고객에게 돌려줄 **반환액과 소멸할 채권이 산식대로** 확정된다.

## 2. 사전 조건 / 사후 조건

- 사전: 원거래가 `CAPTURED` 또는 `SETTLED`다 · `(fileId, recordId)`가 아직 처리되지 않았다(BR-23) · ★ **레코드가 실은 값은 "반환액"이 아니라 거래 축소액이며 매입액 기준**이다(BR-43 ①).
- 사후(부분 — 잔여 채무 > 0): `refundedTotal` 증가 → 소멸 → 계좌 입금 → `returnedTotal` 증가. **상태는 `CAPTURED` 유지**(T11).
- 사후(전액 — 잔여 채무 0): 상태 `REFUNDED`(T10). 같은 3단계이며 **결과 상태만 다르다**.
- 사후(`SETTLED` 원거래): ★ **상태와 `settledBusinessDate`는 불변**이고 `refundedTotal`만 오른다(T16). 축소액은 그날 `refundTotal`에 집계되어 **다음 영업일 순액의 차감분**이 된다(BR-43 ② · BR-47).
- 사후(격리): 상한 초과면 **M5**로 격리되고 자금은 움직이지 않는다.
- 사후(강등): 원거래가 미매입이면 반환할 자금이 없으므로 **`void`로 강등**된다(§4.3) → UC-08의 조작.
- 사후(커밋 실패): E4 전체 롤백 — `markProcessed`도 같은 커밋이므로 **재처리가 안전**하다.
- 사후(공통): 한도는 **복원하지 않는다** — `limitContribution`은 매입 시 확정됐고 매입 완료 후 환불은 복원 대상이 아니다(BR-24 예외 ①).

## 3. 주요 성공 시나리오

1. 매입 파일에서 **취소 레코드**를 판별한다 [BR-33 — 매입·취소 레코드 혼재]
2. `(fileId, recordId)` 멱등 확인 [BR-23 · HS8]
3. 원거래 지목·상태 판정 [BR-12 · BR-17 — 매입·취소는 상관 식별자와 승인번호 모두로 식별]
4. 유형 분기 — 매입 후면 `refund`, 미매입이면 **`void` 강등** [BR-26 · 승인 SM §4.3]
5. 상한 판정 `refundedTotal + 요청액 ≤ capturedAmount` [**INV-7** — 좌변이 누계여야 나눠 환불로 우회되지 않는다]
6. 산식 계산 — `잔여 채무` · `회수액` · `반환액` · `소멸액` [BR-43 ① 산식이 정본]
7. ★ **미수 소멸 먼저** — `소멸액 > 0` **이고** 그 미수가 `OPEN`일 때만 `writeOff` [V4·V5 · VF9 · 자금 이동 없음]
8. 계좌 `refund(반환액, recoverable)` — **반환액이 0이어도 반드시 부른다**(차단 플래그 재평가) · 유입액은 FIFO로 **다른 미수**를 먼저 회수한다 [BR-34 · 예외 ② 자기 미수 제외]
9. `returnedTotal` 증가 + `CaptureBatch.markProcessed` — **전부 한 커밋**(E4) [RC-1·RC-2 검사]
10. `Refunded` 발행 → C5 원장이 역분개로 번역(귀속 영업일 = **파일 표기 영업일** — BR-14) · C4 정산이 `refundTotal`에 집계 [BR-21·43]

### 산식 — ★ **BR-43 ①이 유일 정본이다. 복사하지 않는다**(U-5 — 리뷰가 복사본을 제거했다). 이 UC가 고정하는 것은 §3의 **단계 순서**뿐이며, 네 값(잔여 채무·회수액·반환액·소멸액)의 산식은 BR-43 ①에서 읽는다.

## 5. 대체 시나리오

- **`SETTLED` 원거래의 차감 거래 경로** — 목표(고객에게 돌려준다)는 같지만 **원거래를 한 글자도 건드리지 않는** 유일한 경로다. 승인 상태·`settledBusinessDate`는 불변이고 자금은 **다음 영업일 순액의 차감**으로 흐른다(승인 SM §4.3 마지막 행 · BR-43 ②). ★ 이 경로 때문에 `SETTLED`가 종료 상태로 성립한다.
- 매입 **전** 취소(UC-08)는 대체 경로가 아니다 — 접수 채널(실시간 전문)과 자금 흐름(홀딩 해제 · 역분개 없음)이 다르며 BR-26이 유형 자체를 가른다.

## 6. 인가·감사 ★

- 주체 판정: 배치 진입 시 1회(AU-3·AU-4) — 시스템 주체 + **경로 식별자**(매입 배치). 소유자 필터 없음(AU-2), 근거는 **BR-54 예외 ②**. 반환 대상 계좌는 요청이 지목하지 않고 **원승인 참조로 유도**되므로 IDOR 표면이 아니다.
- L7: **해당 없음** — 파일 채널에는 응답 상대가 없다(§4의 금지는 응답 코드가 아니라 격리 + 불일치로 표현된다). 격리 사유(M5 등)는 운영자 화면용이며 매입사에게 새지 않는다.
- 감사: 성공 = **E4 커밋 내 outbox**(AD-2 — 주체 = 배치 경로, 대상 = 승인/계좌/미수, 축소액·소멸액·반환액) · 격리 = 배치 변경 + 불일치 적재(BR-40 · `별도` 경로) · **자금 이벤트 `Refunded`에는 행위자를 싣지 않는다**(AD-7 ② — 원장은 자금 언어다. 행위자는 감사 수집이 나른다).
