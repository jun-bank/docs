# UC-16. 원장 오기표를 역분개로 정정한다

- 작성일: 2026-08-05
- 상태: **검토대기 (계약 블록 완결)**
- 액터: **운영자 2인** — 요청 = 담당자(maker) · 승인 = 책임자(checker) (BR-55 · 같은 사람 불가)
- 권한 요건: **BR-56 ⑤** (책임자 승인 조작 — 감독규정 제28조 ② 직접 대상) · 스코프 = ★ **계좌 유도**(2026-08-06 UC16-1 확정 — 전표 `subjectId` 계좌들의 개설 조직 **전부**가 요청자 스코프 안이어야 허용, `subjectId` 없는 전표는 **전사만**. BR-55 유도 특칙)
- 트랜잭션 경계: ★ **E1~E5 아님 — 자금 무이동**(BR-40: 기표는 자금 이동과 별도 논리 단위). 커밋은 둘 — ① C8 `consume` + 정정 지시 이벤트 outbox INSERT가 같은 커밋 ② C5 `reverse` 커밋(전표 하나 = 한 트랜잭션) — **R15**
- 관련 규칙: BR-10·40·47·54·55·56·57·58 · JournalEntry INV-1·2·4·5·6·9 · ApprovalRequest INV-1~4·A1~A5 · Settlement INV-4 · ADR-014 O-13 · ADR-017 AD-2·5·6·8 (참조만 — F-24)

## 1. 목표 (한 문장)

잘못 기표된 전표를 **원전표를 건드리지 않고**, 2인 승인을 거쳐 **역분개 전표를 추가**해 정정한다.

## 2. 사전 조건 / 사후 조건

- 사전: 원전표가 존재한다(`reverse` 사전조건). 오기표라는 판단 근거가 있다 — 대개 대사 불일치(M6·M12·M14 등)나 조사 결과(UC-17). 요청자 = 전사 담당자.
- 사후(성공): **새 전표 1건** — `reversalOf` = 원전표 · 차대 반대·동액(INV-5) · `businessDate` = **정정 시점의 영업일**(INV-6 · BR-47) · `instructionId` 저장(INV-9) · `JournalReversed` 발행 · 승인 `CONSUMED` · 감사.
- 사후(성공) ★ **원전표는 그대로다**(INV-2 · BR-10) — 수정·삭제 조작이 애초에 없다.
- 사후(성공) ★ **마감된 영업일의 순액은 움직이지 않는다** — 역분개가 정정 시점 영업일에 잡히기 때문이다(BR-47 · Settlement INV-4).
- 사후(거절/만료): 원장 **무변화** · 요청 `REJECTED`/`EXPIRED` · 사유가 감사에 남는다.
- 사후(승인 후 지시 정체): 승인 `CONSUMED`인데 전표는 없다 — **정체(M17)**이며 재투입이 경로(UC-19). 재투입해도 **INV-9가 이중 기표를 막는다**.

## 3. 주요 성공 시나리오

1. 담당자 A가 오기표를 식별한다 — 근거 = 대사 불일치 또는 조사 결과 [BR-41 · UC-17]
2. A → C8 `request(원장 역분개, instructionId · 원전표 ID · 사유)` — `PENDING` [A1 · 감사 직접 append]
3. 책임자 B → `approve(B)` — **B ≠ A** → `APPROVED` [A2 · INV-1]
4. ★ 승인 시점에 C8이 **`consume` + 정정 지시 이벤트 outbox INSERT를 같은 커밋**으로 [A4 ⑤ 경로 · **R15** · AD-6] — **실행 엔드포인트는 없다**
5. 릴레이가 C5로 전달 — 계좌ID 없는 이벤트라 **파티션 0** [ADR-014 O-6·O-8]
6. C5 `reverse(instructionId, originalId, at, operator)` — **INV-9 유일 검사** → 새 전표 생성 [journal-entry §4]
7. `JournalReversed` 발행 · 감사 outbox(커밋 내 — AD-2). 업무 귀속 = maker, 기술 실행자 = C5 [A4]

## 5. 대체 시나리오

- 없음 — **원장 정정의 유일한 경로**다(BR-10: 정정은 역분개 전표 추가로만 · 수정·삭제 조작이 존재하지 않는다). 환불·입금 정정은 이 경로가 아니다: 환불은 자기 전표를 쓰고(journal-entry §4), 입금 정정은 계좌 조작(UC-02)이 원인 이벤트를 낸다. *(U-6 근거)*

## 6. 인가·감사 ★

- 주체 판정 순서: ★ **① 단계**(자기 속성 — 대상 조회 전) → **② 원전표 존재 + 유도 스코프**(전표 `subjectId` 계좌들의 개설 조직 — 부재·범위 밖 동일 응답 L7. `subjectId` 없는 전표 = 전사만) → **③ 상태·인자**(INV-3·5). (2026-08-06 UC16-1 확정 — 스코프가 대상 유도형이라 ②에서 존재와 함께 판정된다. 원칙(단계→스코프·존재→상태)은 유지)
- L7: 원전표 식별자에 대해 **부재와 범위 밖을 구별하지 않는다**(BR-58). ★ 전표의 `subjectId`(계좌 등 보조부 식별자)는 **소유 축과 동형이되 값이 다르다** — 고객은 계좌 경유로만 유도된다(IS-2). 거절 시도는 기록(독립 커밋 — AD-2).
- 감사 경로: 요청·승인·거절·만료 = **C8 직접 append**(AD-5) / C5 역분개 실행 = **커밋 내 outbox**(AD-2 · R13) / 거절·실패 = **독립 커밋** / 조회 = 비동기(AD-4).
- 항목: AD-8 — 주체·시각·대상(원전표)·스코프·종류·결과 + **사유·요청자·승인자**. ★ **원장과 감사는 별개 기록이다** — 원장은 자금을, 감사는 행위자를 남긴다(BR-57 · ADR-017 기각안 A).

## 7. 계약 (계약 블록)

> **공통 승인 계약의 정본 = UC-02 §7** (`POST /ops/approval-requests` · `/{id}/approve` · `/reject` · `GET /ops/approval-requests`) — 복사하지 않고 참조한다(U-7 · F-24). 이 UC가 정의하는 것은 **⑤의 조작별 인자**와 ★ **R15 지시 이벤트**다.
> ★ **실행 엔드포인트가 없다**(R15) — 승인 커밋이 `consume` + 지시 이벤트 outbox INSERT를 함께 수행하고(A4 ⑤), **실행 1회는 수신측 `instructionId` 유일(INV-9)** 이 보장한다.
> 오류 코드 3계층 = K-1 ⑴ 공통 4종 / ⑵ ★ **전표에는 상태 머신이 없다** — SM 응답 열이 존재하지 않으므로 거절 사유는 **불변식(INV-2·5·9)과 `reverse` 사전조건**에서 나온다 / ⑶ 고유 신설 **없음**.
> 운영자 화면 전환도는 공통이다 — **UC-02 §7 참조**. ★ ⑤에도 *"실행 확인"* 화면이 없다(실행 엔드포인트 부재).

#### `POST /ops/approval-requests` — ⑤ **원장 역분개** 요청 (조작별 인자·오류만 — 공통 계약은 UC-02 §7)

| 항목 | 내용 |
|---|---|
| 주체 | 운영자 **담당자** 이상 · ★ **계좌 유도 스코프**(UC16-1 확정 — 원전표 `subjectId` 계좌들의 **개설 조직 전부**가 요청자 스코프 안이어야 허용 · `subjectId` 없는 전표는 **전사만**) · 판정 = 진입 1회(AU-4) |
| 요청 | 대상 조작 = **원장 역분개**(BR-56 ⑤ 목록 안) · 인자 = ★ **`instructionId`**(maker 생성 — INV-3 검사 대상 · `EXPIRED` 후 재요청은 **새 ID**) · **원전표 ID** · **사유(필수)** — ★ **금액·부분 인자는 없다**(역분개는 전액 대칭 — INV-5 · §4-G) |
| 응답(성공) | 요청 ID · `PENDING` · 반향된 `instructionId` |
| 오류 표 ★ | **K-1 판정 순서** ① `FORBIDDEN_LEVEL`(단계 미달 — 자기 속성, 대상 조회 전) → ② ★ **`NOT_FOUND` — 원전표 부재·유도 스코프 밖이 동일 형태**(L7 · §4-N. **스코프가 대상 유도형이라 존재와 함께 ②에서 판정**된다 — UC16-1 확정. 원칙(단계→스코프·존재→상태)은 유지) → ③ `INVALID_OPERATION`(BR-56 목록 밖) · `ARG_MISMATCH`(`instructionId`·원전표 ID 형식·사유 누락) · `ALREADY_REQUESTED`([판정 필요] — UC-15 ㉢와 같은 계열) |
| 멱등 | 공통 계약 상속 = **비멱등**(UC-02 §7 · UC2-1). ★ 단 같은 원전표에 **두 지시가 승인되면 두 번째는 INV-9가 아니라 "다른 `instructionId`"** 이므로 **역분개가 둘 생긴다** — 중복 정정의 방어선은 멱등이 아니라 **승인 절차와 §4-M(역분개의 역분개)** 뿐이다([판정 필요]) |
| 예산 | 실시간 아님 (관리 조작) |
| 감사 | **C8 자기 조작 = 직접 append**(AD-5) · AD-8 = `sourceRef`(요청 식별자 — AD-3) · 주체 · 시각 · 대상(**원전표 ID**) · ★ **스코프 = 판정에 실제 쓰인 값**(K-4 — 유도된 **개설 조직 값들** · `subjectId` 없으면 `전사`) · 종류 · 결과 + **사유·요청자**. **거절 = 독립 커밋**(AD-2 · §4-N) |

> **[판정 필요 — 유도 스코프를 판정하려면 C8이 원전표를 읽어야 하는데, 그 경로가 정본에 없다.]**
> UC16-1이 스코프 판정 위치를 ②(대상 조회 후)로 확정했으므로 **요청·승인 시점에 C5의 전표 `subjectId`를 읽어야 한다**. 그런데 context-map에 **C8 → C5 조회 관계가 없다**(R15는 C8→C5 **지시 발행** 단방향이고, R14는 C1·C3 한정).
> 선택지 ⓐ **C8 → C5 읽기 전용 조회 동기 호출**(관계 신설 — ADR-010의 금지선은 *"코어가 위성에 동기 의존"* 이라 방향이 반대지만, 조회 가용성이 승인 경로에 묶인다) ⓑ **C8이 전표 스코프 요약을 구독·복제**(`JournalPosted`가 필요 — 발행 여부 확인 필요) ⓒ **스코프 판정을 수신측(C5)으로 미룬다** — 그러면 요청 단계 L7이 무너지고(§4-N의 *"부재와 동일 응답"* 을 줄 수 없다) 승인 후 거절만 남는다.
> **권고 = ⓐ** — UC16-1이 ②를 못박았고, ⓒ는 확정 판정을 되돌린다. **정본 판정 대상**(context-map 관계 신설).

#### `POST /ops/approval-requests/{id}/approve` · `/reject` — ⑤ 승인/거절 (정본 = UC-02 §7 · 이 UC의 차이만)

| 항목 | 내용 |
|---|---|
| 주체 | 운영자 **책임자** · ★ **유도 스코프 동일 적용**(BR-55 특칙 — 승인 단계에서 스코프 통제가 끊기지 않는다: maker·checker가 **같은 유도 스코프 조건**을 통과해야 한다) · `checker ≠ maker`(INV-1 · AF7) |
| 요청 | (`reject`는 **사유 필수** — A3) |
| 응답(성공) | 요청 ID · 전이 상태 · ★ **승인 응답의 의미는 "지시가 발행됐다"까지다**(R15) — **기표 완료가 아니다**(정체는 M17 — §2 사후) |

| 감사 | **AD-5 직접 append** + 승인자·사유 · 스코프 = 유도된 조직 값(K-4). ★ 지시 발행 사실도 같은 커밋(대상 = `instructionId`) |

#### 이벤트 (신설) `JournalReversalInstructed` — ★ **R15 지시 이벤트** · 승인 커밋과 **같은 커밋**에 outbox INSERT

> **[판정 필요 — 이벤트 이름을 무엇으로 확정하는가?]** 선택지 ① **`JournalReversalInstructed`**(★ 권고 — K-2 과거분사 사실명 · 결과 이벤트 `JournalReversed`(C5 발행)와 **지시/결과가 이름으로 갈린다** · UC-15의 `SettlementResumeInstructed`와 **같은 규칙**) ② `JournalReversalApproved`(승인 사실 강조 — `ApprovalRequest`의 `APPROVED` 상태와 겹친다). 아래 블록은 ①을 가정한다(UC16-3).

| 항목 | 내용 |
|---|---|
| payload | ★ **`instructionId`**(멱등 키 → 수신측 **INV-9**가 소유 구현) · `approvalRequestId` · **`originalEntryId`**(조작 인자 — INV-3으로 요청 인자와 동일 보장) · **`maker`**(요청자 = ★ 업무 귀속 · `reverse(…, operator)` 인자의 원천) · **`checker`** · **`reason`** · `approvedAt`(승인 커밋 시각 — [판정 필요] 아래) — ★ **행위자 포함**(AD-6 · AD-7: C8 지시 이벤트는 **원장 번역 입력이 아니다** — 번역 입력의 정의 = 원장 ACL이 전표로 번역하는 자금 이벤트(R5~R7)뿐). 축 필드 = ★ **없다**(계좌ID 없는 이벤트 → **파티션 0** — O-6·O-8 · K-4) |
| 구독 | **C5 원장** 단독. 감사는 구독이 아니다(AD-2 · C8 자기 조작은 AD-5) |
| 멱등 키 | ★ **`instructionId`** — 수신측 `reverse(instructionId, originalId, at, operator)`가 **전표에 저장하고 유일 제약**으로 소유한다(**INV-9** — *"지시 ID 멱등"* 의 소유 구현). at-least-once 전제 · **DLQ 재투입도 같은 키로 막힌다**(§4-D·L · UC-19 §4-G) |
| 스키마 버전 | ★ **`schemaVersion: 1`**(K-3). 의미 필드 추가는 **새 이벤트 타입**(S-6a) |

> **[판정 필요 — `reverse(…, at, …)`의 `at`(정정 시점)은 어디서 오는가?]**
> INV-6/BR-47은 역분개의 `businessDate`를 **정정 시점의 영업일**로 못박는데, `at`의 **원천이 정해져 있지 않다**. 지시가 DLQ에 갇혀 이틀 뒤 재투입되면(§4-L) 두 값이 갈린다.
> 선택지 ⓐ **payload의 `approvedAt`** — 승인 시점 귀속. 지연되면 **이미 마감된 영업일에 기표**하게 되어 INV-6이 막으려던 *"마감된 순액이 움직인다"* 를 되살린다 ⓑ **C5의 기표 커밋 시점**(★ 권고 — *"정정 시점"* 을 문자 그대로 읽으면 실제로 정정 전표를 만드는 순간이고, 마감 순액 불변(Settlement INV-4)이 어떤 지연에서도 성립한다. `approvedAt`은 **추적용으로만** 싣는다).
> **정본 판정 대상**(journal-entry.md INV-6 · `reverse` 인자 의미).

#### (수신) C5 `reverse` — 지시 이벤트 처리 계약 ★ **엔드포인트가 아니다**

| 항목 | 내용 |
|---|---|
| 주체 | **시스템**(릴레이 경로 — 경로 식별자 필수 · C-1). ★ 업무 귀속 = payload의 `maker`(A4 ⑤ · `reverse`의 `operator` 인자) |
| 요청 | 지시 이벤트 payload 그대로. **다른 호출 표면이 없다**(§4-B) |
| 응답(성공) | ★ **응답 상대가 없다**(비동기). 사후 = **새 전표 1건**(`reversalOf` = 원전표 · 차대 반대·동액 INV-5 · `businessDate` = 정정 시점 INV-6 · **`instructionId` 저장** INV-9) · **원전표 불변**(INV-2) · `JournalReversed` 발행 · 감사 outbox — **한 커밋**(전표 하나 = 한 트랜잭션) |
| 오류 표 ★ | ★ 아래는 응답 코드가 아니라 **거절 사유 값(감사·M 적재)** 또는 **재시도 대상**이다. **원전표 부재** = `reverse` 사전조건 미충족 → ★ **처리 실패 → 재시도 → M17**(§4-C·O. 원전표(계좌 파티션)와 지시(파티션 0)는 **다른 파티션이라 순서 보장이 없다** — 정상인지 결함인지 §9 UC16-4) · **중복 `instructionId`는 오류가 아니라 무연산**(INV-9 · §4-D) · **부분 금액·차대 불균형은 발생하지 않는다**(원전표에서 대칭 도출 — §4-G·I) |
| 멱등 | ★ **`instructionId` 유일(INV-9) — 무연산**. 막지 못하면 되돌리는 수단이 **또 다른 역분개(=또 2인 승인)** 뿐이다(§4-D) |
| 예산 | 실시간 아님 — 비동기 릴레이. 재시도·DLQ 상한은 **ADR-014 소관**(O-10·O-11) |
| 감사 | 성공 = **커밋 내 outbox**(AD-2 · R13) — 주체 = 경로 식별자 **+ 업무 귀속 `maker`** · 대상 = 원전표 ID·새 전표 ID · **스코프 = 유도된 조직 값**(K-4) · 결과 + 사유·요청자·승인자. **거절·실패 = 독립 커밋**(AD-2). ★ **원장과 감사는 별개 기록**이다(§6 — 원장은 자금을, 감사는 행위자를) |

#### (조회) 전표·역분개 이력 — ★ **이 패스에서 신설하지 않는다**

|---|---|
