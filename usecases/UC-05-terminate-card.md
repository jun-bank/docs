# UC-05. 카드를 해지한다

- 작성일: 2026-08-05
- 상태: **검토대기 (계약 블록 완결)**
- 액터: **고객(소지자) 단독** — ★ 운영자 경로가 **없는** 유일한 카드 조작 (카드 SM C3 · BR-55 배정 표 각주)
- 권한 요건: 고객 = **자기 카드만** (BR-54·58). 운영자 단계 배정 없음 — 2인 승인 대상도 아니다(BR-56 5조작 밖)
- 트랜잭션 경계: **없음 — 단일 애그리게이트 상태 전이** (카드 `terminate` — 자금 무이동)
- 관련 규칙: BR-15·20·24·35·36·54·57·58 · 카드 INV-4 · 카드 SM C3·C6·CF1·CF2·CF3·CF5·CF8 (참조만 — F-24)

## 1. 목표 (한 문장)

소지자가 더 쓰지 않을 카드를 **되돌릴 수 없게 닫아** 신규 승인을 영구히 막는다 (이미 성립한 승인의 매입은 계속 반영된다 — BR-35).

## 2. 사전 조건 / 사후 조건

- 사전: 요청자가 그 카드의 **소지자 본인**이다. 카드 상태가 `NORMAL` 또는 `SUSPENDED`다 (C3 — 정지 중에도 해지할 수 있다).
- 사후(성공): `status = 해지` — **종료 상태이며 되돌리는 전이가 없다**(INV-4 · CF1). 한도 사용액·홀딩·미수는 **불변**. 기존 승인의 매입·환불·망취소·만료 경로는 계속 작동한다(BR-35 · C6). 해지 사실이 감사에 남는다.
- 사후(거절): 상태 무변화 + 시도 기록(독립 커밋 — AD-2).
- 사후(이미 해지된 카드): **무변화 + 명시 거절 `ALREADY_TERMINATED`**(CF8 — 2026-08-06 CDS3 통일로 ◎→X. UC5-3 닫힘).

## 3. 주요 성공 시나리오

1. 해지 요청 접수 — 주체 판정 **진입 1회**: 고객 유형 · 자기 소유 카드 [BR-54·58 · AU-3·AU-4]
2. 상태 확인 — `NORMAL`·`SUSPENDED`만 진입 가능 (`TERMINATED`면 §4-B) [카드 SM C3]
3. `terminate(requester)` — `NORMAL·SUSPENDED → TERMINATED` [C3 · INV-4]
4. `CardTerminated` 발행 — 자금 이벤트가 아니므로 **원장으로 가지 않는다**(card.md §6). payload **행위자 비포함**(AD-7 ② 확장 — UC5-1 확정)
5. 감사 기록 — 주체·카드·시각·결과 (성공 = 상태 전이 커밋 내 outbox, AD-2·AD-8) [BR-57]
6. 응답에 효과 고지 — 신규 승인 **영구** 차단 · ★ **기존 매입은 계속 반영**(BR-35을 사용자에게도 고지 — UC-04 §7 선례)

## 5. 대체 시나리오

- **없음 — 운영자 대행 경로가 존재하지 않는다.** BR-55 배정 표 각주가 *"카드 해지는 이 표에 없다 — 진입 조건이 소지자 요청(카드 SM C3)"* 로 **명시 배제**했고, 카드 SM C3의 조건 칸도 소지자 단독이다. 대행이 필요해지면 그때 배정한다. *(U-6 근거 — "해당 없음"이 아니라 정본의 명시 배제다)*

## 6. 인가·감사 ★

- 주체 판정 순서: ① **주체 유형**(고객 — 자기 속성이라 대상 조회 전에 판정) → ② **소유·존재**(`NOT_FOUND` 동일 형태) → ③ **상태**(CF 계열). UC-02가 확정한 순서를 고객 채널에 적용한 것 — 고객에는 단계 축이 없으므로 ①이 유형 판정이 된다.
- L7: §4-A. **사람 주체 채널이므로 C-2 채널 조항 적용 ✅** (매입사 전문의 사유 구분 특칙 — §4-E — 과 채널이 다르다).
- 감사: 성공 = 상태 전이 커밋 내 outbox(AD-2) / 거절 = 독립 커밋(AD-2). 항목 = AD-8(주체·시각·대상·스코프·종류·결과).
  ★ **불가역 조작이라 감사가 유일한 사후 설명 수단이다** — INV-4로 되돌리는 전이가 없으므로 "정정 이력"이 남을 자리 자체가 없다.
- 조회 아님 → AD-4(비동기 조회 기록)는 적용 대상이 아니다. *(U-6 근거)*

## 7. 계약 (계약 블록)

#### `POST /me/cards/{cardId}/termination` — 카드 해지 (불가역 · 소지자 단독)

| 항목 | 내용 |
|---|---|
| 주체 | **고객(본인)** — `/me` 채널 · 스코프 = **소유**(자기 카드). ★ 운영자 경로 **없음**(§5 — BR-55 배정 표 각주 · 카드 SM C3). 판정 시점 = 진입 1회 (AU-4) |
| 요청 | 대상 = 경로 `cardId` 하나. 정본이 요구하는 인자는 **주체뿐**(`terminate(requester)` — card.md §5). 사유 코드 체계는 **[미확정]**(정본 요구 없음 — UC-04 §7 정지와 같은 표기) |
| 응답(성공) | `TERMINATED` + 효과 고지 — 신규 승인 **영구** 차단 · ★ **기존 승인의 매입은 계속 반영**(BR-35 · §3-6). 반환 범위 = 본인 카드 1건(BR-58 — 소유 스코프 안). ★ 미결 홀딩·미수가 남은 경우의 고지 요건은 **UC5-2 미판정**(§9) |
| 오류 표 ★ | **K-1 판정 순서**: ① **유형**(고객 채널 — 자기 속성이라 대상 조회 전) `FORBIDDEN_LEVEL` → ② **소유·존재** `NOT_FOUND`(부재·타인 카드 **동일 형태** — L7 · §4-A) → ③ **상태** `ALREADY_TERMINATED`(카드 SM **CF8** 응답 열 — 재해지 명시 거절, K-1 CDS3 일반화 · §4-B). ★ CF1·CF2·CF3·CF5(§4-C~F)는 **해지된 카드에 오는 다른 조작**의 거절이라 이 엔드포인트의 오류가 아니다. 거절도 전부 감사에 남는다(BR-57) |
| 멱등 | **비멱등 — 상태 전이가 멱등 경계**. 재요청은 명시 거절 `ALREADY_TERMINATED`(CF8 · K-1: 사람 채널의 상태 전이 재요청은 무음 무시 금지 — 무시하면 요청자가 상태를 오인한다). UC-04 정지·해제(CF9·CF10)와 같은 판정 |
| 예산 | **실시간 아님** — E1 계열이 아니다(단일 애그리게이트 상태 전이 · 자금 무이동). 목표치 **[미확정]** |
| 감사 | AD-2 경로: 성공 = **상태 전이 커밋 내 outbox** / 거절 = **독립 커밋**. 항목 = AD-8(`sourceRef` · 주체(개인) · 시각 · 대상 `cardId` · **스코프 = 판정에 실제 쓰인 값 = 소유(`ownerId`)** — K-4 · 종류 · 결과). 조회 아님 → AD-4 비적용. ★ **불가역이라 감사가 유일한 사후 설명 수단이다**(§6 — 되돌리는 전이가 없어 "정정 이력"이 남을 자리가 없다) |

#### 이벤트 `CardTerminated` (기존 — card.md §6이 정본. 계약 블록)

| 항목 | 내용 |
|---|---|
| payload | `cardId` · 시각 (card.md §6) — ★ **행위자 비포함 확정**(AD-7 ② 확장 · UC5-1: 소지자 전용 비자금 이벤트. 행위자는 감사가 나른다). 축 = **기존 payload 축 유지** · ★ **`ownerId` 없음**(2026-08-06 U-2 확정 — **A-2·3**: K-4 보정으로 **이벤트 payload에는 `ownerId`를 얹지 않는다(전면 비포함)**. IS-1 선반영 6종은 **저장 모델** 대상이었다 — 초안의 "최초 설계" 해석은 사용자 보정으로 철회됐다. 구독자도 없다 — 아래 칸) |
| 구독 | **없음** — 자금 이벤트가 아니라 원장으로 가지 않는다(card.md §6). 감사 수집은 구독이 아니라 **감사 전용 outbox 레코드**다(AD-2) |
| 멱등 키 | 상태 전이가 경계 — 재해지가 명시 거절(CF8)이라 재발행 자체가 없다. 수신측 없음(구독자가 생기면 `sourceEventId` 유일 — AD-3 형태) |
| 스키마 버전 | **`schemaVersion: 1`** (K-3). 의미 필드 추가는 버전 올림이 아니라 **새 이벤트 타입**이다(S-6a) |
