# UC-14. 보류 격리 매입을 재처리로 승격한다

- 작성일: 2026-08-05
- 상태: **초안 (계약 블록 후속)**
- 액터: **운영자 2인** — 요청·실행 = 담당자(maker) · 승인 = 책임자(checker) (BR-55, 같은 사람 불가)
- 권한 요건: **BR-56 ③** (책임자 승인 조작) · ★ **전사 스코프 운영자만** — 매입 배치는 고객·조직 귀속이 없어 지점 스코프로는 판정할 축이 없다 (BR-55 스코프 특칙)
- 트랜잭션 경계: **E2** (승인 · 계좌 · 카드 · 매입 배치 · 부족 시 미수 — 한 커밋). ★ **C8 `consume`이 같은 트랜잭션에 참여**(R14 · AD-2의 E 표 밖 의식적 예외)
- 관련 규칙: BR-16·20·23·24·28·50·54·55·56·57·58 · `CaptureBatch` INV-2·3·4·**5** · 매입 배치 SM **B8**·**BF11**·**BF12** · 승인 SM F17 (참조만 — F-24)

## 1. 목표 (한 문장)

보류 때문에 반영되지 않고 격리돼 있던 매입 레코드를, 보류가 풀린 뒤 **2인 승인을 거쳐** 실제로 반영하고 격리 → 처리로 승격시킨다.

## 2. 사전 조건 / 사후 조건

- 사전: 대상 레코드가 원 배치의 **격리 목록에 있다**(= 아직 미반영). 원 배치는 **`COMPLETED`** 다(**BF11** — 진행 중 배치에서는 격리가 아직 확정이 아니다).
- 사전: 격리 **사유 = 보류(BR-50)** 다(**INV-5**) · 원승인의 **보류가 해제됐다**(UC-12 §3-5).
- 사전: ★ **승인된 요청이 존재한다**(BR-56 ③ — C8 동기 확인, R14).
- 사후(성공): 계좌에서 **즉시 출금** · 승인 `CAPTURED` · 카드·계좌 한도 복원(기준일 조건 — BR-24) · 부족분은 **새 미수**(BR-20) · 레코드가 **격리 → 처리로 원자 이동**(B8, 사유는 이력 보존) · 승인 요청 `CONSUMED` · 감사 outbox — **전부 한 커밋(E2)**. 원 배치는 `COMPLETED` 그대로이며 **다시 열리지 않는다**(INV-4 · BF3).
- 사후(성공 · 불변식): `|처리| + |격리|`가 **변하지 않으므로** 완료 판정(**INV-3**)이 그대로 성립한다 — 승격은 추가가 아니라 **이동**이다.
- 사후(거절/만료): 자금 무변화 · 레코드는 격리에 남는다(= 미반영) · 승인 요청 `REJECTED`/`EXPIRED`.
- 사후(커밋 실패): 전체 롤백 — 승인 **미소비**. ★ ②(반영)와 ③(승격)이 갈리면 *"출금은 됐는데 배치는 미반영"* 이 되어 **재시도가 같은 레코드를 또 출금**하고 **어떤 대사도 잡지 못한다**(매입 배치 SM §5 재처리 절차).

## 3. 주요 성공 시나리오

1. 보류 해제 확인 — 대상 승인의 `frozen = false` (**UC-12** §3-5)
2. 담당자 A → C8 `request(격리 매입 재처리 승격, fileId·recordId)` — `PENDING` [ApprovalRequest **A1** · 감사 직접 append(AD-5)]
3. 책임자 B → C8 `approve(B)` — **B ≠ A** → `APPROVED` [**A2** · **INV-1**]
4. A가 재처리 배치를 지시 — 레코드마다:
   - ① **원 배치의 격리 목록에 있는가?** 없으면 이미 반영된 것이므로 **건너뛴다** [매입 배치 SM §5 · BR-50 멱등]
   - ② 반영 — `Account.capture(...)` · `Authorization.capture(...)` (부분 매입이면 `Card.restoreLimit`·`Account.restoreAccountLimit` — BR-24, 기준일이 다르면 복원 없음)
   - ③ `CaptureBatch.promoteIsolated(recordId, operator)` — 격리 → 처리 **원자 이동** [**B8**]
   - ④ C8 `consume(A)` 동기 호출 — 인자 일치(INV-3) · `executor = maker`(A4) [**R14**]
5. [E2 커밋] ②③④ + 부족분 `Receivable.incur(CAPTURE, …)` + 감사 outbox + 승인 `CONSUMED` — **같은 커밋**
6. 원 배치는 `COMPLETED` 유지 · 멱등 키는 원 `(fileId, recordId)` 승계 [BR-23]
7. 대사에서 정상화 — 보류 격리는 원래 M1(미매입)으로 잡히지 않았으므로 새로 닫을 불일치가 없다 [BR-50]

## 5. 대체 시나리오

- **없음 — 격리된 보류 매입을 반영하는 정식 경로는 이것 하나다.** 원 배치를 다시 여는 경로(`COMPLETED → PROCESSING`)는 **의도적으로 막혀 있다**(BF3 · INV-4) — 열면 이미 마감·정산된 영업일의 배치가 되살아난다. 매입사 재전송도 대체가 되지 못한다(§4-D 멱등에서 걸러진다). *(U-6 근거)*

## 6. 인가·감사 ★

- **판정 순서** (UC-02 §7 선례): ① **단계**(요청 = 담당자 / 승인 = 책임자 — `FORBIDDEN_LEVEL`) → ② **스코프**(★ **전사 스코프 보유 여부** — 지점 스코프면 여기서 거절, BR-55 특칙) → ③ **존재**(`NOT_FOUND`) → ④ **상태·사유**(§4-A·B·E).
- ★ **L7의 성질이 다르다**: 대상(매입 배치·레코드)에 **고객·조직 귀속이 없어** "남의 것"이라는 축 자체가 없다. 따라서 이 UC의 `NOT_FOUND`는 **부재만** 뜻하고, 존재 비노출은 **전사 스코프 단계 판정**이 대신 담당한다(단계 미달자는 대상을 조회할 수 없다).
- 판정 시점: 요청·승인·실행 각 진입 1회(AU-4).
- 감사(AD-2 경로 규칙): 요청·승인·거절·만료 = **C8 직접 append**(AD-5·6) / 실행 성공 = **E2 커밋 내 outbox** / 거절·실패 = **독립 커밋** / 유실 = **M18**(R16).
- 감사 항목(AD-8): 주체·시각·대상(`fileId`·`recordId`)·스코프(전사)·종류·결과 + **사유·요청자·승인자**. ★ `promoteIsolated`는 5조작 중 **마지막까지 `operator` 인자가 없던 조작**이었고(멀티테넌시 루프 2 F-07) 지금은 시그니처가 행위자를 받는다 — 감사가 실을 것이 있다.
- 승인 흐름: UC-02 §7의 **공통 승인 계약(U-7 정본)** 을 그대로 탄다.

## 9. 열린 의문

| # | 의문 |
|---|---|
| UC14-1 | ★ **스코프 축의 어긋남.** BR-55 특칙은 격리 승격을 *"고객·조직 귀속이 없는 관리 조작"* 으로 보아 전사 스코프로 두는데, 이 조작이 실제로 움직이는 것은 **특정 고객 계좌의 자금**이다. 전사 운영자면 어느 지점 고객의 출금이든 지시할 수 있다 — 정본대로 따랐으나 판정 재확인 필요 |
| UC14-2 | ★ **격리 사유 재분류 경로가 없다**(§4-F). 보류 중 원승인이 종료 상태(`VOIDED` 등)에 도달하면 반영이 F12로 막히는데, 격리 사유는 "보류"로 남아 승격 시도가 반복 실패한다. 실제 사유는 M8(무효 승인 매입)이며 **불일치로 올라가야 하지만**(BR-51) 사유를 바꾸는 조작이 `CaptureBatch`에 없다 — UC12-4와 같은 공백 |
| UC14-3 | 승인 SM **AU6 인용** — 재처리 배치의 **주기·트리거**(운영자 건별 지시인가 보류 해제 시 자동 재투입인가). 본 UC는 **건별 지시 + 건별 2인 승인**을 전제로 썼다. 자동 재투입으로 판정되면 승인 대상이 "레코드"가 아니라 "배치 실행"이 되어 §3·§7이 바뀐다 |
| UC14-4 | 승인 요청 1건이 **레코드 1건**인가 **묶음**인가. 보류 하나에 격리 레코드가 여럿이면 건별 승인은 운영 부담이 크고, 묶음 승인은 INV-3(인자 일치)의 인자 정의가 달라진다 — 계약 전수 패스에서 판정 |
| UC14-5 | 격리 상한(BR-28 `operation.freeze.max-duration`) 도달 시 이 레코드의 처리 — 자동 승격은 2인 승인을 우회하고, 방치는 대사가 계속 어긋난다. **미확정 수치에 묶인 정책 공백** |
