# UC-03. 내 잔액과 거래를 조회한다

- 작성일: 2026-08-05 · 상태: **확정**(파일럿 — 듀얼 1패스 반영, 2026-08-05)
- 액터: **고객**(카드소지자) — 첫 고객 대면 API. 전수 스캔 확인: 이 표면은 지금까지 존재하지 않았다.
- 권한 요건: 고객 = **자기 소유만**(BR-54·58). 운영자 조회는 별도 UC다(스코프 축 — 범위 밖).
- 트랜잭션 경계: **조회 — 경계 없음**(ADR-007: 조회 전용 경로 자유). ★ W-4: 자금 판단 결과를 반환하지 않는다(표시용).
- 관련 규칙: BR-31·54·57·58 · ADR-007 W-4 · ADR-016 AU-1~5 · ADR-017 AD-4 · ADR-018 IS-6 (참조만).

> 이 문서를 다 읽으면 **고객이 자기 잔액·거래를 어떻게 조회하고, 소유자 조건과 존재 비노출(L7)이 조회 계약에 어떻게 내장되는지**를 설명할 수 있어야 한다.

## 1. 목표

고객이 자기 계좌의 **가용잔액·계좌잔액**과 거래 내역을 본다.\
거래는 승인만 된 것과 매입 완료된 것을 구분해 보여준다(BR-31).

## 2. 사전·사후 조건

시작 조건은 하나다.\
요청자가 인증돼 있고, 주체·소유 계좌 목록이 요청 컨텍스트에 전파돼 있다(C7 · R4).

끝 상태는 조회라 자금·상태가 변하지 않고, 셋으로 갈린다.

- **성공** — 상태는 변하지 않고, 조회 사실이 감사에 남는다(BR-57 — 비동기 적재, AD-4).
- **거절** — 상태 무변화 + 거절 시도가 기록된다(독립 커밋).
- **감사 적재 실패** — ★ 조회 자체는 성공하되, 실패가 M18로 적재된다(AD-4 — 무음 유실 금지).

### 동작 구조

인증된 고객 요청이 소유자 조건 내장 조회 UC를 거쳐 두 저장소를 읽고 감사에 남는 경로다.

```
[고객]
   │ 인증된 요청 (주체·소유 스코프 전파 — R4)
   ▼
[C7 인증] ──▶ [조회 UC]  (소유자 조건이 계약에 내장 — AU-1)
   │
   ├──▶ [계좌 저장소] findById(id, requesterScope)
   │       → 가용/계좌 잔액 (표시용 — W-4)
   ├──▶ [거래 저장소] C1(입금·정정) + C3(승인·매입) 조립
   │       → 전순서 정렬·통합 커서 (BR-31)
   └──▶ [감사] 조회 사실 비동기 적재 (AD-4 · 실패 시 M18)
```

## 3. 주요 성공 시나리오

1. 인증된 요청 — 주체(고객)·소유 스코프 전파 [R4 · AU-3]
2. `GET .../balance` — **소유자 조건이 계약에 내장**된 조회 (`findById(id, requesterScope)` 형태 — AU-1)
3. 응답: 가용잔액 · 계좌잔액 (**표시용** — 이 값으로 자금 판단을 하지 않는다, W-4) [BR-31]
4. `GET .../transactions` — 승인/매입 구분 표시 · 커서 페이징 [BR-31 · phase-backlog 조회 기준]
5. 조회 감사 비동기 적재 [AD-4]

### 흐름도

조회 성공 흐름에 소유·페이징 경계 분기(§4 A~E)를 얹었다. 존재 비노출이 핵심이다.

```
[시작: 인증된 조회 요청]
   │  (미인증 → C7 인증 오류, 인가 이전 §4-B)
   ▼
⟨accountId가 소유 목록 안?⟩ ──아니오(타인/부재)──▶ [NOT_FOUND — 존재 비노출]
   │ 예                                        + 시도 기록 (L7·QS-08, §4-A)
   ▼
[GET .../balance] → 가용/계좌 잔액 (표시용 — W-4)
   │
   ▼
⟨cardId 필터 지정?⟩ ──타인/부재 카드──▶ [NOT_FOUND 동일] (2차 소유 L4, §4-A)
   │ 자기 카드 또는 없음
   ▼
⟨페이징 경계 정상?⟩ ──과대 size──▶ [상한 강제 — 전체 적재 금지] (§4-C)
   │ 정상          └─만료 커서──▶ [INVALID_CURSOR · 커서 재발급] (§4-C)
   ▼
[GET .../transactions] → 승인/매입 구분·다음 커서 (BR-31)
   │
   ▼
[조회 감사 비동기 적재] ──▶ (끝)
   │  (적재 실패 → 조회는 성공, M18 적재 — 무음 유실 금지, §4-D)
   ▼
(끝)
```

## 4. 예외 시나리오 ★

아래 표는 조회에서 갈라지는 다섯 예외의 트리거와 응답 코드의 대응이다.

| # | 트리거 | 응답 → 종결 | 근거 |
|---|---|---|---|
| A | 타인 계좌 식별자 지목 (IDOR — L2) | `NOT_FOUND` — 부재와 구별 불가 | BR-58 (L7) · QS-08 |
| B | 미인증 요청 | 인증 오류 (인가 이전) | R4 |
| C | 페이징 경계(과대 size·만료 커서) | 상한 강제 · 커서 재발급 | 리뷰 렌즈(자원) · 상한 [미정 — 수치 표] |
| D | 감사 적재 실패 | 조회 성공 + `M18` 적재 | AD-4 · R16 |
| E | 집계·목록 우회 시도 (L3·L4) | 같은 소유자 조건이 막는다 | BR-58 · C-3 |

네 갈래는 표에 담기지 않는 사정이 있다.

- **타인 계좌 지목(A)** — `NOT_FOUND`는 **존재 비노출**이다.\
  타인 소유 계좌가 부재 계좌와 응답으로 구별되지 않고, 거절 시도는 기록된다(L7 · QS-08).
- **미인증 요청(B)** — 인가 이전 단계라 A와 갈린다.\
  C7 소관의 인증 오류로 끝난다(R4).
- **페이징 경계(C)** — 과대 size·만료 커서는 상한을 강제하고 커서를 재발급하되, **전체 적재는 금지**한다(상한 수치 [미정]).
- **감사 적재 실패(D)** — 조회는 성공하고, 실패는 M18로 적재된다 — **조용한 유실을 금지**한다(AD-4 · R16).
- **집계·목록 우회(E)** — 목록도 합계도 같은 소유자 조건을 받으므로, **계약 형태 자체가** 우회를 막는다(BR-58 · C-3).

## 5. 대체 시나리오

카드별 거래 필터가 하나 있다 — 자기 카드 목록 안에서 좁힌, 같은 목표의 경로다.\
소유자 조건은 동일하다.

## 6. 인가·감사 ★

주체는 진입 시 한 번 판정한다(AU-4).\
고객은 자기 소유 계좌·카드만 볼 수 있고(AU-2), 판정은 인프로세스로 응답 예산 안에서 끝난다(AU-3).

L7은 §4-A에서 선다 — 이 UC가 **QS-08 전수 시험의 원형**이다.\
"내 것이 보인다"는 검증이 아니다.

조회도 감사에 남는다 — 근거가 셋 겹친다(감독규정 13조 ①8호 · 안전성기준 8조 · PCI 10.2.1).\
항목은 AD-8이다(주체·대상·스코프·결과).

캐시는 현재 없다.\
도입되면 키에 주체 범위가 필수다(IS-6 — 이 계약이 그 규정의 착지점).

## 7. 계약 (계약 블록)

#### `GET /me/accounts/{accountId}/balance` — 잔액 조회

| 항목 | 내용 |
|---|---|
| 주체 | 고객 (본인 — `me` 스코프. `accountId`가 소유 목록 밖이면 §4-A) |
| 요청 | 경로 파라미터만 |
| 응답(성공) | 가용잔액 · 계좌잔액 (BR-31 — 둘 다. **표시용** — W-4) |
| 오류 표 ★ | `NOT_FOUND`(부재 **= 타인 소유** — 동일 형태, L7) |
| 멱등 | 조회 — 자연 멱등 |
| 예산 | 실시간 조회 — 목표치 [미검증] (승인 경로 예산과 별개 — Phase 5 실측) |
| 감사 | 주체·계좌·"잔액 조회"·성공/거절 (AD-4 비동기 · 거절은 독립 커밋) |

#### `GET /me/accounts/{accountId}/transactions?cursor=&size=` — 거래 내역

| 항목 | 내용 |
|---|---|
| 주체 | 고객 (본인) |
| 요청 | 커서 · size(상한 [미정] — 강제) · 기간 필터 · cardId 필터(선택 — 아래 산문) |
| 응답(성공) | 거래 목록 — **승인만/매입완료 구분 표시**(BR-31) · 다음 커서 |
| 오류 표 ★ | `NOT_FOUND`(동일 형태 — L7) · `INVALID_CURSOR` |
| 멱등 | 조회 — 자연 멱등 (커서 = offset 아님 — backlog 조회 기준) |
| 예산 | [미검증] |
| 감사 | 잔액 조회와 동일 + 조회 범위(기간·카드 필터) |

`cardId` 필터는 표 밖 설명이 필요하다.

자기 카드 목록 안에서만 지정할 수 있는 **2차 소유 판정**이다(L4 — §5와 대응).\
타인·부재 카드는 `NOT_FOUND`으로 동일하게 응답한다(L7).\
C1 행(입금·정정)은 카드와 무관하므로, 필터를 걸면 제외됨을 응답이 고지한다.
