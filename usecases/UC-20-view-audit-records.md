# UC-20. 감사 기록을 조회한다

- 작성일: 2026-08-05
- 상태: **검토대기 (계약 블록 완결)**
- 액터: **운영자 책임자** (BR-55 배정 표 — *감사 기록 조회 = 책임자. 기록을 보는 행위도 남는다*)
- 권한 요건: **책임자** 단계 · 스코프 = **소속 조직 안**(대상의 스코프 축 — AD-8 스코프 필드 · IS-2 · BR-58 운영자 축). ★ **전용 감사 역할 분리는 Phase 4로 이월**(BR-55 배정 표 각주 — C7 모델과 함께) — 현 구조의 통제 공백은 §9 UC20-1
- 트랜잭션 경계: **조회 — 경계 없음**. 감사 저장은 **append-only이고 수정·삭제 조작이 존재하지 않는다**(AD-1)
- 관련 규칙: BR-10·54·55·57·58 · ADR-017 **AD-1·3·4·5·8** · ADR-016 AU-1~5 · ADR-018 IS-2·IS-6 · M18 · R16 (참조만)

## 1. 목표 (한 문장)

책임자가 **"누가 언제 무엇을 했는가"** 를 조건으로 조회해 사고 조사·감사 요구에 답한다.

## 2. 사전 조건 / 사후 조건

- 사전: 인증됨 · 단계 = **책임자** · 소속 스코프가 요청 컨텍스트에 전파돼 있다(R4 · AU-3).
- 사후(성공): 상태 무변화(조회). ★ **이 조회 자체가 감사에 남는다** — C8 자신의 조작이므로 **자기 저장소에 직접 append**한다(AD-5 — outbox 왕복이 자기 자신을 향할 이유가 없다).
- 사후(성공) ★ **재귀는 여기서 끊긴다** — 감사 append 행위 자체와 M18 적재 조작은 감사 대상이 아니다(BR-57 예외 · AD-5 재귀 차단). *"모든 조작"의 유일한 경계다.*
- 사후(거절): 무변화 + **거절 시도 기록**(독립 커밋 — AD-2).
- 사후(적재 실패): ★ **조회는 성공**하되 실패 사실이 **M18로 적재**된다(AD-4 · R16) — 무음 유실 금지.

## 3. 주요 성공 시나리오

1. 인증된 책임자 요청 — 주체·단계·스코프 전파 [R4 · AU-3 · AU-4 진입 1회]
2. 조건 조회 — **주체 · 대상 · 기간 · 종류 · 결과(성공/거절/실패)** [AD-8 필드]
3. **스코프 조건이 계약에 내장**된 조회 — 대상의 스코프 축(`ownerId`/조직)이 요청자 소속 안인 행만 [AU-1 · BR-58 · IS-2]
4. 결과 반환 — 목록·집계 **어느 형태든 같은 조건**이다(BR-58)
5. 2인 승인 조작(BR-56)의 행은 **사유·요청자·승인자**까지 포함해 반환 [AD-8 · BR-57]
6. 이 조회 사실을 C8 자기 저장소에 직접 append [AD-5]

## 5. 대체 시나리오

- **대상 축으로 좁힌 조회** — 특정 계좌·카드·승인 요청의 이력만 본다. 목표(누가 무엇을 했나)는 같고 진입 축이 다르며, **스코프 조건은 동일**하다(BR-58: 형태가 달라도 같은 조건).

## 6. 인가·감사 ★

- 주체 판정 순서: ★ **① 단계(책임자 — 자기 속성)** → **② 스코프·존재**(범위 밖 = 부재와 동일, L7) → **③ 조회 파라미터 유효성**. 판정은 진입 1회(AU-4), 인프로세스(AU-3).
- L7: **§4-B가 이 UC의 핵심 시험**이다 — *"내 조직 것이 보인다"* 는 검증이 아니다. **남의 스코프 식별자로 조회해 부재와 구별되지 않는지**를 본다(BR-58 검증 · QS-08).
- 감사: ★ **조회도 남는다**(BR-57 — 감독규정 제13조 ①8호가 조회·출력을 직접 통제 대상으로 둔다). 경로 = **C8 자기 조작이므로 직접 append**(AD-5), 실패 시 **M18**(AD-4). 거절 시도는 **독립 커밋**(AD-2).
- 항목: AD-8 — 멱등 키(`sourceRef` = 조회 요청 식별자 · AD-3) · 주체 · 시각 · 대상 · **스코프** · 종류 · 결과. 조회 범위(기간·필터)도 남긴다.
- 보존: 가동기록 **1년 이상**(확정) · 거래 관련 기록 **5년 범위**(상한 확정, 세부 분류는 **[미확정]** — 시행령 원문 미확인) [BR-57 수치].

## 7. 계약 (계약 블록)

> ★ **조회 UC이지만 통제 강도는 조작급이다** — 주체 = **책임자**(BR-55 배정 표: *기록을 보는 행위도 남는다*) · 스코프 = **소속 조직**(대상의 소유 축 — AD-8 · IS-2 · BR-58 운영자 축).
> ★ **BR-58은 전 형태에 같은 조건을 요구한다**(C-3) — 단건·목록·**집계**가 하나라도 새면 위반이다. 그래서 집계는 별도 표면이 아니라 **같은 계약의 응답 형태**다(신설 엔드포인트 없음 — C-6).
> ★ **이벤트가 없다**(§4-J) — C8 자기 저장소 **직접 append**이고 outbox를 타지 않는다(AD-5). 그래서 payload 유출 경로 자체가 없다.
> 오류 코드 3계층 = K-1 ⑴ 공통 4종 / ⑵ 해당 SM 없음(감사 저장은 append-only — 상태 전이가 없다, AD-1) / ⑶ 고유 신설 **없음**.

#### `GET /ops/audit-records?subject=&target=&type=&result=&from=&to=&groupBy=&cursor=&size=` — 조건 조회 (목록·집계 공통)

| 항목 | 내용 |
|---|---|
| 주체 | 운영자 **책임자** · **소속 조직 스코프** · 판정 = **진입 1회**(AU-4) · 인프로세스(AU-3) · 소속이 요청 컨텍스트에 전파(R4 · AU-3). ★ **확정 (D-UC20 — 축 없는 기록의 조회 자격)**: AD-8 스코프 값이 **`전사`** 인 행(대상이 영업일·outbox 레코드·배치 경로 — UC-15·18·19가 그렇게 적었다. K-4가 준 구체 앵커)은 ★ **전사 스코프 책임자에게만 보인다** — 지점 스코프 책임자의 결과에는 **나타나지 않는다**(빈 목록·집계 0으로, 부재와 구별되지 않는다 — ② 참조). 값이 정해졌으므로 조건도 정해진다(모든 책임자 공개도, 조회 대상 제외(감사 공백)도 아니다) |
| 요청 | `subject`(주체 — 개인 또는 **경로 식별자**) · `target`(대상 — ★ **대상 축 조회(§5)가 이 필터다**: 계좌·카드·승인 요청 이력. **별도 엔드포인트가 아니다**) · `type`(종류) · `result`(성공/거절/실패) · `from`·`to`(기간) · ★ **`groupBy`(집계 축 = 주체 / 종류 / 결과 / 일자 — 4종 한정 확정, D-UC20**: 카디널리티 폭발을 막는다. 축 추가는 계약 변경이다) · 커서 · `size`(상한 **[미확정]** — 강제. ★ **집계도 같은 상한을 공유한다**) |
| 응답(성공) | ★ **스코프 조건이 계약에 내장된** 행만(§3-3) — AD-8 필드 = `sourceRef` · 주체 · 시각 · 대상 · **스코프** · 종류 · 결과 (+ 조회 행은 **조회 범위**). ★ **2인 승인 조작(BR-56)의 행은 사유·요청자·승인자까지** 포함한다(§3-5 · BR-57). `groupBy` 지정 시 **건수 집계** — ★ **같은 스코프 조건**(C-3: 단건만 막고 합계가 새는 것도 위반) · 다음 커서 |
| 오류 표 ★ | **K-1 판정 순서** ① `FORBIDDEN_LEVEL` — **담당자·조회 단계**(§4-A. ★ 단계는 자기 속성이라 **대상 조회 전에 판정**된다: 단계 미달자는 대상 존재를 영원히 모른다) → ② ★ **오류가 아니다** — 스코프 밖 조건은 **그 행이 결과에 없다**(빈 목록 · 집계 0). **부재와 구별되지 않는다**(§4-B · L7 · AU-5 · QS-08) → ③ `INVALID_CURSOR`(만료 — 재발급) · `ARG_MISMATCH`(기간 역전·`groupBy` 미지원 축) · `size` 상한 초과는 **상한 강제**(§4-G — ★ **전체 적재 금지**) |
| 멱등 | 조회 — 자연 멱등 (커서 = offset 아님). ★ **기록 적재 쪽의 멱등**은 `sourceRef` = **조회 요청 식별자**(AD-3) — 같은 요청이 두 번 적재되지 않는다 |
| 예산 | 실시간 아님 — 목표치 **[미검증]**(§9 UC20-4 · UC-03 UC3-2와 같은 계열, QS 수치 대장 등재 대상) |
| 감사 | ★ **조회도 남는다**(BR-57 — 감독규정 제13조 ①8호가 조회·출력을 직접 통제한다) · 경로 = ★ **C8 자기 조작이므로 자기 저장소에 직접 append**(AD-5 — outbox 왕복이 자기 자신을 향할 이유가 없다) · 항목 = AD-8 + **조회 범위(기간·필터·`groupBy`)** · ★ **스코프 = 판정에 실제 쓰인 조직 값**(K-4) · ★ **확정 (D-UC20 — 자기 감사 보완)**: **자기 행위 기록 열람은 별도 종류(`type`) 값으로 기록**한다(전용 감사 역할 분리 전까지의 보완 — 계약 표면은 그대로이고 감사 항목의 종류 값만 갈린다. §9 UC20-1) · **거절 = 독립 커밋**(AD-2) · **적재 실패 = 조회는 성공 + M18 적재**(AD-4 · R16 — 무음 유실 금지, §4-D) · ★★ **재귀 차단**: 이 append 행위 자체와 M18 적재는 **감사 대상이 아니다**(BR-57 예외 · AD-5 · §4-E — 기록의 기록은 무한 회귀다. *"모든 조작"의 유일한 경계*) |

| 항목 | 내용 |

| 주체 | 운영자 **책임자** · 소속 조직 스코프 |
| 요청 | 경로 파라미터 `recordId`만 |
| 응답(성공) | 위와 같은 AD-8 필드 1건 |
| 오류 표 ★ | ① `FORBIDDEN_LEVEL`(§4-A) → ② `NOT_FOUND` — ★ **부재·스코프 밖 동일 형태**(L7 · §4-B. 단건이 목록보다 약하면 **ID 탐색 채널**이 된다) |
| 멱등 | 조회 — 자연 멱등 |
| 예산 | **[미검증]** |

#### (조작 부재로 강제되는 것) — ★ 계약에 **없는 것이 계약이다**

| 항목 | 내용 |
|---|---|
| 수정·삭제 | ★ **엔드포인트가 존재하지 않는다**(§4-C · **AD-1** — 변조 방지를 조작 부재로 강제. 원장 INV-2·BR-10과 같은 원리). `PUT`·`PATCH`·`DELETE` 표면을 두지 않는 것이 이 UC의 핵심 계약이다 |
| 이벤트 발행 | ★ **없다**(§4-J) — C8 자기 저장소 직접 append이며 outbox를 타지 않는다(AD-5). *이벤트 payload로 감사 기록이 새는가* 라는 질문 자체가 성립하지 않는다 |
| 보존·파기 | 가동기록 **1년 이상**(확정) · 거래 관련 **5년 범위**(상한 확정, 세부 분류 **[미확정]**) — ★ **확정 (D-UC20): 파기는 AD-1의 "삭제 조작 부재"와 다른 층이다**(보존 정책 실행 — 운영자에게 노출되는 삭제 표면은 여전히 존재하지 않는다) · ★ **파기 사실 자체는 남는다**(무음 소멸 금지 — 경과분은 조회 결과에 없지만 *"파기됐다"* 는 사실이 잔존한다, §4-F. UC20-3 닫힘) |
| 캐시 | ★ 도입 시 **캐시 키에 주체 범위가 반드시 들어간다**(IS-6 · §4-K) — 안 넣으면 남의 결과가 그대로 반환된다. 지금은 캐시가 없다는 것이 계약이다 |
