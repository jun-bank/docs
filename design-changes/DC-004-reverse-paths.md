## 1. 무엇이 깨졌나

Phase 3 리뷰에서 **치명 4건**이 나왔고 **전부 같은 뿌리**다.

| # | 결함 | 숫자 |
|---|---|---|
| **T1** | 정산 결과가 승인으로 돌아올 길이 없다 — M15 우변 정본 `settledBusinessDate`가 `SettlementCompleted` 도착 후 채워지는데, 커트오프에 **두 번째 게이트가 없다** | 매일 M15 1건 확정 |
| **T2** | 스냅샷 시점이 영업일 경계가 아니다 — 드레인은 이벤트를 멈추지 **코어 쓰기를 안 멈춘다** | 20분 창 × 80 TPS = **96,000건 허위** |
| **T3** | 위성 → 코어 이벤트 경로가 **어떤 ADR에도 없다** | BR-52 커트오프가 **실행 불가** |
| **T4** | 대사가 M9·M10·M11의 값을 **읽을 수단이 없다** | ★ **③ 예외 4건 중 3건의 탐지 붕괴** |

### 자금 보존은 깨지지 않았다

리뷰가 승인→매입→미수→환불→입금→정정→정산→원장→대사를 숫자로 굴려
**예치금 = 고객예금 = 계좌 balance, 미수금 0, 미지급금 0** 으로 닫히는 것을 확인했다.

> ★ **Phase 2 도메인은 건드릴 것이 없다. 깨진 것은 Phase 3이 새로 그은 이음매뿐이다.**

## 2. 뿌리 — 무엇을 안 봤나

**ADR-004는 "밖으로 나가는 경로"만 보고 "밖에서 안을 다시 보는 경로"를 안 봤다.**

컨텍스트 맵을 그대로 읽으면 방향이 전부 코어 → 위성이다:

```
R5·R6·R7  →  C5 원장     이벤트 (비동기 ACL)
R8        →  C4 정산     이벤트 (비동기)
R9        →  C6 대사     읽기 전용 (순응자)
```

**그래서 "위성은 이벤트만 받으면 된다"고 판단했다**(ADR-002 M-5).
그런데 실제로는 **되돌아오는 것이 셋 있다.**

| 되돌아오는 것 | 왜 필요한가 | 컨텍스트 맵에 있나 |
|---|---|---|
| 정산 결과 → 승인 (`settledBusinessDate`) | M15 우변을 채운다 · BR-21 | ❌ **없다** |
| 진짜 값 → 대사 | M9~M15를 계산한다 | ⚠️ R9가 *"읽기 전용"* 이라 했으나 **읽을 수단은 안 정했다** |
| 드레인 실패 → 운영 | M16 적재 | ❌ 없다 |

> ★ **컨텍스트 맵의 관계는 "누가 누구에게 말하는가"이지 "누가 누구를 읽는가"가 아니다.**
> **R9(순응자·읽기 전용)가 그 함정이었다** — *"읽기 전용"* 은 **쓰기를 안 한다**는 뜻이지
> **읽을 수 있다**는 보장이 아니다. 같은 프로세스일 때는 자명해서 아무도 묻지 않았다.

### 판정 절차를 적용하면 진단이 명확하다

DC-002·003이 세운 **상한을 쓸 때 묻는 네 가지**를 대사에 적용한다:

| 질문 | 답 |
|---|---|
| ① 좌변을 누가 드는가 | 계좌·카드 (③ 저장 필드) |
| ② 언제 바뀌는가 | 실시간 |
| ③ **우변을 계산할 정본이 실재하는가** | ★ **승인 `heldAmount`·`limitContribution` — 코어 안에 있다.** 대사는 밖이다 → **닿을 수 없다** |
| ④ 부분집합을 고를 키가 있는가 | ⚠️ 스냅샷은 **영업일**, M11 subject는 **달력일** → 어긋난다 (D9) |

> ★ **③이 "닿을 수 없는 정본"을 지목한 상태다.** DC-001이 *"등식을 적었는데 우변을 계산할 정본이 없다"* 를
> 흔한 실수로 등재했는데, **이번엔 정본은 있고 손이 안 닿는다.** 같은 결과다.

## 3. 선택지와 기각 이유

| # | 안 | T1 | T2 | T3 | T4 | 대가 |
|---|---|---|---|---|---|---|
| **A** | **C6 대사를 코어로 되돌린다** (배포 3) | ⚠️ 남음 | ✅ 해소 | ⚠️ 축소 | ✅ **해소** | 배치·실시간 자원 공유 |
| **B** | 위성에 역방향 이벤트·조회 API를 전부 신설 | ✅ | ❌ | ✅ | ⚠️ 사본 | ★ **대사가 사본을 본다 — 감사가 아니다** |
| **C** | 코어를 하나로 되돌린다 (ADR-001 A) | ✅ | ✅ | ✅ | ✅ | §0 학습 목적 후퇴 |
| **D** | 커트오프를 write barrier로 | ❌ | ✅ | ❌ | ❌ | 가용성 2순위 침해 |

### 기각

| 안 | 기각 이유 |
|---|---|
| **B** | ★ **대사가 사본을 보면 감사가 아니다.** 이 판단은 대화에서 **두 번** 확인했고, 그때마다 *"그럼에도 분리하자"* 로 갔다. 세 번째는 안 된다. 그리고 **사본이 맞는지를 또 대사해야 한다** |
| **C** | T1~T4가 전부 해소되지만 **ADR-005(Outbox)·ADR-008(파티션)이 다룰 것이 없어진다.** §0이 *"최대한 크게"* 를 요구하고, 이벤트 경계를 하나도 안 다루면 학습 목적이 무너진다 |
| **D** | 쓰기를 멈추는 것은 **가용성 2순위 침해**다. 그리고 T1·T3·T4를 못 푼다 |

## 4. 판정

### **A. 대사(C6)를 코어로 되돌린다 — 배포 단위 3개**

```
[실시간 코어]  C1 뱅킹 · C2 카드 · C3 결제 · ★ C6 대사   ← E1~E5 + 대사
[정산] C4      [원장] C5
```

### 왜 대사만 되돌리나

| 위성 | 밖에 있어도 되나 | 왜 |
|---|---|---|
| **C4 정산** | ✅ | 집계를 **받는다**. 되돌아갈 것은 `settledBusinessDate` 하나뿐이고 **이벤트로 충분**하다 (T1·T3은 경로만 신설하면 해소) |
| **C5 원장** | ✅ | append-only 수신. **되돌아갈 것이 없다** |
| **C6 대사** | ❌ | ★ **다섯 컨텍스트의 진짜 값을 동시에 읽어야 한다.** 이벤트로는 사본만 얻는다 |

> ★ **분할선은 "무엇이 나가는가"가 아니라 "무엇이 돌아와야 하는가"가 정한다.**
> ADR-004는 앞쪽만 봤다. 이것이 이 DC의 핵심 교훈이다.

### 무엇이 해소되나

| 결함 | 해소 방식 |
|---|---|
| **T2** 스냅샷 시점 | ★ **마감 스냅샷이 불필요해진다.** 대사가 코어 안이면 **한 읽기 트랜잭션**으로 M9~M14를 계산한다 — ADR-006 안 D가 원래 그 뜻이었다 |
| **T4** 대사가 값을 못 읽음 | ★ **소멸** — 같은 DB다 |
| **T1·T3** 정산 역방향 | ⚠️ **남는다.** 별도로 푼다 (§5) |
| **D7** 드레인 실패 통지 | ⚠️ 축소 — 대사가 코어 안이므로 **자기 DB에 M16을 적재**할 수 있다 |
| **D9** 달력일/영업일 | ⚠️ 남는다 — 스냅샷이 없어지면 **M11이 실시간 값을 보므로** 문제가 줄지만 확인 필요 |

### 대가

| | |
|---|---|
| **배치와 실시간이 자원을 공유**한다 | ADR-004가 안 A를 기각한 이유가 돌아온다 → **되돌리는 조건 R1** |
| ADR-006이 대부분 무효가 된다 | 커트오프·드레인은 **원장·정산 대사에만** 남는다 |
| `DailySnapshot` 애그리게이트의 역할 축소 | **폐기하지 않는다** — 원장 대사(M12·M14)에는 여전히 필요하다 (§5) |

## 5. 남는 것 — 별도로 푼다

**A가 T2·T4를 없애지만 T1·T3은 안 없앤다.** 정산·원장은 여전히 밖이다.

| # | 무엇 | 어떻게 |
|---|---|---|
| **N-1** | 정산 결과 → 승인 (`settledBusinessDate`) | **역방향 이벤트 경로 신설.** context-map에 **C4 → C3** 관계를 추가한다 |
| **N-2** | 커트오프 두 번째 게이트 | 정산 완료 후 **드레인을 한 번 더** 하고 M15를 검증한다 |
| **N-3** | 원장 대사(M12·M14)의 시점 | `DailySnapshot`을 **원장 대사 전용**으로 유지. 단 **T2를 다시 겪지 않게** 시점 확정 방법을 정한다 |
| **N-4** | M16 적재 주체 | 대사가 코어 안이므로 **자기 DB에 적재** |
| **N-5** | C7 인증의 배포 위치 | 코어에 넣는다 (R4가 **동기**다) |

> ⚠️ **N-3이 T2의 잔여다.** 대사가 코어 안이어도 **원장은 밖**이므로 M12·M14는 여전히 시점을 맞춰야 한다.
> **다만 범위가 4개에서 1개로 줄었다** — 계좌 잔액 하나만 맞추면 된다.

## 8. 절차에 남기는 것 ★

**이 실패의 형태를 기록한다.**

```

그것을 배포 경계로 옮길 때는 "누가 누구를 읽는가"를 따로 물어야 한다

```
