### R10 치명1이 실제로 무엇인가

```
BR-06     매입 반영 D+1 09:00
card.md   restoreLimit(amount, at)   기준일 불일치 = 무시(no-op) · 금액 초과 = 거절
```

승인일과 매입일의 기준일은 **정의상 항상 다르다.** 그래서:

| | 일어나는 일 |
|---|---|
| 복원 호출 | **항상 no-op** (기준일이 다르므로) |
| `limitContribution` | **무조건 감액** (산식에 조건이 없다) |
| 결과 | **모든 부분 매입이 RC-1 등식을 깬다** → M10·M11 허위 불일치를 매건 적재 |
| 더 나쁜 경우 | 그날 사용액 < 복원액이면 **거절 → E2 전체 롤백 → 매입 영구 미반영** |

8/3 승인 100 · 8/4 부분매입 40 → 복원 60이 무시되고 `limitContribution`만 40이 된다.
8/4 오전에 같은 카드로 20을 썼다면 `60 ≤ 20` 위반으로 매입 자체가 실패한다.

## 2. 뿌리 — 무엇이 없어서 반복되나

**"한도 기준일"이 모델 어디에도 필드로 없다.**

```
restoreLimit(amount, at)          at 이 무슨 날짜인가?
capture(amount, at)               at 이 무슨 날짜인가?
usage = 기준일 + 누적액            이 기준일과 위 at 의 관계는?
```

세 곳이 **암묵적으로 같은 날짜를 가정**하는데, 그 가정을 적은 곳이 없다.
그래서 한쪽을 고칠 때마다 다른 쪽의 가정이 깨진다 — **네 번 다 그 형태였다.**

> ⚠️ **BR-24는 이미 답을 갖고 있었다** — *"**해당 기준일**의 1일 한도 사용액에서 차감 복원"*.
> "해당 기준일"이 무엇인지 **모델이 표현하지 못했을 뿐이다.**

## 3. 선택지와 기각 이유

| # | 안 | 기각 이유 |
|---|---|---|
| **①** | **승인이 `limitBasisDate`를 든다** | **채택** |
| ② | 복원 조작이 *무시했는지*를 반환하고 승인이 그 결과를 보고 판단 | 두 애그리게이트가 서로의 반환값에 의존하게 된다. **카드와 계좌가 다른 답을 내면** 어떻게 할지가 또 열린다 — 둘의 기준일이 같다는 보장이 어디에도 없다 |
| ③ | BR-24에서 *"부분 매입"* 을 빼고 한도 복원을 취소·만료 경로로 한정 | 가장 단순하지만 **당일 매입 경로에서 고객이 손해**를 본다. BR-24 자신의 근거(*"복원이 없으면 고객이 묶인다"*)와 부분 충돌 |

## 4. 판정

**승인이 `limitBasisDate`를 필드로 든다.** 승인 성립 시 확정되고 이후 불변이다.

```
Authorization
  limitBasisDate     승인 성립 시 확정, 이후 불변
  limitContribution  그 기준일 한도에서 차지하는 몫

capture(amount, at)
  if at.영업일 == limitBasisDate:
      복원액 = limitContribution − min(매입액, limitContribution)
      Card.restoreLimit(복원액, limitBasisDate)
      Account.restoreAccountLimit(복원액, limitBasisDate)
      limitContribution −= 복원액
  else:
      셋 다 불변            ← 그 기준일 버킷은 이미 닫혔다
```

### 왜 이것으로 닫히나

| 명제 | 왜 참인가 |
|---|---|
| 지난 기준일을 안 건드려도 등식이 성립한다 | **RC-1이 *"그 기준일 승인들"* 한정**이다. 어제 승인은 오늘 `usage` 계산에 들어가지 않는다 |
| 지난 버킷이 틀린 채 남지 않는다 | `usage`는 **기준일이 바뀌면 0으로 시작**한다. 어제 버킷은 존재하지 않으므로 검증 대상이 아니다 |
| 한쪽만 움직일 수 없다 | 복원 호출과 `limitContribution` 감액이 **같은 조건 하나**를 공유한다 |
| 날짜 인자가 어긋날 수 없다 | 세 호출이 전부 **`limitBasisDate`라는 같은 값**을 받는다. `at`은 원장 영업일에만 쓴다 |

> ★ **`at`과 `limitBasisDate`를 가른 것이 이 변경의 전부다.** 매입 시각은 **원장 귀속 영업일**을,
> 한도 기준일은 **승인이 소비한 버킷**을 가리킨다. 둘을 한 인자로 쓰던 것이 네 번의 원인이었다.
